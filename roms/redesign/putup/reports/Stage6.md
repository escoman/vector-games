# Stage 6. Исследование главного игрового цикла

**ROM:** `./src/putup.rom`
**Метод:** Дизассемблирование + трассировка потока выполнения
**RDB объектов:** 68 (добавлено 7 новых)

---

## 1. Поток выполнения от запуска до игры

```
0x0100: func_rom_entry
  └─ JMP 0x0B57
0x0B57: func_main_init
  ├─ DI; SP=0x0100
  ├─ Очистка VRAM (0x8000-0xFFFF)
  ├─ CALL func_rom_init (0x0383)
  ├─ Установка [0x08DB] = 0x08B2, [0x08C3] = 0x09
  ├─ Очистка RAM (0x5000-0x53FF)
  ├─ CALL func_decompress (0x0401)
  ├─ Копирование данных из ROM (28 блоков × 8 байт)
  ├─ Инициализация переменных (0x08EB-0x08FB)
  ├─ CALL 0x3D4E (настройка)
  ├─ CALL 0x1BE5 (отрисовка)
  ├─ Отображение заставки (6 вызовов func_store_data_ptr + func_data_loader)
  │
  ├─ **lbl_title_key_poll (0x0C65)** ← цикл ожидания пробела
  │   ├─ LXI B, 0C00
  │   ├─ CALL func_keyboard_timer (0x017C)
  │   ├─ CMP M; JNZ 0x0C9D (клавиша нажата → выход)
  │   ├─ DCX B; ADD M; JNZ 0x0C68 (продолжить цикл)
  │   └─ Поиск данных (0x0C78-0x0C9A): скан 0x5180, поиск 0x75/0xFE
  │       └─ JMP 0x0C65 (повтор цикла)
  │
  ├─ **Нажатие пробела → 0x0C9D**
  │   ├─ CALL func_timer_init (0x3DCD) ← инициализация ВИ53
  │   └─ JMP func_level_init (0x197C)
  │
0x197C: func_level_init
  ├─ [0x08F5]++ (номер уровня)
  ├─ CPI 10 (проверка макс. уровня)
  ├─ Загрузка данных уровня из ROM (таблицы 0x1C0E/0x1C8E)
  ├─ Копирование в RAM через func_data_loader
  ├─ Инициализация игровых переменных (0x090D-0x0924)
  ├─ CALL 0x130A (подсчёт)
  ├─ Установка [0x0907] = 3, [0x090D] = результат
  └─ JMP func_game_main_loop (0x0E85)
```

## 2. Цикл ожидания пробела (0x0C65)

```asm
; lbl_title_key_poll (0x0C65)
0x0C65: LXI B, 0C00       ; B=12 (таймер), C=0
0x0C68: CMP L              ; A=0 (сброс)
0x0C69: PUSH B
0x0C6A: CALL 017C          ; func_keyboard_timer
0x0C6D: POP B
0x0C6E: CMP M              ; проверка результата
0x0C6F: JNZ 0C9D           ; клавиша нажата → выход
0x0C72: DCX B
0x0C73: MOV A, C
0x0C74: ADD M
0x0C75: JNZ 0C68           ; продолжить ожидание
; Поиск данных в 0x5180 (0x0C78-0x0C9A)
0x0C78: LXI H, 5180
0x0C7B: MVI B, 20          ; 32 итерации
0x0C7D: MOV A, M
0x0C7E: CPI 75             ; поиск маркера 0x75
0x0C80: JZ 0C90            ; найден
0x0C83: CPI FE             ; или маркер 0xFE
0x0C85: JNZ 0C95           ; не найден → следующий
0x0C95: INX H; DCR B; JNZ 0C7D
0x0C9A: JMP 0C65           ; повтор цикла ожидания
```

| Свойство | Значение |
|----------|----------|
| **Адрес** | 0x0C65–0x0C9A |
| **Условие выхода** | Пробел (SPACE) нажат → JNZ 0x0C9D |
| **Метод опроса** | func_keyboard_timer (0x017C) — IN 0x01, ANI 0x20 |
| **Таймер** | B=12 итераций, декремент через ADD M |

## 3. Переход к игре (0x0C9D)

```asm
0x0C9D: CALL 3DCD          ; func_timer_init
0x0CA0: JMP 197C           ; func_level_init
```

### 3.1. func_timer_init (0x3DCD)

Инициализация таймера ВИ53 (КР580ВИ53) через порт 0x08:
```asm
LXI H, 3DE8          ; таблица данных
LXI D, 03F8          ; адрес в RAM
LXI B, 0003          ; 3 итерации
DI
CALL 3DB8            ; копирование
EI
MVI A, 36            ; режим: счётчик 0, режим 3
OUT 08               ; записать в ВИ53
MVI A, 76            ; режим: счётчик 1, режим 3
OUT 08
MVI A, B6            ; режим: счётчик 2, режим 3
OUT 08
RET
```

| Свойство | Значение |
|----------|----------|
| **Порт** | 0x08 (ВИ53 control) |
| **Значения** | 0x36 (counter 0, mode 3), 0x76 (counter 1, mode 3), 0xB6 (counter 2, mode 3) |
| **Назначение** | Настройка всех 3 счётчиков ВИ53 в режим 3 (square wave) |

## 4. func_level_init (0x197C)

Инициализация уровня:

```asm
0x197C: LXI H, 08F5       ; номер уровня
0x197F: INR M              ; [0x08F5]++
0x1980: MOV A, M
0x1981: CPI 10             ; макс. 16 уровней
0x1983: JNC 1A3B           ; если >= 16 → альтернативный путь
; Загрузка данных уровня
0x1986: CMP L
0x1987: STA 090F           ; сохранить номер
0x198A: LXI H, 1C0E        ; таблица уровней (ROM)
0x198D: LDA 08F5           ; номер уровня
0x1990: RLC; RLC; RLC      ; × 8 (каждый уровень = 8 байт)
0x1993: MOV E, A
0x1994: MVI D, 00
0x1996: DAD D              ; HL += offset
0x1997: LXI D, 0911        ; приёмник в RAM
0x199A: LXI B, 0008        ; 8 байт
0x199D: CALL 1BC9          ; копирование
0x19A0: LXI SP, 0100       ; сброс стека
0x19A3: CALL 1BE5          ; отрисовка
; Инициализация переменных
0x19A6-0x19B8: вычисление адреса таблицы (0x1C8E + level × 0xB0)
; Копирование данных уровня (0xB0 = 176 байт)
0x19E9: MVI A, 10          ; A = 16
0x19EB: STA 091E           ; [0x091E] = 16 ← таймер "Hurry Up"
0x19EE: CALL 121A
0x19F1: MVI A, 01
0x19F3: STA 0901           ; [0x0901] = 1
0x19F6: INR A              ; A = 2
0x19F7: STA 0902           ; [0x0902] = 2
0x19FA: CMP L
0x19FB: STA 0900           ; [0x0900] = 0
0x19FE-0x1A22: копирование данных фигур (0x0913→0x091A, 0x0916→0x091B, ...)
0x1A22: CMP L
0x1A23: STA 0910
0x1A26: LXI H, 0000
0x1A29: SHLD 08E9          ; обнуление координат
0x1A2C: CALL 130A          ; подсчёт
0x1A2F: CMP L
0x1A30: STA 090D           ; результат → rows
0x1A33: MVI A, 03
0x1A35: STA 0907           ; [0x0907] = 3 ← сброс жизней на уровне
0x1A38: JMP 0E85           ; → func_game_main_loop
```

| Свойство | Значение |
|----------|----------|
| **Таблица уровней** | 0x1C0E (ROM, указатели) и 0x1C8E (данные) |
| **Размер уровня** | 8 байт (указатель) + 0xB0 = 176 байт (данные) |
| **Макс. уровней** | 16 (CPI 10 в BCD) |
| **Приёмник** | 0x0911 (RAM) |
| **Переход** | JMP 0x0E85 (func_game_main_loop) |

## 5. Главный игровой цикл (0x0E85)

```asm
; func_game_main_loop (0x0E85)
0x0E85: LXI B, 0001        ; начать с индекса 1
; === Цикл по B = 1, 2 ===
0x0E88: PUSH B
0x0E89: MOV A, C
0x0E8A: STA 090E           ; сохранить индекс
0x0E8D: LXI H, 0919        ; таблица состояний
0x0E90: DAD B              ; HL + B
0x0E91: MOV A, M           ; A = state byte
; Диспетчер состояний (CPI 1-10):
0x0E92: CPI 01; CZ 1489    ; state 1 → func_game_state1
0x0E99: CPI 02; CZ 14F9    ; state 2 → func_game_state2
0x0EA0: CPI 03; CZ 1568    ; state 3 → func_game_state3
0x0EA7: CPI 04; CZ 15DF    ; state 4
0x0EAE: CPI 05; CZ 164F    ; state 5
0x0EB5: CPI 06; CZ 16FC    ; state 6
0x0EBC: CPI 07; CZ 17A8    ; state 7
0x0EC3: CPI 08; CZ 1851    ; state 8
0x0ECA: CPI 09; CZ 18FE    ; state 9
0x0ED1: CPI 0A; CZ 191B    ; state 10
; После диспетчера:
0x0ED6: CALL 0CE0          ; func_game_loop
0x0ED9: MVI B, 02
0x0EDB: CALL 0EF7          ; func_vram_clear (B=2)
0x0EDE: POP B
0x0EDF: INX B              ; B++
0x0EE0: MOV A, C
0x0EE1: CPI 03             ; если B < 3 → повтор
0x0EE3: JC 0E88            ; цикл по B = 1, 2
; После цикла: swap 0x08F9 ↔ 0x08FA
0x0EE6: LDA 08F9
0x0EE9: MOV B, A
0x0EEA: LDA 08FA
0x0EED: STA 08F9
0x0EF0: MOV A, B
0x0EF1: STA 08FA
0x0EF4: JMP 0E85           ; бесконечный цикл
```

### 5.1. Структура цикла

```
┌──────────────────────────────────────────────────────┐
│ func_game_main_loop (0x0E85)                          │
│                                                        │
│  for B = 1 to 2:                                      │
│    state = [0x0919 + B]                               │
│    switch(state):                                     │
│      1 → func_game_state1 (0x1489)                    │
│      2 → func_game_state2 (0x14F9)                    │
│      3 → func_game_state3 (0x1568)                    │
│      4 → func_game_state4 (0x15DF)                    │
│      5 → func_game_state5 (0x164F)                    │
│      6 → func_game_state6 (0x16FC)                    │
│      7 → func_game_state7 (0x17A8)                    │
│      8 → func_game_state8 (0x1851)                    │
│      9 → func_game_state9 (0x18FE)                    │
│     10 → func_game_state10 (0x191B)                   │
│                                                        │
│    CALL func_game_loop (0x0CE0)                       │
│    CALL func_vram_clear (B=2)                         │
│                                                        │
│  swap [0x08F9] ↔ [0x08FA]                            │
│  JMP 0x0E85 (повтор)                                  │
└──────────────────────────────────────────────────────┘
```

## 6. Игровые переменные

### 6.1. Новые переменные

| Адрес | Имя | Размер | Назначение |
|-------|-----|--------|-----------|
| **0x08EF** | `var_lives` | 1 | **Количество жизней.** Инициализируется = 3 в func_main_init (0x0BB1) |
| **0x091E** | `var_hurry_timer` | 1 | **Таймер до "Hurry Up".** Инициализируется = 16 в func_level_init (0x19E9) |
| 0x08F5 | `var_level_counter` | 1 | Номер уровня (1-16) |
| 0x08E9 | (координаты) | 2 | Позиция фигуры (обнуляется при инициализации) |
| 0x0907 | `var_lives_level` | 1 | Сброс жизней на уровне (= 3 в func_level_init) |
| 0x090D | (rows) | 1 | Количество рядов |
| 0x090E | (loop index) | 1 | Текущий индекс цикла (1-2) |
| 0x090F | (level copy) | 1 | Копия номера уровня |
| 0x0910 | (level data) | 1 | Данные уровня |
| 0x0911-0x0924 | (level data) | 20 | Данные уровня (приёмник из ROM) |
| 0x08F9/0x08FA | (swap vars) | 1+1 | Обмениваются значениями каждый цикл |

### 6.2. Таблица состояний (0x0919)

Адрес 0x0919 — таблица байтов состояний. Для каждого индекса B (1-2) читается байт `[0x0919+B]`, который определяет вызываемый обработчик.

## 8. Данные уровней

### 8.1. Таблица указателей (0x1C0E)

Каждый уровень описывается 8-байтной записью:
```
Уровень 0: [8 байт] → указатель на данные
Уровень 1: [8 байт] → указатель на данные
...
Уровень 15: [8 байт] → указатель на данные
```

Адрес вычисляется: `HL = 0x1C0E + level × 8`

### 8.2. Данные уровней (0x1C8E)

Каждый уровень = 0xB0 (176) байт данных:
```
Адрес = 0x1C8E + level × 0xB0
```

Данные копируются в RAM по адресу 0x0911.

## 9. Ключевые выводы

1. **Цикл ожидания пробела** — 0x0C65–0x0C9A. Опрашивает клавиатуру через func_keyboard_timer, ищет маркеры 0x75/0xFE в данных 0x5180.

2. **func_timer_init (0x3DCD)** — настраивает ВИ53 (порт 0x08) в режим square wave для всех 3 счётчиков.

3. **func_level_init (0x197C)** — загружает данные уровня из ROM-таблиц (0x1C0E/0x1C8E), инициализирует переменные, передаёт управление в func_game_main_loop.

4. **Главный игровой цикл** — 0x0E85. Бесконечный цикл с диспетчером состояний (10 состояний), вызовом func_game_loop и func_vram_clear.

5. **10 обработчиков состояний** — каждый вызывается по условию (CPI 1-10). Состояния управляют различными аспектами игры (движение фигур, вращение, очистка рядов и т.д.).

6. **Данные уровней** — 16 уровней, каждый 176 байт в ROM (0x1C8E+), копируются в RAM (0x0911+).

7. **RDB обновлён**: 68 объектов (+7 новых: func_game_main_loop, func_timer_init, func_level_init, var_level_counter, func_game_state1-3).

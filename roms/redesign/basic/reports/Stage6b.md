# Stage 6b — Таблица пользовательских переменных, векторы, DATA/FOR

Продолжение Stage 6 (п.6 ТЗ): формат таблицы переменных, её указатель, указатель
`DATA` (`READ/RESTORE`), размещение `FOR`-счётчиков и роли служебных векторов.
Итог: **+4 объекта `variable`** (547→551) + обогащение ролей/комментариев у 3
существующих (`var_free_limit`, `var_stack_ptr`, `var_type_flag`). Round-trip
**byte-for-byte identical** (17152 байт, 6/6 стадий SUCCESS).

---

## 0. Метод: статика + живое чтение (REPL-ввод не усваивается)

Эти ячейки автостарт-демо **не трогает** (их нет в 46 рантайм-патчах): демо
рисует PLOT/COLOR/CLS и не создаёт переменных/строк, не вызывает GET/PUT.

Попытка живой проверки через REPL:
- В boot-программе текста нет (область `0x4301` = нули) — `COLOR15,0,1:CLS`
  выполняется из буфера `0x3F77` в immediate-режиме, поэтому STORE-переменные не
  создаются;
- PC постоянно в `0x2Cxx/0x32xx` — Вектор-06Ц **непрерывно перерисовывает экран
  силами CPU**; интерпретатор опрашивает клавиатуру только между кадрами, и
  короткие импульсы `debug_type_key` в этом харнессе не снимаются матричным
  сканированием (набранные `A=40` в буфер `0x3F77` не попали).

Поэтому подтверждение — **статика** (инициализация в `main_loop`/boot +
функции-потребители) плюс **живое чтение указателей** отладчиком:
```
0x0CB3 (var_free_limit / vartab) = 0x4303
0x0C33 (var_program_end)         = 0x4303   => vartab == program_end => таблица пуста
0x03E7                           = 0xFFFF   (cold-сентинел, не двигался)
```
Совпадение `0x0CB3 == 0x0C33 == 0x4303` — прямое живое доказательство, что
переменные аллоцируются сразу за текстом программы и сейчас их нет.

## 1. Формат таблицы переменных (главный вывод)

Разбор `func_var_lookup 0x0BCD` и аллокатора слота `0x0C45..0x0C84`:

- **Запись = 6 байт:** `[имя: 2 байта][значение: 4 байта]`. Обход таблицы шагает
  по 6: `LXI D,0006` … `DAD D` (`0x0C45`, `0x0C54`). Сравнение имени: байт записи с
  `C` (2-й символ, `0x0C49`), затем с `B` (1-й символ, `0x0C4F`).
- **Имя — 1..2 буквы A..Z.** Первый символ — через токен: `MVI A,BF / ADD B /
  CPI 1A` (`0x0BCE`); второй — `SUI 41H / CPI 1A` (`0x0BF5`). Для `'A'`(0x41):
  `0xBF+0x41=0x100→0x00 < 26` OK; для `'Z'`(0x5A): `→0x19=25 < 26` OK.
- **Тип.** Строковый флаг по `$`: `CPI 24H` (`0x0BEB`/`0x0C1B`) → `MVI A,01 / STA
  0C8C`; иначе `XRA A / STA 0C8C` (число). Числовой/строковый флаг — в
  `var_type_flag 0x0C8C`.
- **Вершина таблицы = `var_free_limit 0x0CB3`.** Создание новой переменной
  (`0x0C62..0x0C71`): `LHLD 0CB3` → `LXI B,0006 / DAD B` (+6) → проверка места
  (`CALL 003B`) → `SHLD 0CB3`; слот обнуляется (`DCX H / MVI M,00 / RST 20`).
  То же значение — нижняя граница free: guard оценщика `LHLD 0CB3 / SUB L / JC
  0069` (out-of-memory), FRE читает её. **Переименован семантически** в отчёте как
  *vartab-указатель* (имя `var_free_limit` оставлено — это и есть граница free).
- **Парный указатель значения — `0x0C8B`** (адрес найденного/созданного слота,
  пишут `func_cmd_dim`/`0x01C5`, читают `0x0C90/0x0CC1/...`). Объектом НЕ заведён:
  `SHLD 0C8B` покрывает байты `0x0C8B..0x0C8C`, т.е. **пересекает**
  `var_type_flag 0x0C8C` → нарушил бы «один объект на адрес». Задокументирован.

## 2. DATA, RESTORE и FOR — отдельных ячеек нет

- **DATA/READ (`func_cmd_read 0x0869`, `func_cmd_data 0x0679`).** `func_cmd_data`
  сканирует текст до стоп-маркеров `:`(0x3A) и `"`(0x22) (`LXI B,3A22`), работая
  по текущему текстовому указателю. `func_cmd_read` позиционируется через самомод
  `LXI H,0000 … STA 0882` и разбор имени (`CALL 0BCD`). **Выделенной ячейки
  DATA-указателя в workspace нет** — позиция данных идёт через
  `var_text_ptr 0x404D` / `var_stmt_ptr 0x0464`; `RESTORE` = перемотка к началу
  программы (`var_program_base`).
- **FOR-счётчики.** Не отдельная ячейка: 17-байтные блоки FOR кладутся на
  интерпретаторский **стек `var_stack_ptr 0x0625`** (`CALL 0x01E8` создаёт блок),
  рядом GOSUB-маркер `0x8C`. `NEXT` (`func_cmd_next`) ищет блок на стеке. Роль
  добавлена в комментарий `var_stack_ptr`.

## 3. Служебные векторы и окно строк (новые объекты)

| ячейка | имя | размер | роль | доказательство |
|---|---|---|---|---|
| `0x0ED3` | `var_string_window` | 2 | окно строчной аллокации | FRE (`lhld 0ed3`), `func_str_window`/`0fe9`/`0f51` двигают; init `label_01B0` рядом с `var_stmt_ptr` |
| `0x0609` | `var_step_vector` | 2 | вектор подпрограммы шага | main_loop `LXI H,0619/SHLD 0609`; трамплин `MVI A,C3/STA 0608` (`JMP [0x0609]`) |
| `0x05D1` | `var_resume_vector` | 2 | вектор возобновления | main_loop `LXI H,05E1/SHLD 05D1`; трамплин `STA 05D0` (`JMP [0x05D1]`) |
| `0x3559` | `var_getput_ptr` | 2 | рабочий указатель блока GET/PUT | метки `0x34xx/0x35xx` (lda/lhld/shld ×9) в обработчиках GET `0x3441`/PUT `0x357f` |

Примечание: `0x0608`/`0x05D0` — байты опкода `JMP` (`0xC3`) тех же трамплинов,
т.е. **самомод-код**, объекты `variable` там не заводим.

## 4. Осталось неклассифицированным

- `0x03E7` — `LXI H,FFFF / SHLD 03E7` в main_loop (сентинел рядом со стеком);
  пишется `func_error_stub`/`label_03C7`, читается `lbl_1aca`. Роль (второй
  указатель/адрес останова) не доказана — объект не создаём.
- `0x0C8B` — см. §1 (пересечение с `var_type_flag`).
- Прочие ячейки из Stage 6 §5 (`0x086C`, `0x2D04/07/0B`, `0x3A1F/0x3A22`, `0x2B3E`,
  `0x2CB1`, `0x2DD8`, `0x3DB3`, `0x3DC6`) — семантика не установлена.

Живое подтверждение роста vartab и печатного формата имени требует исполнения
программы **с переменными** — в данном харнессе ввод через MCP-клавиатуру не
усваивается (§0); структура доказана аллокатором кода и живым `vartab==
program_end==0x4303`.

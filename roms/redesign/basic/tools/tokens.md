# Карта токенов BASIC 2.997 (Вектор-06Ц) — токен ↔ ключевое слово ↔ обработчик

Рабочий чек-лист Stage 5. Декодируется из образа `src/basic.r0m` напрямую:
таблица ключевых слов `data_keyword_table` = `0x256E..0x26D6` (101 слово,
кодировка «байт на символ, bit7 = конец слова»), **токен = `0x80` + номер слова**.
Источники имён: собственные обработчики Stage 2 + официальные ключевые слова из
`Basic_Vector-06C.pdf` (Бейсик v2.5, Приложение 1 и §3 «Классификация»).

Сверка с документом (Приложение 1, коды внутреннего представления): из 89
слов документа **85 совпали** с таблицей ROM точно; `FOR`/`LLIST` в PDF —
OCR-ошибки (в ROM авторитетно `FOR=0x81`, `LLIST=0xDB`); `SPC(`/`TAB(` в ROM
хранятся со скобкой (`0x9F`/`0x9D`). Диапазон токенов ROM `0x80..0xE4` =
диапазон кодов документа. Авторитет при расхождении — всегда ROM.

Статус: `✓` — обработчик доказан и именован (Stage 2/3); `→S5` — имя известно
из документа, обработчик ещё не вскрыт (диспетчер команд, открытый пункт).

## 4. Как регенерировать

```
PYTHONPATH=utils python3 roms/redesign/basic/tools/dump_tokens.py  # токен ↔ слово из data_keyword_table
```

Таблица слов `0x256E`, 101 слово. При расширении RDB (Stage 5) отмечать `→S5`
как `✓` и обновлять адрес/имя обработчика. Имена `func_cmd_*` — предварительные
(по стандарту нейминга `func_` + слово); фактические подтверждать по телу.

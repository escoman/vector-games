# Nu, pogodi! — что проверено и что ещё нужно проверить

Порт с Phaser-JS (`src/scene_play.js`) на Вектор-06C. Два ROM'а сборки:
`nu_pogodi.rom` (КР580ВИ53) — 27 849 Б (27,3 КБ), запас до 32 КБ 4919 Б,
`nu_pogodi_ay.rom` (AY-3-8910) — 27 794 Б, запас 4974 Б (`make consist` для
ВИ53-варианта; из ~1400 Б стоят звуки `lib/snd/sfx.c` + таблицы эффектов: до
`sfx.c` запас был 6780 Б).

## Как собирать и прогонять

```sh
make -C roms/games/nu_pogodi                      # сборка nu_pogodi.rom
make -C roms/games/nu_pogodi consist KEEP_MAP=1   # состав ROM + карта nu_pogodi.map
make -C roms/games/nu_pogodi deploy               # в каталог ROM'ов PPSSPP-эмулятора
```

### Пайплайн ассетов (`tools/gen_assets.py`)

ИСХОДНИКИ (правятся руками в GIMP, сборка их НЕ перезаписывает):
- `src/screen.bmp` — поле + панель, 256×256, 4-битный BMP с настоящей векторной
  палитрой; БЕЗ призраков. Индексы пикселей = слоты палитры.
- `src/sprites/*.bmp` — 48 спрайтов 1× (WYSIWYG), чёрный штрих на белом.

ГЕНЕРИРУЕМОЕ (в `.gitignore`, не править руками):
- `src/bg.inc` — плоскости `bg_zx0`; призраки накладываются на поле из масок
  спрайтов при генерации. Палитры здесь НЕТ.
- `src/sprites.inc` — битмапы сегментов из `src/sprites/*.bmp`.

Финальная палитра — `bg_palette[16]` в `main.c` (`V06_RGB`), правится без
регенерации ассетов.

```sh
make -C roms/games/nu_pogodi assets               # создать screen.bmp + sprites/*.bmp, если их нет
make -C roms/games/nu_pogodi assets FORCE=1       # пересоздать с нуля (сотрёт ручную правку!)
python3 tools/gen_assets.py inc                   # bg.inc + sprites.inc из исходников
python3 tools/gen_assets.py preview               # preview.png — composed-фон как в ROM
```

Функциональная проверка на `v06c-mcp` (нужна карта, поэтому сначала
`consist KEEP_MAP=1`):

```sh
python3 tools/npg_check.py boot            # меню: состояние, слоты, инвариант плоскости, PNG
python3 tools/npg_check.py menu            # заставка: волк ходит от клавиш, инвариант плоскости
python3 tools/npg_check.py play [кадров]   # Ф1 и N кадров автоигроком с инвариантом
python3 tools/npg_check.py remap           # Ф3 и четыре назначения клавиш
python3 tools/npg_check.py keys            # снимок матрицы клавиатуры
python3 tools/check_sfx.py [кадров]        # привязка звуков: тик/клик/гудок + трель конца игры
```

Скриншоты падают в `.scratch/shots/npg_*.png` (яркость = вес пикселя по
плоскостям). Клавиши в эмуляторе: ↖ = `F7`, СТР = `F8`.

### Привязка звука к событию — как в `src/scene_play.js`

Эталон — не имена файлов `src/sounds/*.wav`, а места вызова `.play()` в JS.
По ним на одно нажатие клавиши приходится ОДИН звук, а четыре файла
`lu/ld/ru/rd` относятся к движению яйца (а не к волку):

| Событие | Звук в JS | Вызовов | У нас |
|---|---|---|---|
| сдвиг жёлоба, в котором есть яйцо (`needSound = groove[0]+…+[4]` после `GrooveTurn`) | `lu/ld/ru/rd.wav`, по файлу на жёлоб | 4×4 | `fx_move` в `turn()` — ОДИН общий чпок (903→638, 2 кадра), приоритет 5 |
| любое нажатие назначенной клавиши волка — в заставке, в игре, во время анимации и после проигрыша | один и тот же `click` | 8× (4 клавиатуры + 4 тач-зоны) | `fx_click` (приоритет 20) в `input()`, вне проверки `state` |
| яйцо в корзине (`IncreaseScore`) | `catch` | 1× | `fx_catch` в `groove_turn()` |
| яйцо разбилось / цыплёнок / мигание возвращаемой жизни | `miss`, 7 миганий в `AddLivesAnimation` | 9× (`StartEggBrokeAnimation`, шаг 1 `ChickenAnimation`, 7 шагов `AddLivesAnimation`) | `fx_miss` — `sfx_play()` в `start_egg_broke()`, `start_chicken()`, в зажигании шага `anim_addlives_tick()` |
| `lifeCount <= 0` → `ST_LOOSE` | `gameover` | 1× | `fx_loose` (приоритет 100) |

Почему «один общий чпок», а не четыре высоты: `git log --diff-filter=A --
src/sounds/` показывает, что WAV'ы приехали в самом первом скелете порта
(коммит 2c7b8a1) — это современные сэмплы веб-порта, а не звуки ИМ-02.
Замер спектра (`measure_wav.py`) подтверждает: lu/ld/ru/rd — широкополосные
чпоки 0,1…0,22 с без различимой основной высоты (у lu пик скачет 899/1633/
2753 Гц), так что четыре разных ноты из них не извлекаются: различие файлов
в веб-порту — его artifact, а не звук игры.

Почему всё тональное: тот же вывод по `miss.wav` — это реально записанное
разбивающееся яйцо, а не гудок пьезоизлучателя. Раз «как в игре» из ассетов
не следует, шумовой путь (Tape Out + `.smp`) удалён, а «разбилось» делается
гудком с падением на ВИ53 — тем же способом, что и трель конца игры.

## Осталось проверить

### Только глазами (эмулятор с RGB-выходом или железо)

1. **Интерлейсинг фона на реальном экране.** В BMP порядок пар верный, но
   вывод Y-плоскостей на ЦАП/лампе — то, что автоматикой не доказывается.
2. **Клавиши ↖ и СТР на настоящей клавиатуре Вектора.** В эмуляторе это
   F7/F8; на железе у этих клавиш другой скан-код, и именно они стоят по
   умолчанию для «влево-вверх» и «вправо-вверх».
3. **Мигание подписи при переназначении** (каждые 16 кадров то стирать, то
   рисовать) — не слишком ли часто/редко, не дёргается ли текст у кнопки.
4. **Панель кнопок** (req1,2,4,5,6): круглые кнопки (светлый обод, красная
   середина) с чёрной стрелкой на ободе к своему углу поля, логотип
   «Ну, погоди!» приподнят в середине. Подписи клавиш — СВОИМ кириллическим
   шрифтом (src/font.asm, транслит: код `R` рисует Р): `DOM`→`ДОМ`,
   `STR`→`СТР`, `<-`, `->`. Проверить глазами на RGB-выходе: красный слот
   черепицы/кирпичей/гребешков отличается от коричневого насестов; верх поля
   (крыша) не обрезан (поле сдвинуто на 28 строк); текст подписей и верхняя
   строка Ф-клавиш не наезжают на кнопки/логотип и не оставляют хвоста при
   смене контекста (все три строки верхнего меню по 29 символов).
5. **Старт игры без перерисовки фона** (req7): фон распаковывается один раз
   (`bg_load` по флагу `bg_ready`), переход меню↔игра трогает только
   плоскость сегментов (`screen_reset`). Проверить, что при Ф1/Ф2 поле
   появляется мгновенно и следов старого текста меню не остаётся.
6. **Табло при полном счёте**: цифры — сегменты спрайтов (не текст),
   4 разряда; счёт > 9999 в оригинале не растёт дальше — проверить,
   что старший разряд не обрезается.

### Автотесты, которых ещё нет

7. **Целиком раунд**: `eggs_needed` → смена раунда (`rounds`), рост
   `speed16`/`factor5`, и главное — **проигрыш**: `life_count == 0` →
   сохранение рекорда и возврат в меню, затем старт второй раз без мусора в
   слотах.
8. **Анимации** `anim_broke`, `anim_chicken`, `anim_addlives`, `anim_blink`:
   покадрово проверить, что все слоты возвращаются в исходное состояние
   (ни «висящих» кусков в плоскости после стирания).
9. **АП2 в игре**: сейчас это не пауза, а выход в меню с сохранением рекорда
   (верхняя строка при этом подписана «AP2 PAUZA» — либо править подпись,
   либо делать настоящую паузу).
10. **Ф3 во время игры**: игра должна замирать (`update()` не вызывается), а
    после отмены — продолжаться без «проглоченного» кадра и без лишнего
    движения яйца.
11. **Обмен местами при коллизии**: назначить на «влево-вверх» клавишу СТР и
    убедиться, что освобождённая ↖ ушла в тот слот, который держал СТР, и
    обе клавиши работают как новые.
12. **Бюджет кадра**: замерить, сколько кадров в секунду реально держит игра
    в самые тяжёлые моменты (одновременно волк + заяц + курица + табло).
    Распаковка 24 КБ фона (`bg_load`) — ~55 кадров (~1,1 с) — теперь
    однократна при первом входе в меню, на старте игры не повторяется
    (req7). На железе время может отличаться.
    **Первый замер сделан** (`.scratch/measure_music_tempo.py`, свободный прогон
    без точек останова): заставка живёт на **24,4 кадра/с** вместо 50 — итерация
    главного цикла стоит ~41 мс (2,1 кадра луча, ~126 000 T-состояний при бюджете
    59 904). VBL при этом 48,8 Гц, то есть тормозит не эмулятор, а сама игра.
    Следствия, которые ещё не разобраны: (а) `FRAME_MS = 20` в `main.c` не
    соответствует действительности — все таймеры игры (тик жёлоба, анимации,
    скорость падения) идут примерно вдвое медленнее задуманного; (б) темп
    мелодии тоже считается на 50 Гц, поэтому он скомпенсирован вручную (п.13);
    (в) в бою кадр может быть ещё тяжелее — там ход волка с двумя большими
    перекладками сегментов, отдельного замера боя нет (в прошлый раз точка
    останова на каждый кадр сама тормозила CPU, и цифры были неверны).
    Что с этим делать — не решено: оптимизировать отрисовку или признать
    ~25 Гц и пересчитать `FRAME_MS`.
13. **Музыка заставки**: партитура `src/sounds/title.mus` (3 голоса, правится
    руками; `title.mid` — только точка импорта `make mus`) играет, пока
    мы в меню/аттракте; при старте игры (`F1`/`F2`) замолкает, после возврата в
    меню — снова играет. Зациклываем штатно (`music_set_loop(1)`): движок сам
    переставляет потоки на начало по MUS_END; выдержка между повторами заложена
    в хвосте самих партитур (паузы), отдельной паузы в коде нет. Ударные молчат
    (партия пустая, а с удалением Tape Out `drum_tick()` из главного цикла
    вообще не вызывается — партитуру это не трогает: тон ведёт `music_tick()`).
    Вывод — по флагу сборки: `nu_pogodi.rom` на КР580ВИ53, `nu_pogodi_ay.rom` на
    AY-3-8910 (`-DMUSIC_AY_DRUMS_AY` + `lib/snd/ay.c` вместо `vi53.c`, как в
    `roms/musics/mk`); выбираются обе цели одним `make`.
    Варианты мелодии лежат в `src/music/` (Grok, «под Вектор»): `titleA`,
    `titleA_loop`, `titleB`, `titleB_loop` + прежняя `title`. `make mus
    TITLE=<имя>` кладёт выбранный трек в `src/sounds/title.mid` и импортирует
    его (аккуратно: затирает ручную правку партитуры). Сейчас на заставке
    `titleA`.
    **Темп.** Движок считает тики из 50 кадров/с, а цикл их даёт 24,4 (п.12), то
    есть без правки мелодия играет вдвое медленнее записанной. Важно: `midi2mus
    --tempo` скорости НЕ меняет — при импорте длины в тиках и тиков/кадр
    масштабируются вместе. Скорость задаёт строка `Tempo:` уже в готовом `.mus`
    (движок берёт из неё num/den, длительности нот остаются), поэтому `make mus`
    импортирует на сетке T118 и тут же правит заголовок на `TEMPO` (по умолчанию
    242 = 118 × 50/24,4). Проверено: полный цикл мелодии в заставке вышел **47,7 с**
    вместо ~96 с (`.scratch/measure_music_tempo.py` ловит возврат `g_ch[0].pc` к
    началу партитуры) — это ровно те ~24 такта на 118 уд/мин, что в MIDI. Дальше
    уточнять темп смысла нет: он и так в пределах слышимости, а цифра 24,4 всё
    равно плывёт вместе с нагрузкой. Если кадр починят до 50 Гц (п.12), `TEMPO`
    надо вернуть к ~118.
14. **Звуки игры на слух** (`lib/snd/sfx.c`, три независимых тональных голоса —
    в ВИ53-варианте это каналы КР580ВИ53, в AY-варианте A/B/C со
    фиксированной громкостью `SFX_AY_VOLUME` = 12; Tape Out не используется
    вовсе): движение яйца — один общий чпок на
    каждый сдвиг жёлоба с яйцом (903→638, 2 кадра, низкий приоритет 5 — на
    максимальной скорости тик идёт каждые ~4 кадра, длинный звук их бы «съел»);
    клавиша волка — один и тот же клик (717/957 — заведомо вне чпока и поимки,
    чтобы на слух отделялся); поймал — короткий свип вверх (`catch`); разбилось,
    цыплёнок, мигание возвращаемой жизни — гудок с падением (`fx_miss`:
    784/587 Гц попеременно по 2 кадра, хвост 392→~320 Гц, 16 кадров);
    конец игры — трель ~1,3 с со спадом (`gameover`; хвост сделан глайссандо
    +100 к делителю в кадр — знаковое поле `detune`, больше 127 не влезает).
    Проверить на слух: похож ли гудок «разбилось» на ИМ-02 (выбрано руками,
    эталона нет), не лижет ли чпок мелодию в заставке (в меню каналы общие с
    музыкой — атакующая нота партитуры перебивает эффект), не обрывается ли
    трель при выходе в меню, и хватает ли кадра на `sfx_tick()` в самые
    тяжёлые моменты (см. п.12). Высоты и длительности правятся в `step_move`,
    `step_miss`, `step_click`, `step_catch` (`main.c`, ~470…530). Автоматикой
    не покрыто только одно: что `fx_miss` играет именно при мигании
    возвращаемой жизни (тот же вызов, что и «разбилось», — достигнуть бонусной
    жизни в прогоне на 400 кадров не удалось).

15. ~~**Что рисует x=184, y=104…106 в игре**~~ — **разобрано, починено** (см.
    таблицу «Инвариант плоскости в игре»): это была не отрисовка, а игра —
    корзина вытирала пиксели живого крайнего яйца в общем слое 0xE000.
    Перепись всех пар спрайтов показала ровно три таких перекрытия (15, 3 и 1
    пиксель), все — корзина ↔ крайнее яйцо; цифры табло перекрываются только
    внутри своего разряда, то есть в одном слоте. Починено адресно
    (`overlap_mate()`), а не перебором 32 слотов: generic-перебор стоил ровно
    одного дополнительного кадра луча на каждый кадр с идущим волком

16. **Тернарный оператор с `||` в условии компилируется навыворот** (ловушка
    sccz80, на ней держался баг «разбилось слева — скорлупа справа»). В `groove_turn`
    стояло `broken_side = (position == POS_LU || position == POS_LD) ? SIDE_LEFT
    : SIDE_RIGHT`; дизассемблирование (`groove_turn` в ROM, ~$5B07) показало, что
    для `position = 0` (LU) нулевой флаг уходит в ветку, где остаётся `HL = 1`, и
    в `broken_side` пишется `SIDE_RIGHT` — инвертированно для всех четырёх
    положений. Правка — арифметика вместо тернарника:
    `broken_side = (unsigned char)(position >> 1)` (тот же приём, что
    `wolf_body[position >> 1]`). Проверено адресно на всех четырёх лотках
    (`.scratch/diag_side_all.py`). **Что с этим делать:** таких тернарников на всё
    дерево репозитория ровно один (искали грепом `? .*\|\|`), но при правке
    любого ROM надо держать в голове: условие из двух равенств через `||` внутри
    `?:` лучше заменять сдвигом/таблицей. Симптом — поведение ровно наоборот при
    явно верном исходнике, и никакая логика вокруг не виновата.

### Известные ограничения (это не баги)

- **Звуки подобраны руками, а не сняты с ИМ-02.** `src/sounds/*.wav` —
  современные сэмплы Phaser-версии (коммит 2c7b8a1): треск разбитого яйца там
  буквально записанное разбивающееся яйцо. Поэтому высоты взяты только как
  ориентир (максимум спектра по кадрам 50 Гц), «разбилось» переделано в
  тональный гудок с падением, а шумовой путь удалён: `src/sounds/*.smp` и
  `src/miss_smp.inc` в ROM не входят (`SFX_SMP` пуст), `sfx_hit()` в
  библиотеке больше нет. Если появится аутентичная запись ИМ-02 — таблицы
  `step_*` в `main.c` перезаписываются по ней, движок трогать не нужно
  (`tools/check_sfx.py` при этом меняет только имена таблиц, предсказания по
  ОЗУ остаются те же).
  Тайминг игры от звука не зависит — всё на счётчике кадров.
- **Рекорды не выводятся на экран** (`draw_scores` убран, req6): `hiscore[]`
  ведётся внутренне (`save_hi_score`) и сгорает при выключении —
  энергонезависимости у Вектора нет.
- **Сдвиг спрайтов по горизонтали кратно 8 пикселям** — следствие формата
  сегмента (колонка VRAM = 8 пикселей). Плавного хода по X нет ни у волка,
  ни у зайца.
- **Кадр 256×256, один цветной слой**: фон занимает только чётные индексы
  палитры, поэтому спрайты выводятся в свободную плоскость веса 1
  (`gfx_plane_or` / `gfx_plane_andn`). Текст всегда рисуется цветом 8 —
  другим цветом он стирал бы фон под собой.

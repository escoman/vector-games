# putup — распакованная ROM `PUTUP_NEW.ROM` (games/putup)

Адресно-точная реконструкция оригинала `src/putup.rom` (asm-ветка Stage 12
[`redesign/putup`](../../redesign/putup)) с **вынесенной из ROM распаковкой**:
блок из 256 глифов (8192 Б) лежит в ROM распакованным, загрузчики выведены из
исполнения. Две стадии:

| | этап A | этап B (итог, с Фазой 1) |
|---|--------|---------------|
| блок глифов | RAM-адрес распаковки 0x6000 (исторический) | ROM по `GLYPH_BASE` (одна константа), итог **0x4600** |
| текстовый back-буфер | 0x5000..0x53FF (исторический) | **перенесён на 0x6600..0x69FF** (Фаза 1): окно над глиф-блоком, дыра 0x4600..0x55FF схлопнута |
| мёртвые блоки | на исторических адресах | выжжены: `func_load_glyph_block`, `func_load_gfx_2761`, `data_packed_font_3041`, `data_gfx_2761` |
| копир спрайтов | исполняется (пишет в снимок те же байты) | выжжен NOP-ами (0x0B86, 34 Б) — вестигий: reader у 0x7418 отсутствует |
| образ | 32512 Б | 25856 Б (0x100..0x65FF) |

## Сборка

Дефолт — **компактный** образ (Фаза 2, `COMPACT=1`, 21768 Б, GLYPH_BASE=0x3608).
Дефолт смещён в compact осознанно: образ и дальше будет уходить от оригинала,
поэтому главный гейт корректности — **сравнение экранов и поведения**
(`compare_color.py` — раскрашенная картинка; `compare_behavior.py` — VRAM/глифы
/порты), а не побайтовый diff. Побайтовый A/B-режим Фазы 1 —
`make COMPACT=0` (25856 Б, byte-exact `[0x0100,0x45FF)`, GLYPH_BASE=0x4600).

```bash
make                        # PUTUP_NEW.ROM компактный (21768 Б, 0x100..0x5607, GLYPH_BASE=0x3608)
make verify                 # compact: byte-exact [0x0100,0x2761) + инвариант чистого сдвига new_addr выше
python3 tools/lint_ptrs.py  # линт символьных ссылок (glyph_base/режим из dead_ranges.json)
make deploy / make full     # стандарт проекта (finally.mk) — собирает и деплоит компактный образ
python3 tools/compare_behavior.py --new PUTUP_NEW.ROM --glyph-base 0x3608 --label B
                            # поведенческий гейт orig→new→orig: VRAM/глифы title/play1/play2 (см. ниже)
python3 tools/compare_color.py --new PUTUP_NEW.ROM
                            # цвет-гейт orig↔new: раскрашенный экран title/play1/play2 = 0 расхождений (Фаза 3)

# Побайтовый A/B-режим Фазы 1 (byte-exact весь код):
make COMPACT=0              # 25856 Б, GLYPH_BASE=0x4600
make COMPACT=0 verify        # побайтовая сверка 0x0100..0x45FF
make COMPACT=0 GLYPH_BASE=0x6000 KEEP_DEAD=1   # регрессия этапа A
make layout                 # перегенерировать компоновку (asm/putup_unpacked.asm + gap-бины)
```

Перенос блока = одна константа `GLYPH_BASE`. Изначально кандидат 0x4600 был
отбракован: read-only окно глифов наезжало на текстовый back-буфер
`data_ram_buffer_5000` (0x5000..0x53FF), который пишется каждый кадр. **Фаза 1
устранила блокировку**: буфер перенесён на 0x6600 (выше блока), база стала
единственной константой переноса, и `GLYPH_BASE=0x4600` легален — дыра
0x4600..0x55FF схлопнута, образ с 29952 Б сократился до 25856 Б. Оригиналы
`putup.rom`/`putup.rdb` не дублируются — читаются из
[`redesign/putup/src`](../../redesign/putup/src). Сборка не оставляет
промежуточных файлов, кроме `tools/dead_ranges.json`.

## Фаза 1: перенос текстового буфера (0x5000 → 0x6600)

Текстовый back-буфер (32×32 кодов символов) — чистая runtime-RAM: обнуляется
`func_main_init`/`func_clear_textbuf`, пишется каждый кадр (HUD, текст). Пока
он сидел на 0x5000, read-only глиф-блок не мог опуститься ниже 0x5600 (окно
8192 Б наезжало на буфер). Фаза 1 переносит буфер на 0x6600 — сразу за хвостом
образа (0x100+25856 = 0x6600), то есть в RAM над глиф-блоком.

Поверхность связки базы 0x5000 сведена к одной EQU-константе `data_text_buffer`:
- **20 литералов позиции курсора** `LXI H,5xxxh` (6 файлов) → `LXI H,data_text_buffer+ofs`
  (ofs = значение − 0x5000);
- **4 символьных ссылки на базу** (`func_game_update`, `func_coords_to_textbuf`,
  `func_clear_textbuf`, `func_main_init`) → `data_text_buffer`;
- **константа `LXI B,0B000h`** в `func_render_glyph` (= 0x10000 − база, перевод
  адреса буфера в линейный индекс клетки) → `LXI B,textbuf_to_vram` (= `0 - data_text_buffer`).

`make verify` легализует релокацию по строгой сигнатуре: при дельте базы +0x1600
меняется ровно ВЫСШИЙ байт операнда (курсоры 0x50..0x53 → +0x16; render 0xB0 →
0x9A); любой иной diff — провал. A/B-регрессия (`make GLYPH_BASE=0x5000` на
старой базе) даёт reloc=0 — доказательство, что символическая перетасовка
байт-точно эквивалентна оригиналу. Итог: reloc=25 (20 курсор + 4 база + 1 render).

Копир спрайтов (`func_main_init` 0x0B86..0x0BA7) остаётся ВЫКЛЮЧЕННЫМ: он писал
`data_sprites_2F61 → 0x7418`, но (а) reader у 0x7418 в ROM отсутствует, (б)
источник читается ВНИЗ от 0x2F61 (DCX D) в хвост `data_gfx_2761`, обнулённый как
мёртвый пакет. Это остаток распаковщика — поведенческий снимок подтверждает:
VRAM побайтово совпадает с оригиналом и без копира (0x7418 инертен).

## Фаза 2: компакция мёртвых пакетов (relocation-модель)

Компоновщик умеет второй режим `COMPACT=1`: две мёртвые data-дыры внутри кодовой
зоны вырезаются из образа вовсе, а верхняя половина сдвигается вверх. Экономия
~4 КБ: 25856 → **21768 Б** (дыры 2048 + 2041 = 4089 Б, плюс глиф-блок опускается).

Модель адресации (`new_addr` в `tools/gen_layout.py`):

```
new_addr(a) = a          для a < 0x2761            (нижняя зона — byte-exact не тронута)
            = a - 2048   для 0x2F61 <= a < 0x3041  (между-дырный гэп — живые спрайты)
            = a - 4089   для a >= 0x383A           (весь код/данные после 2-й дыры)
```

Дыры: `data_gfx_2761` = `[0x2761,0x2F61)`, `data_packed_font_3041` = `[0x3041,0x383A)`.
Между-дырный интервал `[0x2F61,0x3041)` (224 Б живых спрайтов) сдвигается на −2048.
Новый `code_end_new = new_addr(0x4600) = 0x3607`, блок поднимается вплотную:
`GLYPH_BASE = 0x3608`, образ `[0x0100,0x5608)`.

Жертва: компоновщик перестаёт быть verbatim-реконструктором для `a >= 0x2761`.
Побайтовая эквивалентность сохранена только для `[0x0100,0x2761)`; выше —
гарантия переносится на **поведенческую сверку** (gate) + структурный инвариант
`verify` (см. ниже).

Что сделано:
- **Символизация сырых abs-ссылок в перемещаемую зону** (иначе `new_addr` их не
  поймает): `LXI H,421Ah`→`data_music_period_table` (нотная таблица промоутнута из
  gap-verbatim в `asm/data/`), `3DCAh`→`data_pad_3DCA`/`3DC5h`→`func_memcpy_trampoline`
  (trampoline `DW func_music_tick` — цель тика переезжает сама), `3890h`→`func_music_sub_3890`
  (gap-подпрограмма промоутнута в именованный слот), `3BC9h`→`var_music_voice2_flag_hi`.
- **Relocate-якоря** `var_music_*` / `data_voice_param_buf` / `var_music_voice2_flag(_hi)`
  больше не EQU-литералы: их адреса пишет компоновщик в генерируемый
  `asm/var_reloc_anchors.asm` (= `new_addr` оригинала; verbatim = исходный адрес).
  Инициализированные значения (var-init блок `0x383A..0x3857`) — часть образа,
  едут вместе с кодом; встроенные 16-бит указатели потоков (`pointer_sites`
  `0x383F/0x3841/0x3843/0x3854/0x3856`) переписываются на `new_addr` при эмиссии.
- **Assert-ловушки** в компоновщике: перемещённые RAM-якоря и `data_text_buffer`
  (0x6600, Фаза 1 — выше компактного блока) не пересекают read-only окно
  `[GLYPH_BASE,GLYPH_BASE+8192)`; `GLYPH_BASE >= code_end_new`.
- **RDB**: исходный `redesign/putup/src/putup.rdb` НЕ мутируется; компакт-режим
  эмитирует `putup_compact.rdb` (адреса/ссылки `>=0x2761` через `new_addr`, объекты
  внутри дыр удалены; RAM-артефакты `data_glyph_block`→`GLYPH_BASE`,
  текстовый буфер→0x6600 — не сдвигаются `new_addr`).

Инвариант `verify` (компакт): длина == 21768; нижняя зона byte-exact; выше
`0x2761` — каждый байт обязан быть равен оригиналу на `new_addr⁻¹`, кроме
16-бит операндов/указателей, значение которых перемещается согласованно
(`new_word == new_addr(orig_word)`); filler до `GLYPH_BASE` — нули. На текущем
образе: 123 операнд-фиксапа + var-init указатели, **0 необъяснённых расхождений**.

Первичный гейт картинки — `compare_color.py` (раскрашивает 4 плоскости через
палитру каждой ROM и сравнивает ИТОГОВЫЕ ЦВЕТА orig↔new на совпадающих
CPU-кадрах, фазы title/play1/play2): **0 расхождений цвета / 65536** на всех
фазах — картинка побайтово идентична, несмотря на инверсию E000 (см. Фазу 3).

Поведенческий гейт — `compare_behavior.py` (три прогона orig→new→orig, фазы
title/play1/play2, синхронизация по CPU-кадрам beam state): до Фазы 3 VRAM
(32768) и глиф-блок (8192) совпадали **0 расхождений**. После инверсии E000
байтовый diff new↔orig РОВНО равен следу инверсии: VRAM 8192/32768 (целая
плоскость 0xE000) и глифы 2048/8192 (чанк 24..31 × 256). Это ожидаемо и
покрывается цвет-гейтом; сравнение compact↔verbatim остаётся 0 расхождений
(общий изменённый блок глифов). Скретч music-state и `.scratch/behavior_phase2.py`
(textbuf/glyph/VRAM на заставке) — справочно. Деплой/прогон — `make full` (дефолт compact).

Caveat по музыке: io-трек порта music на заставке у реконструкции отличается от
`orig` (~0.54 jaccard) ОДИНАКОВО и в compact, и в verbatim, тогда как
compact-музыка ↔ verbatim-музыка совпадают **1.000**. Значит это свойство
реконструкции Фазы 1, а не регрессия компакции. Ио-трек к оригиналу как гейт
НЕ использовать — только цвета (`compare_color.py`) и compact↔verbatim.

A-регрессия сохранена: `COMPACT=0` = прежний verbatim-режим Фазы 1 (byte-exact
25856 Б по коду); `make COMPACT=0 verify` требует побайтовой точности кода, а
таблица палитры 0x08A3..0x08B2 разрешена как осознанное отхождение в обоих режимах.

## Фаза 3: инверсия плоскости E000 + компенсация палитрой

Осознанное расхождение с оригиналом (продолжение ухода от verbatim). Плоскость
0xE000 — младший бит индекса цвета (вес 1, LSB); в оригинальном снимке её чанк
(байты 24..31 каждого 32-байтного глифа) хранился комплементом (фон глифа-0 =
0xFF, из-за чего плоскость E000 выглядела «инвертированной»). Сделано:
- **Глифы** (`asm/data/data_glyph_block_unpacked.asm`): XOR 0xFF по байтам
  24..31 у всех 256 глифов → фон E000 = чистый 0x00.
- **Палитра** (`asm/funcs/func_render_glyph.asm`, таблица 0x08A3..0x08B2):
  перестановка соседних пар слотов `PAL'[j]=PAL[j^1]` (0↔1, 2↔3, …, 14↔15):
  old `00 00 30 7B C9 DA 0D F2 0F A7 37 3F 21 DE AD FF` →
  new `00 00 7B 30 DA C9 F2 0D A7 0F 3F 37 DE 21 FF AD`.

Компенсация точна: инверсия LSB меняет индекс `I→I^1`, а `PAL'[I^1]=PAL[I]` —
итоговый цвет каждого пикселя не меняется. Незанятые пиксели (все плоскости 0)
тоже идентичны, т.к. `PAL[0]=PAL[1]=0x00`. Гейт — `compare_color.py`
(0 расхождений цвета на title/play1/play2). Побайтовые расхождения new↔orig в
VRAM/глифах равны следу инверсии и разрешены в `verify_image.py` (allow-list
палитры 0x08A3..0x08B2; содержимое блока глифов verify не сверяет).

## Стадия 1 (поверх Фазы 3): текст — в одну плоскость

Анализ расхода памяти: 163/256 глифов одноканальные (1 бит/пиксель), из них 128
букв хранят один и тот же битмаст во всех 4 плоскостях (цветовой индекс 15 =
`0b1111`). Чтобы буква писалась ОДНОЙ плоскостью, её цвет должен стоять в
однобитном индексе {1,2,4,8}; но все они заняты спрайтами под другие цвета, поэтому
простой перестановки палитры мало — нужна глобальная перемаркировка индексов.

Сделано (транспозиция цветов 15 <-> 8, та же механика, что Фаза 3, но над
произвольной перестановкой индексов):
- **Глифы**: пиксель idx15 -> idx8 (только `0x8000`), idx8 -> idx15, фон idx0 не
  трогаем. Текст (128 букв) стал одноплоскостным: `0x8000` = маска, `A000/C000/E000` = 0.
- **Палитра** (`0x08A3..0x08B2`): свап слотов 8 и 15 (`slot8=0xAD` — серый текста).

Компенсация точна: цвет пикселя = `PAL'[sigma(i)] = PAL[i]`, итоговая РАСКРАШЕННАЯ
картинка побайтово идентична (гейт `compare_color.py`: 0 расхождений цвета;
плоскость `w8` против orig вообще не изменилась). Единственный производитель
color-индексов — блок глифов (VRAM чистится в 0; text_buffer/tile_table хранят
КОДЫ глифов, не цвета) — поэтому перестановка безопасна. Открывает компакцию
1-битного шрифта в формат «маска 8 Б + цвет» (Стадия 2, в работе).


## Как это работает

Оригинал на старте распаковывает шрифт в RAM 0x6000..0x7FFF
(`func_load_glyph_block`, вызов из `func_main_init` @0x0B83). В PUTUP_NEW этот
CALL запатчен в 3×NOP, а распакованный блок — побайтовый снимок RAM пост-иниц
оригинала (вербатим через MCP, стабильность подтверждена двумя снятиями) —
вкомпонован по `GLYPH_BASE` и читается как ROM. Таблица указателей
`data_glyph_ptr_table` (0x0600, читается страницей: `MVI H,06h` — позиция
закреплена кодом) собрана символично `DEFW data_glyph_block+N*32`, поэтому
переезд блока не требует правки её байтов.

## Инструменты

| | |
|---|---|
| `tools/gen_layout.py` | компоновщик: мастер-asm с inline DEFB для гэпов + `tools/dead_ranges.json`; `COMPACT=1` — relocation + `putup_compact.rdb` |
| `tools/get_glyph_block.py` | снятие блока 0x6000..0x7FFF через MCP (вербатим → DEFB в asm) |
| `tools/verify_image.py` | `make verify`: verbatim (байт-точность) / compact (byte-exact низ + инвариант чистого сдвига) |
| `tools/lint_ptrs.py` | этап B: абсолютные ссылки на удаляемые/смещаемые адреса (+ RDB-сверка) |
| `tools/compare_behavior.py` | поведенческая сверка orig→new→orig: VRAM/глифы/порты по CPU-кадрам (Фаза 1) |
| `tools/compare_color.py` | цвет-гейт orig↔new: 4 плоскости → индекс цвета → палитра, сверка раскрашенного экрана (первичный гейт после Фазы 3) |
| `.scratch/behavior_phase2.py` | behavioral гейт Фазы 2: textbuf/glyph/VRAM orig↔compact на совпадающем кадре |

Подтверждение корректности: `make verify` (байты) + поведенческие прогоны
`compare_behavior.py` (ориг→new→ориг, заставка/play1/play2): VRAM 0/32768
расхождений — совпадает с шумовым полем оригинал-против-оригинала; глиф-окно
стабильно, записей в игру нет. Все данные — побайтовыми DEFB в `asm/` (без
bin-артефактов); карты уровней — отдельные файлы `data_level_01..15.asm`
(1 DEFB-строка = 1 ряд уровня, 16 тайл-индексов), включаемые `data_level_maps.asm`
последовательно; глиф-блок — 2 строки на глиф с номером и адресом.

## Структура `asm/`

- `asm/funcs/` — код: `func_*` и точки входа `lbl_*`;
- `asm/data/` — данные: `data_*` (в т.ч. `data_level_*.asm`, `data_glyph_block_unpacked.asm`)
  и строковые константы `str_*` (в RDB тип `string` — категория данных);
- `asm/var_ram_symbols.asm` — EQU-алиасы RAM-переменных; `asm/putup_unpacked.asm` —
  мастер-компоновка (генерируется, include-и с префиксами `funcs/` и `data/`).

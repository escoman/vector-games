# Техническое задание на деассемблирование файла TESTAY.ROM

## Stage 0

Изучаем документацию по Вектор-06Ц в docs/VECTOR_VERIFIED.md

Префиксы объектов:
- функции - "func_"
- блоки данных - "data_"
- текстовые строки - "str_"
- музыкальные дорожки (ноты) - "music_"
- одиночные переменные - "var_"

Суффиксы объектов:
- для объектов с пока неизвестным предназначением - "_unknown". 
- у объектов, назначение которых установлено, суффикс "_unknown" убираем.

Важное примечание. Никаких дополнительных скриптов не писать для пост-обработки полученных от MCP-сервера данных. Если что-то неверно делает или возвращает MCP-сервер, то проверить ещё раз и, убедившись в ошибке, остановиться и сообщить пользователю о найденной ошибке.

## Stage 1. Общее исследование карты памяти, активности программы в чтении/записи

1) Запускаем ROM (reset не нужен)
2) Ожиданием 5 секунд, пока программа отработает
3) Не останавливая эмуляцию, анализируем карту памяти на наличие данных, активность по чтению/записи блоков памяти
4) Ставим эмуляцию на паузу, анализируем данные по обращениям к портам
4) Сохраняем промежуточный отчёт в ./reports/Stage1.md

## Stage 2. Исследование и выгрузка функций

Открыть на mcp-сервере программу ./src/TESTAY.ROM, исследовать её, найти и выгрузить абсолютно все функции в папку ./asm/. По мере исселедования заполняем ROM Database (RDB). Установить параметры каждой функции и добавить в properties. Установить связи между функциями (links). Определить назначение всех используемых переменных и блоков памяти и добавить в RDB. Для всех найденных объектов заполнить комментарий по назначению объекта. По завершению сохранить RDB-файл.

Написать отчёт по выполненной работе и сохранить его в ./reports/Stage2.md

## Stage 3. Сборка нового TESTAY_NEW.ROM из исходников в ./asm/

Собрать новый ROM. При необходимости подкорректировать экспортированные функции в ./asm и в RDB.

Конечная цель: получить программу, которая работает также как исходный ./src/TESTAY.ROM, пусть даже со сдвинутым адресным пространством. TESTAY_NEW.ROM не обязана получиться байт-в-байт как TESTAY.ROM

Начальный указатель стека передвинуть на 0x8000 вместо 0xC300.

Написать отчёт по выполненной работе и сохранить его в ./reports/Stage3.md

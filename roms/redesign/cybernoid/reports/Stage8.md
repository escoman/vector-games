# Stage 8 — Игровые данные: уровни, спрайты, паттерны (обзорно)

## Постановка

Каталог игровых данных cybernoid: таблица паролей/уровней (`3.PASS`),
спрайтовая база, переменные игры (SCORE/LIFE/STAGE). Scope — обзорный,
без глубокой семантики движения/коллизий (TZ §Stage 8).

## Метод

Дизассемблирование обработчиков экранов (screen_pass@0x020A, screen_start@0x02F6,
screen_load@0x0FA5) для выхода на указатели данных; чтение памяти EXEC
(`debug_read_memory_range`) для подтверждения структуры таблиц.

## Факты

### 1. Таблица паролей/уровней (data_password_table @0x264D)

Обработчик экрана 3.PASS (`screen_pass@0x020A`) загружает `LXI B, 0x264D` @0x020F.
По адресу 0x264D — 0-терминированные строки с разделителем `%` (0x25):

| Адрес | Содержимое |
|---|---|
| 0x264D | `START\0` |
| 0x2653 | `ROOM%%\0` |
| 0x265A | `KISS%%\0` |
| 0x2661 | `LEFT%%\0` |
| 0x2668 | `CLEAR%%\0` |

Записью `0x266F` — нулевой паддинг. Размер таблицы ~36 байт. Используется для
отображения имени текущего уровня/пароля на экране 3.PASS.

### 2. Спрайтовая база (data_sprites_base @0x4000, кандидат)

Память @0x4000 содержит структурированные байт-паттерны:
- Симметричные последовательности: `220 231 220 231 220 231` (пиксельные маски).
- Битовые структуры: `3 128`, `7 64`, `7 128` (вертикальные/горизонтальные линии).
- Повторяющиеся блоки ~16 байт (возможно, 8x8 или 16x16 спрайты).

Точная раскладка (количество спрайтов, размер, порядок) не установлена —
глубокий разбор вне scope Stage 8.

### 3. Переменные игры (SCORE/LIFE/STAGE/LEVEL/FIRE)

HUD выводится через `func_video_frame_out@0x0F45` (Stage 5). Точные адреса
переменных (`var_score`, `var_lives`, `var_stage`) не каталогизированы —
находятся в RAM-области после распаковки (0x1000-0x2500). Горячий блок
`memory_access_map` во время игры: 0x1700 (fetch 6.77M — внутренний цикл/растер),
0x1100 (2.55M), 0x1400/0x1500/0x1000.

## Итог в RDB

Новые объекты:
- `data_password_table` @0x264D (Table, 36B) — таблица паролей/имён уровней.
- `data_sprites_base` @0x4000 (Data, размер не установлен) — кандидат на базу
  спрайтовых данных.

Сохранено, проверено на диске.

## Ограничения

- Глубокая семантика спрайтов (анимация, коллизии, движение) не разобрана.
- Точные адреса переменных игры (SCORE/LIFE/STAGE) не установлены.
- Паттерны врагов/волн не каталогизированы (обзорный scope).

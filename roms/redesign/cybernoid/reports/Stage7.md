# Stage 7 — Генератор голоса из текста (главная цель)

## Постановка

Разобрать speech-движок cybernoid: как translit-текст превращается в речь
(1-битный PDM-поток на порт 0x00), построить chain str_voice_* → декодер →
синтез, зафиксировать формат так, чтобы по RDB + `tools/voice_spec.md`
воспроизводить произношение любой фразы (TZ §Stage 7).

## Метод

Только EXEC-пространство (живая память после boot self-relocation −0x59):
разбор через `debug_disassemble_range` на исполняемых адресах + **живой
single-step** декодера (BP@0x06C3, пойман во время речи заставки) для
подтверждения адресации таблиц. Дампы таблиц `debug_read_memory_range`.
IO-период/протокол — из io_trace Stage 3/4.

## Ключевой прорыв: разрешение «аномалии» Stage 3

Stage 3 фиксировал «ветвления в строку» при разборе движка в **FILE**-адресах
(0x06BC/0x06C2/0x071C/…). Причина — self-relocation: boot копирует блок
file→exec со сдвигом −0x59 без фикса операндов, поэтому в FILE-пространстве
кодовые цели выглядят попадающими в данные. В **EXEC**-пространстве цепочка
полностью связна (проверено stepping'ом: `'D'`@HL=0x09D1 даёт index 0x073B →
codes 0x0776 ровно как в дизассембле). Аномалии сняты.

## Цепочка (EXEC)

    func_title_speech_caller@0x0573 (LXI H,0x0600; CALL 0x0660)
      → label_str_in_0663@0x0663  DI; CALL walker; RET   (IRQ-free на всё время)
      → func_speak_walker@0x0669  классификация литер; паузы '.'/','/' '→DE; ADI 1A
      → func_speak_phoneme@0x06C3 ДВОЙНАЯ индексация → PDM-эмиттер → OUT 00

## Кодировщик символ→артикулограмма

Двойная индексация (raw ASCII charcode):
1. `data_speak_char_index` @0x0738: charcode → смещение (A=0,B=2,C=6,D=0A,…,Z=5C;
   слияния V=W=0x50, Y=I=0x1A — транслит-эквиваленты фонем).
2. `data_speak_codes` @0x076C: дескрипторы-пары. byte0: длительность(bits0-3),
   plane#(bits4-6), флаг(bit7); byte1 bit7 — продолжение. plane#==0 → конец.

## Синтез единиц (форм-фактор сигнала)

Носитель = заранее оцифрованные **дифограммы**, разложенные по бит-плоскостям
`data_pdm_planes` @0x082E (~262B высокоэнтропийных данных). Длина/итерации
плоскости — `data_speak_plane_lengths` @0x0935 (00 2E 5A 5E FE). Эмиттер
побитово (RAL/ANA M/MVI A,80) льёт в **порт 0x00** значения строго 0x00/0x01 —
это **1-бит PDM (sigma-delta)**, а не PCM и не параметрический генератор.

## Темп/исполнение

Период бита — софтверный busy-loop `LDA 0733/DCR/JNZ` (`var_voice_period`),
~40 T-с → ~37 кГц. DI на всём время речи → VBlank не тикает. Курсор сэмпла —
`var_voice_bufptr` @0x0734 (LHLD). Терминатор фразы — 0x00 (обходчик ORA A/RZ).

## Итог в RDB

Новые EXEC-объекты: `data_speak_char_index`@0x0738(Table), `data_speak_codes`
@0x076C(Table), `data_speak_plane_lengths`@0x0935(Table). Обогащены комментарии
`func_speak_phoneme`(0x06C3, ядро), `data_pdm_planes`(0x082E). Цепочка links
0x06C3→{0x0738,0x076C,0x0935}, 0x0738→0x076C. Сохранено, проверено на диске.
Артефакт формата: **`tools/voice_spec.md`** (вход, chain, таблицы, алгоритм
воспроизведения, ограничения).

## Ограничения

- Порядок обхода бит plane-сэмпла (RAL/0x082E-транспозиция) подтверждён
  структурно, не осциллографически — точный тембр под вопросом.
- Второй OUT-00 эмиттер (file 0x0D59/0x0D90) не разобран подробно.
- Спец-коды интонации ('C','H',0x27) и pitch B=0xBB зафиксированы как точки,
  но кривая высоты тона не калибрована на слух.
- Полная расшифровка audio-WAV по формуле (приёмка TZ п.7) — следующая итерация
  в `tools/`; формат и таблицы для неё уже задокументированы.

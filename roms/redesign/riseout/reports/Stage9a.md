## 1. Verified Facts

**F1. Драйвер заставки — это тот же кадровый шаг, что и в игре: `func_irq_music_step @0x2EFB`**
(алиас `func_music_driver_title`). Цепочка: `RST 7` → `0x0038 = C3 D6 04` →
`func_irq_vblank_dispatcher @0x04D6` → `CALL 0x04EE @0x04E1` → самопатч-слот `0x04EE = C3 FB 2E`
(`JP 0x2EFB`) → `0x2EFB` → `CALL 0x2D94 @0x2F17`, `CALL 0x2F34 @0x2F1D`, `CALL 0x2FA6 @0x2F23`.
*Evidence:* `debug_read_memory_range(0x0038,3)`, `debug_read_memory_range(0x04EE,3)`,
`debug_disassemble_range(0x04D6)`, остан по BP в `0x2EFB` с `[SP] = 0x04E4` — адрес возврата ровно
этого `CALL`; ниже на стеке кадр `RST 7`.

**F2. Один адрес — один объект.** `func_music_driver_title` заведён **алиасом**
(`properties.aliases`) к существующему `func_irq_music_step @0x2EFB`, дубль-объект не создавался.
Реальные «функции-исполнители» — три worker'а, ранее без объектов; заведены:
`func_music_voice1_service @0x2D94`, `func_music_voice2_service @0x2F34`,
`func_music_voice3_service @0x2FA6`.

**F3. Темп.** `[0x7DC3] = 3` → делитель шага `[0x7DCB]` ⇒ **1 шаг музыки = 3 тика VBlank = 60 мс**;
базовая ступенька ноты `MVI A,02h` (`0x2D9E`/`0x2F3E`/`0x2FB4`) = 2 шага = 120 мс.
*Evidence:* `debug_read_memory_range(0x7DC3,30)` на живом экране заставки.

**F4. Чип — КР580ВИ53, не AY.** Порт `0x08` = управляющее слово, `0x0B` = счётчик 0 (v1, CW `0x36`),
`0x0A` = счётчик 1 (v2, CW `0x76`), `0x09` = счётчик 2 (v3, CW `0xB6`) — соответствие портов подтверждено
`docs/VECTOR_VERIFIED.md` §8.3. Вариант ТЗ «0x0B/0x0D — AY регистр/данные» отвергнут: `0x0D` — зеркало
палитры (§8.4), а последовательность `OUT 0x08,CW → OUT порт,lo → OUT порт,hi` + три разных CW
описывают только 8253-совместимый таймер.
*Evidence:* дизассемблирование `0x0237/0x0241/0x0263/0x026D/0x0284/0x028E` (cmd0..cmd5),
`0x024B` (`OUT 0B` @0x0252/0x0255), `0x0277` (`OUT 0A` @0x027E/0x0281), `0x0298` (`OUT 09` @0x029F/0x02A2);
I/O-трасса живого сеанса: `OUT 0x0B,0x34`, `OUT 0x0B,0x35`.

**F5. «Код ноты → значение в порт» = 12 × период.** `0x0258..0x0261`:
`DAD H; MOV E,L; MOV D,H; DAD H; DAD D; DAD H` (×2, ×4, +×2 = ×6, ×12).
*Evidence (живое):* код дорожки `0x33` → период 1135 → `HL = 0x3534 = 13620 = 12·1135` →
две `OUT` в `0x0B`; `f = 1 497 600 / 13 620 = 109.96 Гц = A2`. **Это опровергает ранее записанное
в RDB утверждение «масштаб периода x7 в 0x0258»** — комментарий `func_sound_cmd_dispatch @0x0206` исправлен.

**F6. Формат байта дорожки** (полностью в `Stage9a_music_spec.md` §2): `0x00` = цикл к базе
(0 шагов, у v1 + `INR [0x7DE2]`); бит7=1 = **холд** `(ниббл×2)` шагов без смены тона
(`ANI 0F / RAL / STA` @0x2E27/0x2F9F/0x3015); бит7=0 = **индекс таблицы периодов**, 2 шага;
только v1: `0xE0..0xEF` = inline-команда `cmdC` (0 шагов). Рест = код, чьё слово таблицы = 0
(`ADD M / ORA A / JNZ`), в заставке это `0x38`.

**F7. Таблица периодов `0x301C`, 182 байта (91 слово), 87 ненулевых, нули 0/56/66/90.**
Структура блочная. Равнотемперированность ряда **67..78 = C1..B1**: |cents| max **0.45**,
`period[i] = round(K/2^(i/12))` при **K = 3816** и **f = 1 497 600 Гц**, max|ΔP| = 0.
При номинальных 1 500 000 Гц тот же ряд даёт **K = 3822** — ровно оценка ТЗ ⇒ таблица считалась
от 1 497 600 Гц. Диатонический банк 1..20 ET-точности не имеет (до ±22,5 ц).

**F8. Единый `note_offset` невозможен**: по 87 индексам получается 40 разных смещений
(67→24 = −43, но 11→69 = −58). `−43` справедлив только для ряда 67..78. Решение — новый
encoding `period_table` в конвертере (высота из периода, а не из константы).

**F9. Дорожки заставки = трек №1 загрузчика `func_music_load_track @0x2E2E`** (разбор
`CPI 01/02/03 @0x2E37..0x2E43`), адреса — прямые константы в дескрипторе
`data_music_scores_title @0x2E46` (`LXI H,4E23 / LXI B,4CC4 / LXI D,4FB4 @0x2E46..0x2E4E`),
**без таблицы указателей и без `base + N*stride`**: v1 `0x4E23` (401 Б), v2 `0x4CC4` (351 Б),
v3 `0x4FB4` (259 Б); живые указатели чтения `[0x7DC7]=0x4E58`, `[0x7DD2]=0x4CF2`, `[0x7DDC]=0x4FD8`.

**F10. Кросс-валидация формата:** три независимых потока дают **ровно 800 шагов = 48.00 с** каждый.
Это сильнейшее подтверждение разбора (note = 2 шага, hold = ниббл×2, цикл/команда = 0).

**F11. Артикуляция.** v1 — стаккато: `cmd8 @0x0332` при бите 4 параметра `0x1F` армит one-shot
`[0x03CF]/[0x03D1] = (([0x03CD]>>2)&0x3E)+1 = 3` кадра (`[0x03CD]=0x0C`), по истечении
`func_irq_sound_one_shot @0x035E` пишет `MVI A,36 / OUT 0x08` (@0x0370/0x0372) — нота звучит 1 шаг из 2.
v2 — легато: `cmd9 @0x0397` при бите 4 делает `JNZ 0x02B8` (ничего). v3 — легато с ре-тригом:
`[0x7DE0]=0x0E` → бит4=0, ниббл≥3 → `A=0x00` → `CALL 0x0310` → `JZ 0x0298` (перезагрузка делителя без CW).

**F12. Исправлен ещё один устаревший факт.** Комментарий `func_music_sound_cmd @0x2F30` гласил
«используется только кодом загрузки мелодии». `debug_find_immediate_in_range(0x2D94..0x301B, 2F30h)`
даёт **17 совпадений (перечислено 16 адресов), из них 13 внутри трёх worker'ов**
(v1: 0x2DC2/0x2E04/0x2E0E/0x2E14/0x2E1A/0x2E23; v2: 0x2F84/0x2F8E/0x2F95/0x2F9B;
v3: 0x2FFA/0x3004/0x300B) — то это путь портов **на каждом шаге** музыки. Комментарий исправлен.

**F13. Якоря ТЗ перепроверены и подтверждены:** `func_music_start @0x2D7A` (пишет `C3` +
`SHLD 0x04EF = 0x2EFB` — монтаж хука), `func_music_stop @0x2D72` (`C9` в слот),
сброс `[0x7DE2]` из `0x2D90`, worker `0x2D94` инкрементирует `[0x7DE2]` (`INR M` при `0x2DB1`),
`0x2F30 → 0x0206`. Ни один якорь не оказался ложным; ложными оказались два *комментария* (F5, F12).

## 2. Inferences (не доказано фактами напрямую)

**I1.** Тот же драйвер обслуживает игру. Цепочка и слот едины, переключение — сменой трека
(`0x2E2E`), но «в игре играет именно через `0x2EFB`» проверено статикой, не трассой игрового сеанса.
*Закрытие:* BP в `0x2EFB` после нажатия SPACE и входа на уровень.

**I2.** Inline-команды `0xE0..0xEF` = управление длиной гейта (они пишут `[0x03CD]` через `cmdC @0x02AB`).
Механика доказана; «музыкальный» смысл (детаче/акцент) — интерпретация. В заставочном v1 таких кодов **0**,
поэтому на результат MIDI это не влияет.

**I3.** `[0x7DE2]` — счётчик пройденных циклов дорожки v1. Инкремент доказан, назначение — нет.

**I4.** Механизм «рест = тишина» описан через модель эмулятора (`src/8253.h`: `SetMode()` сбрасывает
`enabled/load`, `out=1`; `Count()` при `!enabled && !load` возвращает `out` ⇒ постоянный уровень).
Это **Emulator Behavior**, а не доказанное Hardware Behavior; порядок `CW → lo → hi` тоже мандатится
моделью (`write_state` сбрасывается записью CW).

## 3. Limitations

**L1.** MIDI не сохраняет микрохроматику банка 1..20 (до ±22,5 ц) и не передаёт one-shot-огибающую v1
иначе как приближением `gate_steps = 1`. *Закрытие:* рендер эталонного звука эмулятором и сравнение
attack/decay с MIDI-версией.

**L2.** Порт-паттерн v1 подтверждён живым I/O-событием; для v2 (`0x0A`) и v3 (`0x09`) порты выведены
дизассемблированием `0x0277`/`0x0298` и `STA 0x03C9/0x03CB`, но отдельные `OUT` в `0x0A`/`0x09`
в снятом окне трассы не пойманы. *Закрытие:* BP на `0x027E` и `0x029F` на заставке + `debug_get_io_trace`.

**L3.** Громкость и тембр в ROM отсутствуют аппаратно (ВИ53 — только тон). `velocity = 100` и
GM-программы 82/80/81 — художественское назначение, не факт ROM'а. Фактами не закрывается.

**L4.** Статическое покрытие ROM ~44 %; порт-остров `0x0217..0x03D1` из `0x0100` недостижим, поэтому
весь звуковый путь подтверждён трассой, а не CFG. Possible paths, не пройденные в снятом окне
(например, ветки `cmd7`-подтаблицы `0x02E0`), не исключены. *Закрытие:* `debug_coverage_report`
от `0x2EFB` и `0x0206`.

**L5.** Индекс 55 таблицы = 1 — назначение не объяснено (гипотеза: sentinel). *Закрытие:* поиск кода
`0x37` в потоках всех трёх треков (`debug_find_bytecode_sequence`).

**L6.** Треки №2 (уровень) и №3 (финал) не разобраны — это Stage 9b, вне этого захода. Их базы
известны из дескриптора `0x2E2E` и зафиксированы в комментарии загрузчика.

**L7.** Служебный scratch `tools/_t.txt` (672 Б) остался: удаление файлов shell-командами запрещено
правилами сессии. Просьба удалить вручную.

# Stage 1. Общее исследование карты памяти и активности программы

## ROM

- Файл: `./src/putup.rom`
- Размер: 17664 байт (0x4500)
- Адрес загрузки: `0x0100` → образ занимает `0x0100`–`0x45FF`
- Точка входа (mapping entry): `0x0100` → `DI; JMP 0B57`
- MCP: ROM загружен через `debug_load_rom`, PC установлен в `0x0100`, эмуляция запущена (~5 с), затем пауза.

## Экранное состояние (debug_get_screen_info)

| Параметр | Значение |
|----------|----------|
| Режим | 256×256 (`mode512 = false`) |
| видимая область | 256×256 (полная 576×288) |
| vram_base | 0xC000 |
| pixels_per_byte | 8 |
| scroll | 0 |
| Прерывания | разрешены (`iff = true`) → активен RST 7 (VBlank ~50 Гц) |

При паузе: PC=0x032C, SP=0x00F6.

## Карта памяти

| Диапазон | Назначение | Активность (access map) |
|----------|-----------|--------------------------|
| 0x0000–0x00FF | Нулевая страница: векторы RST + **стек CPU** | read≈1.67M / write≈1.68M (стек), fetch≈7426 (трамплин RST7) |
| 0x0100–0x05FF | Код программы (ядро) | fetch: 0x0100≈4.29M (самый горячий), 0x0200≈137K, 0x0300≈598K, 0x0400≈318K, 0x0500≈20K |
| 0x0600–0x07FF | Данные (только чтение) | read only, fetch=0 |
| 0x0800–0x08FF | Код (0x0800/0x0803 — вывод символа) + **переменные 0x08B2–0x08FF** | read≈154K, write≈13K, fetch≈346K |
| 0x0900–0x0AFF | Данные (только чтение) | read only |
| 0x0B00–0x0CFF | Код + переменные (0x0B53 — указатель; 0x0B57 — main init) | 0x0B00: read≈30K/write≈25K/fetch≈275K; **0x0C00: fetch≈2.04M** (очень горячий цикл), read≈93 |
| 0x1B00 | Код | fetch≈17.7K |
| 0x2700–0x3700 | **Константные таблицы (только чтение)** — не пишутся | read only, fetch=0 |
| 0x3800–0x3DFF | Код (в т.ч. 0x3858, 0x3D4E) | 0x3800 read≈21K/write≈3.6K/fetch≈53K; 0x3900–0x3D00 fetch |
| 0x3E00–0x4400 | Константные данные (только чтение) | read only, fetch=0 |
| 0x5000–0x53FF | RAM-буфер (инициализируется 0xFF) | read/write, fetch≈256/блок |
| 0x6000–0x7FFF | RAM: рабочее пространство, таблицы спрайтов (0x7418…) | read/write |
| 0x8000–0xFFFF | **VRAM (4 плоскости)** — пишется целиком | read=0, write≈576–1008/блок, fetch=256 (видеодоступ) |

### Ключевой факт о памяти

Весь диапазон `0x0000`–`0x7FFF` в эмуляторе — RAM (образ `.rom` копируется в память). Программа использует часть собственного образа как переменные: блоки `0x0800`, `0x0B00`, `0x3800`, `0x5000` имеют ненулевую `write_count`. Гenuinely константные (никогда не пишутся) таблицы: `0x2700–0x3700` и `0x3E00–0x4400`.

## Активность по чтению/записи (write-зоны = переменные/буферы)

- **Стек**: страница 0 (SP=0x0100, растёт вниз).
- **Переменные ядра**: 0x08B2–0x08FF (в т.ч. 0x08C3 = таймер палитры, 0x08CF = скролл, 0x08D0 = режим экрана, 0x08D3–0x08DA = буфер клавиатурной матрицы, 0x08DB = указатель палитры, 0x08DF = счётчик кадров).
- **Указатель**: 0x0B53 (курсор вывода/позиция).
- **RAM-буферы**: 0x5000–0x53FF (заполняются 0xFF при старте), 0x6000–0x7FFF (таблицы спрайтов, копия данных из 0x2F61→0x7418).
- **VRAM**: 0x8000–0xFFFF пишется полностью (отрисовка 256×256, 4 плоскости).

## Активность по портам (debug_get_io_trace)

В установившемся режиме (заставка) наблюдается **только непрерывный `IN 01h`** (значение `0xE2`), ~1 чтение на 25 инструкций.

Полный набор портов, найденный в образе (поиск байтовых последовательностей + подтверждён дизассемблером MCP):

| Порт | Адрес(а) инструкции | Направление | Назначение (по VECTOR_VERIFIED.md) |
|------|--------------------|-------------|-----------------------------------|
| 00h | 0x03D3, 0x03E8 | OUT | ВВ55#1 управляющее слово (0x8A / 0x88) |
| 01h | 0x018C | IN | ВВ55#1 Port C: бит5=СС(Shift), бит6=УС(Ctrl), бит7=РУС/ЛАТ, бит0/4=магнитофон |
| 01h | 0x03EC | OUT | Port C вывод |
| 02h | 0x03DD | IN | ВВ55#1 Port B: чтение столбцов клавиатурной матрицы |
| 02h | 0x03BC, 0x03F6 | OUT | Port B: бордюр/бит4=512px (режим) |
| 03h | 0x03DB, 0x03F1 | OUT | ВВ55#1 Port A: маска строки клавиатуры + скролл |
| 0Ch | 0x03BF, 0x03C2, 0x03C8, 0x03CC | OUT | Палитра (запись физического цвета) |
| 10h | 0x0384 | OUT | Квазидиск/банковая память |
| 00h | 0x2E10, 0x2F10 | IN | (вспомогательные чтения, вне горячего пути заставки) |

### Значение 0xE2 из порта 01h

`0xE2 = 1110 0010b`: бит7=1 (ЛАТ), бит6=1 (Ctrl не нажат), бит5=1 (Shift не нажат), бит4=0, бит1=1. Модификаторы не нажаты — состояние ожидания ввода на заставке.

## Обнаруженная структура прерываний (предварительно, для Stage 5)

- `func_hw_init` @ **0x0383**: `XRA A; OUT 10` (банк 0), scroll=0→0x08CF, mode=0xE0→0x08D0, запись `JMP` (0xC3) по 0x0000 и 0x0038, вектор RST7 = 0x03A4, reset-вектор = 0x0B57, `EI; RET`.
- В RAM: `0x0038 = C3 A4 03` (JMP 0x03A4) — подтверждено чтением памяти.
- **ISR (RST 7 / VBlank) @ 0x03A4**: PUSH H/D/B/PSW → INR [0x08DF] (счётчик кадров) → логика обновления палитры (OUT 02/0C, с тайминговыми NOP) → скан 8×8 клавиатуры (OUT 03 маска строки / IN 02 столбцы → 0x08D3…) → OUT 00 (0x88) → восстановление скролла/режима (LDA 08CF→OUT 03; LDA 08C4→OUT 02) → CALL 0x3858 → POP → EI → RET.

## Выводы (Fact / Inference)

**Facts (наблюдаемо через MCP):**
1. ROM 17664 байт загружен по 0x0100, точка входа 0x0100 → JMP 0x0B57.
2. Режим экрана 256×256, прерывания разрешены.
3. Стек в странице 0 (SP=0x0100).
4. VRAM 0x8000–0xFFFF пишется целиком.
5. В установившемся режиме единственный I/O — `IN 01h` (0xE2).
6. RST7-вектор 0x0038 содержит `JMP 0x03A4`; ISR сканирует клавиатуру и обновляет палитру/скролл.

**Inferences:**
1. Горячий цикл `fetch` в блоке 0x0C00 (~2M) — плотно исполняемый участок (цикл отрисовки/ожидания) — требует уточнения в Stage 2/6.
2. Константные таблицы 0x2700–0x3700 и 0x3E00–0x4400 — кандидаты на данные глифов/спрайтов/карт уровней (Stage 7/9).
3. Заставка опрашивает модификаторы через порт 01h; полный матричный скан клавиатуры выполняется в ISR и сохраняется в 0x08D3 — нажатие пробела определяется по буферу матрицы, а не по порту 01h (Stage 6).

## Unknowns
- Точное назначение горячего цикла 0x0C00.
- Содержимое/назначение таблиц 0x2700–0x3700 и 0x3E00–0x4400.
- Полный список портов, используемых вне заставки (звук/ВИ53 не наблюдались в окне заставки).

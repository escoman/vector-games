# colors — тест цвета бордюра и экрана

Тестовый ROM для проверки видеовыхода на **ч/б телевизоре с осциллографом**:
замер уровней сигнала на каждом RGB-пине.

## Что делает

Экран **и бордюр** становятся одним цветом, четыре состояния по кругу:

| Состояние | Цвет     | Формат RRRGGGBB |
|-----------|----------|-----------------|
| 0         | BLACK    | `V06_RGB(0,0,0)`  |
| 1         | RED 100% | `V06_RGB(7,0,0)`  |
| 2         | GREEN 100% | `V06_RGB(0,7,0)` |
| 3         | BLUE 100%  | `V06_RGB(0,0,3)` |

В середине экрана две надписи с названием текущего цвета: **белая** и
**чёрная** — по ним виден размах уровней (чёрный = гасящий/синхро, белый =
максимум).

## Как устроено управление цветом

Режим 256x256, 16 цветов. Цвет фона и бордюра задаётся **только палитрой**,
никакой заливки «цветом» в VRAM:

- VRAM залита нулями → каждый пиксель = индекс 0;
- слот 0 палитры = текущий цвет фона;
- бордюр — индекс палитры в битах 0-3 порта `0x02` (PB); после сброса ПИА
  (и после каждой записи управляющего слова, которую делает `kbd_scan`)
  PB = 0, то есть бордюр всегда смотрит в слот 0 — порт не трогаем;
- смена цвета = одна перезагрузка палитры (порт `0x0C`).

> Почему нельзя `gfx_clear(1)`: в 16-цветном режиме байт VRAM = 8 пикселей
> (бит = пиксель), а 4-битный индекс собирается по одноимённым битам четырёх
> плоскостей. Заливка всех плосостей числом цвета даёт полосатый узор, а не
> сплошной цвет. Поэтому фон — нулевая VRAM + палитра.

## Управление

**Любая клавиша** — следующий цвет (0 → 1 → 2 → 3 → 0).

## Сборка

```bash
make          # собрать colors.rom
make deploy   # собрать + положить в ROMS эмулятора PPSSPP
make full     # clean + deploy
```

ROM входит в общий `make all` (модуль `roms/tests/colors`).

ФОРМАТ ФАЙЛА .AY (ZXAY/EMUL) — проверенное описание
====================================================

Зачем этот файл. Из .ay берётся партитура мелодии заставки H.A.T.E.
(SOUND_FIX.MD §2): внутри архива лежит не стрим регистров AY-3-8910, а
оригинальный Z80-плеер бипера вместе с блоками данных. Эталонная
реализация разбора — tools/ay_beeper.py: она читает ровно те поля, что
описаны ниже, а её вывод (assets/title_music_ay.txt) сверен с прежним
захватом и с записью на слух.

Многобайтовые значения — BIG-endian (формат родом с Amiga/68000), на
КР580ВМ80 их надо переворачивать. Все указатели ЗНАКОВЫЕ и считаются от
позиции самого указателя, а не от начала файла:

    абсолютное_смещение = позиция_поля + BE(поле)


1. Заголовок — 20 байт от начала файла
--------------------------------------
+0    4   FileID            'ZXAY'
+4    4   TypeID            'EMUL'
+8    1   FileVersion       (в HATE_title_theme.ay — 1)
+9    1   PlayerVersion     (3 — правила запуска см. §5)
+10   2   PSpecialPlayer    относительный указатель на данные спец-плеера
+12   2   PSAuthor          на строку автора
+14   2   PSMisc            на строку комментария/игры
+16   1   FirstSong         номер первого трека (обычно 0)
+17   1   CountSongs        число треков минус 1 (0 = один трек)
+18   2   PSSongStruct      на массив структур треков (§2)

Строки — ASCII с завершающим нулём.


2. TSongStructure — по одной записи на каждый трек (CountSongs + 1)
--------------------------------------------------------------------
+0    2   PSSongName        относительный указатель на имя трека
+2    2   PSongData         относительный указатель на TSongData (§3)

Это НЕ «таблица адресов» с INIT/PLAY: здесь только имя и ссылка на
данные трека. Адреса входа лежат глубже, в TPoints (§4).


3. TSongData — параметры одного трека
-------------------------------------
+0    1   AChan             каналы AY-3-8910 (0..15)
+1    1   BChan
+2    1   CChan
+3    1   Noise
+4    2   SongLength        длина трека в тиках по 1/50 с (BE)
+6    2   FadeLength        длительность затухания, тики (BE)
+8    1   HiReg             значения всех общих регистров AY: Hi-байт
+9    1   LoReg                                  и Lo-байт
+10   2   PPoints           на TPoints (§4)
+12   2   PAddresses        на таблицу блоков памяти (§5)

SongLength — единственное место, где объявлена длина трека: без него не
узнать, что цикл мелодии 2800 кадров (§6).


4. TPoints — точки входа плеера
-------------------------------
+0    2   Stack             начальный SP (BE, абсолютный адрес в памяти Z80)
+2    2   Init              адрес инициализации трека
+4    2   Inter             адрес вызова по прерыванию (50 Гц); 0 — не нужен


5. Блоки памяти и правило запуска
---------------------------------
Таблица по PAddresses: записи по 6 байт, конец — нулевое слово в поле
Address.

+0    2   Address           адрес загрузки блока в памяти Z80 (BE)
+2    2   Length            длина блока в байтах (BE)
+4    2   DataOffset        относительный указатель на сами данные

Правила PlayerVersion = 3 (первоисточник — readme пакета Micro Speccy,
повторены в шапке tools/ay_beeper.py):
    память $0000-$00FF := $C9, $0100-$3FFF := $FF, $4000-$FFFF := $00,
    в $0038 записать $FB, затем загрузить блоки, все общие регистры :=
    HiReg/LoReg, I := 3, SP := Stack, PC := 0, а в нулевой адрес собрать
    цикл:

        DI / CALL Init / LOOP: IM 2 / EI / HALT / JR LOOP    (Inter = 0)
        DI / CALL Init / LOOP: IM 1 / EI / HALT /
                              CALL Inter / JR LOOP           (Inter <> 0)

Нюанс нашего файла: Inter = $001B лежит в странице, залитой $C9, поэтому
CALL Inter вырождается в RET — треком рулит маска прерываний, а патч
обработчика ($0064, 300 байт) уже внутри блоков.


6. Конкретно в assets/HATE_title_theme.ay
-----------------------------------------
FileVersion 1, PlayerVersion 3, один трек: «H.A.T.E. - Title (Beeper)»,
автор Benn Daglish, комментарий «(c) 1989 Gremlin Graphics».
SongLength = 5602 тика = 112.04 с — ровно ДВА прохода цикла по 2800
кадров (56.00 с); FadeLength = 0; HiReg/LoReg = 0; Stack = 0.
Init = $7FF4, Inter = $001B.
Блоки: $7FF4 (1500 Б — сам плеер), $FDFD (347 Б — данные партитуры),
$0064 (300 Б — патч ROM-обработчика прерываний).
Раскладка внутри файла (проверено побайтово): TSongStructure @$14,
TSongData @$18, TPoints @$26, таблица блоков @$2C (три записи по 6 байт,
терминатор @$3E):

    +18 -> $0014 (PSSongStruct)
    $14: PSSongName -> $0067 «H.A.T.E. - Title (Beeper)», PSongData -> $0018
    $18: A=0 B=1 C=2 N=3, SongLength=$15E2 (5602), Fade=0, Hi=Lo=0
         PPoints -> $0026, PAddresses -> $002C
    $26: Stack=$0000, Init=$7FF4, Inter=$001B
    $2C: $7FF4/1500, $FDFD/347, $0064/300, $0000 — конец таблицы

Партитура снимается трассировкой OUT ($FE), бит 4: 2850 кадров дают
32 250 переключений — это и есть assets/title_music_ay.txt.


7. Чем прежняя редакция этого описания была неверна
---------------------------------------------------
Выдержка из documentation.help и vgmrips читалась так, что парсер уходил
в мусор и давал 246 фиктивных блоков. Три ошибки:

  1) пропущена TSongStructure (§2): указатель из +18 читался как «таблица
     адресов» из двух слов, и указатель на строку имени трека принимался
     за смещение к блокам памяти;
  2) пропущена TSongData (§3) целиком: ни SongLength, ни PPoints, ни
     PAddresses — то есть ни длины трека, ни точек входа;
  3) INIT/PLAY описаны как отдельная «таблица треков», хотя это поля
     TPoints.Init и TPoints.Inter внутри TSongData.


8. Проверка разбора
-------------------
    python3 tools/ay_beeper.py --frames 2850         # -> assets/title_music_ay.txt
    python3 tools/ay_beeper.py --frames 2850 --wav   # + эталонный WAV
    python3 tools/ay_beeper.py --frames 2850 --split # + WAV на каждый голос
    python3 tools/ay_beeper.py --voice drums         # только клик и ударные

Голоса разделяются по адресу записи в порт $FE (SOUND_FIX.MD §10):
A $82D1/$82D9, B $8333/$833B, C $836A/$8375, N $8389, S1 $83A6,
S2 $83B9, S3 $83D1; группы melody, drums, sweeps — таблица VOICES.

Скрипт печатает разобранные метаданные и число блоков; при неверном
layout блоки не лягут в 48K-образ и трасса останется пустой.

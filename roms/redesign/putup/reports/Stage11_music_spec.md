# Stage 11 — Спецификация мелодии заставки для MIDI-конвертера

Источник всех фактов — MCP `vector-debugger` на живой эмуляции `putup.rom`
(load org=0x0100, SHA256 `8486442efc390b15860ec7f69c32db93b0884908565fa11fec57d5c551b4e9a6`).
`asm/*` использованы только как справочник; каждая величина подтверждена
`debug_read_memory_range` / `debug_disassemble_range` / `debug_get_io_trace`.

Назначение документа: по этому тексту + `asm/` мелодия заставки **однозначно**
восстанавливается в MIDI **без эмулятора**.

---

## 1. Общая модель движка

- 3-голосный шаговый секвенсор. Голоса = 3 счётчика тон-генератора **KR580VI53**
  (клон i8253 PIT). **AY-3-8910 не используется** (в ROM нет обращений к портам AY;
  он есть только как опциональное расширение).
- Тик движка = один кадр VBlank (вызывается из `func_vblank_isr` по RST 7 `0x0038`
  через trampoline `CALL func_music_tick` в RAM `0x03F8`).
- Драйвер: `func_music_tick` @ **0x3858** (он же `func_music_driver`).
- Шаг (step) = фиксированная длительность **6 тиков** (задаётся заголовком).
- Каждый голос — независимый цикл из **96 шагов**.
- Высота ноты — полутоновая таблица периодов; результат умножается на **12** и
  пишется как делитель в порт канала VI53.
- Вибрато — небольшой поправочный офсет периода каждый тик (таблица `0x445D`).

### 2.1 О «таблице указателей» (пункт 2 плана)
Движок **НЕ** содержит отдельной DEFW-таблицы указателей на дорожки. Это
подтверждено: (`1`) `debug_get_xrefs` на 0x421A/0x3E29 не показал таблицы-источника;
(`2`) в `func_music_init` @0x3D4E базовые адреса потоков записываются как
`base`, `base+0x100`, `base+0x200` (шаг `DAD B`, B=0x0100), где `base =
var_music_track_base = 0x3E29`. Таким образом «таблица указателей» = формула
`stream_N = 0x3E29 + N*0x100`, N=0,1,2. Роль «таблицы партитур» выполняет
15-байтовый заголовок `data_music_scores` @0x3E1A.

## 3. Формат заголовка `data_music_scores` @0x3E1A

Фактические байты (MCP `debug_read_memory_range`, 15 байт):
```
38 06 06 0F 00 0E 60 60 60 1F 00 03 02 05 00
```

| Смещение | Значение | Смысл |
|----------|----------|-------|
| +0x00 | 0x38 | base-байт для op7 (toggle/маршрутизация), к высоте не относится |
| +x01 | 0x06 | **BASE NOTE** — полутонный сдвиг, прибавляется к коду ноты каждого голоса |
| +x02 | 0x06 | **DURATION = 6** тиков VBlank на шаг (темп) |
| +x03 | 0x0F | op8 — gate/маршрут канала ch0 |
| +x04 | 0x00 | op9 — gate канала ch1 |
| +x05 | 0x0E | op10 — gate канала ch2 |
| +x06 | 0x60 (96) | длина цикла голоса 0 (шагов) |
| +x07 | 0x60 (96) | длина цикла голоса 1 |
| +x08 | 0x60 (96) | длина цикла голоса 2 |
| +x09 | 0x1F | op6 |
| +x0A | 0x00 | op11 |
| +x0B | 0x03 | op12 |
| +x0C | 0x02 | op13 |
| +x0D | 0x05 | **строка вибрато** = индекс ряда в `data_music_vibrato_table` |
| +x0E | 0x00 | (резерв) |

Для MIDI-конвертера существенны: **BASE=6**, **DURATION=6**, **LOOP=96** (на голос),
**vibrato row=5**. Остальные поля — внутренняя маршрутизация оп-кодов, на высоту/тайминг не влияют.

## 4. Формат события дорожки (поток нот)

Каждый голос — массив из 96 байт. Байт = **КОД НОТЫ** (не частота, не период):

| Значение кода | Тип события | Действие |
|---------------|-------------|----------|
| `0x00` | REST (пауза) | канал в этом шаге молчит (соответствующий слот периода = 0; gate гасит канал) |
| `0x01 .. 0x7F` | NOTE | высота = `period_table[ BASE(6) + code ]`; звучит ровно `DURATION` (=6) тиков |
| `>= 0x80` (бит7=1) | EXTENDED / спец (только голос 2) | ветка `func_music_set_note_params`: берётся 8-байтовый блок из `data_note_param_table_43F9[((code&0x7F)-1)*8]` — буквальная высота + параметры огибающей/gate/timbre |

**Длительность фиксирована** (=6 тиков на шаг); в потоке нет кодов удержания,
легато или произвольной длительности. Повторяющиеся одинаковые коды = реартикуляция
ноты (штрих), а не удержание.

**Признак конца/петли:** явного терминатора нет — каждый голос зациклен, индекс
инкрементируется на завершении ноты и оборачивается по `LOOP` (=96) к началу
потока. Оборот петли = конец фразы и начало новой.

> **Важно для заставки:** во всех трёх потоках заставки **нет кодов с битом 7**
> (все байты < 0x80; максимумы: ch0=0x39, ch1=0x30, ch2=0x24). Значит расширенная
> ветка `set_note_params` / `data_note_param_table_43F9` мелодией заставки **не
> задействуется** — для MIDI достаточно правил REST и NOTE выше.

### 4.1 Примеры декодирования реальных байт
- `data_music_track_01[0] = 0x30 (48)` → idx = 6+48 = 54 → period=169 → MIDI = 54+24 = **78 (F#5)**, 6 тиков.
- `data_music_track_01[1] = 0x00` → **REST** (6 тиков тишины).
- `data_music_track_03[0] = 0x0C (12)` → idx = 18 → period=1352 → MIDI = 18+24 = **42 (F#2)** (бас).
- `data_music_track_02[8] = 0x1F (31)` → idx = 37 → period=451 → MIDI = 37+24 = **61 (C#4)**.

## 5. Закон высоты: код ноты → период → частота

### 5.1 Формула (подтверждена дизассемблированием + живым трассированием портов)
```
idx    = BASE(=data_music_scores+1 = 6) + note_code        ; 0..95
period = data_music_period_table[idx]                       ; слово LE из 0x421A
count  = 12 * period                                         ; func_snd_calc_period @0x020E (DAD: 2v,4v,6v,12v)
freq   = f_VI53 / count = f_VI53 / (12 * period)            ; делитель N = count
MIDI   = idx + 24 = note_code + 30                          ; (A4=440 при f_VI53=1.5 МГц)
```
`f_VI53` — входная частота счётчика VI53. По `docs/VECTOR_VERIFIED.md` ≈ 1.5 МГц
(диапазон 1497600..1500000). При 1.5 МГц таблица даёт ровно A4=440 Гц
(idx=45, period=284 → 1500000/(12*284)=440.1 Гц), что подтверждает и формулу, и
октавный сдвиг `+24`.

> **Историческая поправка:** множитель именно **12×** (не 6×), и MIDI = **idx+24**
> (не +36). Проверено повторной трассировкой DAD-последовательности в 0x020E и
> сверкой периодов живого снапшота: ch0 period=113=idx61, ch1=179=idx53, ch2=1073=idx22.

## 6. Темп и длительность тика

- Длительность шага = `DURATION = 6` тиков.
- Тик = 1 кадр VBlank. Частота кадров ≈ **50.08 Гц** (312 строк; по
  `docs/VECTOR_VERIFIED.md §7.4.2`). Точный интервал тика = **19.97 мс**.
- **Шаг ≈ 119.8 мс** (6 / 50.08). Полный цикл = 96 шагов ≈ **11.50 с**.
- ⚠️ Статус: «частота кадров 50.08 Гц» = **Emulator Behavior** (наблюдено в
  эмуляторе; подтверждено документацией железа только как номинал VC, а не как
  гарантия точного темпа музыки). Для MIDI использовать абсолютный шаг 119.8 мс.

Рекомендуемый маппинг в MIDI: принять **шаг = 1/16 нота**. Тогда 16-я = 119.8 мс
⇒ четверть = 479.2 мс ⇒ **♩≈ 125 BPM**. Длительность каждой NOTE/REST = ровно один
шаг (одна 16-я), реартикуляция повторов — штрихом.

## 7. Алгоритм вывода звука через порты

### 7.1 Инициализация (`func_music_start_track` @0x3DCD)
В порт управления **08h** последовательно пишутся управляющие слова VI53:
```
MVI A,36h ; OUT 08h   ; ch0: mode 3 (square), LSB/MSB, binary
MVI A,76h ; OUT 08h   ; ch1
MVI A,B6h ; OUT 08h   ; ch2
```
(0x36/0x76/0xB6 — SC=00/01/10, RL=11 (LSB затем MSB), M=011 (mode 3), B=0 binary.)

### 7.2 Запись ноты в канал
Кадр за кадром `func_music_play_note_ch0` @0x3BCA (и ch1 @0x3C7D) вызывают
обработчики оп-кодов; для канала:
```
HL = <период канала в RAM: ch0=0x31A, ch1=0x31C, ch2=0x31E>
CALL 0x020E           ; func_snd_calc_period -> HL = 12 * период
MOV A,L ; OUT <порт>  ; младший байт делителя
MOV A,H ; OUT <порт>  ; старший байт делителя
```
Порты каналов: **ch0=0Bh** (`op0` @0x0201), **ch1=0Ah** (`op2` @0x022D),
**ch2=09h** (`op4` @0x024E). REST (период 0) канал глушит (gate op8/op9/op10 из
заголовка).

Перед записью к периоду добавляется поправка вибрато `data_music_vibrato_table`
(см. §8).

### 7.3 Подтверждение живым трейсом
`debug_get_io_trace` на проигрывании заставки зафиксировал:
`OUT 0Bh <- 0x64, <- 0x05` и `OUT 0Ah <- 0x64, <- 0x08` (lo/hi делителя).
Порт 09h (ch2/бас) в короткий трейс не попал, т.к. бас часто в паузе; запись в
09h доказана дизассемблированием обработчика `op4` @0x24E (двойной `OUT 09h`).

### 7.4 Итог для конвертера
В MIDI не нужно эмулировать порты — достаточно: для NOTE записать
`MIDI = code + 30`,velocity фикс., длительность = 1 шаг; для `code=0` — паузу.
Три потока = три MIDI-дорожки.

## 8. Вибрато / огибающая

- `data_music_vibrato_table` @0x445D, stride 20 байт на ряд. Читаемый ряд =
  `scores[+0x0D] = 5`. Значение = `table[(row-1)*20 + tick]`, маленькие 0..3.
- Добавляется к периоду каждый тик ⇒ лёгкая расстройка высоты (десятки центов) —
  **это не отдельная частотная таблица**. Для базового MIDI-воспроизведения вибрато
  можно опустить (высота считается по §5 без поправки); при желании — pitch-bend ±
  (поправка периода 1..3 из ~100..478 ≈ 2..3 % ≈ 35..50 центов).
- Громкость/огибающая: в движке заставки отдельной динамики нет — фиксированная
  длина 6 тиков и gate-байты (op8/9/10). В MIDI: равномерная velocity.

## 11. Критерий приёмки (п.7 TZ)
По §2 (адреса), §4 (события), §5.2 (таблица периодов) и §6 (темп) мелодия
полностью восстанавливается детерминированно:
```
for stream in [track_01, track_02, track_03]:
    for step_i, code in enumerate(stream):     # 96 шагов
        t = step_i * 6 ticks (tick = 19.97 ms)
        if code == 0: REST длительностью 6 тиков
        else: MIDI_note = code + 30, onset=t, duration=6 тиков
```
Эмулятор для восстановления не требуется.

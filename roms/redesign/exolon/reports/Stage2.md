# Stage 2. Семантика функций (exolon.rom)

> Источник фактов — MCP `vector-debugger` + полный дизассембл-дамп пайплайна (`.scratch/export/pipeline/code/code.asm`, 6000 строк). Механические цифры Stage 1 не дублируются.

## Goal

Дать всем **153** функционным объектам RDB осмысленное имя по правилам `utils/analyze/naming.py`, русскую формулировку назначения в `comment` и подтверждённые статикой связи `function → function / data`. Никаких правок, выходящих за Stage 2 (data-объекты, метки `lbl_*`, экспорт ASM, размеры), не выполнялось.

## Method

1. **Канал — только MCP** (ТЗ §3, §150). ROM загружен `debug_load_rom` (org 0x0100, sha256 `92be64d1…`); RDB — `roms/redesign/exolon/src/exolon.rdb` (406 объектов). Сохранение — только `debug_save_rdb`, файл на диске руками не редактировался.
2. **Экспертиза тел** — по пакетному дизассемблу `v06c-asm-export` (`code.asm`) вместо 153 отдельных вызовов: семантика выводилась из сопоставления таблиц, портов и state-переменных; выборочно — `debug_disassemble`, `debug_get_call_graph`, `debug_get_rdb_object`.
3. **Порядок обхода** адресами сверху (0x0100 → 0x76FC) по кластерам: загрузка/boot → ядро (кадровый sync, спрайт-XOR, интерпретатор отображения) → глифы/текст → HUD-числа → звук КР580ВИ53 → объекты/враги/пришельцы/пехота/десант → коллизии → бонус/звёзды → мигание/заставка → game over.
4. **Драйвер** (`.scratch/st2/apply_stage2.py`) сначала прошёл `--check` (сверка каталога с RDB: 153↔153, 0 расхождений), затем `--apply`: `debug_update_rdb_object` (только `name`; `type=function`, `size` сохранены как в RDB) → `debug_set_rdb_comment` → `debug_add_rdb_link` → `debug_save_rdb`. Итого 420 вызовов MCP, 1 сохранение, `dirty=false` после сейва.
5. **Точность.** Неподтверждённые гипотезы помечены `предположительно`; технические имена таблиц оставлены с адресным суффиксом (`_05b1`, `_06f6`, `_46f7` …) как единственный способ развести несколько одноимённых объектов-таблиц — это предупреждение линтера, не ошибка.
6. **Связи:** из ~140 заданных 108 применены; **4 отброшены** — исток `0x786B` (`label_786B`, бут-диспетчер) не является функционным объектом RDB, завести исходящую связь из метки нельзя (см. Open questions). Все аргументы `address/source/target` передавались десятичными.

## Ключевые находки движка

* **Self-modifying вход.** `func_entry_jmp` (0x0100) = `JMP` на текущий экран; бут-цепочка `label_786B` патчит цель через `SHLD 0101h` (boot→title `762D`→gameplay). Отсюда `func_entry_jmp → 0x762D`.
* **Ядро кадра.** `func_frame_sync` (0x0147) ждёт ВBlank по счётчику луча (`IN 0Ah`), выставляет палитру (`func_palette_latch8` 0x2142: 8×`OUT 0Ch`) и стробирует клавиатуру (`OUT 03h`/`IN 02h`→[0197]). Спрайты — 4-плоскостной XOR (`func_xor_sprite8` 0x01A9, `func_draw_object_4plane` 0x0960).
* **Интерпретатор отображения** `func_display_interpreter` (0x3CC1) — RLE-рендер списка опкодов позиция/цвет/повтор/адрес/текст; зовёт blit глифов 0x3B00/0x3BA2/0x3C5A. Через него рисуются экраны, HUD (`func_draw_hud_static` 0x3F38) и взрывы (`func_player_hit` 0x4167).
* **Порт-карта:** 00h — видео/палитровая защёлка (мигание звёзд `func_blink_*`, вспышка `func_flash_video` 0x4C8E); 08h/09h/0Ah — КР580ВИ53 (`func_vi53_ch1/ch2_init`); 01h bit7 — РУС/ЛАТ (active-0), опрос `func_poll_rus_continue` 0x73FD.
* **State:** [2090]/[2091]=X/Y игрока, [1FFB]=номер уровня, [01A5]=текущий цвет, [0197]=код клавиши, 1E47..1E4B=векторы движения (`func_decode_input` 0x1E62).
* **Объектные таблицы** (несколько независимых очередей): движение 05B1/06F6, волны/десант 252B→VRAM 9550, пришельцы 4063/46F7, пехота 44C8, падающие 4144, пули врагов 43E1, выстрелы 4BB1, бонусы 4B15, HUD-объекты 4063. Агрегатор `func_update_all_objects` (0x48FF) вызывает подсистемы коллизий.

## Cluster-обзор (что сгруппировано)

* **Boot/sys:** entry/clear-ram/clear-vram, frame-sync, init-palette+vblank-вектор, полная инициализация таблиц `func_init_all_tables` (0x5950, 23 связи — самый «толстый» узел), переход уровня `func_level_advance`, game over 0x6BE9.
* **Gfx/glyph:** адресация плоскостей (0x0465/0475/048E), scale `0x3CB5`, blit глифов, интерпретатор 0x3CC1, растер 4-плоскости.
* **HUD/числа:** BCD-вывод `func_render_bcd_value` 0x3DF1, счётчики 0x3EC6/3ED2/3EDE/3EF2, div-цифры 0x3EAB/3F14, статический HUD 0x3F38.
* **Game-объекты:** контроллер игрока 0x1F18 (+размещение 0x1FA4/1FA9/1FE5), коллизии 4 сторон (0x04A7/04C8/04E9/050A) и bbox 0x20B1, спавн/движение врагов 0x22E7/236E, пришельцы 0x400F/4078/4085/464F/46AF/4716, пехота 0x4432/44B6/44D5, десант 0x45E3/4635, рельеф 0x4535/45B6.
* **Пули/взрывы:** пуля игрока 0x47EB, попадание 0x47FF, бомбы 0x4232/4259/4277/42D4/4305, пули врагов 0x437D/43AF/4400/4425, эффекты поражения 0x473E/0x4A45.
* **Бонус/аттракт:** начисление бонуса 0x557A, полка/анимация бомб 0x562D/5688, звёздное поле 0x1589/4B41/5869, мигание 0x7335/737A/73BE, заставка 0x76FC.

## Open questions

1. **Бут-диспетчер `0x786B` (`label_786B`)** вызывает `func_clear_ram`/`func_init_palette_vblank`/`func_display_interpreter`, но сам — метка, а не функционный объект RDB. 4 соответствующие связи отброшены. Решение — продвинуть `0x786B` в функцию (Stage создания функций) и завести связи тогда.
2. **Размеры** функций остались `size=-1` (extent за `lbl_*` не пересчитывался) — Stage 5/6.
3. **Имена с адресным суффиксом** (`_05b1`, `_06f6`, `_46f7`, `_48d9`, `_4bb1`, `_067b`, `_0690`) — предупреждение naming-линтера; осознанно сохранены, т.к. в движке несколько одноимённых очередей объектов и адрес таблицы — единственный недвусмысленный идентификатор.
4. **Точные подписи HUD-счётчиков** `func_draw_counter_a/b/c` (0x3EC6/3ED2/3EDE): позиции и BCD-разряды подтверждены, буквальное назначение (жизни/бомбы/счёт) — предположительно.
5. **Вражеские таблицы 4063 vs 43E1 vs 4BB1** разделены по признаку «столбцы пришельцев / пули врагов / записи выстрелов»; семантика различения требовала бы трассы портов/VRAM-диффа, сейчас выводена статически.
6. **Музыка/звуковые эффекты** (`func_alien_hit_effect`, `func_landing_hit_effect`, вызовы `func_render_bcd_value` как «звук») описаны по адресам таблиц эффектов, без живой расшифровки КР580ВИ53 — наблюдение, не подтверждённое поведение железа.

# putup-beam — демо beam-подсистемы

Демо библиотеки [lib/gfx/beam.c](../../../lib/gfx/beam.c) (beam-синхронный
планировщик спрайтов, паспорт `roms/games/putup/BEAM_TZ.MD`) на ассетах игры
putup: уровень 16×32 клетки (512px = ровно 2 кольца VRAM) с аппаратным
вертикальным скроллингом, плавной анимацией героя и тремя патрулирующими
врагами трёх видов (ходок, ворона, вертолёт). Вся видимая графика идёт через
`beam_*`; единственный писатель VRAM в кадре — `beam_render` (блокирует до
конца кадра); цикл тикает раз в 6 кадров (`TICK_FRAMES`) — 8.33 тика/с.

По плану демо НЕ содержит: HUD, счёт, время, Hurry Up, огонь, музыку.

## Структура

| файл | назначение |
|---|---|
| `main.c` | игровая логика демо (герой, враги, камера, ключи/выход, «?»-кубики) |
| `tools/gen_assets.py` | генератор `assets.inc`: тайлы 16×16 из глифов putup (герой — маска, 2 кадра ходьбы; вариант `[1]` = сдвиг 4px на 3 столбца — не используется: шаг клеточный; враги — плоские) |
| `tools/gen_level.py` | разовая генерация `level.inc`: level_01 ×3 по вертикали со стыками-шахтами |
| `tools/level_editor.py` | редактор карты (окно Tkinter): правит `level.inc` напрямую, рисует превью настоящими тайлами putup, гейты flood-fill перед сохранением |
| `assets.inc` | АВТОГЕНЕРАЦИЯ из `tools/gen_assets.py`, не править |
| `level.inc` | карта; правится `tools/level_editor.py` |
| `Makefile` | `make full` — сборка ROM (org 0x0100) + раскладка в каталог эмулятора |

## Управление

| клавиша | действие |
|---|---|
| ← / → | шаг — клетка 16px за тик (8.33 клетки/с; с зажатой клавишей — непрерывно, работает и в полёте) |
| ПРОБЕЛ / СС | прыжок: подъём на 2 клетки, зависание на апексе, отпускание — сразу падение |
| ↑ | подъём по шахте на клетку (удобство демо: шахты выше прыжка) |
| ESC | fade-out и выход |

Цель: собрать все предметы (коды 07/0A/0B/0C/0D/0E — яйцо, вишни, яблоко,
ананас, виноград, кольцо) — замок (24) на месте выхода превращается в мигающий
выход (фазы 22/23); войти в выход — рестарт уровня. Касание врага — рестарт.
Дополнительные фрукты можно выбить из «?»-кубиков (04), включая скрытые
кирпичи (05) — на счёт предметов для выхода они не влияют.

## Механика, перенесённая из оригинального putup

- **Прыжок** — action-клавиша (ПРОБЕЛ/СС) как `func_gamestate_catch`/`_evade`:
  подъём 2 клетки (4 глиф-строки оригинала), счётчик зависания на апексе
  (3 тика = 18 кадров при темпе 6 кадров/тик), отпускание клавиши —
  немедленная гравитация.
- **Управление в полёте**: диспетчер клавиш X работает во всех вертикальных
  фазах (в оригинале — внутри catch/evade); easing по осям независимый
  (`mv_x`/`mv_y`).
- **Твёрдость**: как в оригинале по глифам тайла ≥ 77h — коды 02/04/05/08,
  включая «?»-кубик (04h, глифы 7E..82h) и скрытый кирпич (05h, глиф 7Dh):
  герой стоит на них, не проваливается. Замок/выход (22/23/24) твёрд, пока не
  собраны все предметы.
- **Скрытый кирпич → «?»-кубик → фрукт** (по `func_player_move_d` putup).
  Нажатие сверху на клетку 05h превращает её в «?»-кубик 04h; повторное
  нажатие на 04h ставит в клетку случайный фрукт из 0Ah..0Dh (вишни/яблоко/
  ананас/виноград) или 0Eh (кольцо — вдвое реже, как отбраковка `CPI 04h` в
  `func_spawn_egg`). Нажатие — событие, а не состояние: засчитывается один раз
  на клетку (иначе кирпич и кубик превратились бы в один кадр), а прыжок и
  возвращение на ту же клетку — новое нажатие. Фрукт из кубика не входит в
  `keys_left`: он бонусный, уровень остаётся выигрышным в любом случае.
- **Коллизии героя — по рамке 16×16 px**, а не по клетке центра: проверяются
  все 1..4 клетки, которые рамка перекрывает, и по X, и по Y. Раньше при шаге
  вбок проверялась только верхняя строка рамки, и в прыжке герой въезжал
  нижней половиной в стену; теперь при упоре Y выравнивается по границе клетки.
- **Враги**: проходимы только коды 00/01 (как `CPI 20h` по глифу цели в putup
  `func_entity_state1`), поэтому предметы и невидимый блокиратор (03) их
  останавливают. Проверка «клетка под ногами» оригинала не перенесена: под
  коридорами патруля здесь лежит кирпич. Кадры: ходок — tg20/tg19 по
  направлению, ворона — tg18/tg17 по направлению, вертолёт — tg15/tg16
  (фаза ротора по `anim_tick`, не по направлению). Кадр героя — по формуле
  putup `idx = work_const + 3*move_dir − 1` (ходьба/стойка на обе стороны).

## Контракт цикла (BEAM_TZ §2.2)

Кадровый ISR = `timer_start()` + `kbd_scan_now()` (последний flush-ит регистр
скролла в порт 03h на VBlank). Цикл: сон `v06_wait_frame()` до темпа тика
(6 кадров по `frame_count`) → игровая логика (только мутаторы `beam_*`) →
`beam_update` → `beam_render`. Тик привязан к счётчику кадров, а не к числу
итераций: скорость не плавает вместе со стоимостью кадра. Открытая полоса
камеры перерисовывается в бланкинге до flush скролла; мировая адресация
кольца (`ring y = world_y & 0xFF`).

## Редактор уровня

```sh
python3 tools/level_editor.py          # окно редактора (нужны python3-tk + python3-pil.imagetk)
python3 tools/level_editor.py --print  # ASCII-превью карты
python3 tools/level_editor.py --check  # гейты без сохранения
```

Окно: слева палитра (карточки тайлов нарисованы настоящими глифами putup +
маркеры героя/выхода/врагов, клик = инструмент), в центре карта с сеткой и
масштабом 16/24/32/48 px на клетку, справа — сводка и результат гейтов.

Невидимые в игре клетки — 03h (невидимый блокиратор) и 05h (скрытый кирпич) —
в ROM выглядят как пустота/обычный кирпич (глифы совпадают), поэтому на карте
они накрыты серым квадратом с прозрачностью 25% и тонкой пунктирной рамкой
(галочка «невидимые 03/05», по умолчанию включена).

| мышь/клавиша | действие |
|---|---|
| ЛКМ | нарисовать выбранным инструментом (протяжка — линия, один шаг отмены на штрих) |
| ПКМ | пипетка: код клетки под курсором — в кисть |
| колесо | прокрутка карты |
| стрелки / Tab / Shift+Tab | курсор / следующая / предыдущая кисть |
| пробел | поставить инструмент в курсоре |
| H / E / 1 2 3 | спавн героя / выхода / врага N в курсоре |
| V | сменить вид врага под курсором (ходок → ворона → вертолёт) |
| Del | стереть клетку (код 01h) |
| Ctrl+Z / Ctrl+Y | отмена / повтор |
| Ctrl+S / Ctrl+Q | сохранить (с прогоном гейтов) / выход |

Гейты: герой не в твёрдой клетке, выход/предметы/спавны достижимы flood-fill'ом
от героя, виды врагов 0..2, у каждого кода клетки есть графика в `assets.inc`
(иначе `bg_tiles[N]` — заглушка `bg_tile_000` и клетка отрисуется чёрной).
При ошибке файл не пишется. После сохранения — `make full`.

## Гейты и результаты

- **Сборка**: `make full` — чисто, ROM 24726 байт.
- **Генерация**: flood-fill level.inc — достижимы выход, 22 предмета, три
  спавна (ходок/ворона/вертолёт); шахты стыков сквозные.
- **Края/коллизии** (живая эмуляция): после 12 с зажатой ← герой стоит
  `x=16`, дескрипторы inst/shad тоже `x=16` — зазора 4px нет; патрульные
  враги не выходят из коридора 5..10, т.е. не входят ни в клетку с фруктами
  (4), ни в невидимый блокиратор (11); герой, поставленный в прыжке вплотную
  к кирпичу (`x=192,y=50`), при ←/→ не перекрывает твёрдую клетку.
- **Темп**: ровно 6 кадров на тик (8.33 тика/с, замер по `frame_count`
  точками останова на `game_logic`: подряд 6,6,6,6…); герой 16px за тик
  (8.33 клетки/с = 133 px/с), враги — 16px через тик (4.17 клетки/с),
  шаги по тикам чередуются 16,0,16,0 — отношение 2:1, как в putup.
  Двойных/пропущенных шагов нет, кроме пауз fade-in после рестарта
  (логика в это время стоит — это ожидаемо).
- **Растер-бюджет**: `beam_overbudget()` = 0 за прыжки, полёт, скролл камеры и
  патрулирование (`ovb_seen` в BSS — для часов отладчика).
- **Tearing**: снапшоты TV-кадра в движении (падение по шахте со скроллом
  камеры) — разрывов растра нет: запись за лучом по контракту beam.
- **Функциональные** (живая эмуляция, чтение статики из `.map`): прыжок
  32px вверх и 32px вниз (8px/тик, апекс 3 тика); рулёжка X на апексе
  идёт тем же клеточным шагом 16px/тик; посадка на
  «?»-кубик y=96 (не проваливается); дескриптор врага переключается между
  зеркальными рядами кадров по знаку направления.
- **Скрытый кирпич** (живая эмуляция): герой на (4,10) — клетка 05h→04h;
  падение на ту же клетку — 04h→0Ch, фрукт подобран (keys_left 22→21).

## Отладка

Статика демо в BSS (адреса — в `putup-beam.map`: `keys_left`, `hero_x/y`,
`hero_vstate`, `anim_tick`, `enemy_dir`, `enemy_pat`…); запись памяти — только
на паузе эмулятора. Таблицы кадров: `hero_frames`, `enemy_frames[3][2][2]`
(вид → фаза/направление → субшаг), используется вариант `[0]` (клеточный
шаг), и `bg_tiles[25]` (`bg_lock_key` = код 24).

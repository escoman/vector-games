# Система команд КР580ВМ80А / Вектор-06Ц

> Полная справочная документация по системе команд процессора, используемого в ПК «Вектор-06Ц».
>
> КР580ВМ80А — отечественный аналог Intel 8080A. Система команд Вектора соответствует 8080.
>
> Для команд, кодов и общих таймингов использованы справочные материалы по КР580ВМ80А/8080. citeturn1search1turn0search29

## 1. Общие сведения

Процессор имеет 8-разрядную шину данных и 16-разрядную адресную шину. Адресное пространство памяти — `0000h–FFFFh` (64 КБ). Порты ввода-вывода адресуются 8-битным номером (`00h–FFh`).

Всего определено **244 команды из 256 возможных кодов**; 12 кодов являются неиспользуемыми/зарезервированными. citeturn1search5

Команда состоит из 1, 2 или 3 байт:

| Размер | Назначение |
|---:|---|
| 1 байт | только код операции |
| 2 байта | код операции + 8-битный непосредственный операнд / номер порта |
| 3 байта | код операции + 16-битный адрес или непосредственный операнд |

**Важно для Вектора:** процессор — семейство 8080/КР580ВМ80, а не Z80. Команды `RIM`, `SIM`, `EXX`, `IX/IY`, `LD`, `JR`, `DJNZ` и другие специфические команды Z80 отсутствуют.

## 2. Регистры

| Обозначение | Размер | Назначение |
|---|---:|---|
| `A` | 8 бит | аккумулятор |
| `B`, `C`, `D`, `E`, `H`, `L` | 8 бит | регистры общего назначения |
| `BC`, `DE`, `HL` | 16 бит | регистровые пары |
| `SP` | 16 бит | указатель стека |
| `PC` | 16 бит | счётчик команд |
| `PSW` | 16 бит | пара `A + F` при операциях со стеком |
| `F` | 8 бит | регистр флагов |

### 2.1. Регистровый код

| Код | Регистр |
|---:|---|
| `000` | `B` |
| `001` | `C` |
| `010` | `D` |
| `011` | `E` |
| `100` | `H` |
| `101` | `L` |
| `110` | `M = (HL)` |
| `111` | `A` |

`M` не является отдельным регистром: это байт памяти по 16-битному адресу, находящемуся в `HL`.

### 2.2. Регистровые пары

| Код | Пара |
|---:|---|
| `00` | `BC` |
| `01` | `DE` |
| `10` | `HL` |
| `11` | `SP` |

Для `PUSH/POP` код `11` означает `PSW`, а не `SP`.

## 3. Флаги

Регистр `F` содержит пять рабочих флагов:

| Флаг | Обозначение | Значение |
|---|---|---|
| Sign | `S` | старший бит результата (`D7`) |
| Zero | `Z` | результат равен нулю |
| Auxiliary Carry | `AC` | перенос из бита 3 в бит 4 |
| Parity | `P` | чётное число единичных битов результата |
| Carry | `CY` | перенос/заём из старшего разряда |

Не все команды изменяют все флаги.

- `—` — флаги не изменяются.
- `S,Z,P,AC,CY` — вычисляются.
- `S,Z,P,AC` — `CY` сохраняется.
- `CY` — изменяется только перенос.
- `CY=0` / `CY=1` — принудительная установка.

# 5. Подробное описание

## 5.1. `MOV`

```text
MOV dst,src
dst ← src
```

`dst` и `src` — `B,C,D,E,H,L,M,A`.

Код:

```text
01 DDD SSS
```

`DDD` — код приёмника, `SSS` — код источника.

`MOV M,M` (`76h`) не существует как пересылка: opcode `76h` — `HLT`.

## 5.2. `MVI`

```text
MVI r,D8
r ← D8
```

или:

```text
MVI M,D8
(HL) ← D8
```

## 5.3. `LXI`

```text
LXI rp,D16
rp ← D16
```

Поддерживаются `BC`, `DE`, `HL`, `SP`.

16-битная константа хранится младшим байтом вперёд.

## 5.4. `LDA` / `STA`

```text
LDA adr
A ← memory[adr]

STA adr
memory[adr] ← A
```

## 5.5. `LHLD` / `SHLD`

```text
LHLD adr
L ← memory[adr]
H ← memory[adr+1]
```

```text
SHLD adr
memory[adr]   ← L
memory[adr+1] ← H
```

## 5.6. `LDAX` / `STAX`

Только `BC` и `DE`:

```text
LDAX BC    A ← memory[BC]
LDAX DE    A ← memory[DE]

STAX BC    memory[BC] ← A
STAX DE    memory[DE] ← A
```

## 5.7. `INX` / `DCX`

16-битный инкремент/декремент регистровой пары. Флаги не изменяются.

```text
INX rp
rp ← rp + 1

DCX rp
rp ← rp - 1
```

## 5.8. `PUSH` / `POP`

`PUSH` помещает пару в стек, уменьшая `SP` на 2.

`POP` извлекает пару и увеличивает `SP` на 2.

Для `PSW`:

```text
PUSH PSW
```

сохраняет `A` и `F`.

```text
POP PSW
```

восстанавливает `F` и `A`.

## 5.9. `XCHG`

```text
HL ↔ DE
```

Флаги не изменяются.

## 5.10. `XTHL`

Обмен с вершиной стека:

```text
L ↔ memory[SP]
H ↔ memory[SP+1]
```

## 5.11. `SPHL`

```text
SP ← HL
```

## 5.12. `PCHL`

```text
PC ← HL
```

Это безусловный косвенный переход.

# 6. Арифметика

## 6.1. `ADD`

```text
A ← A + operand
```

## 6.2. `ADC`

```text
A ← A + operand + CY
```

## 6.3. `SUB`

```text
A ← A - operand
```

`CY` при вычитании трактуется как заём.

## 6.4. `SBB`

```text
A ← A - operand - CY
```

## 6.5. Непосредственные операции

```text
ADI D8    A ← A + D8
ACI D8    A ← A + D8 + CY
SUI D8    A ← A - D8
SBI D8    A ← A - D8 - CY
```

## 6.6. `INR`

```text
INR r
r ← r + 1
```

или:

```text
INR M
(HL) ← (HL) + 1
```

**`CY` не изменяется.**

## 6.7. `DCR`

```text
DCR r
r ← r - 1
```

**`CY` не изменяется.**

## 6.8. `DAD`

```text
DAD rp
HL ← HL + rp
```

Из флагов изменяется только `CY`.

## 6.9. `DAA`

Десятичная коррекция аккумулятора после BCD-сложения.

Аппаратный алгоритм должен реализовываться точно, поскольку `DAA` зависит от содержимого `A`, `AC` и `CY`.

# 7. Логические операции

## 7.1. `ANA`

```text
A ← A AND operand
```

`CY` сбрасывается; `S,Z,P` вычисляются по результату.

## 7.2. `XRA`

```text
A ← A XOR operand
```

`CY=0`.

## 7.3. `ORA`

```text
A ← A OR operand
```

`CY=0`.

## 7.4. `CMP`

Выполняется внутреннее:

```text
A - operand
```

но `A` **не изменяется**. Флаги устанавливаются как при `SUB`.

## 7.5. Непосредственные

```text
ANI D8
XRI D8
ORI D8
CPI D8
```

# 8. Сдвиги и вращения

## `RLC`

```text
old bit 7 → CY
old bit 7 → bit 0
A ← (A << 1) | old_bit7
```

## `RRC`

```text
old bit 0 → CY
old bit 0 → bit 7
A ← (A >> 1) | (old_bit0 << 7)
```

## `RAL`

```text
old bit 7 → CY
old CY   → bit 0
```

## `RAR`

```text
old bit 0 → CY
old CY   → bit 7
```

У всех четырёх команд изменяется только `CY`.

## `CMA`

```text
A ← NOT A
```

Флаги не изменяются.

## `STC`

```text
CY ← 1
```

## `CMC`

```text
CY ← NOT CY
```

# 9. Переходы

## `JMP`

```text
PC ← adr
```

## Условные переходы

| Условие | Команда | Переход |
|---|---|---|
| `Z=0` | `JNZ adr` | если не ноль |
| `Z=1` | `JZ adr` | если ноль |
| `CY=0` | `JNC adr` | нет переноса |
| `CY=1` | `JC adr` | есть перенос |
| `P=0` | `JPO adr` | нечётная паритетность |
| `P=1` | `JPE adr` | чётная паритетность |
| `S=0` | `JP adr` | плюс |
| `S=1` | `JM adr` | минус |

При ложном условии переход не выполняется, но `PC` пропускает оба байта адреса.

# 10. Вызовы и возвраты

## `CALL`

```text
SP ← SP - 2
push PC
PC ← adr
```

## Условные вызовы

```text
CNZ  CZ
CNC  CC
CPO  CPE
CP   CM
```

Условия соответствуют условным переходам.

## `RET`

```text
PC ← pop()
```

## Условные возвраты

```text
RNZ RZ
RNC RC
RPO RPE
RP RM
```

## `RST`

| Команда | Адрес |
|---|---:|
| `RST 0` | `0000h` |
| `RST 1` | `0008h` |
| `RST 2` | `0010h` |
| `RST 3` | `0018h` |
| `RST 4` | `0020h` |
| `RST 5` | `0028h` |
| `RST 6` | `0030h` |
| `RST 7` | `0038h` |

Для Вектора особенно важен `RST 7` → `0038h`: штатная система использует этот вектор для кадрового прерывания примерно каждые 20 мс.

# 11. Ввод-вывод

## `IN`

```text
IN port
A ← I/O[port]
```

Opcode:

```text
DB port
```

## `OUT`

```text
OUT port
I/O[port] ← A
```

Opcode:

```text
D3 port
```

Для Вектора команды `IN/OUT` являются основным способом работы с аппаратными портами.

# 12. Управление процессором

## `NOP`

Ничего не делает.

## `HLT`

Останавливает процессор до принятия прерывания.

## `DI`

Запрещает маскируемые аппаратные прерывания.

## `EI`

Разрешает маскируемые аппаратные прерывания.

# 14. Форматы операндов

| Обозначение | Значение |
|---|---|
| `D8` | 8-битное непосредственное значение |
| `D16` | 16-битное непосредственное значение |
| `adr` | 16-битный адрес |
| `port` | 8-битный номер порта |
| `r` | `B,C,D,E,H,L,A` |
| `M` | память по адресу `HL` |
| `rp` | `BC,DE,HL,SP` |
| `PSW` | `A` + `F` |

16-битные значения и адреса хранятся **младшим байтом вперёд**.

Например:

```asm
LXI H,1234h
```

кодируется:

```text
21 34 12
```

А:

```asm
JMP 8000h
```

кодируется:

```text
C3 00 80
```

# 15. Стек

Стек растёт в сторону уменьшения адресов.

`PUSH` уменьшает `SP` на 2 и сохраняет данные.

`POP` читает данные и увеличивает `SP` на 2.

Стек используется командами:

```text
PUSH
POP
CALL
RET
RST
```

а также программными обработчиками прерываний.

# 16. Прерывания

`DI` запрещает маскируемое прерывание, `EI` разрешает его.

Для ПК «Вектор-06Ц» особенно важен адрес:

```text
0038h
```

то есть вектор `RST 7`.

По технической документации Вектора кадровое прерывание происходит примерно каждые 20 мс.

# 17. Практические примеры

## 17.1. Сложение

```asm
MVI A,10h
MVI B,22h
ADD B
; A = 32h
```

## 17.2. Работа с памятью

```asm
LXI H,9000h
MVI M,55h
MOV A,M
```

После выполнения:

```text
[9000h] = 55h
A       = 55h
```

## 17.3. Цикл

```asm
MVI B,10h
loop:
    DCR B
    JNZ loop
```

`DCR` изменяет `Z`, поэтому `JNZ` может использовать результат цикла. `CY` при этом сохраняется.

## 17.4. Подпрограмма

```asm
CALL routine

routine:
    MVI A,42h
    RET
```

## 17.5. Работа с портом

```asm
MVI A,88h
OUT 00h
```

Конкретное значение управляющего слова ВВ55 зависит от требуемой конфигурации портов.

# 18. Важные особенности для эмулятора Вектора

1. `M` всегда означает `memory[HL]`.
2. `INR` и `DCR` **не изменяют `CY`**.
3. `DAD` изменяет только `CY`.
4. `CMP` не изменяет `A`.
5. Условные `Jcc`, `Ccc`, `Rcc` имеют разные тайминги в зависимости от результата условия.
6. 16-битные операнды хранятся little-endian.
7. `MOV M,M` (`76h`) — это `HLT`.
8. Не следует добавлять в эмулятор команды Z80.
9. Для точного эмулятора Вектора одного количества T-states недостаточно: необходимо учитывать машинные циклы, обращения к общей памяти и арбитраж между CPU и видеоконтроллером.
10. Системное кадровое прерывание Вектора связано с `RST 7` / `0038h`.

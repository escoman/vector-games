# Эталон: штатный загрузчик NEWROM v2.0

Листинги оригинального загрузчика Vector-06C — они же исходный текст
декодера ленты, который перенесён в [`../../lib/boot/loader_stage2.asm`](../../lib/boot/loader_stage2.asm)
(спека: [LOADER_TZ.MD](../LOADER_TZ.MD), §6 и §9.2).

| Файл | Что это |
|------|---------|
| `newrom2.asm` | NEWROM V(2.0), 15.09.88 / TMK SOFT'1991 — та же программа с символическими метками (`TBIT`, `TSBIT`, `READB`, `MITAP`, `REATP`, `RCON3`, `LOA11`…`LOA19`); основной файл для сверки логики |
| `kish1.asm` | фрагмент с разметкой сырыми адресами (`M0038H`, `M01BFH`, …) — удобен для сверки байтов и обработчика `RST 7` в 0x0038 |
| `boot.png` | снимок экрана штатного загрузчика (карта загрузки) — с ним сверяют ручную проверку §9.5; геометрия линий и угловой блок меток/столбиков приёма у нас совпадают (порт `AKART`, LOADER_TZ §5.1, §5.3); не воспроизведён только fade-in 15 кадров `WRCLR` |

Кодировка — **CP866** (комментарии по-русски), у `kish1.asm` окончания строк
CRLF. Смотреть в UTF-8:

```sh
iconv -f cp866 -t utf-8 docs/etalon/newrom2.asm | sed -n '200,300p'
```

Файлы — чужая работа (TMK Soft'91), лежат здесь только как эталон для
побайтовой сверки переноса: наш декодер обязан совпадать с ними логикой,
а расхождения должны быть перечислены в LOADER_TZ.MD §9.2, а не «улучшены»
молча.

## Что в них важно для переноса

* **0x0038 (`RST 7`)** — обработчик `LDA CONR → DELAY: DCR A/JNZ → REATP:
  IN 01h / ANI 10h / MOV E,A / RET`. У узла **два входа**: `MITAP` на своём
  входе зовёт `CALL REATP` — без задержки; с задержкой работает только
  `RST 7` из цикла битов. Смещение этого порядка ломает разбивку по байтам
  (LOADER_TZ §6).
* **Переменные** — `ABUFF = 0DED0h`, `PRINV = ABUFF+36`, `CONR = ABUFF+38`,
  `STEK = 0DCF0h`, `MASK = 00010000B` (бит 4 порта 01h). NEWROM обнулял все
  64 КБ, поэтому `PRINV = 0` получался «сам»; у нас область 0xE200.. выше
  стирания — `PRINV` обнуляется явно в точке входа (LOADER_TZ §2).
* **Не переносятся сознательно:** `TESTL` (сверка «0x81 в VRAM») — вместо
  скана карты счётчик подблоков `SBCNT`; `JMP 0000H` (холодный рестарт всего
  ROM) — вместо него `JMP LOADF`. `AKART` и метки прогресса ПЕРЕНЕСЕНЫ
  (`loader_stage2.asm`, LOADER_TZ §5.3): столбики в группах и угловой блок
  на boot.png воспроизводятся ровно тем же путём `CALL AKART` / `MOV M,E`.

## Наши расширения (в NEWROM их нет)

С сверкой по эталону не путать: эти пункты — наше добавление, а не перенос,
и в `newrom2.asm` / `kish1.asm` их искать незачем (детали — LOADER_TZ §3.8,
§4.2, §5.2):

* **Выход `PCHL` на `addrhi:0000`** — NEWROM заканчивал приём по `JMP 0000H`;
  мы прыгаем на фактический старт принятого образа, поэтому один выход годится
  и для `.rom` (`0x0100`), и для `.r0m` (`0x0000`).
* **Заглушка сброса `JMP 0E000h` в `0x0000..0x0002`** — ставится сразу после
  стирания, чтобы аппаратный сброс возвращал в загрузчик; у `.r0m` её затирает
  собственный код образа, и сброс ведёт прямо в него.
* **Две панели-картинки в углы и цвета фона/линий из конфига** (`loader_cfg`,
  `utils/png2panel.py`) — плоскость C000, карта рисуется поверх панелей OR-ом.
  У эталона была только одноцветная карта без панелей (снимок `boot.png`).

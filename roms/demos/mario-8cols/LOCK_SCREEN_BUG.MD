# Баг: локи соседних экранов с противоположными направлениями

## Ситуация

На карте два соседних экрана 32×32:
- **Экран A** (тайлы 0–31): `LOCK_R` — камера не может сдвинуться правее `cam = 0`
- **Экран B** (тайлы 32–63): `LOCK_L` — камера не может сдвинуться левее `cam = 32`

Экраны примыкают друг к другу. Ожидаемое поведение:

| Сценарий | Ожидание |
|----------|----------|
| Марио идёт вправо в экране A | Допускается до правого края, камера стоит на 0 |
| Марио пересекает границу A→B | Камера плавно переходит, Марио видим |
| Марио идёт влево в экране B | Допускается до леого края, камера стоит на 32 |
| Марио пересекает границу B→A | Камера плавно переходит, Марио видим |
| Марио падает сверху в экран B | Камера следует за Марио, лок включается |

## Наблюдаемые баги

### 1. Марио не может пройти вправо из A в B

**Причина:** проверка движения (строки 496–509) использует экран **назначения** (`nb / 32`), а camera lock (строки 534–552) — экран **текущей позиции** Марио (`wblk / 32`).

На границе (wblk = 31, nb = 32):
- Проверка движения берёт лок экрана B (`LOCK_L` → `sc = 32`)
- `nb = 32 >= sc = 32` → проверка проходит, движение разрешено
- Camera lock берёт лок экрана A (`LOCK_R` → `cam = 0`)
- Марио на тайле 32, камера на 0 → Марио **видим** (rel = 32, в пределах 0..31)

Но в реальности проверка движения с `LOCK_L` экрана B устанавливает `sc = 32`, и при `cam = 0` (из-за `LOCK_R` экрана A в sim) — `sc` уже 32, а `nb = 32` виден. Однако если `LOCK_R` экрана A в sim устанавливает `sc = 0`, то `LOCK_L` экрана B перезаписывает `sc = 32`. Движение разрешено. Но camera lock по экрану A (wblk = 31) удерживает `cam = 0`. Марио на 32 при cam = 0 — **видим**, но на следующем шаге camera lock переключится на экран B (wblk = 32) и `LOCK_L` установит `cam = 32`. Марио на 32 при cam = 32 — виден на краю.

Проблема возникает, когда deadzone пытается подтянуть камеру: `rel = 0 < CAM_MIN_BLK(10)` → камера хочет двигаться влево на `cam = 22`, но `LOCK_L` не пускает (`cam < 32` → `cam = 32`). Камера остаётся на 32. Марио идёт дальше вправо — `rel` растёт, камера следует. **Работает нестабильно**: камера дёргается.

### 2. Марио не может войти слева в экран с LOCK_L сверху

Когда Марио падает сверху в экран B (тайл 32, камера ещё на 0):
- Camera lock: `LOCK_L` экрана B → `cam = 32`
- Проверка видимости: `wblk(32) < cam(32)` → **false**, `wblk(32) > cam+31(63)` → **false**. Марио видим!
- Но deadzone: `rel = 0 < CAM_MIN_BLK` → камера хочет `cam = 22`, лок тянет обратно на 32.
- Камера **oscillates**: 0 → 32 → deadzone → 22 → lock → 32 → ...

### 3. Oscillation камеры на границе

Корень: camera lock и deadzone **борются** на границе экрана. Lock ставит камеру на фиксированную позицию, deadzone тянет её обратно к Марио. Результат — камера дёргается между двумя позициями каждый кадр.

## Архитектура (текущая)

```
Движение Марио:
  sim_cam = естественная камера на nb
  sim_cam = apply_lock(SCREEN_OF(nb), sim_cam)    ← экран НАЗНАЧЕНИЯ
  if (nb visible at sim_cam) → allow move

Камера:
  cam = deadzone_follow(cam, wblk)
  cam = apply_lock(SCREEN_OF(wblk), cam)           ← экран МАРИО
  if (Mario invisible at cam) → skip lock          ← «пропуск невидимого»
  wblk = wall_clamp(cam)                           ← аварийная стена
```

**Рассинхронизация**: проверка движения использует `nb/32`, camera lock — `wblk/32`. На границе это разные экраны.

## Ключевые параметры

| Параметр | Значение |
|----------|----------|
| VIEW_BLOCKS | 32 тайла (ширина экрана) |
| CAM_MIN_BLK | 10 (левая мёртвая зона) |
| CAM_MAX_BLK | 20 (правая мёртвая зона) |
| SPR_W | 16 px (2 тайла, ширина спрайта) |
| Screen cell | 32×32 тайла |
| MAX_CAM | LEVEL_COLS − VIEW_BLOCKS |

## Попытки исправления (безуспешные)

1. **Wall clamp** (пост-движение): Марио застревал в стене.
2. **Pre-movement check** с sim_cam: Марио на границе не мог войти в locked экран.
3. **Двухпроходный lock** (экран Марио + экран камеры): конфликты локов, Марио выкидывало.
4. **Одинарный lock + skip invisible**: камера oscillates на границе.
5. **Гистерезис** (lock_active + deadzone skip): не решил проблему входа сверху.

## Гипотеза правильного решения

Lock должен применяться к **границам видимой области**, а не к позиции камеры напрямую. Камера ограничивается `[lock_left, lock_right]`, но deadzone работает внутри этого диапазона. Если диапазон уже deadzone — камера стоит на границе.

Альтернатива: lock определяет **физическую стену** на границе экрана (как край уровня). Марио не может пройти за неё. Камера свободна. Это проще, но требует коллизии «лок-стена» в проверке движения.

# Спецификация генератора голоса из текста (cybernoid, Vector-06C)

Единственный разрешённый «длинный» артефакт Stage 7 (см. TZ §Stage 7 п.6).
Описывает формат speech-движка так, чтобы по RDB + этому файлу можно было
воспроизвести произношение **любой** фразы из ROM.

Все адреса — **EXEC** (пространство выполнения после self-relocation boot'ом
на −0x59). Разбор в FILE-адресах давал «фантомные» ветки в строку (Stage 3
«аномалия»); в EXEC-пространстве цепочка полностью связна — подтверждено
живым single-step декодера на символе `'D'` фразы по курсору `HL=0x09D1`.

## 1. Точки входа и вызова

    CALL-цепочка момента речи:
      func_title_speech_caller @0x0573   (заставка; LXI H,0x0600; CALL 0x0660)
      → label_str_in_0663 @0x0663        (DI; CALL func_speak_walker; RET)
      → func_speak_walker  @0x0669       (обходчик строки текст→речь)
      → func_speak_phoneme @0x06C3       (декодер фонемы + PDM-эмиттер, ядро)

    DI на входе глушит прерывания на всё время бит-бэнга (нет EI во всей цепи
    0x0663..0x0732) → ISR VBlank не тикает речь, темп задаётся софтверно.

    Вход обходчика: HL = указатель на 0-терминированную translit-строку.
    Строки-источники: str_voice_title@0x0600, str_voice_098d@0x098D,
    str_voice_09b8@0x09B8, str_voice_0a23@0x0A23 (буфер-очередь 0x0600).

## 2. Обходчик (func_speak_walker @0x0669)

Посимвольно читает (HL), классифицирует и вызывает декодер на литеру:

- Терминатор: `ORA A / RZ` (0x066E/0x066F) — конец фразы.
- Фильтр литер: `CPI 41` ('A') + `JM`, `CPI 5B` ('[') + `JP` — вне A..Z →
  в ветку пауз 0x069B. Спец-коды `CPI 43`('C'), `CPI 48`('H'), `CPI 27`('''')
  — управляемая интонация.
- Ремэп: `ADI 1A` (0x068C).
- Литера → `PUSH B/H; CALL 0x06C3; POP H/B; INX H; JMP 0x066B` (0x0692..0x0698).
- Паузы (0x069B..0x06BA): `DE` = длительность busy-ожидания:
  - '.' → DE=0x0000 (кратчайшая, стык слогов)
  - ',' → DE=0x8000
  - ' ' → DE=0x4000
  затем `CALL 0x06BC` (цикл `DCX D / MOV A,D / ORA E / JNZ 0x06BC / RET`).
- B=0xBB — стартовая высота тона (pitch seed).

## 3. Декодер фонемы (func_speak_phoneme @0x06C3) — двойная индексация

Вход: `A` = raw ASCII charcode литеры.

    (1) LXI B,06F7 ; HL = 0x06F7 + A  → data_speak_char_index  → L = смещение
    (2) LXI B,076C ; HL = 0x076C + см → data_speak_codes       → дескриптор

Разбор дескриптора (2 байта, читается парами в цикле):

    byte0:  bits0-3 = длительность   (ANI 0F → C)
            bits4-6 = номер бит-плоскости сэмпла (RLC×3 ; ANI 07)
            bit7    = флаг
    byte1:  bit7    = флаг продолжения пары
    plane# == 0  → JZ 0x071B → конец фонемы ( тишина / стык)

Затем:

    LXI D,0935 ; HL = 0x0935 + plane#  → data_speak_plane_lengths → B = число
                                          итераций внутреннего цикла эмита
    LXI D,082E ; HL = 0x082E + смещение(RAL)  → data_pdm_planes   → бит-плоскость

## 4. PDM-эмиттер (0x06FD..0x0718)

    PUSH PSW
    ANA M            ; бит плоскости AND маска
    JZ  0x0704       ; 0
    MVI A,01         ; 1
0x0704 OUT 00        ; порт 0x00 = TapeOut, 1-бит PDM/PWM, значения строго 0x00/0x01
    LDA 0733         ; var_voice_period
0x0709 DCR A
    JNZ 0x0709       ; busy-wait = период бита (~40 T-с → ~37 кГц при такте машины)
    POP PSW
    DCR B ; JZ 0x071B
    ORA A ; RRC ; JNC 0x06FD / INX H ; JMP 0x06FD  ; сдвиг на следующий бит

Курсор сэмпла: `LHLD 0734` (var_voice_bufptr) → `XCHG; XRA A; CALL 0x06BC` —
промеж-тактовая задержка. Длительность фонемы: `DCR C; ANI 0F; JNZ 0x06DC` —
повтор дескриптора. Возврат/конец: `MOV A,C; RAL; RC`.

## 5. Таблицы данных (EXEC)

| Объект | Адрес | Роль |
|---|---|---|
| data_speak_char_index | 0x0738 (base-операнд 0x06F7) | charcode → смещение в коды |
| data_speak_codes      | 0x076C | дескрипторы артикулограмм (пары) |
| data_pdm_planes       | 0x082E | бит-плоскости PDM-сэмплов (~262B) |
| data_speak_plane_lengths | 0x0935 | длина/итерации эмита на плоскость |
| var_voice_period      | 0x0733 | софтверный счётчик периода бита |
| var_voice_bufptr      | 0x0734 | курсор буфера сэмплов (LHLD) |

### 5.1 data_speak_char_index — карта A..Z (подтверждено stepping)

Смещения в data_speak_codes (raw ASCII-индекс, только литеры валидны):

    A=00 B=02 C=06 D=0A E=0E F=10 G=12 H=16 I=1A J=1C K=22 L=26 M=2A
    N=2E O=32 P=34 Q=38 R=42 S=48 T=4A U=4E V=50 W=50 X=56 Y=1A Z=5C

Слияния фонем (одинаковое смещение): `V=W=0x50` (оба → «В»),
`Y=I=0x1A` (оба → «И») — транслит-эквиваленты. Шаг 2 байта/ед → артикулограмм
~46 штук в data_speak_codes.

## 6. Формат «единицы» (units) — форм-фактор сигнала

Носитель звучания = **1-битный PDM (sigma-delta) поток** бит-плоскостей из
data_pdm_planes @0x082E, выводимый побитово в порт 0x00 строго значениями
0x00/0x01. Не PCM и не генератор параметров — это заранее оцифрованные
дифограммы, разложенные по плоскостям (plane# в дескрипторе выбирает вариант
артикуляции). Длительность/пауза/просодия кодируются в дескрипторах
data_speak_codes (длительность — низкий ниббл, число итераций — plane-length)
и в обходчике (паузы '.'/','/' ' → DE).

## 7. Алгоритм воспроизведения фразы (приёмка TZ п.7)

Для translit-строки S:

1. Для каждого символа c:
   - если c ∈ {'.', ',', ' '} → вставить паузу DE (0 / 0x8000 / 0x4000);
   - если c ∈ 'A'..'Z' (и спец 'C','H','\'') → смещение = index[ord(c)];
2. По смещению читать дескрипторы data_speak_codes парами до plane#==0:
   - plane# → длина B = plane_lengths[plane#];
   - выбрать plane-сэмпл из data_pdm_planes, побитово (RAL/ANA M) выдать
     последовательность 0x00/0x01 в порт с периодом var_voice_period;
   - повторить «длительность» раз.
3. Строить WAV: каждый OUT-бит = образец на частоте ~37 кГц (период 40 T-с);
   склейка дифограмм по порядку обходчика = непрерывный речь-поток.

Готовые скрипты разбора/синтеза (ROM-specific) — в этом же `tools/`.

## 8. Доказательная база

- Живой single-step декодера (BP@0x06C3, пауза во время заставки-речи):
  A=0x44('D'), DE=0x4000 (пауза ' ' только что), HL=0x09D1 (курсор фразы),
  DAD-цепочка → 0x073B (index) → 0x0776 (codes). Совпало с ручной трассировкой.
- Дампы памяти EXEC: 0x06F7+0x41..=monotone offsets; 0x076C..=дескрипторы;
  0x082E..=высокоэнтропийные плоскости; 0x0935..=00 2E 5A 5E FE + строки.
- OUT-00 PDM-протокол и период 40 T-с — из io_trace (Stage 3/4, func_speak_emit_plane).

## 9. Ограничения

- Точная транспозиция бит→время внутри plane-сэмпла (порядок обхода плоскостей
  RAL/082E) подтверждена структурно, не попиксельно-осциллографически.
- Второй OUT-00 эмиттер на file 0x0D59/0x0D90 (тот же протокол, др. модуль) —
  не разобран подробно.
- Просодические спец-коды ('C','H',0x27) и pitch-модуляция B=0xBB зафиксированы
  как точки, но их точная высота/киривая не калиброваны на слух.

> метки — экспорт `.scratch/export/pipeline/layout.asm`, роли портов —

> 2026-10-17. Имена и адреса не изобретаются — каждое подтверждено телом
> обработчика и(или) местами вызова/обращения к ячейкам.

## 0. Главный вывод: интерпретатор прозрачен к прерываниям

По всему ROM **нет ни одной `DI`, нет `IM 0/1/2`, нет `IRET`**; `EI` встречается
ровно дважды:

| адрес | контекст | зачем |
|---|---|---|
| `0x2D09` | `lbl_irq_resume` — хвост `func_irq_handler` | разрешить прерывания перед возвратом по прерванному PC |
| `0x3E9F` | `func_term_putc` (Stage 3) | краткое `EI` в начале вывода символа (полное сохранение регистров рядом) |

Режим маскирования прерываний не выставляется — используется **векторная схема
К580ВМ80А**: сигнал `INT` приводит к исполнению команды по вектору `0x0038`
(`RST 7`-подобный переход), а тот `JMP`-ит в `func_irq_handler`. Безопасность
обеспечивает не запрет прерываний, а сам обработчик: он сохраняет весь контекст
и работает на **выделенном стеке**. Это прямое подтверждение инвариантов
change log:

- **п.18** — толерантность к внедрению обработки прерывания в любой код: ISR
  переключает стек (`LXI SP,0x26F7`) и ничего не оставляет в стеке прерванного;
- **п.72** — очистка экрана без запрета прерываний: `DI` в ROM нет вообще;
- **п.31** — дуги/графика без стека и без `DI`: то же отсутствие `DI`;
- **п.93** — запись палитры с увеличенными паузами: см. §3 `0x239D`
  (`XTHL`-задержки в цикле `OUT 02`/`OUT 0C`).

## 1. Тракт обработки: вектор → ISR → возврат

```
0x0038  func_rst_irq          JMP 2C7F          ; вектор INT (RST 7)
0x2C7F  func_irq_handler      ── тело ниже ──    ; тикер 50 Гц
0x2D00  lbl_irq_resume        POP D/B/PSW / LXI SP/HL,0000 (самомод.) / EI / JMP 0000 (самомод.)
```

### 1.1 `func_irq_handler` — `0x2C7F`

```
0x2C7F  SHLD 2D07          ; HL → контекст
0x2C82  POP H / SHLD 2D0B  ; сохранённый PC → контекст
0x2C86  PUSH PSW
0x2C87  LXI H,0002 / DAD SP / SHLD 2D04   ; SP → контекст
0x2C8E  MOV L,C / MOV H,B / XTHL
0x2C91  LXI SP,26F7        ; ★ переход на выделенный IRQ-стек
0x2C94  PUSH H / PUSH B / PUSH D
0x2C97  CALL 239D          ; палитра-синхронизация (§3)
0x2C9A  LXI H,3A1F / INR M / JNZ 2CA8     ; прескейлер тика
0x2CA1  LHLD 3A20 / INX H / SHLD 3A20      ; кадровый счётчик ++
0x2CA8  MVI A,8A / OUT 00  ; управление экраном (ВВ55#1 УС)
0x2CAC  IN 01 / ANI 80 / STA 2CB1          ; latch РУС/ЛАТ (бит7 порта C)
0x2CB5  JNC 2CBF
0x2CB8  LXI H,2DCD / MOV A,M / XRI 08 / MOV M,A   ; ★ мигание курсора (бит3)
0x2CBF  XRA A / OUT 03 / IN 02 / INR A / JZ 2CE0  ; ★ скан матрицы клавиатуры
0x2CC8  … (обход 8 строк: B=FE, RLC, OUT 03 / IN 02) …
0x2CD4  JNZ 2D0D           ; найдена нажатая строка → разбор клавиши
0x2CE0  CALL 2DC8          ; прайминг матрицы (§4)
```

Роль: единственный обработчик прерываний, 50 Гц. Делает четыре вещи за кадр —
обновляет палитру, ведёт кадровые часы, моргает курсором и опрашивает
клавиатурную матрицу, пополняя буфер, из которого читает `func_kbd_dequeue`.
Возврат — через `lbl_irq_resume` (`EI` + самомодифицируемый `JMP` на PC из
`0x2D0B`), без `IRET`.

### 1.2 `lbl_irq_resume` — `0x2D00` (inline-хвост, метка)

```
0x2D00  POP D / POP B / POP PSW
0x2D03  LXI SP,0000        ; самомодифицируется значением из 0x2D04
0x2D06  LXI H,0000         ; самомодифицируется значением из 0x2D07
0x2D09  EI                 ; единственное осмысленное EI интерпретатора
0x2D0A  JMP 0000           ; самомодифицируется значением из 0x2D0B (прерванный PC)
```

Три слова `0000` патчатся в начале ISR из блока контекста `0x2D04/0x2D07/0x2D0B`
(отдельного объекта-функции не заводим — это хвост `func_irq_handler`; помечен
меткой `lbl_irq_resume`).

## 2. Ячейки состояния прерываний (объекты)

| адрес | объект | размер | доказательство |
|---|---|---|---|
| `0x2D04` | `var_irq_context_block` | 8 | `SHLD 2D04/07/0B` (SP/HL/PC) |
| `0x26F7` | `var_irq_stack_top` | 1 | `LXI SP,26F7` — вершина IRQ-стека |
| `0x3A1F` | `var_irq_prescaler` | 1 | `INR M`; биты читают как фазу (`ANI 08`) |
| `0x3A20` | `var_irq_frame_counter` | 2 | `LHLD/INX H/SHLD 3A20` по переполнению |
| `0x2DCD` | `var_cursor_blink` | 1 | `XRI 08 / MOV M,A` — мигание курсора |
| `0x3A22` | `var_kbd_strobe` | 1 | `LDA 3A22 / OUT 03` — маска строки матрицы |

Ячейки `0x3A1F..0x3A22` лежат внутри RAM-образа (`hi=0x42FF`) и являются
рабочими переменными тикера. **Расхождение с документом:** ТЗ/§3.18 v2.5 указывает
ячейки таймера `768…770` и звуковых счётчиков `772…775` (dec) — в этом ROM (v2.997)
фактические адреса иные (`0x3A1F`/`0x3A20`), а звуковых счётчиков в ISR нет (см. §6).
Маппинг «документ v2.5 ↔ ROM v2.997» оставляем открытым, не подгоняем.

## 3. Палитра-синхронизация: `func_irq_palette_refresh` — `0x239D`

```
0x239D  LXI D,2C7E          ; таблица 16 цветов
0x23A0  MVI B,0F
0x23A2  MOV A,B / OUT 02    ; адрес/бордюр (порт B ВВ55#1)
0x23A5  LDAX D / OUT 0C     ; физический цвет в палитру (порт 0C)
0x23A8  XTHL / XTHL         ; намеренные задержки (racing the beam)
0x23AA  LHLD 0000 / DCX D / DCR B / OUT 0C / JP 23A2
```

Каждый кадр перезаписывает палитру по 16 ячейкам из `data_irq_palette_table`
(`0x2C7E`), синхронно с развёрткой — пары `OUT 02`/`OUT 0C` с задержками `XTHL`
вписываются в луч. Это и есть **п.93** («запись палитры с увеличенными паузами»);
роли портов подтверждены `VECTOR_VERIFIED.md §7.3.2` (`02h`=порт B: бордюр/скан
клавиатуры, `0Ch`=запись цвета в палитру). Точный подбираемый визуальный эффект
НЕ вскрыт — доказан только механизм (открытый пункт).

## 4. Клавиатура: прайминг и выборка

### 4.1 `func_kbd_matrix_prime` — `0x2DC8`

```
0x2DC8  MVI A,88 / OUT 00     ; ВВ55#1 УС
0x2DCC  MVI A,00 / ORI 00 / OUT 01
0x2DD2  LDA 3A22 / OUT 03     ; strobe выбранной строки (var_kbd_strobe)
0x2DD7  MVI A,00 / OUT 02     ; подтяжка чтения
0x2DDB  RET
```

Аппаратная подготовка матрицы перед `IN 02`. Зовётся из ISR (`0x2CE0`, `0x2D15`)
и из цикла ожидания символа. Был `func_2dc8`.

### 4.2 `func_kbd_dequeue` — `0x2C40`

```
0x2C40  PUSH H / LXI H,2B3F / MOV A,M / ORA A / CMA / JZ 2C6D   ; буфер пуст → A<0
0x2C4A  … DCR M … LXI H,4012 …                                   ; снять символ из кольца
0x2C5C  CPI 84 / JNZ 2C6B                                        ; special-код
0x2C61  LXI H,2DCF / MOV A,M / XRI 02 / MOV M,A                  ; сдвиг фазы повтора
0x2C6B  ANI 7F / 2C6D POP H / RET
```

Выборка клавиши из буфера, который пополняет ISR: `A` = код либо `<0`/`0xFF`
(пусто). Зовут `func_inkey` (INKEY$) и редакторский цикл. Был `func_2c40`.

## 6. Открытые пункты (не выдумываем)

- **Звук в тикере.** В v2.5-документе ISR ведёт звуковые счётчики (`772…775`) —
  «музыкант-фоновик». В этом ROM в `func_irq_handler` обращений к КР580ВИ53
  (`08h..0Bh`) **нет**: таймера-музыканта в прерывании не обнаружено. Звук,
  если он и есть, живёт в другом месте (область BIOS-драйвера звука) — на Stage 5.
- **Точный эффект палитра-тикера** (`0x239D`): механизм доказан, семантика
  подбираемых цветов — нет.
- **Клавиатурные таблицы** `0x2D7E`/`0x2D8E` (scan → символ, РУС/ЛАТ) — разбор
  отложен в Stage 5 (токенизатор/РЕПЛ).
- **`0x003C` «INTERPT»** из перечня ТЗ: по факту это не вектор — сразу за
  `JMP 2C7F` в `0x0038` идёт плотный код (`CALL 005C`, петли копирования),
  отдельного вектора таблицы прерываний в образе нет.
- **NMI**: в ROM не встречается (`IM`/обработчик NMI отсутствуют).

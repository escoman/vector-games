# Stage 1. Карта памяти и активность чтения/записи (TESTAY.ROM)

**ROM:** ./src/TESTAY.ROM — 3712 байт (0xE80), i8080, origin 0x0100.
**Метод:** MCP vector-debugger: debug_load_rom(org=0x100) → debug_run ~5-11 c →
debug_get_memory_map / debug_get_memory_access_map / debug_get_memory_access_log (без остановки) →
debug_pause → debug_get_io_trace; два debug_create_memory_snapshot + debug_compare_memory_snapshots.

## 1. Активные блоки памяти

| Блок | fetch | read | write | Интерпретация |
|------|-------|------|-------|---------------|
| 0x0000 | 256 | 0 | 0 | NOP-sled RAM 0x0000-0x00FF (путь CPU после reset к 0x0100) |
| 0x0100 | 298k | 57k | 35.8k | вход + код + самомодиф. указатели (0x0101,0x0103,0x0111) |
| 0x0200 | 144k | 27 | 0 | код |
| 0x0300 | 409k | 7k | 0 | код |
| 0x0400 | 17.3M | 106k | 37k | главный цикл + рабочие переменные |
| 0x0500 | 132k | 23k | 0 | код + XOR-трик 0x055F-0x0579, ключ 0x0553 |
| 0x0600 | 6.2k | 18.7k | 13.5k | данные трека (XOR-слоты 12 байт), есть execution |
| 0x0700-0x0D00 | 0 | ~19k | 0 | только чтение: данные (паттерны/таблицы) |
| 0x0E00 | 0 | 482 | 0 | только чтение: хвост данных (0x0E00-0x0E7F) |
| 0x0F00 | 0 | 43 | 0 | чтение за концом ROM (0x0E80+, RAM=0) |
| 0xC200 | 2.6k | 178k | 181k | стек (SP=0xC300, растёт вниз) |

VRAM 0x8000-0xFFFF: read/write/fetch = 0. Графики нет. (Fact, High)

## 2. Порты (debug_get_io_trace)

- IN 0x01 (Port C BB55 #1) — опрос в главном цикле (0x04AC: IN 01; RAL; JC), всегда 0xEF.
- OUT 0x15 — номер регистра AY; OUT 0x14 — значение регистра.
- Регистры: только 0x00-0x0A (тон A/B/C, noise, mixer, volume 3 каналов).
  Пишутся пачкой в обратном порядке 0x0A -> 0x00 каждый кадр.
- Конверт 0x0D-0x0F не используется (ни одного обращения).
- Порты 0x00-0x0B, 0x0C, 0x10 — не используются.

Типичный кадр (фрагмент трассы): OUT 15,0A/14,0A; OUT 15,09/14,0C; OUT 15,08/14,09;
OUT 15,07/14,38; OUT 15,06/14,00; OUT 15,05/14,00; OUT 15,04/14,90; OUT 15,03/14,00;
OUT 15,02/14,FC; OUT 15,01/14,02; OUT 15,00/14,7C. Период между пачками ~6200 T-состояний
(последовательностей) эмулятора. (Fact)

## 3. Точка входа и самомодификация

- Файл: 0x0100 = C3 CF 04 (JMP 0x04CF = инициализация).
- Инициализация 0x04CF-0x053A: DI; LXI H,0657; STA 0466 (темп); SHLD 0111; чтение
  заголовка (CALL 010B x3, CALL 053F сохранение 045E/0460/0462); очистка таблицы
  0x046F+ (45 байт, MVI M,00; первый байт 0xFF); инициализация каналов; JMP 0549.
- 0x0549: CALL 0442; LXI H,049D; SHLD 0101 (PATCHET вход: JMP 0x0100 -> JMP 0x049D);
  PCHL (уход в главный цикл).
- Проверено: breakpoint 0x054F срабатывает один раз за 3+ с работы -> патч однократный.
- В рантайме 0x0100 = C3 9D 04 (наблюдалось debug_disassemble_range после прогона).
- Непрерывные записей в блок 0x0100 (write_count 16810 -> 35810) — это НЕ повторный патч
  0x0101, а рабочие указатели поверх «мёртвых» байтов кода: SHLD 0103 (0x01C1, 0x01DE,
  0x0120) и SHLD 0111 (0x04D7). 0x0103/0x0111 = переменные-указатели потока музыки,
  встроены в код (самомодифицируемые данные). (Inference, High)

## 4. Снимки памяти (дельта за ~6 с)

Изменены: 0x0419, 0x0467, 0x0469, 0x046B, 0x046D, 0x0472+2, 0x0479, 0x047C+2, 0x0483,
0x0486+2, 0x0489+9, 0x0493+2, 0x0496+4, 0xC2F7+2.
=> переменные состояния 3 каналов в 0x0466-0x0499 + стек.
0x0101 не изменился между снимками (патч уже выполнен ранее) — согласуется с п.3.
0x0600+ дельта нулевая из-за XOR-инволюции (зашифровано<->расшифровано) — НЕ вывод
«нет записей»: access-лог показывает writes из 0x056D по 0x064E-0x0659 и др. (Fact)

## 5. XOR-дешифровка музыки (0x055F / 0x0600+)

Access-лог (без остановки) зафиксировал цикл с PC 0x056B-0x0571:
LDAX D (читает 0x064E..), XRA M (ключ из 0x0556..), STAX D (пишет 0x064E..), INX H/INX D,
DCR B / JNZ 056B — 12-байтовый слот. DE = 0x0600 + 2*младший_байт_адреса_возврата
(POP D в 0x055F, ADD A в 0x0561, MVI H,06 в 0x0563). Ключ: 0x0553-0x055E
(77 6C 67 D0 B6 6A 7F 7F 3F B3 38 9F). После цикла: LHLD 0103; POP PSW; POP D; RET (0x0574-0x0579).
Fetch-активность блока 0x0600 = исполняются куски дешифрованного кода/данных по
вычисляемым адресам (PCHL) — дефект статического анализатора, сидируем в Stage 2. (Fact+Inference)

## 6. Итоговая классификация

### Verified Facts
1. Вход: файл JMP 0x04CF; после init 0x0100 = JMP 0x049D; патч однократный (SHLD 0101 @0x054F).
2. Порты: IN 0x01 (=0xEF), OUT 0x14/0x15; AY регистры 0x00-0x0A; конверт не используется.
3. VRAM не трогается; ВИ53/палитра/квазидиск не используются.
4. SP=0xC300; стек в 0xC2xx.
5. Динамические переменные: 0x0419, 0x0466-0x0499; указатели-в-коде 0x0101, 0x0103, 0x0111.
6. Данные трека в 0x0600-0x0E7F; XOR-слоты 12 байт; writes подтверждены логом.

### Inferences
- 0x049D-0x04CC — главный цикл: CALL 01AE (тик проигрывателя), software-delay 0x04A1-0x04A9,
  опрос IN 01, ветка 0x04BB/0x04B2 (счётчик 0x04A2 как переменная-слот внутри кода LXI H).
- 0x01AE+ — реплеер: LDA 0467/DCR/STA (деление темпа), разбор 3 каналов (LHLD 0469/046B/046D).
- 0x04CF — загрузка заголовка трека (темп 0x0466, параметры каналов 0x045E/0x0460/0x0462).
- Байты 0x0103-0x0104, 0x0111 и операнд 0x04A2 — данные, легально «прописанные» в мёртвых
  участках кода (приём защиты/утеснения).

### Hypotheses (не проверено)
- 0x04B2 MVI A,07; OUT 15; OUT 14 — запись mixer-регистра при «другом» состоянии клавиатуры.
- 0x032E, 0x0437, 0x0470 — реальные кодовые цели JCC/PCHL (сидируем в Stage 2).

### Unknowns
- Назначение 0x0419 и полей 0x0472/0x047C/0x0486 до точной разбора Stage 2.
- 43 чтения из блока 0x0F00: выход указателя потока за 0x0E7F (метка конца?) — проверить.

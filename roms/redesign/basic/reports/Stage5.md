# Stage 5 — Архитектура интерпретатора (под-пакеты 5a, 5b)

Здесь закрыт **главный открытый пункт всего исследования**: механизм диспетча
КОМАНД, оставленный незакрытым со Stage 2. Плюс задокументирован каркас REPL,
подписано ядро операторов акцепт-критерия Stage 5, а в 5b — весь оставшийся набор
команд/расширений и хранение строк программы.

Итог: **5a — +16 объектов** (470→482); **5b — +24 объекта** (482→506) и 2
обновления на месте. Round-trip **byte-for-byte identical** (экспорт 17152 байт,
6/6 стадий пайплайна SUCCESS).

---

## 0. Что доказано (и почему это важно)

Со Stage 2 было известно: диспетчер **функций** `0xAE..0xC9` — это таблица
адресов `data_dispatch_table` `0x2770` с вычислительным прыжком `PCHL`
(`func_exec_dispatch` `0x0B09`). Команды `0x80..0xAD` исполнялись «иным путём»,
не вскрытым; регион `0x26D7..0x2770` казался мусором, `SUI 80H` в ROM нет,
цепочек `CPI <команда>` тоже нет.

Разгадка: **диспетчер команд — самомодифицируемый индексный переход** по таблице
`data_cmd_table` в `0x2700`. Регион `0x26D7..0x2770` — не мусор, а именно эта
таблица (прежнее впечатление дал линейный дизасемблинг поверх встроенных данных
плюс то, что сервер отладчика держал чужой ROM; сейчас `basic.r0m` загружен,
байты совпали с файлом).

## 1. Механизм диспетча (`func_cmd_dispatch` `0x049A`)

```
0x049A  INX H / MOV A,M / CPI 3A / JNC 04A7 / CPI 20 / JZ 049A   ; пропуск `:` и пробелов, взять токен
0x04A7  LXI D,046B / PUSH D / RZ                                ; токен==0 (конец строки) — выход
0x04AC  ADD A                                                   ; A = 2*token (carry = бит7)
0x04AD  JNC 0691        ; token < 0x80 (идентификатор) -> путь присваивания (func_cmd_let)
0x04B0  CPI 3A / JC 04BC
0x04B5  CPI 94 / JC 0074 ; вне диапазона команд -> заглушка (ошибка)
0x04BA  SUI 5A            ; поправка под старший блок токенов
0x04BC  XCHG
0x04BD  STA 04C1          ; младший байт адреса LHLD <- A  (самомодификация)
0x04C0  LHLD 2700         ; HL = word из data_cmd_table[0x2700 + (token-0x80)*2]
0x04C3  PUSH H            ; адрес обработчика на стек (дальше — вычислительный переход)
```

Формула: **смещение = (токен − 0x80) · 2**, база `0x2700`. `ADD A` удваивает
токен; для `0x80..0x9C` это `0..0x38` (младший байт). Запись `0x0074` = оператор
не реализован / не вызывается из позиции команды либо отсутствует аргумент
(`* / ^ AND OR > =`; у DELETE — `JNC 0074`).

**Плотная двухсегментная таблица (уточнено в 5b).** Range-проверка `CPI 3A / JC
04BC` и `CPI 94 / JC 0074` отклоняет токены `0x9D..0xC9` (это функции/операторы/
синтаксис, а не операторы) — они **не занимают слотов**. Ветка `SUI 5A` для
токенов `>= 0xCA` даёт `off = (2·token mod 256) − 0x5A` = `0x3A..0x6E`, то есть
**расширения `0xCA..0xE4` идут вплотную за командами**. Итого один диспетчер
роутит оба сегмента, таблица `0x2700..0x276F` = `0x70` байт (56 записей).

Формула проверена поведением: `0x88→0x2710`=`0x0602` (GOTO), `0x95→0x272A`=
`0x072D` (PRINT); кросс-проверка сегмента B: `HOME(0xCD)→0x2740` и `CLS(0x80)→
0x2700` оба дают `0x4022` (плотная упаковка подтверждена).

## 3. Каркас REPL (`func_boot_init` → `func_main_loop` → `func_tok_tokenize`)

- **`0x0000`** — `LXI SP,7FFF / JMP 19CC`.
- **`func_boot_init` `0x19CC`** — PIA2 (`OUT 04=0x81`), расстановка текстовых
  указателей (`0x3F21`/`0EF6`/`0ED6`/`3DFC`), первичные вызовы (`0x07BC`/
  `0x019F`/`0x01C5`), самомодификация начальных адресов, затем `JMP 0x00E5`.
- **`func_main_loop` `0x00E5`** — состояние `_READY`: печать баннера (строка
  `0x254B`), ввод/редактирование строки (до 127 симв., п.85 change log), далее
  `0x0124` → `func_tok_tokenize`; строка с номером — вставка в программу, без
  номера — immediate-exec (→ `func_cmd_dispatch`).
- **`func_tok_tokenize` `0x01EF`** — скан буфера ввода `0x3F77` против
  `data_keyword_table` `0x256E` (`LXI D,256D`); токен = `0x80 + номер слова`
  (`MOV A,B / ORI 80`).

## 4. Подписанные обработчики (ABI + page-zero)

Контракт (единый для команд, ТЗ §3): вход — `HL` = текстовый указатель на поток
токенов после кода команды; выход — указатель на конец команды; продвижение —
через `0x404D` (текстовый указатель в page-zero FAC).

| объект | адрес | ключевые доказательства тела | page-zero/RAM |
|---|---|---|---|
| `func_cmd_let` | `0x0691` | `CALL 0BCD` (var) / `CPI 0AC` (`=`) / `CALL 09B1` (eval) | читает/пишет `0x404D`, FAC `0x404F..0x4052` |
| `func_cmd_print` | `0x072D` | `,`/`;` разделители, `TAB( 9D`/`SPC( 9F`/`AT C8`, `CALL 1C7A`, `LDA 0C8C` | `0x404D`, `0x0C8C` (стр. флаг) |
| `func_cmd_goto` | `0x0602` | `CALL 053E` (номер) + цикл сравнения `BC`/`DE` строк | `0x404D` на строку |
| `func_cmd_gosub` | `0x05B9` | `MVI D,8C / PUSH D` (маркер) + `LHLD 0625` (стек возвратов) | стек GOSUB `0x0625` |
| `func_cmd_return` | `0x063C` | `POP PSW / CPI 8C` — размотка до маркера GOSUB | стек `0x0625`, `0x404D` |
| `func_cmd_if` | `0x0712` | `CALL 09B1` / `CPI A1` (THEN) / `LDA 4050` / `JZ 0672` | FAC `0x4050` (истина/ложь) |
| `func_cmd_for` | `0x03F3` | `MVI A,11 / CALL 01E8` (блок 17б) / `CALL 0691` (LET) / `CPI 81` | стек блоков FOR |
| `func_cmd_next` | `0x08F6` | `CPI 81` (маркер FOR) / `JNZ 007E` (NEXT без FOR) | стек блоков FOR |
| `func_cmd_input` | `0x0819` | prompt `0x22` / `CALL 0E72` / `,`/`;`-список | `0x404D`, вывод |
| `func_cmd_read` | `0x0869` | `PUSH H` / `CALL 0BCD` (var) / поиск эл-та DATA | указатель DATA, `0x404D` |
| `func_cmd_data` | `0x0679` | `LXI B,3A22` — пропуск до `:`/`"`/конца (`RZ`) | `0x404D` |

Парности доказаны маркерами: GOSUB кладёт `0x8C`, RETURN ищет `0x8C`; FOR
кладёт `0x81`, NEXT ищет `0x81`; FOR вызывает `func_cmd_let` (`0x0691`) для
инициализации переменной.

## 5. Применённые изменения (RDB)

16 объектов: 3 переквалификации метка→функция (`0x049A`/`0x00E5`/`0x0691`),
1 переименование (`func_01ef`→`func_tok_tokenize`), 12 созданий (`data_cmd_table`,
`func_boot_init`, 10 обработчиков). Действий: add 12 / retype 3 / rename 1 /
comment 16 / property 81 / link 14 / save 1. Связи вызовов: `func_cmd_dispatch →
data_cmd_table/func_cmd_let`; `func_tok_tokenize → data_keyword_table`;
`func_main_loop → func_tok_tokenize/func_cmd_dispatch`; `func_cmd_let/print/if →
func_eval_expression`; `func_cmd_let/read → func_var_lookup`; `func_cmd_goto/
gosub → func_053e`; `func_cmd_for → func_cmd_let`.

Round-trip: `export_asm → toolchain_lint → symbolic_operand_lint → syntax_check
→ roundtrip_verify → measure_sizes` — 6/6 SUCCESS, **byte-for-byte identical**.

> Замечание по именованию: в согласованном плане диспетчер команд значился как
> `func_exec_dispatch`, но это имя уже занято диспетчером **функций** (`0x0B09`,
> Stage 2). Командный диспетчер назван `func_cmd_dispatch` — тот же смысл, без
> коллизии.

## 6. Открытые пункты (остаток Stage 5 → под-пакет 5d)

- **Ввод-вывод / графика / лента** (`OUT`/`POKE`/`PLOT`/`LINE`/`CLOAD`/`CSAVE`/
  `LPRINT`/`LLIST`/`SCREEN`/`COLOR`/`GET`/`PUT`/`BSAVE`/`BLOAD`/`PLAY`/`PAINT`/
  `CIRCLE`) — адреса обработчиков уже есть в таблице §2 (именование отложено);
  подсистемы (ВГД-вывод `0x1C95`/`func_putchar`, звук, магнитофон) — 5d.
- **Карта page-zero/RAM** (`0x404D` текст, `0x404F..0x4052` FAC, `0x0625` стек
  GOSUB, `0x0C33`/`0x0464` указатели строк, `0x0609` возобновление скана,
  `0x0EF6`/`0x0ED6` границы, `0x3F21` база программы, `0x3F77` буфер токенов) —
  5d/Stage 6. В 5b эти ячейки упоминаются в ABI-комментариях обработчиков.
- **Оценщик выражений** (`func_eval_expression` `0x09B1`, приоритеты, реляционный
  хвост `0x09DD`) — подтверждён как вызываемый, подробности — 5d.

## 8. Под-пакет 5b — команды, расширения, хранение строк

**Что закрыто сверх 5a:**

1. **Диспетчер расширений.** Тот же `func_cmd_dispatch`, плотная двухсегментная
   таблица (`SUI 5A` → второй сегмент `0xCA..0xE4`). См. §1, §2. Размер
   `data_cmd_table` исправлен `0x5C → 0x70`.
2. **CLS/HOME.** `0x4022` = **код** (`MVI A,1F / JMP 1C95` — байт очистки экрана
   в ВГД). Оговорка 5a («RAM-мусор») была артефактом чтения по неверному адресу
   (`0x4042`). Именован `func_cmd_cls_home` (общий для CLS `0x80` и HOME `0xCD`).
3. **Ветка REPL `0x012B`.** `CALL 053E` (есть номер? carry) + `CALL 01EF`
   (токенизировать) + `POP PSW` + `JNC 049A`: нет номера → исполнить оператор;
   есть номер → вставка/замена строки (`func_prog_line_insert`).
4. **Формат хранения программы.** `[LN_младш LN_старш][токены…][00]`, последо-
   вательно, без связок; `00 00` = конец. `func_prog_line_insert` (`0x012E`) —
   поиск точки → сдвиг (`CALL 003B`) → запись номера+токенов+`00` → правка конца
   (`CALL 01AA`). `func_prog_step` (`0x0619`, указатель возобновления `0x0609`) —
   резюмируемый пошаговый скан (общий для GOTO/LIST/RUN/DELETE/INSERT).
5. **`0x0074`** — stub «нет/неверный аргумент» (DELETE `JNC 0074`), он же в
   таблице как «не вызывается оператором».

**Тела подтверждены дизасемблом:** `func_cmd_new`, `func_cmd_cls_home`,
`func_cmd_edit`, `func_cmd_list`, `func_cmd_delete`, `func_cmd_cur`,
`func_prog_line_insert`, `func_prog_step` (скан GOTO). Остальные — из доказанной
таблицы токен→адрес (+ токен→слово из Stage 2).

**Применено (RDB):** +24 объекта (506 всего; 482→506), 2 обновления на месте
(`data_cmd_table` size+mechanism, `func_cmd_dispatch` note). Действий: add 24 /
comment 26 / property 123 / link 22 / resize 1 / save 1. Связи: обработчики →
`func_prog_step`/`func_cmd_dispatch`/`func_053e`/`func_var_lookup`/
`data_keyword_table`/`func_putchar`; вставка/слияние/авто → `func_prog_line_insert`.

Round-trip: 6/6 SUCCESS, **byte-for-byte identical** (экспорт 17152 байт).

## Эталонный эмулятор и тестовый стенд Vector-06C

В проекте используются следующие исходные файлы:

- v06_emu.py — основной Python-эмулятор Intel 8080 / KR580VM80A и исполнитель ASM-кода;
- v06_test_template.py — шаблон и инфраструктура автоматического тестирования ASM-процедур.

Эти файлы являются рабочей основой тестового стенда проекта «Конвертер C-кода в ASM».

### Назначение v06_emu.py

v06_emu.py используется для машинной проверки ASM-кода, предназначенного для классического Вектора-06Ц.

При работе с ASM необходимо по возможности запускать код через этот эмулятор, а не ограничиваться визуальным анализом исходника.

Эмулятор должен рассматриваться как исполняющая модель Intel 8080. Не использовать Z80-специфичные инструкции, регистры или возможности, если пользователь явно не указал иное.

### Назначение v06_test_template.py

v06_test_template.py используется как основа для создания автоматических тестов ASM-процедур.

Предпочтительная схема проверки:

    C algorithm
        ↓
    Python reference model
        ↓
    expected result / expected trace
        ↓
    ASM
        ↓
    v06_emu.py
        ↓
    actual result / actual trace
        ↓
    automatic comparison

При наличии исходного C-кода необходимо по возможности создавать независимую reference-модель алгоритма на Python.

### Обязательная проверка

После генерации или существенного изменения ASM необходимо, если это технически возможно:

1. загрузить ASM в v06_emu.py;
2. выполнить процедуру на 8080;
3. получить фактическое состояние регистров, памяти и trace;
4. получить ожидаемый результат reference-модели;
5. автоматически сравнить expected и actual;
6. при расхождении определить первое несовпадение.

Нельзя считать ASM проверенным только потому, что он выглядит логически правильным.

### Диагностика первого расхождения

При FAIL необходимо прежде всего сообщить первое обнаруженное расхождение:

- операция;
- PC;
- инструкция ASM;
- предыдущие значения регистров;
- текущие значения регистров;
- флаги;
- адрес памяти;
- ожидаемое значение;
- фактическое значение;
- соответствующая операция reference-модели.

Не исправлять ASM на основании предположения о причине ошибки, если её можно установить экспериментально через эмуляцию.

После каждого исправления необходимо повторно выполнить тест.

### Соглашение о вызовах

Все ASM-процедуры, вызываемые из C через z88dk, должны разрабатываться с учётом calling convention:

    __z88dk_callee

Тестовый стенд должен уметь формировать соответствующую начальную раскладку стека и параметры процедуры.

### Реальные тестовые данные

Если пользователь предоставляет BIN, INC, ASM, C, изображения, таблицы данных или другие тестовые материалы, необходимо использовать именно их.

Не заменять реальные данные искусственными примерами без явной необходимости.

### Vector-06C VRAM

Для операций с видеопамятью нельзя предполагать, что физическая организация VRAM совпадает с простой линейной адресацией CPU.

При тестировании графического ASM необходимо отдельно учитывать фактическую адресацию плоскостей, байтов, строк, тайлов и т.п., если это относится к конкретному алгоритму.

### Ограничения эмулятора

v06_emu.py предназначен прежде всего для проверки ASM-процедур и алгоритмов.

Вывод изображения на экран и эмуляция звука для целей этого проекта не требуются.

Если для проверки конкретного ASM встречается инструкция или конструкция, которую текущая версия эмулятора не поддерживает, необходимо сначала расширить эмулятор и проверить её, а не заменять реальное выполнение предположением.

### Приоритет

При конфликте между визуальным анализом ASM и результатом машинной проверки приоритет имеет воспроизводимый результат эмуляции.

Цель проекта — получать ASM, подтверждённый исполнением:

    reference result == emulator result

или, для trace:

    reference trace == emulator trace

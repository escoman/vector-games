# putup-beam — демо beam-подсистемы

Демо библиотеки [lib/gfx/beam.c](../../../lib/gfx/beam.c) (beam-синхронный
планировщик спрайтов, паспорт `roms/games/putup/BEAM_TZ.MD`) на ассетах игры
putup: уровень 16×32 клетки (512px = ровно 2 кольца VRAM) с аппаратным
вертикальным скроллингом, плавной анимацией героя и двумя патрулирующими
врагами. Вся видимая графика идёт через `beam_*`; единственный писатель VRAM в
кадре — `beam_render` (блокирует до конца кадра, темп 50 Гц).

По плану демо НЕ содержит: HUD, счёт, время, Hurry Up, огонь, музыку.

## Структура

| файл | назначение |
|---|---|
| `main.c` | игровая логика демо (герой, враги, камера, ключи/выход) |
| `tools/gen_assets.py` | генератор `assets.inc`: тайлы 16×16 из глифов putup (герой — маска + субпиксель 4px вариантами v0/v1, враги — плоские) |
| `tools/gen_level.py` | генератор `level.inc`: level_01 ×3 по вертикали со стыками-шахтами; гейт flood-fill (выход/ключи/спавны достижимы) |
| `assets.inc`, `level.inc` | АВТОГЕНЕРАЦИЯ, не править |
| `Makefile` | `make full` — сборка ROM (org 0x0100) + раскладка в каталог эмулятора |

## Управление

| клавиша | действие |
|---|---|
| ← / → | шаг на клетку (работает и в полёте — управление в воздухе) |
| ПРОБЕЛ / СС | прыжок: подъём на 2 клетки, зависание на апексе, отпускание — сразу падение |
| ↑ | подъём по шахте на клетку (удобство демо: шахты выше прыжка) |
| ESC | fade-out и выход |

Цель: собрать все ключи (коды 07/0A/0B) — выход (23) открывается и мигает
фазами 22/23; войти в выход — рестарт уровня. Касание врага — рестарт.

## Механика, перенесённая из оригинального putup

- **Прыжок** — action-клавиша (ПРОБЕЛ/СС) как `func_gamestate_catch`/`_evade`:
  подъём 2 клетки (4 глиф-строки оригинала), счётчик зависания на апексе
  (3 тика оригинала ≈ 18 кадров), отпускание клавиши — немедленная гравитация.
- **Управление в полёте**: диспетчер клавиш X работает во всех вертикальных
  фазах (в оригинале — внутри catch/evade); easing по осям независимый
  (`mv_x`/`mv_y`).
- **Твёрдость**: как в оригинале по глифам тайла ≥ 77h — коды 02/04/05/08,
  включая «?»-ящик (04h, глифы 7E..82h): герой стоит на нём, не проваливается.
- **Враги**: пара кадров state1/state2 оригинала (tg[20]/tg[19]) = направление
  вправо/влево, а не фаза анимации; субшаг ходьбы — субпиксель X. Кадр героя —
  по формуле putup `idx = work_const + 3*move_dir − 1` (ходьба/стойка на обе
  стороны).

## Контракт цикла (BEAM_TZ §2.2)

Кадровый ISR = `timer_start()` + `kbd_scan_now()` (последний flush-ит регистр
скролла в порт 03h на VBlank). Цикл: `v06_wait_frame` → игровая логика (только
мутаторы `beam_*`) → `beam_update` → `beam_render`. Открытая полоса камеры
перерисовывается в бланкинге до flush скролла; мировая адресация кольца
(`ring y = world_y & 0xFF`).

## Гейты и результаты

- **Сборка**: `make full` — чисто, ROM 21240 байт.
- **Генерация**: flood-fill level.inc — достижимы выход, 22 ключа, оба спавна;
  шахты стыков сквозные.
- **Темп**: 1 тик логики на VBlank (пейсер `beam_render`); шаги детерминированы
  (враг 4px/тик, герой 2px/тик по Y), двойных/пропущенных шагов не наблюдалось.
- **Растер-бюджет**: `beam_overbudget()` = 0 за прыжки, полёт, скролл камеры и
  патрулирование (`ovb_seen` в BSS — для часов отладчика).
- **Tearing**: снапшоты TV-кадра в движении (падение по шахте со скроллом
  камеры) — разрывов растра нет: запись за лучом по контракту beam.
- **Функциональные** (живая эмуляция, чтение статики из `.map`): прыжок
  y 48→16 с апексом и зависанием; рулёжка X на апексе 128→224; посадка на
  «?»-ящик y=96 (не проваливается); дескриптор врага переключается между
  зеркальными рядами кадров по знаку направления.

## Отладка

Статика демо в BSS (адреса — в `putup-beam.map`: `keys_left`, `hero_x/y`,
`mv_x/mv_y`, `hero_vstate`, `enemy_dir`, `enemy_pat`…); запись памяти — только
на паузе эмулятора. Таблицы кадров: `hero_frames` @0x1952, `enemy_frames`
@0x1CCF (ряд 0 вправо, ряд 1 влево).

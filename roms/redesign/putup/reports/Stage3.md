## Детальное описание всех функций

### 1. Точка входа и инициализация

#### `rom_entry` (0x0100, 4 байта)
```asm
DI              ; запрет прерываний
JMP 0B57        ; переход к rom_init
```
**Назначение:** Точка входа ROM. Сразу передаёт управление на `rom_init`.

#### `rom_init` (0x0B57, 313 байт)
**Назначение:** Полная инициализация системы при старте.
**Алгоритм:**
1. `LXI SP, 0100` — установка стека
2. Очистка RAM 0x8000–0xFFFF нулями
3. `CALL init_1` — настройка прерываний
4. `CALL init_2` — обработка графики
5. Копирование графики: ROM 0x2F61 → RAM 0x7418
6. `CALL init_objects` — инициализация ISR-объектов
7. `CALL obj_setup` — загрузка данных объектов в 0x5000
8. Переход к основному циклу

**Связи:** → `init_1`, `init_2`, `init_objects`, `obj_setup`, `gfx_source_data`

#### `init_1` (0x0383, 33 байта)
**Назначение:** Настройка векторов прерываний и видеоконтроллера.
**Алгоритм:**
1. `OUT 0x10` — запись в порт видеоконтроллера
2. `STA 08CF` — сохранение параметра
3. `MVI A, 0xE0; STA 08D0` — установка draw_offset
4. `MVI A, 0xC3; STA 0038` — opcode JMP по адресу RST 7
5. `LXI H, 03A4; SHLD 0039` — вектор RST 7 → `isr_handler`
6. `LXI H, 0B57; SHLD 0001` — вектор Reset → `rom_init`
7. `EI; RET`

**Связи:** → `isr_handler` (устанавливает вектор)

#### `init_2` (0x0401, 46 байт)
**Назначение:** Цикл обработки графических данных. 256 итераций от базы 0x6000.
**Алгоритм:**
1. Сохранение регистров (H, D, B, PSW)
2. `CALL gfx_sub_04CD` — подготовительная подпрограмма
3. `LXI H, 6000` — база графической области
4. `LXI D, 3041` — ROM-данные
5. Цикл (256 итераций): вызывает `main_logic`, `gfx_sub_045E`, `gfx_sub_0483`, `gfx_sub_04A8`
6. Восстановление регистров; RET

**Связи:** → `gfx_sub_04CD`, `main_logic`, `gfx_sub_045E`, `gfx_sub_0483`, `gfx_sub_04A8`

#### `init_objects` (0x3D4E, ~124 байта)
**Назначение:** Инициализация структуры ISR-объектов.
**Алгоритм:**
1. Обнуление счётчиков анимации 0x383A–0x383D
2. Чтение базового указателя из 0x3856
3. Запись указателя в 0x0B41
4. Заполнение полей объекта: [0B41+0]=E, [0B41+1]=D, [0B41+2]=E, [0B41+3]=D, [0B41+4]=E
5. Копирование 3 байт из 0x3DCA в VRAM 0x03F8
6. `EI; RET`

**Связи:** → `obj_ptr_0B41`, `anim_frame_counter`

#### `obj_setup` (0x1BE5, 21 байт)
**Назначение:** Инициализация 0x400 байт по адресу 0x5000 из ROM. Ожидает клавишу.
**Алгоритм:**
1. `LXI H, 5000; LXI B, 0400` — цель и размер
2. Цикл: `CALL data_read_loop` — чтение данных
3. `MVI A, 0x20; CALL kbd_input_handler` — ожидание клавиши Space
4. Цикл по B с проверкой клавиатуры
5. RET

**Связи:** → `data_read_loop`, `kbd_input_handler`

### 2. Прерывания (ISR)

#### `isr_handler` (0x03A4, 93 байта)
**Назначение:** Обработчик прерываний RST 7 (50 Гц).
**Алгоритм:**
1. Сохранение регистров (H, D, B, PSW)
2. Инкремент счётчика по 0x08DF
3. Проверка счётчика по 0x08C3 — если 0, переход к музыкальному блоку
4. AY-3-8910: запись регистров через OUT 0x0C (данные из 0x08DB)
5. Чтение клавиатуры: `IN 02`, сохранение в 0x08D3
6. `MVI A, 0x88; OUT 00` — выбор AY-регистра
7. `CALL isr_anim_update` (0x3858)
8. Восстановление регистров; `EI; RET`

**Связи:** → `isr_frame_counter`, `isr_counter_08C3`, `isr_data_ptr`, `ay_init_data`, `isr_anim_update`

#### `isr_anim_update` (0x384E, 48 байт)
**Назначение:** Обновление анимации объектов в ISR.
**Алгоритм:**
1. Чтение указателя из 0x3854 → 0x0B41
2. Чтение типа объекта из [HL+2]
3. Чтение `anim_frame_counter` (0x383A), удвоение
4. Если 0 — сброс счётчика, вызов `isr_sub_3890`
5. `CALL isr_obj_update_1`
6. `CALL isr_obj_update_2`

**Связи:** → `obj_data_ptr_3854`, `obj_ptr_0B41`, `anim_frame_counter`, `isr_obj_update_1`, `isr_obj_update_2`, `isr_sub_3890`

#### `isr_obj_update_1` (0x3BCA, 52 байта)
**Назначение:** Обновление объектов типа 1 в ISR.
**Алгоритм:**
1. Чтение указателя из 0x3854 → 0x0B41
2. Чтение типа из [HL+0x0D]
3. Если 0 — выход
4. Диспетчеризация по типу через таблицу 0x445D (шаг 0x14 байт)
5. Вычисление позиции: HL = 0x445D + (type-1) × 0x14

**Связи:** → `obj_data_table_1` (0x445D)

#### `isr_obj_update_2` (0x3C7D, 60 байт)
**Назначение:** Обновление объектов типа 2 в ISR.
**Алгоритм:** Аналогично `isr_obj_update_1`, но таблица 0x42F9, шаг 0x0A байт. Проверяет флаг `isr_flag_3BC8`.

**Связи:** → `obj_data_table_2` (0x42F9), `isr_flag_3BC8`

#### `isr_sub_3890` (0x3890)
**Назначение:** Подпрограмма сброса кадров анимации. Вызывается из `isr_anim_update` когда счётчик обнуляется.

### 3. Основная логика

#### `main_logic` (0x0439, 226 байт)
**Назначение:** Главная логика игры/меню. Содержит таблицу диспетчеризации и обработку состояний.
**Вызовы:** `data_read_loop` (×5), `kbd_input_handler` (×4)

#### `data_process_loop` (0x0C65, 123 байта)
**Назначение:** Основной цикл обработки данных. Сканирует RAM 0x5180 на маркеры.
**Алгоритм:**
1. `LXI H, 08F5; INR M` — инкремент счётчика кадров
2. Проверка счётчика < 0x10
3. `LXI H, 1C0E` — таблица ROM-данных
4. Загрузка данных по индексу из 0x08F5
5. `CALL copy_to_vram_3DCD` — копирование в VRAM
6. `LXI SP, 0100; CALL obj_setup` — переинициализация
7. Цикл обработки объектов: `CALL obj_copy_data`, `CALL obj_draw_data`
8. `CALL sub_1197`, `CALL sub_11E9`, `CALL sub_121A`
9. Установка состояний 0x0901, 0x0902

**Связи:** → `dec_mod8`, `data_read_loop`, `kbd_input_handler`, `calc_and_draw`, `copy_to_vram_3DCD`, `obj_copy_data`, `obj_draw_data`, `game_main_loop`

#### `game_main_loop` (0x197C, ~200 байт)
**Назначение:** Главный игровой цикл.
**Алгоритм:**
1. Инкремент `frame_counter_08F5`
2. Загрузка данных из ROM-таблиц (0x1C0E/0x1C8E)
3. Цикл по 32 объектам: `CALL obj_copy_data`, `CALL obj_draw_data`
4. Вызов `sub_1197`, `sub_11E9`, `sub_121A`
5. Установка таймеров и состояний

**Связи:** → `obj_copy_data`, `obj_draw_data`, `rom_data_table_1C0E`, `obj_coords_table`

#### `scan_loop_tail` (0x0C95, 8 байт)
**Назначение:** Хвостовая часть `data_process_loop`. Не самостоятельная функция.
```asm
INX H           ; HL++
DCR B           ; B--
JNZ 0C7D        ; продолжить цикл
JMP 0C65        ; вернуться к началу data_process_loop
```

### 4. Обработка данных и ввод

#### `data_read_loop` (0x0145, 14 байт)
**Назначение:** Цикл чтения данных из ROM и вывода на экран.
```asm
MOV E, M        ; E = [HL]
CALL 1BD4       ; calc_obj_addr
MOV A, M        ; A = [HL]
CALL 0803       ; draw_to_vram
RET
```
**Связи:** → `calc_obj_addr`, `draw_to_vram`

#### `kbd_input_handler` (0x01A1, 13 байт)
**Назначение:** Обработчик клавиатуры.
**Алгоритм:** `IN 01` → `ANI 0x20` (проверка бита 5) → возврат результата.

#### `calc_and_draw` (0x01AE, 11 байт)
**Назначение:** Отрисовка по координатам из RAM.
**Алгоритм:**
1. `LDA 08FE` → D (X-координата)
2. `LDA 08FF` → E (Y-координата)
3. `CALL calc_obj_addr` — вычисление адреса
4. `JMP data_read_loop` — отрисовка

**Связи:** → `var_08FE`, `calc_obj_addr`, `data_read_loop`

#### `dec_mod8` (0x017C, 6 байт)
**Назначение:** Циклический декремент mod 8.
```asm
DCR A           ; A = A - 1
JM wrap         ; если ушёл в минус
CMP L; RET      ; иначе выход
wrap: MVI A, 07 ; A = 7
CALL sub_0197   ; дополнительная обработка
ANI 0x80        ; проверка бита 7
JZ exit         ; выход если 0
```
**Связи:** → `sub_0197`

#### `data_dispatch` (0x0321, 94 байта)
**Назначение:** PCHL-диспетчеризация к подфункциям.
**Цели:** 0x0439, 0x045E, 0x0483, 0x04A8, 0x04CD
**Связи:** → `data_reader_032C`

#### `data_reader_032C` (0x032C)
**Назначение:** Чтение данных через адресную таблицу. Вызывается из `data_dispatch` и dispatch-таблицы 0x01BC.

#### `sub_0197` (0x0197)
**Назначение:** Подпрограмма обработки 8-состояний. Вызывается из `dec_mod8`. Читает данные из 0x08D3.

### 5. Отрисовка и объекты

#### `draw_to_vram` (0x0800, 163 байта)
**Назначение:** Запись байта в VRAM с вычислением адреса.
**Алгоритм:**
1. `ORA A; RZ` — если A=0, выход
2. Сохранение регистров
3. Вычисление VRAM-адреса: HL = HL + 0xB000, маппинг координат
4. Сохранение SP в 0x08DD
5. Запись 16 байт (8 пар DE) в VRAM через POP/MOV
6. Восстановление SP, регистров; `EI; RET`

#### `calc_obj_addr` (0x1BD4, 17 байт)
**Назначение:** Вычисление RAM-адреса объекта по индексу.
**Формула:** `HL = E × 32 + D × 256 + 0x5000`
```asm
MOV L, E; MVI H, 0  ; HL = E
DAD H × 5           ; HL = E × 32
MOV E, D; MVI D, 0  ; DE = D
DAD D               ; HL += D × 256
LXI D, 5000
DAD D               ; HL += 0x5000
RET
```

#### `obj_copy_data` (0x1B87, 33 байта)
**Назначение:** Копирование 5 байт данных объекта из ROM в RAM.
**Алгоритм:**
1. `CALL calc_obj_addr` — адрес в RAM
2. 5× `LDAX D; CALL data_read_loop; INX D; INX H`

**Связи:** → `calc_obj_addr`, `data_read_loop`

#### `obj_draw_data` (0x1BA8, 32 байта)
**Назначение:** Отрисовка объекта в VRAM.
**Алгоритм:** Аналогично `obj_copy_data`, но вызывает `draw_to_vram` (0x0803) вместо `data_read_loop`.

**Связи:** → `calc_obj_addr`, `draw_to_vram`

#### `copy_to_vram_3DCD` (0x3DCD)
**Назначение:** Копирование блока данных в VRAM. Вызывается из `data_process_loop`.

## Неисследованные области для Stage 4

1. **Текстовый вывод:** Функции `data_process_loop` и `game_main_loop` работают с данными в 0x5000, которые содержат текст "Hi 2000". Необходимо найти функцию, которая выводит текст из 0x5000 в VRAM.

2. **Глифы:** Графика по адресу 0x7418 (скопированная из 0x2F61) содержит спрайты. Необходимо определить, какие из них являются глифами для текстового вывода.

3. **Подфункции 0x045E–0x04CD:** Четыре графические подфункции требуют детального исследования.

4. **Подфункции 0x1197, 0x11E9, 0x121A:** Вызываются из `game_main_loop`, назначение не установлено.

5. **Функция 0x3890:** Условный вызов из `isr_anim_update`.

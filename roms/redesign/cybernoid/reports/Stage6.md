# Stage 6. Вывод текста на экран + каталог строк (cyberno.rom) — кратко

## Постановка (TZ §Stage 6)

`strings_scan` находит кандидатов; ИИ подтверждает и классифицирует, создаёт
объекты `str_*` (комментарий = расшифровка транслита в русский; для речевых —
пометка `str_voice_*`). Установить **кодировщик экранного шрифта** (транслит +
разделитель `%`) и **базовый адрес глифов** `data_glyph_block` (подтвердить
`glyph_scan`).

## Метод

Кандидаты из `.scratch/pipeline/cybernoid/strings_scan.json`. Подтверждение —
живыми дампами `debug_read_memory_range` **на PC=0 сразу после
`debug_load_rom`** (до прогона): runtime-область строк boot обнуляет/переиспользует,
поэтому читать надо на незагруженном образе. Кодировщик — `debug_disassemble_range`
по exec-адресам рендера. Структурная валидация глифов — `analyze.glyph_scan`
(свой `v06c-mcp`, планарный stride 0x20).

## Факты

### Кодировщик экранного шрифта (два слоя)
1. **Интерпретатор display-list — `func_display_list_interp` @ 0x11D8.**
   Цикл `0x11E0 MOV A,M` читает байт экранного скрипта; цепочка `CPI/CZ` —
   управляющие коды (позиция/атрибут/спец): `1C/1F→0x12D9`, `3D→0x1303`,
   `45/46→0x1328`, `27/31→0x134F`, `51→0x1388`, `91→0x13C2`, `A6→0x13AA`,
   `26/2F→0x1270`, `93/97→0x12A4`, `A7→0x1276`, `A8/A9/AA→0x13C6`. Обычный
   печатный символ (в т.ч. `%`) → `0x1240 INX H; CALL 0x114D`.
2. **Рендер глифа — `func_render_glyph` @ 0x114D.** Вход `A` = код символа.
   Адрес глифа = **`A·32 + 0x3780`** (`MOV L,A; MVI H,00; DAD H`×5 = ×32;
   `LXI D,3780; DAD D`). Далее адрес в VRAM из курсора (`ANI 1F; ADI A0` →
   плоскости 0xA000/0x8000) и копирование (`LXI B,0210; CALL 0x111A`).

**Кодировщик = транслитный ASCII, шаг глифа 32 байта (4 плоскости × 8 строк,
8×8), разделитель слов `%` (0x25).** Речевые строки используют разделитель
**пробел** (0x20), экранные — `%`.

### `data_glyph_block` @ 0x3780
Регулярный массив 32-байтных глифов. `glyph_scan` (планарно, stride 0x20):
ink>0 по всему блоку, групп повторов в 0x00..0x0F нет. Попадания `strings_scan`
«koi8-мусор» на 0x35xx/0x3Axx/0x43xx–0x45xx — это и есть растровые глифы,
ошибочно принятые за текст. Точный порядок бит/плоскостей (column-major /
инверсия) — рендер-деталь, **не** подтверждена попиксельно (см. ограничения).

| адрес | текст | по-русски |
|-------|-------|-----------|

### Отбраковано (не строки)
`0x439C/0x44E3/0x45CC/0x4578/0x3566/0x3AF8/0x352E/0x36CA/0x2813/0x04A5/0x0165/
0x3CDA` — high-entropy «koi8»-набор = растровые данные (глифы/спрайты/PCM),
кандидаты `strings_scan` с `confidence low/medium` и `distinct ≤ 11`. Не
созданы. `0x6835` «inskomu andre iwanowiu» — имя в hi-score-данных, не
экранный/речевой скрипт.

## Итог в RDB
- `data_glyph_block` @0x3780 (Data) — base + комментарий (формула, stride).
- `func_render_glyph` @0x114D (переименовано с `func_114d`, исправлен
  ложный Stage-3 комментарий «клавиатурный диспетчер»); link → 0x3780.
- `func_display_list_interp` @0x11D8 (переименовано с `func_11d8`); link → 0x114D.
- `str_voice_title`@0x0600, `str_voice_098d/09b8/0a23`; `str_screen_0b96/0bb5/
  0bd7/0c39` — тип String, комментарий = транслит→русский.
Сохранено `debug_save_rdb`; grep `.rdb` — имена/комментарии/links подтверждены.

## Ограничения и открытые вопросы
- **Попиксельная ориентация глифов** (column-major / порядок 4 плоскостей) не
  сверена с реальным VRAM — `vram_credits`/`debug_get_vram_bytes` даст точное
  соответствие символ→растр; это Stage 7/8. Формула адреса (`A·32+0x3780`)
  при этом достоверна из дизассембли.
- Каталог **репрезентативен, не полон**: заведены читаемые фразы/экраны;
  полные пулы строк и их адреса покрываются по мере надобности в Stage 7.
- Точный смысл управляющих кодов display-list (0x1C/0x93/0xA7…) — не
  декодирован (за рамками «кратко»); зафиксированы как таблица ветвлений.

## Карта функций

### Точка входа и инициализация

| Адрес | Имя | Размер | Описание |
|-------|-----|--------|----------|
| 0x0100 | `rom_entry` | 4 | DI; JMP 0x0B57. Точка входа ROM |
| 0x0B57 | `rom_init` | 313 | Основная инициализация: очистка RAM 0x8000-0xFFFF, загрузка данных из ROM в 0x5000, копирование графики 0x2F61→0x7418 |
| 0x0383 | `init_1` | 33 | Инициализация #1. Вызывается из `rom_init` |
| 0x0401 | `init_2` | 46 | Инициализация #2. Вызывается после `init_1` |
| 0x3D4E | `init_3` | 124 | Инициализация #3. Финальный шаг перед главным циклом |
| 0x1BE5 | `obj_setup` | 21 | Инициализация 0x400 байт по адресу 0x5000 из данных ROM. Ожидает клавишу (0x20) |

### Прерывания (ISR)

| Адрес | Имя | Размер | Описание |
|-------|-----|--------|----------|
| 0x03A4 | `isr_handler` | 93 | ISR: сохранение регистров, AY-3-8910 музыка, чтение клавиатуры (IN 02), вызов `isr_anim_update`. Вектор 0x0038→JMP 0x03A4 |
| 0x384E | `isr_anim_update` | 48 | Обновление анимации: счётчик кадров 0x383A, данные объектов 0x0B41/0x3854. Вызывает `isr_obj_update_1` и `isr_obj_update_2` |
| 0x3BCA | `isr_obj_update_1` | 52 | Обновление объектов #1: чтение типа из [HL+0x0D], диспетчеризация. Таблица 0x445D, шаг 0x14 байт |
| 0x3C7D | `isr_obj_update_2` | 60 | Обновление объектов #2: аналогично, но таблица 0x42F9, шаг 0x0A байт |

### Основная логика

| Адрес | Имя | Размер | Описание |
|-------|-----|--------|----------|
| 0x0439 | `main_logic` | 226 | Главная логика игры/меню. Таблица диспетчеризации и обработка состояний |
| 0x0C65 | `data_process_loop` | 123 | Цикл обработки данных: сканирование RAM 0x5180 на маркеры 0x75/0xFE, вызов `data_read_loop` и `kbd_input_handler`. JMP 0x197C |
| 0x197C | `game_main_loop` | ~200 | Главный игровой цикл: счётчик кадров 0x08F5, загрузка из ROM-таблиц (0x1C0E/0x1C8E), копирование/отрисовка объектов |

### Обработка данных и ввод

| Адрес | Имя | Размер | Описание |
|-------|-----|--------|----------|
| 0x0145 | `data_read_loop` | 14 | Цикл чтения данных: байт из [HL] → вызов 0x0803 (draw) → инкремент HL. Вызывается 5 раз |
| 0x017C | `sub_017C` | 6 | Вспомогательная подпрограмма (вызывается из `data_process_loop`) |
| 0x01A1 | `kbd_input_handler` | 13 | Обработчик клавиатуры: сканирование через IN 01, проверка бита 5 (ANI 20) |
| 0x01AE | `calc_and_draw` | 11 | Читает X/Y из 0x08FE/0x08FF, вызывает `calc_obj_addr`, затем JMP `data_read_loop` |
| 0x0321 | `data_dispatch` | 94 | Диспетчеризация данных: PCHL-переход к подфункциям 0x0439, 0x045E, 0x0483, 0x04A8, 0x04CD |
| 0x0C95 | `sub_0C95` | 8 | Вспомогательный цикл (INX H; DCR B; JNZ; JMP 0x0C65) |

### Отрисовка и объекты

| Адрес | Имя | Размер | Описание |
|-------|-----|--------|----------|
| 0x0800 | `draw_to_vram` | 163 | Рисование байта в VRAM. Вычисляет VRAM-адрес из координат (HL+B000), записывает 8 байт из стека. Маппинг экранных координат |
| 0x1B87 | `obj_copy_data` | 33 | Копирование данных объекта: `calc_obj_addr` → 5 байт из [DE] через `data_read_loop` |
| 0x1BA8 | `obj_draw_data` | 32 | Отрисовка объекта: аналогично `obj_copy_data`, но вызывает `draw_to_vram` (0x0803) |
| 0x1BD4 | `calc_obj_addr` | 17 | Калькулятор адреса: HL = E×32 + D×256 + 0x5000. Преобразует индекс объекта в RAM-адрес |

## Граф вызовов (Call Graph)

```
rom_entry (0x0100)
  └→ rom_init (0x0B57)
       ├→ init_1 (0x0383)
       ├→ init_2 (0x0401)
       ├→ init_3 (0x3D4E)
       └→ obj_setup (0x1BE5)
            └→ data_read_loop (0x0145) × N

0x0038 → isr_handler (0x03A4)
          └→ isr_anim_update (0x384E)
               ├→ isr_obj_update_1 (0x3BCA)
               └→ isr_obj_update_2 (0x3C7D)

main_logic (0x0439)
  ├→ data_read_loop (0x0145) × 5
  ├→ kbd_input_handler (0x01A1) × 4
  └→ data_dispatch (0x0321)
       └→ PCHL → {0x0439, 0x045E, 0x0483, 0x04A8, 0x04CD}

data_process_loop (0x0C65)
  ├→ sub_017C (0x017C)
  ├→ data_read_loop (0x0145)
  ├→ kbd_input_handler (0x01A1)
  ├→ calc_and_draw (0x01AE)
  │    └→ calc_obj_addr (0x1BD4)
  └→ JMP → game_main_loop (0x197C)
       ├→ obj_copy_data (0x1B87)
       │    └→ calc_obj_addr (0x1BD4)
       ├→ obj_draw_data (0x1BA8)
       │    └→ calc_obj_addr (0x1BD4)
       ├→ sub_1197 (0x1197)
       ├→ sub_11E9 (0x11E9)
       └→ sub_121A (0x121A)

draw_to_vram (0x0800) — вызывается из:
  ├→ data_read_loop (0x0145) → CALL 0x0803
  └→ obj_draw_data (0x1BA8) → CALL 0x0803
```

## Анализ ключевых данных

### RAM 0x5000 — текстовый буфер

Область 0x5000 содержит:
- Символы 0x77/0x78 (повторяющийся паттерн — возможно, фоновая графика)
- Пробелы (0x20)
- Текст "Hi 2000" в ASCII (0x48, 0x69, 0x20, 0x32, 0x30, 0x30, 0x30)
- Символы 0x9B (декоративные элементы)

### ROM 0x42F9 — таблица анимации

Содержит значения 0–15, сгруппированные по 10 байт:
```
13 13 13 13 13 13 13 13 13 13   ← равномерное распределение
15 10  8  6  4  2  1  0  0  0   ← убывающая последовательность
15 15 15 15 11  7  3  0  0  0   ← убывающая (быстрее)
15 13 11  9  7  5  3  0  0  0   ← линейное убывание
15 15  9  9  9  9  5  0  0  0   ← ступенчатая
```
Похоже на таблицы траекторий/позиций для анимации объектов.

### ROM 0x445D — таблица смещений

Содержит значения 0–4, сгруппированные:
```
01 00 01 00 01 00 ...   ← чередование
00 01 02 03 03 02 01 00 ← треугольный паттерн
00 00 00 00 02 00 02 ... ← позиционные смещения
```
Похоже на lookup-таблицу для вычисления смещений спрайтов.

### ROM 0x1C0A — таблица координат

Пары значений в диапазоне 0–30, вероятно X/Y координаты объектов на экране:
```
14 10 01 0A 06 01 0A 0C 1C 10 ...
```

## Предварительные выводы

1. **Архитектура**: ROM реализует игру/приложение с объектной моделью. Объекты хранятся в RAM 0x5000, управляются через ISR и главный цикл.

2. **Два уровня обновления**:
   - **ISR** (50 Гц): обновление анимации через `isr_anim_update` → `isr_obj_update_1/2`
   - **Главный цикл**: обработка логики, копирование данных, отрисовка

3. **Отрисовка**: Побайтовая через `draw_to_vram` (0x0800). Координаты маппятся в VRAM через формулу с базой 0xB000.

4. **Текстовый вывод**: RAM 0x5000 содержит текст "Hi 2000" — вероятно, заголовок/меню.

5. **Графика**: Спрайты загружаются из ROM 0x2F61 в RAM 0x7418 при инициализации (~2343 байта графики).

6. **Неисследованные области**:
   - 0x045E, 0x0483, 0x04A8, 0x04CD — подфункции `data_dispatch`
   - 0x1197, 0x11E9, 0x121A — подпрограммы, вызываемые из `game_main_loop`
   - 0x3DCD — подпрограмма, вызываемая из `data_process_loop`
   - 0x1C8E — вторая таблица данных (аналог 0x1C0E)
   - 0x2F61–0x383A — большая область ROM с графическими данными

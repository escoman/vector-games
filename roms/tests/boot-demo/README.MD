# boot-demo — заставка под второй загрузчик с ленты

Тестовый ROM модуля `lib/boot`: показывает табличку, ждёт любую клавишу и
зовёт `loader_boot_cfg(&cfg)`. Возврата из вызова нет — stage-2 стирает всю
машину ниже `0xE000` вместе с этой заставкой и принимает следующий ROM с ленты.
Заставка демонстрирует кастомизацию: два цвета и две панели-картинки в углы.

Спека загрузчика: [`docs/LOADER_TZ.MD`](../../../docs/LOADER_TZ.MD).

## Что происходит по шагам

1. ROM-монитор Вектора грузит `boot-demo.rom` (первый файл ленты) — обычная
   загрузка, ничего особенного;
2. `main()` рисует заставку, ставит чёрный бордюр, ждёт нажатие любой клавиши
   (`kbd_wait_any_key()` из `lib/kbd` — фронт-детектор по кадрам);
3. `loader_boot_cfg(&loader_cfg)` (`lib/boot/loader.asm`) гасит прерывания,
   копирует 712-байтовый blob в `0xE000`, рядом — 14 байт конфига (цвета и
   геометрию панелей) в `0xFB10`, а картинки — РАСПАКОВЫВАЕТ из ZX0-потоков
   в слоты `0xE300` / `0xEF00` (по 3 КБ, формула `base + номер·stride`);
   затем передаёт управление stage-2;
4. stage-2 (`lib/boot/loader_stage2.asm`) стирает `0x0000..0xDFFF`, ставит в
   `0x0000` заглушку `JMP 0E000h` (после аппаратного сброса — снова
   загрузчик), перезапускает ПИА, вслепую ставит палитру «только C000»
   цветами из конфига, рисует панели в углы и поверх них OR-ом — карту
   загрузки, включает мотор и декодирует бифазный сигнал ленты;
5. следующий файл ленты ложится линейно от адреса в своём заголовке, и
   stage-2 передаёт управление именно ему — `PCHL` на `addrhi:0000` (§3.8).
   Один выход годится и для `.rom` (старт `0x0100`), и для `.r0m` (старт
   `0x0000`); у `.r0m` его код попутно затирает заглушку в `0x0000`, и сброс
   ведёт прямо в него.

## Сборка

```bash
make          # собрать boot-demo.rom
make deploy   # собрать + положить в ROMS эмулятора
make full     # clean + deploy
```

Blob загрузчика в ROM берётся из `lib/boot/loader_stage2.inc` — он
сгенерированный, пересобирается в корне проекта:

```bash
make loader2           # z80asm -b + bin2inc + disasm8080: бюджет кода 768 Б,
                       # чистый i8080-поток, ссылки в 0E000h..0E2FFh
                       # (+ whitelist: заглушка сброса, C000, high-RAM)
```

## Лента для ручной проверки (§9.5)

Вторым файлом кладём любой ROM, адресуемый `0x0100` и не длиннее 48896 байт
(`rom2wav.py` именно туда и ставит `.rom`), например тест `cls`:

```bash
make -C roms/tests/cls
python3 utils/rom2wav.py roms/tests/boot-demo/boot-demo.rom /tmp/boot-demo.wav
python3 utils/rom2wav.py roms/tests/cls/cls.rom          /tmp/cls.wav
```

Проигрываем по очереди: сначала `boot-demo.wav` (штатная загрузка первым
файлом), после нажатия клавиши — `cls.wav`. На эмуляторе первый файл можно
положить в `ROMS/` и запустить как обычную ROM, а второй подать на вход ленты.

Ориентир по времени: `cls.rom` (4763 Б, 19 страниц) — ~43 с непрерывного
звука; полный образ 48896 Б (191 блок) — ~419 с. Экран с картой появляется
сразу после клавиши, но первые секунды уходят на преамбулу и калибровку
декодера: столбики приёма (§5.3) начинают расти после первого синхробайта,
неподвижная карта в первые секунды — это норма, а не зависание.

Ожидаемый экран после клавиши — карта загрузки поверх двух панелей: 8 групп
по 4 строки, жёлтый на голубом (цвета — из конфига §4.2, геометрия карты — §5,
панели — §5.2, порт `AKART` и столбики прогресса — §5.3; эталонный снимок
[`docs/etalon/boot.png`](../../../docs/etalon/boot.png) — тот же NEWROM с
tеми же столбиками и угловым блоком меток, но без панелей). По мере приёма
в группе вырастает вертикальный «столбик» из 8 жёлтых засечек 6×1 — по одной
на принятый 32-байтный подблок; страницы с большим `addrhi` (начиная с 0xE0)
кладут засечки в правый верхний угол — это и есть «блок меток» на boot.png.
Запись безусловная, `MOV M, E`, поэтому засечка перетягивает панель, если
попала на её арт. Панели `panel_top.png` (172×88, левый верхний
угол) и `panel_bottom.png` (144×72, правый нижний) генерируются из `assets/`
правилом `panels` и лежат в `include/panel_*.h`. В ROM они записаны
СЖАТЫМИ ZX0 (`png2panel.py --zx0`), распаковывает стаб — поэтому 3232 байта
арта стоят в образе 1077 байт.

## Ограничения

* после `loader_boot_cfg()` возврата нет — прерывать приём можно только СБРОСом,
  и после сброса заглушка `JMP 0E000h` вернёт управление в загрузчик (кроме
  случая, когда последним грузился `.r0m`, затёрший её своим стартом);
* следующий ROM обязан быть собран под `0x0100` (`.rom`: `--no-crt` + startup
  из `lib/sys` это дают) и целиком влезать в `0x0100..0xBFFF`, либо под
  `0x0000` (`.r0m`, до 48896 байт суммарно вниз от `0xE000`);
* stage-2 работает без прерываний вообще: ни `EI`, ни `RST`, ни векторов ПР.

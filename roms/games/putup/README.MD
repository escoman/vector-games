# putup — реконструкция ROM `putup_new.rom` (games/putup)

Реконструкция оригинала `src/putup.rom` (asm-ветка Stage 12
[`redesign/putup`](../../redesign/putup)) со **свободной раскладкой**: мёртвый
шлак вырезан, блок глифов запечён в ROM, emit-файлы идут подряд, адреса меток
переставляемы. Образ **не адресно-точен** оригиналу — корректность держится
**поведенческими гейтами** (раскрашенный экран + снимок данных), а не побайтовым
diff.

| | оригинал | PUTUP_NEW |
|---|----------|-----------|
| раскладка | фикс. адреса оригинала | свободная конкатенация (закреплён только вход 0x0100) |
| блок глифов | распаковывается в RAM 0x6000 (`func_load_glyph_block`) | запечён в ROM, читается через `data_glyph_ptr_table`; распаковщик удалён |
| мёртвый код/данные | на своих адресах | физически удалены из образа |
| VBlank-синк стирания | трамплины | инлайн `EI; HLT; CALL func_draw_tile_at_ptr` в 5 erase-точках |
| гейт корректности | — | `compare_color` (картинка) + SHA блока + `lint_ptrs` + `compare_behavior` |
| размер образа | 32512 Б | 18094 Б |

## Сборка

Единый режим — свободная конкатенация (`COMPACT`/`make verify`/`GLYPH_BASE`
удалены). Компоновщик `tools/gen_layout.py` кладёт файлы подряд в порядке
`tools/order.json`; гэпов нет.

```bash
make                        # putup_new.rom: gen_layout → assemble → mk_manifest → срез векторной страницы
make layout                 # перегенерировать компоновку (asm/putup_new.asm + tools/order.json)
make deploy / make full     # стандарт проекта (finally.mk)
python3 tools/compare_color.py --new putup_new.rom     # первичный гейт: раскрашенный экран title/play1/play2
python3 tools/compare_behavior.py --new putup_new.rom  # поведенческий: VRAM/глифы/порты orig→new→orig
python3 tools/lint_ptrs.py                             # линт relocation-враждебных ссылок
```

Конвейер (Makefile): `gen_layout.py` → `cd asm && z80asm -b -m=8080_strict -s
putup_new.asm` → `mk_manifest.py` (`.sym` → `tools/layout.json`) → срез
`d[256:]` (отбрасывается векторная страница 0x0000..0x00FF) → `putup_new.rom`;
промежуточные артефакты очищаются. Оригиналы `putup.rom`/`putup.rdb` не
дублируются — читаются из [`redesign/putup/src`](../../redesign/putup/src).

### Манифест адресов

Свободная конкатенация не сохраняет адреса оригинала, поэтому метки переезжают
на каждой правке порядка. Источник истины адреса — ассемблер: `-s` пишет
`asm/putup_new.sym`, а `tools/mk_manifest.py` снимает ключевые метки в
`tools/layout.json`. Все гейты и линт берут адреса **из манифеста**, а не
хардкодом. Текущий снимок (свидетельство приёмки):

```
func_vblank_isr   = 0x03A4   (эмуляторный break-адрес кадра)
data_palette      = 0x06AC   ( func_main_init: LXI H,data_palette+00Fh → var_palette_ptr)
data_glyph_ptr_table = 0x0421 (func_render_glyph: LXI H,метка + DAD D — без зашитой страницы)
data_glyph_block  = 0x33F6   (ЧЁТНЫЙ — см. инвариант ниже), glyph_size = 5048 Б
```

## Ключевой инвариант: чётность блока глифов

Tier-2 занимает **бит0** слова указателя в `data_glyph_ptr_table` как тег
компактности (`DEFW data_glyph_block+N`, нечётное N = compact-маска 8 Б, чётное =
raw 32 Б). Это требует **чётной** базы `data_glyph_block`. При свободной
конкатенации база зависит от суммы размеров кода и может упасть на нечётный
адрес → все глифы ложно читаются compact и адрес записи съезжает на 1 (полный
мусор на экране). Компоновщик вставляет `defs $ & 1` перед include блока —
выравнивает базу на чётный (0 или 1 байт padding). Гейт `compare_color` ловит
нарушение мгновенно.

## Перенос/сдвиг кода: символ, а не литерал

Все межфайловые ссылки символьны (этап 3A + 4A), иначе конкатенация их сломает:
- таблица глифов — `LXI H, data_glyph_ptr_table; DAD D` (было: зашитая страница
  `MVI H,06h`);
- палитра — метка `data_palette` + смещение (был пин `defs 0x08A3 - $`);
- ISR — `LXI H, func_vblank_isr; SHLD 0039h` (вектор ставится меткой);
- значения ptr_table — `DEFW data_glyph_block+N` (переезд блока не правит байты).

`lint_ptrs.py` сторожит класс регрессии «числовая ссылка в окно relocatable-блока».

## Порядок файлов (`tools/order.json`)

Список имён emit-файлов = порядок конкатенации. По умолчанию генерируется по
адресному порядку оригинала (низкий риск). Правка порядка (группировка hot-путей,
реформат данных) — это следующий заход **оптимизации**; каждое изменение = свой
прогон гейтов приёмки. Точка входа `func_entry` закреплена на 0x0100.

## Почему байты запечённого блока отличаются от оригинала

Отхождения накоплены осознанно и защищены гейтом цвета (картинка побайтово та же,
`compare_color` = 0/65536). Побайтовый `make verify` удалён — сверка теперь
поведенческая + SHA снятого блока.

- **Фаза 3 — инверсия LSB плоскости 0xE000.** Чанк 24..31 каждого 32-байтного
  глифа хранился комплементом. XOR 0xFF по этим байтам у всех глифов → фон
  E000 = 0x00; компенсация — перестановка соседних пар палитры `PAL'[j]=PAL[j^1]`
  (`I→I^1`, итоговый цвет не меняется).
- **Стадия 1 — текст в одну плоскость.** Транспозиция цветов 15↔8: буквы пишутся
  только в `0x8000` (маска), `A000/C000/E000 = 0`; компенсация — свап слотов 8 и
  15 в палитре. Открывает компакцию 1-битного шрифта.
- **Стадия 2 (Tier 2) — компакция записей.** 131 однопотокный глиф хранится 8-Б
  маской вместо 32-Б; блок 8192→**5048 Б**. Тег — бит0 указателя (см. инвариант
  чётности). Движок `func_render_glyph` — цикл по 4 плоскостям (raw — DE, compact
  plane0 — маска, compact plane1..3 — `MVI M,00h` напрямую).
  SHA256 компактного блока (снимок `data_glyph_block_unpacked.asm`):
  `a489876c896c53efbbdbf57c87b840ca9a0e920e36790668fc7dc77416e8ff2a`.

## Приёмка (гейты свободной раскладки)

| гейт | критерий | текущий результат |
|---|---|---|
| build | gaps: 0, детерминизм (`cmp` двух сборок) | **0 гэпов**, byte-identical |
| compare_color | title/play1/play2 = 0/65536 (минимум по ленте кадров, адреса из манифеста) | **0 / 65536** |
| SHA глиф-блока | ROM[`glyph_base`,+`glyph_size`) == снимок | **PASS** (a489876c…) |
| lint_ptrs | 0 relocation-враждебных блокеров | **CLEAN** |
| compare_behavior | ≤ шумового поля orig↔orig | шум-флор **0**; см. оговорку ниже |

**Оговорка по `compare_behavior`.** Точечная сверка на фиксированных CPU-кадрах
даёт VRAM-diff (фазовый рассинхрон: инлайн-режим слегка меняет такты →
переходные кадры анимации сдвигаются) и diff глиф-окна (сравнивается compact-блок
в ROM с развёрнутым RAM-блоком оригинала — разные представления одних данных).
Это артефакты измерения, не регрессия: визуальный оракул `compare_color` даёт 0,
а SHA блока подтверждает идентичность данных. Тайминг-зависимые ветки (вход через
RAM-вектор, ISR) `compare_behavior` не покрывает — финальную уверенность даёт
прогон на эмуляторе.

## Инструменты

| | |
|---|---|
| `tools/gen_layout.py` | компоновщик свободной конкатенации: мастер `asm/putup_new.asm` + `tools/order.json` ( DEAD-множество исключает мёртвые файлы) |
| `tools/order.json` | порядок emit-файлов (источник истины раскладки; правится вручную для оптимизации) |
| `tools/mk_manifest.py` | `.sym` → `tools/layout.json` (адреса меток для гейтов) |
| `tools/layout.json` | манифест адресов (генерится на сборке; читают compare_*/lint) |
| `tools/compare_color.py` | первичный гейт: 4 плоскости → цвет → палитра, сверка раскрашенного экрана |
| `tools/compare_behavior.py` | поведенческая сверка orig→new→orig: VRAM/глифы/порты по CPU-кадрам |
| `tools/lint_ptrs.py` | линт relocation-враждебных числовых ссылок (+ RDB-сверка справочно) |
| `tools/get_glyph_block.py` | снятие блока 0x6000..0x7FFF через MCP (вербатим → DEFB в asm) |

## Структура `asm/`

- `asm/funcs/` — код: `func_*` и точки входа `lbl_*`;
- `asm/data/` — данные: `data_*` (в т.ч. `data_level_*.asm`,
  `data_glyph_block_unpacked.asm`) и строковые константы `str_*` (в RDB тип
  `string` — категория данных);
- `asm/var_ram_symbols.asm` — EQU-алиасы RAM-переменных;
- `asm/putup_new.asm` — мастер-конкатенация (генерируется `gen_layout.py`, include
  с префиксами `funcs/`/`data/`, руками не править).

# Stage 7. Исследование функций вывода текста на экран

## Цель

1. Запустить ROM, дать поработать 5 секунд
2. Найти функции, выводящие текст на экран по текстовым блокам
3. Исследовать области памяти, из которых происходит копирование данных в VRAM
4. Исследовать область памяти с набором глифов (включая распакованные данные)
5. Сохранить сведения о блоке с глифами в RDB
6. Экспортировать глифы в BMP для визуальной проверки
7. Сохранить отчёт

## ROM

- Файл: `./src/putup.rom`
- Размер: 17664 байт
- Адрес загрузки: 0x0100

## Ход исследования

### 1. Запуск ROM

ROM загружен, эмуляция запущена на 5 секунд, затем приостановлена.
К моменту паузы заставка уже отображается: видны надписи «PUSH SPACE KEY»,
«MSX MEGA ZINE, 1987», «HI», «SCORE», «ROUND».

### 2. Текстовый буфер (RAM 0x5287)

По адресу 0x5287 в RAM обнаружен текстовый буфер:
- Первые 19 байт: ASCII-строка `"MSX MEGA ZINE, 1987"`
- Далее — закодированные текстовые данные (диапазон значений 0xC3–0xF7)
- Загружается из ROM 0x0AD6 во время инициализации

В ROM по адресу 0x0AD6 расположены строки:
- `"MSX MEGA ZINE, 1987"`
- `"HI"`, `"SCORE"`, `"ROUND"` и другие

### 3. Функции вывода текста

#### `draw_to_vram` (0x0800–0x08A2) — ядро отрисовки глифов в VRAM

Основная функция, расширяющая байт глифа в 8 строк VRAM.

**Алгоритм:**
1. `ORA A; RZ` — если байт = 0, возврат (прозрачный глиф)
2. `LXI D, 0B000h; DAD D` — к адресу VRAM прибавляется 0xB000
3. Извлекается столбец (`L & 0x1F`) и строка
4. По таблице кодов (dispatch table) по адресу ROM 0x051B определяется вариант отрисовки
5. SP устанавливается на вычисленный адрес, через `POP` записываются 2 байта × 4 плоскости × 8 строк
6. Сохраняет/восстанавливает стек через [0x08DD]
7. Завершается `EI; RET` (0x08A1–0x08A2)

Таблица по 0x051B — это **не данные глифов**, а исполняемый код диспетчеризации
(8080-инструкции для разных позиций столбца).

#### `function_01A1` (0x01A1–0x01AD) — обёртка «нарисовать следующий байт»

```
01A1: PUSH H
01A2: LHLD 0B53       ; загрузить сохранённый указатель VRAM
01A5: CALL 0800       ; draw_to_vram
01A8: INX H           ; сдвинуть указатель
01A9: SHLD 0B53       ; сохранить указатель
01AC: POP H
01AD: RET
```

#### `sub_1BD4` (0x1BD4–0x1BE4) — вычисление адреса объекта в RAM

```
1BD4: MOV L, E        ; HL = столбец
1BD5: MVI H, 00
1BD7-1BDB: DAD H ×5   ; HL *= 32
1BDC: MOV E, D        ; DE = строка × 256
1BDD: MVI D, 00
1BDF: DAD D           ; HL += строка × 256
1BE0: LXI D, 5000     ; базовый адрес
1BE3: DAD D           ; HL += 0x5000
1BE4: RET
```

**Формула:** `HL = col × 32 + row × 256 + 0x5000`

#### `data_process_loop` (0x0C65–0x0CA0) — сканирование блоков

Просматривает 32-байтные блоки в поисках маркеров 0x75/0xFE, переключает их,
затем вызывает `sub_3DCD` и передаёт управление в `game_main_loop`.

### 4. Конвейер отрисовки текста

```
ROM 0x0AD6 (строки)
  → RAM 0x5287 (текстовый буфер, загружается при инициализации)
    → data_process_loop (0x0C65) — обработка блоков
      → sub_1BD4 (0x1BD4) — вычисление координат
        → function_01A1 (0x01A1) — отрисовка байта за байтом
          → draw_to_vram (0x0800) — расширение глифа в 8 строк VRAM
            → Таблица 0x051B — диспетчеризация по позиции столбца
              → VRAM (0xC000+)
```

### 5. Таблица глифов (RAM 0x6400–0x6BFF)

**Адрес:** RAM 0x6400
**Размер:** 2048 байт
**Формат:** 128 записей × 16 байт

Каждая запись состоит из:
- **8 байт** — нормальное изображение глифа
- **8 байт** — битово-инвертированное изображение (для отрисовки справа налево)

**Формат глифа:** 8×8 пикселей, бит 7 = левый пиксель, каждый байт = 1 строка.

Таблица глифов находится в **распакованных данных** по адресам > 0x6000.
Данные распаковываются из ROM во время инициализации.

**Структура записей:**
| Индекс  | Описание                          |
|---------|-----------------------------------|
| 0–1     | Пробел (пустые глифы)             |
| 2–29    | Служебные символы, цифры, знаки   |
| 30–57   | Заглавные латинские буквы (A–Z)   |
| 58–91   | Строчные буквы и спецсимволы      |
| 92–103  | Дополнительные символы            |
| 104–127 | Дубликаты/варианты глифов (пары)  |

Записи идут парами: чётная — нормальный глиф, нечётная — инвертированный.
Визуально пары 0–1, 2–3, 4–5 и т.д. содержат одинаковые нормальные половины.

### 6. Данные спрайтов (RAM 0x6000–0x61A0)

Перед таблицей глифов, по адресу 0x6000, расположены данные спрайтов:
- Парные блоки: нормальное изображение + битово-инвертированное
- Используются для объектов игры (уровни, стрелки, ромбы, кресты)

### 7. VRAM-структура глифов

В VRAM по адресу 0xD000–0xD1FF глифы размещаются с 16-байтным интервалом.
Каждый видимый глиф занимает 8 байт данных + 8 байт заполнения/дубликата.
Читаемые буквы: E, F, L, C, A, P, X, O, D, B и другие.

### Скрипт извлечения

- **Путь:** `./extract_glyphs.py`
- **Описание:** Python-скрипт для извлечения глифов из RAM-дампа и создания BMP + .inc

## RDB: новые объекты

| Адрес | Имя          | Тип  | Размер | Описание                                    |
|-------|--------------|------|--------|---------------------------------------------|
| 0x6400| font_table   | data | 2048   | Таблица глифов: 128 записей × 16 байт       |
| 0x5287| text_buffer  | data | 128    | Текстовый буфер (ASCII + закодированные)    |

**Связь:** `text_buffer` → `font_table` (текстовый буфер использует таблицу глифов для отрисовки)

**Свойства font_table:**
- `glyph_count`: 128 entries, 16 bytes each (8 normal + 8 bit-reversed)
- `glyph_format`: 8x8 pixels, bit7=leftmost, each byte=1 row
- `source`: Unpacked from ROM during initialization to RAM 0x6400

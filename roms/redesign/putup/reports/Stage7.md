## 2. Функция вывода глифов на экран

### Цепочка вызовов

```
func_text_render (0x0321)
  └─ func_data_loader (0x01A1)
       └─ func_copy_to_vram (0x0800)
```

**`func_text_render` (0x0321)** — читает символы из строки по адресу в `HL`, пока не встретит `0xFF`:
```
0x0321: MOV A, M       ; A = [HL] — очередной символ
0x0322: INR A          ; проверка на 0xFF (терминатор)
0x0323: RZ             ; возврат, если терминатор
0x0324: DCR A          ; восстановить A
0x0325: CALL 0x01A1    ; func_data_loader — вывод символа
0x0328: INX H          ; следующий символ
0x0329: JMP 0x0321     ; повтор цикла
```

### Вычисление адреса глифа в `func_copy_to_vram` (0x0800)

Умножения кода символа на фиксированное значение **не происходит**. Вместо этого используется **таблица смещений**:

```
0x081D: MOV A, D       ; A = код символа
0x0826: CMP B          ; сравнить с 0x80
0x0827: MVI H, 06      ; H = 0x06 → базовый адрес 0x0600
0x0829: MOV L, A       ; L = код символа → HL = 0x0600 + code
0x082A: JNC 0x082E     ; если code < 0x80 → оставить H=0x06
0x082D: INR H          ; иначе H = 0x07 → HL = 0x0700 + code
0x082E: MOV E, M       ; младший байт адреса глифа из таблицы
0x082F: INX H
0x0830: MOV D, M       ; старший байт адреса глифа из таблицы
```

**Две таблицы смещений:**
- `data_glyph_table_lo` (`0x0600–0x06FF`) — для символов 0–127, 256 записей по 2 байта
- `data_glyph_table_hi` (`0x0700–0x07FF`) — для символов 128–255, 256 записей по 2 байта

Каждая запись содержит предвычисленный адрес: `0x6000 + N × 32`. Таким образом, в рантайме происходит лишь обращение к таблице по индексу `0x0600 + code` (шаг 2 байта на запись), а умножение на 32 выполнено на этапе упаковки данных.

### Блок данных глифов

| RDB-объект          | Адрес       | Размер    | Описание                                       |
|---------------------|-------------|-----------|------------------------------------------------|
| `data_glyph_block`  | `0x6000`    | 8192 байт | 256 глифов × 32 байта (4 битплейна × 8 байт)   |
| `data_glyph_table_lo` | `0x0600`  | 256 байт  | Таблица смещений для символов 0–127             |
| `data_glyph_table_hi` | `0x0700`  | 256 байт  | Таблица смещений для символов 128–255           |

Источник сжатых данных: ROM `0x2761` → распаковка через `func_decompress` (0x0401) в RAM `0x6000`.

### Формат глифа и объём вывода на экран

Каждый глиф занимает **32 байта**: 4 битплейна по 8 байт (8 строк × 8 байт, 4 бита на пиксель = 16 цветов).

`func_copy_to_vram` выводит на экран **40 байт** на каждый глиф (5 байт на битплейн), что соответствует **10 строкам** высотой:

```
Группа 1: 8 × POP D → [HL]=E; INX H; [HL]=D; INX H  → 16 байт (строки 0–7)
  DAD B (смещение VRAM +0x051B)
Группа 2: 8 × POP D → [HL]=E; INX H; [HL]=D; INX H  → 16 байт (строки 0–7)
  DAD B (смещение VRAM +0x051B)
Группа 3: 4 × POP D → [HL]=E; INX H; [HL]=D; INX H  →  8 байт (доп. строки 8–9)
```

SP устанавливается на адрес глифа и последовательно читает 20 пар байт (40 байт). Поскольку данные глифа занимают только 32 байта, третья группа (8 байт) захватывает первые 8 байт **следующего** глифа — фактически первую строку каждого битплейна соседнего символа. Видимо, сверху и снизу каждого символа выводится ещё по одной дополнительной строке, итого 10 линий × 4 плоскости = 40 байт.

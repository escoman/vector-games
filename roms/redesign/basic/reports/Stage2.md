# Stage 2. Семантика интерпретатора (basic.r0m, RAM-образ)

> Разбор живого образа через MCP-отладчик. Модульные verdict'ы (`report_gen.py`)
> — в `.scratch/pipeline/basic/pipeline.md`. Здесь — модель интерпретатора,
> применённый каркас RDB и доказательно зафиксированный открытый пункт.
> Дата прогона каркаса: 2026-10-16.

## 1. Модель токенов (доказана)

Ключевые слова хранятся в таблице `0x256E` в кодировке «байт на символ,
bit7 = последний символ слова». **Токен = `0x80` + номер слова.** Якоря взяты
непосредственно из кода оценщика выражений (`layout.asm`, блок `func_0a43`):

| слово | № | токен | подтверждение в коде |
|---|---:|---|---|
| FN | 32 | `0xA0` | `cpi 0a0h / jz lbl_0dc0` |
| NOT | 34 | `0xA2` | `cpi 0a2h / jz lbl_0ba8` |
| `+` | 36 | `0xA4` | `cpi 0a4h / jz func_0a43` |
| `-` | 37 | `0xA5` | `cpi 0a5h / jz lbl_0aae` |
| `>` | 43 | `0xAB` | гейт отношений `sui 0abh` |
| SGN | 46 | `0xAE` | `sui 0aeh` → индекс таблицы функций |
| `&` | 73 | `0xC9` | конец диапазона функций (`cpi 0cah / jc`) |

Таблица слов: `0x256E .. 0x26D6` (101 слово, CLS=0 … CIRCLE=100), размер 361
байт. Слово сразу за `0x26D7` декодируется мусором — правая граница подтверждена.

## 2. Диспетчер встроенных ФУНКЦИЙ (доказан)

Единственный вычисляемый переход во всём образе — `0x0B09`:

```asm
label_0B09:
    lxi     b,2770h      ; база таблицы
    dad     b            ; + индекс*2
    mov     c,m          ; низ адреса обработчика
    inx     h
    mov     h,m          ; вершина
    mov     l,c
    pchl                 ; прыжок
```

Достигается из оценщика (`lbl_0ad0`, после `sui 0aeh` → `rlc`, т.е. индекс =
`токен − 0AEh` = `номер слова − 46`, смещение ×2). Таблица `0x2770` — **28
записей**, слова `46..73` (`SGN … &`). Запись 28 (`0x27A8` = `8379h`) вне образа
⇒ длина ровно 28. Запись 26 (`AT`) = `0x0074` — page-zero заглушка «не
реализовано» (`MVI E,02 / XRA A / STA 03E7`), а не функция.

## 3. Применённый каркас RDB

Инструмент: `roms/redesign/basic/tools/stage2_dispatch_table.py` (`--check` →
0 расхождений; `--apply`). Запись только через MCP (`RdbWriter`).

Объекты: `data_keyword_table` (0x256E, 361B, 101 слово), `data_dispatch_table`
(0x2770, 56B, 28 записей, `index = token − 0AEh`), `func_exec_dispatch` (0x0B09),
27 функций-обработчиков со свойствами `role/function/token/word_index/
dispatch_index` и связями `func_exec_dispatch → handler` (+ → таблица).

Итог прогона: `434 → 459 объектов`, `dirty: False`. Контракт round-trip:
**`roundtrip_verify` — byte-for-byte identical** (6/6 стадий, 0 отказов).
`measure_sizes` PARTIAL (455 без размера из 459) — ожидаемо: каркас заводит
функции с `size=0`, длины померяются на этапе semantic.

## 4. Семантика обработчиков (пачки 1–4, применены)

Инструмент: `roms/redesign/basic/tools/stage2_semantics.py`. Для каждого из **27**
обработчиков записаны свойства `params`/`reads`/`writes`/`calls` и русский
комментарий; факт берётся из дизасма тела (`.scratch/dis.py`), ничего не
изобретается. Пачки применялись по 6–8 функций, после каждой — round-trip.

| Пачка | Функции | Особенности |
|---|---|---|
| 1. Арифметика | SGN INT ABS LOG EXP | FAC-карта подтверждена: знак `0x404F`, экспонента `0x4050`, точка целого `0x98`; EXP зовёт INT+ABS |
| 2. Тригонометрия/степень | COS SIN TAN ATN SQR RND | `COS=SIN(x+π/2)`, `TAN=SIN/COS`, `SQR=x^0.5` через EXP; RND — ЛКГ, состояние `0x3DFC` |
| 3. Строки | LEN STR$ VAL ASC CHR$ LEFT$ RIGHT$ MID$ | стр. дескриптор `dim 0x4049 / ptr 0x404B`; VAL гонит строку через парсер `0x15A8` |
| 4. Системные | INP POS PEEK FRE POINT USR INKEY$ `&` | INP — самомодификация порта `IN`; USR — хвост-вызов `PCHL`; PEEK — `LDAX D` |

Сводка прогона: **149 действий** (108 свойств, 27 комментариев, 13 связей,
save), `459 объектов`, `dirty: False`. Round-trip: **byte-for-byte identical**.

Найденные общие помощники (перекрёстные зависимости в кодовом потоке, связи
`add_link` ведут на вход владельца хвоста):

- `0x100F` — хвост `func_len`: вычислить строковый аргумент (`CALL 0FE2`).
  Его переиспольуют `ASC` и `VAL` (`CALL 100F`).
- `0x103F`/`0x1041` — хвост `func_left`: экстрактор подстроки. `RIGHT$`
  (`JMP 103F`, старт = len−n) и `MID$` (`PUSH` на `1041`) падают в него.
- `0x0D95` — хвост `func_pos`: «байт A → число FAC» (`MVI E,00 / JMP 1493`).
  В него прыгают `INP`/`PEEK`/`POINT` (возврат результата). Не оформлено
  отдельной функцией — это часть тела `func_pos`.
- `0x1493` / `0x1183` — float-хелперы записи FAC (шкала `0x90`/`0x98`).

### Поправка к каркасу: оператор `&`

Каркас (п. 2) предположил `&` = конкатенация. Дизасм тела `0x15FA` это
опроверг: цикл `RST 10 → JC … цифра('0'..'9')/буква('A'..'F': CPI 41/47,
SUI 07) → SUI 30 → DAD H×4 (×16) → ADD E` накапливает **16-битное
шестнадцатеричное число**, а в конце `MOV A,D / RLC / SBB A` (знак) →
`MVI B,98 / CALL 1493` выдаёт его в FAC как целое. То есть `&` — синтаксис
hex-константы (так задают адреса памяти и hex-числа в целом), а не строка и
не символ. Комментарий в RDB перезаписан.

## 5. Открытый пункт: диспетчер КОМАНД (`CLS..CLEAR`, токены `0x80..0x99`)

Команды **не** исполняются таблицей адресов. Перебрано и отвергнуто:

| Гипотеза | Метод | Результат |
|---|---|---|
| Ещё один computed-jump | байт-скан всех `E9h` (18 шт) по `0x0100..0x42EF` | ни один, кроме `0x0B11`, не диспетчер (float/данные/середина инструкций) |
| LXI-база таблицы команд | скан `LXI B/H/D → 0x26xx..0x2770` | только `0x2770` (функции) и `0x26AC` (текст слов) |
| Таблица `0x2702` (31 запись) | дизасм каждой записи | адреса низкоуровневых помощников (поиск `:`/`"`, стек GOSUB), не обработчики команд |
| Цепочка `cpi <token>` | анализ кластеров `cpi 80h..99h` (`0x06xx`, `0x1Bxx`) | фильтры имён/массивов, не 26-проходный dispatch |
| Runtime-перехват | BP на токенизатор `0x049A`, ввод `CLS<ENTER>` | CPU в idle `0x037B`, клавиши до REPL не доходят — 0 срабатываний |

Исполнение операторов живёт в статически недостижимых gap-байтах и раскрывается
только на живом REPL. Штатная подача клавиш в текущем harness до него не доходит.

**Что нужно для закрытия:** либо наладить ввод в REPL (перехват после
`debug_reset`+`debug_run`, отладка цикла опроса клавиатуры BASIC), либо ручная
декомпиляция области парсера от `lbl_04a7` (вход оператора, пушит continuation
`0x046B`, различает `:`/`0x3A` и токены). До получения доказательств имена
`func_cmd_*` НЕ присваиваются.

# Stage 9a — музыка заставки RISE OUT: формат партитуры, таблица периодов, карта портов

Спека формата для `tools/music_spec_title.json`. Все числа сняты фактами: живой сеанс MCP
(`debug_load_rom`, ROM на экране «HIT BUTTON OR SPACE KEY»), `debug_disassemble_range`,
`debug_read_memory_range`, `debug_get_io_trace`, `debug_get_memory_access_map`,
`debug_get_stack`. Арифметика ниже только **проверяет** снятое, а не заменяет MCP.

ROM: `src/riseout.rom`, 20480 байт, org `0x0100..0x50FF`, sha256 `c265014b…5a6991`.

---

## 1. Тикер и темп

Цепочка вызова (подтверждена статикой и трассой):

```
RST 7 (VBlank ~50 Гц)
  -> 0x0038 = C3 D6 04            JMP 0x04D6
  -> func_irq_vblank_dispatcher 0x04D6
       PUSH H / PUSH D / PUSH B / PUSH PSW / LDA 082A / PUSH PSW
       CALL 0x04F7 (func_irq_frame_service)
       CALL 0x04EE @0x04E1  <------ слот монтирования
       POP PSW @0x04E4 ... EI / RET
  -> слот 0x04EE = C3 FB 2E       JP 0x2EFB   (монтирует func_music_start 0x2D7A,
                                               снимает func_music_stop 0x2D72 -> C9)
  -> func_irq_music_step 0x2EFB   (алиас func_music_driver_title)
       CALL 0x2D94 @0x2F17   voice1 -> счётчик 0, OUT 0x0B
       CALL 0x2F34 @0x2F1D   voice2 -> счётчик 1, OUT 0x0A
       CALL 0x2FA6 @0x2F23   voice3 -> счётчик 2, OUT 0x09
```

Динамическое доказательство именно этой ветки: остан в `0x2EFB`, `[SP] = 0x04E4` — адрес
возврата ровно того `CALL 0x04EE`.

Темп: делитель шага `[0x7DCB]`, перезагружается из `[0x7DC3] = 3` (значение прочитано с живой
RAM). Значит **1 шаг музыки = 3 кадра VBlank = 60 мс**. Страж реентерабельности `[0x7DE1]`.
Базовая ступенька ноты — `MVI A,02h` (`0x2D9E` / `0x2F3E` / `0x2FB4`) = **2 шага = 120 мс**.

Отсюда тайминг MIDI: PPQ 96, `step_ticks` 24 (1 шаг = 2,5 мс), четверть = 4 шага,
`tempo_us_per_quarter` = 240000 мкс.

## 2. Разбор байта дорожки

Байт дорожки — это **не «нота + длительность» в одном поле**, а код одного из четырёх родов.
Разбор сделан по worker'ам (адреса условий — из дизассемблирования):

| род | условие | что делает | шагов |
|-----|---------|------------|-------|
| ЦИКЛ | `code == 0x00` | возврат указателя чтения на базу; у voice1 дополнительно `INR [0x7DE2]` (`0x2DA9..0x2DB2`) | 0 (тот же шаг) |
| INLINE-КОМАНДА | только voice1: `(code & 0xF0) == 0xE0` (`ANI F0 / CPI E0 @0x2DB3`) | `cmdC` с `E = (code & 0x0F) * 2` → `STA 03CD @0x02AC`, т.е. меняет **длину one-shot гейта**, а не тон | 0 |
| ХОЛД | `code & 0x80` (`ANI 80 / JNZ @0x2DD4 → 0x2E27` / `0x2F9F` / `0x3015`) | `ANI 0F; RAL; STA <slot>` → слот = `(ниббл × 2)` шагов; **тональная защёлка не пишется**, нота продлевается | ниббл × 2 |
| НОТА / РЕСТ | иначе | `code` = индекс 16-битного слова в `0x301C`; если сумма слов (lo+hi, `ADD M @0x2DF8/0x2F78/0x2FEE`) равна 0 → **РЕСТ**, иначе нота | 2 |

Младший бит 7 различает «ноту» и «удержание», а высоту даёт **индекс таблицы**, поэтому
«тон» и «длительность» разделены по разным кодам, а не по нибблам одного байта.

Команды на ноту/рест (через `CALL 0x2F30 → 0x0206`, таблица переходов `0x0217`):

| голос | гейт | латч lo | латч hi | рест | хвост |
|-------|------|---------|---------|------|-------|
| voice1 `0x2D94` | `cmd8` E=`[0x7DCD]` @0x2E0E (нота) / E=0 @0x2E04 (рест) | `cmd0` @0x2E14 | `cmd1` @0x2E1A | `cmd8` E=0 | `cmdD` E=`[0x7DCF]`=9 @0x2E23 (`0x02A8` = nop, инертен) |
| voice2 `0x2F34` | `cmd9` E=`[0x7DD8]` @0x2F8E / E=0 @0x2F84 | `cmd2` @0x2F95 | `cmd3` @0x2F9B | `cmd9` E=0 | — |
| voice3 `0x2FA6` | `cmdA` E=`[0x7DE0]` @0x3004 / E=0 @0x2FFA | `cmd4` @0x300B | `cmd5` @0x3011 | `cmdA` E=0 | — |

Голоса **различаются алгоритмически**, не только константами: только у voice1 есть inline-команды
и «хвостовая» `cmdD`; voice3 дополнительно держит собственный счётчик шагов (`LXI H,7DC4 / INR M @0x2FAE`).

## 3. Артикуляция (это не громкость)

КР580ВИ53 громкости не имеет, поэтому «динамика» в ROM сделана гейтом:

* `cmd8` (`0x0332`): если в параметре взведён бит 4 → ветка `0x034A`: `[0x03CF] = [0x03D1] = (([0x03CD]>>2) & 0x3E) + 1`
  и `CALL 0x024B` (сразу перезагрузить делитель). У заставочного voice1 `[0x03CD] = 0x0C` → **3 кадра**,
  `func_irq_sound_one_shot 0x035E` (из `func_irq_frame_service 0x04F7`, `CALL 0x035E @0x054D`) по истечении
  пишет `MVI A,36 / OUT 0x08` (@0x0370/0x0372) → канал замолкает. Нота звучит 1 шаг из 2 → **стаккато**.
* `cmd9` (`0x0397`): `ANI 10 / JNZ 0x02B8` — при взведённом бите 4 **ничего не делает** → voice2 без гейта → **легато**.
* `cmdA` (`0x03AF`): у voice3 параметр `[0x7DE0] = 0x0E`, бит 4 сброшен, ниббл 14 ≥ 3 → `A = 0x00` →
  `CALL 0x0310` → `ANI 04` → `JZ 0x0298` → перезагрузка делителя **без** записи CW → **легато с ре-тригом**.
* Ветка рест (A = 0x0F) → helper `0x02F4/0x0302/0x0310` пишет `OUT 0x08, CW (36/76/B6)` — тишина.

В `music_spec_title.json` это поля `gate_steps`: 1 шаг у v1, 0 (легато) у v2 и v3.

## 4. Таблица периодов `data_note_freq_table_title @0x301C`

Монтируется на HL тремя загрузками `LXI H,301Ch`: `@0x2DDC`, `@0x2F5C`, `@0x2FD2`.
Слово = `[HL + 2*code]` (индекс готовится `RAL`, смещение прибавляется `DAD B`).
Объём **182 байта = 91 слово** (последнее слово — индекс 90 — занимает `0x30D0..0x30D1`);
граница подтверждена тем, что индекс 91 читался бы из `0x30D2`, а там лежит база 3-го голоса трека #2.

Ненулевых слов 87, нули на индексах **0, 56, 66, 90** (= тишина; в дорожках заставки используется
код `0x38` = 56). Индекс 55 = 1 — служебный (дал бы 124 800 Гц), в треках не встречается.

Структура **блочная**, а не равномерная хроматическая лесенка:

| индексы | содержимое | периоды |
|---------|-----------|---------|
| 1..20 | диатонический ряд E3..C6 | 757 723 636 565 508 474 426 381 359 316 284 256 239 213 190 178 160 143 126 120 |
| 21..31 | альтерации (смешанный регистр) | 301 533 269 341 199 225 401 450 535 601 675 |
| 32..46 | альтерации высокого регистра | 169 150 134 106 95 89 80 71 63 60 113 100 85 75 67 |
| 47..54 | басовый банк F2, C#3, D#3, G2, A2, B2, C3, D3 | 1430 900 802 1274 1135 1013 954 850 |
| 57..65 | басовые альтерации | 1908 1700 1514 1429 1801 1604 1349 1202 1071 |
| 67..78 | **полный хроматический ряд C1..B1** | 3816 3602 3400 3209 3029 2859 2698 2547 2404 2269 2142 2021 |
| 79..89 | высокий регистр 2228..3782 Гц | 56 53 50 47 45 42 40 38 35 33 … |

### Проверка равнотемперированности

Формула ТЗ: `period[i] ≈ round(K / 2^(i/12))`, `K ≈ 3822` при 1,5 МГц, A4 = 440 Гц.
Частота таймера взята **не из допущения**, а из фактов: `docs/VECTOR_VERIFIED.md` §8.3/§11.1 —
ВИ53 clock = `50*768*312/8 = 1 497 600 Гц`; prescale = 12 доказан цепочкой `0x0258..0x0261`
и живой трассой (см. §5).

По ряду 67..78 (`f = 1 497 600 / (12 * P)`):

| i | P | f, Гц | MIDI | откл., центы | `P·2^(i/12)` |
|---|---|-------|------|--------------|--------------|
| 67 | 3816 | 32.704 | 24 C1 | +0.06 | 3816.00 |
| 68 | 3602 | 34.647 | 25 C#1 | −0.02 | 3816.00 |
| 69 | 3400 | 36.706 | 26 D1 | −0.10 | 3816.00 |
| 70 | 3209 | 38.891 | 27 D#1 | −0.01 | 3816.00 |
| 71 | 3029 | 41.202 | 28 E1 | −0.07 | 3816.00 |
| 72 | 2859 | 43.652 | 29 F1 | −0.08 | 3816.00 |
| 73 | 2698 | 46.256 | 30 F#1 | +0.27 | 3816.00 |
| 74 | 2547 | 48.999 | 31 G1 | −0.02 | 3816.00 |
| 75 | 2404 | 51.913 | 32 G#1 | +0.01 | 3816.00 |
| 76 | 2269 | 55.002 | 33 A1 | +0.07 | 3816.00 |
| 77 | 2142 | 58.263 | 34 A#1 | −0.21 | 3817.00 |
| 78 | 2021 | 61.752 | 35 B1 | +0.45 | 3815.00 |

**Вывод: ряд 67..78 — строго равнотемперированный, |cents| max 0.45, K = 3816,
`round(K/2^(i/12))` сходится с max|ΔP| = 0 при f = 1 497 600 Гц.**
При номинальных 1 500 000 Гц тот же ряд даёт K = 3822 — ровно ожидаемое из ТЗ. То есть
ТЗ-«3822 при 1,5 МГц» подтверждается с точностью до того, что реальная тактовая частота
эмулятора/железа 1 497 600 Гц, а 1,5 МГц — округление.

Второй ET-прогон — индексы 79..89 (C#7..B7), |cents| max 24.21. Диатонический банк 1..20
равнотемперированным **не** является: отклонения до ±22,5 ц (пример: индекс 12, P = 256 →
487.50 Гц против B4 = 493.88 Гц, −22,5 ц). Это осознанная потеря: см. §6.

## 5. Карта портов по каналам (КР580ВИ53)

Альтернатива ТЗ «0x0B/0x0D — AY регистр/данные» **отвергнута трассой**: `0x0D` является
зеркалом порта палитры (`docs/VECTOR_VERIFIED.md` §8.4), а последовательность
`OUT 0x08, CW` + `OUT <порт>, lo` + `OUT <порт>, hi` и наличие трёх разных CW
(`0x36/0x76/0xB6` = счётчики 0/1, mode 3, lsb-msb) однозначно описывают ВИ53.

| голос | счётчик | CW | порт данных | латч lo/hi в RAM | helper записи |
|-------|---------|----|-------------|------------------|---------------|
| voice1 `0x2D94` | 0 | `0x36` | `0x0B` | `0x03C7` / `0x03C8` | `0x024B` (`OUT 0B, L` @0x0252; `OUT 0B, H` @0x0255) |
| voice2 `0x2F34` | 1 | `0x76` | `0x0A` | `0x03C9` / `0x03CA` | `0x0277` (`OUT 0A` @0x027E/0x0281) |
| voice3 `0x2FA6` | 2 | `0xB6` | `0x09` | `0x03CB` / `0x03CC` | `0x0298` (`OUT 09` @0x029F/0x02A2) |

Последовательность на **одну ноту voice1**: `cmd8`(гейт: арм one-shot + `CALL 0x024B`) →
`cmd0` (`STA 03C7`, `CALL 0x024B`) → `cmd1` (`STA 03C8`, `CALL 0x024B`), то есть пара
`OUT lo, OUT hi` в `0x0B` передаётся несколько раз за шаг — безвредно, потому что 8253 в
latch-режиме 3 принимает именно lo→hi, а запись CW сбрасывает состояние записи.
Выключение ноты — отдельный `OUT 0x08, 0x36` из `0x035E` через 3 кадра (не «нота 0»).

**Преобразование «код → значение в порт»:** `port_value = 12 × period[code]`,
`f = 1 497 600 / port_value`. Цепочка `0x0258`: `MOV A,M; INX H; MOV H,M; MOV L,A` (HL = слово)
→ `DAD H` (×2) → `MOV E,L/MOV D,H` → `DAD H` (×4) → `DAD D` (×6) → `DAD H` (×12).

Живое подтверждение (I/O-трейс, экран заставки): код дорожки `0x33` → период 1135 (`[0x03C7]=0x6F,[0x03C8]=0x04`)
→ `HL = 0x3534 = 13620 = 12·1135` → `OUT 0x0B,0x34`, `OUT 0x0B,0x35` (seq 19536200/19536202) →
`f = 1 497 600 / 13 620 = 109.96 Гц = A2`.

## 6. Смещение кода → MIDI note (эксперимент)

Гипотеза «`midi = code + note_offset`» проверялась по фактическим порт-значениям. Итог:
по 87 ненулевым индексам отображение `индекс → MIDI` даёт **40 различных смещений**
(например, 67 → 24 = −43, но 11 → 69 = −58), то есть единая константа невозможна —
из-за блочной структуры таблицы. `−43` корректно **только** для хроматического ряда 67..78.

Поэтому в спеке введено поле `note_offset: -43` как справочное (оно честно описывает ряд
67..78), а реальная высота считается конвертером по таблице:
`midi = 69 + round(12·log2(f / 440))`, `f = timer_hz / (prescale · period)`.
Это новый encoding `period_table` в `utils/analyze/music2midi.py` (старый `note_code`
не затронут — регрессия на putup совпала побайтово).

Соответствия, использованные в дорожках заставки (факт = период из таблицы, нота = ближайшее ET):

| голос | коды | периоды | ноты |
|-------|------|----------|------|
| v1 | 0x2F 0x30 0x32 0x33 0x34 0x35 0x36 0x3B | 1430 900 1274 1135 1013 954 850 1514 | F2 C#3 G2 A2 B2 C3 D3 E2 |
| v2 | 0x01 0x33 0x34 0x40 (+рест 0x38) | 757 1135 1013 1202 | E3 A2 B2 G#2 |
| v3 | 0x0B..0x14, 0x1A, 0x20, 0x21, 0x3B, 0x3D, 0x4C (+рест 0x38) | 284..120, 225, 169, 150, 1514, 1801, 2269 | A4..C6, C#5, F#5, G#5, E2, C#2, A1 |

Потери: для кода v3 `0x0C` (487.50 Гц) ближайшее ET — B4, отклонение −22,5 ц; MIDI это
не сохраняет (ограничение формата, см. `Stage9a.md`, Limitations).

## 7. Дорожки заставки

Трек заставки — **№1** у загрузчика `func_music_load_track 0x2E2E` (выбор по `CPI 01/02/03 @0x2E37..0x2E43`).
Адресация — **прямые 16-битные константы** в дескрипторе `data_music_scores_title @0x2E46`
(`LXI H,4E23 / LXI B,4CC4 / LXI D,4FB4 @0x2E46..0x2E4E`): ни таблицы указателей, ни `base + N*stride`.
Дескриптор лежит внутри тела загрузчика как inline-константы.

| голос | база | дамп, байт | указатель чтения (живой) | шагов | длительность |
|-------|------|-----------|--------------------------|-------|--------------|
| v1 (cnt0) | `0x4E23` | 401 (терминатор `0x00`) | `var_music_ptr_title_01 [0x7DC7] = 0x4E58` | 800 | 48.00 с |
| v2 (cnt1) | `0x4CC4` | 351 | `var_music_ptr_title_02 [0x7DD2] = 0x4CF2` | 800 | 48.00 с |
| v3 (cnt2) | `0x4FB4` | 259 | `var_music_ptr_title_03 [0x7DDC] = 0x4FD8` | 800 | 48.00 с |

**Три независимых потока дают ровно 800 шагов каждый** — это главное сквозное подтверждение
формата: note = 2 шага, hold = ниббл×2, цикл и inline-команда = 0 шагов. Любое иное
прочитывание разбило бы совпадение.

Признак конца/петли — `0x00` (он же терминатор дампа): указатель возвращается на базу,
у voice1 дополнительно `INR [0x7DE2]` (счётчик пройденных циклов).

## 8. Соответствие полей спеки фактам

`tools/music_spec_title.json`, schema `v06c-music-spec/1`, encoding `period_table`:

| поле | значение | факт-источник |
|------|----------|---------------|
| `org` / `rom` | `0x0100` / `../src/riseout.rom` | параметры `debug_load_rom` |
| `format` / `ppq` | 1 / 96 | решение: 3 голоса на отдельных каналах |
| `step_ticks` | 24 | 1 шаг = 60 мс при PPQ 96 |
| `tempo_us_per_quarter` | 240000 | четверть = 4 шага (`MVI A,02` × 2 шага) |
| `note_offset` | −43 | справочно, ряд 67..78 (§6) |
| `rest_code` | `0x38` | слово таблицы 56 = 0 (§4) |
| `pitch_table.address/length` | `0x301C` / 182 | `LXI H,301Ch` ×3 |
| `pitch_table.timer_hz / prescale / a4_hz` | 1497600 / 12 / 440 | §4, §5 |
| `tracks[].address/length/expect` | §7 | `debug_read_memory_range`, побайтово сверяется конвертером |
| `tracks[].gate_steps` | 1 / 0 / 0 | §3 |
| `vi53.*` | порты/CW/команды/латчи | §5 |
| `source` | `image` | `write_count = 0` на блоках `0x3000`, `0x4C00..0x50FF` в живом сеансе ⇒ RAM идентична образу |

GM-программы 82/80/81 (lead/truck) — **художественское назначение**, не факт ROM'а: у ВИ53
тембра нет. Громкость `velocity 100` — константа, так как регулятора громкости в чипе нет.

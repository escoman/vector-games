# Stage 3. Параметры функций (cyberno.rom)

Инструмент: `utils/analyze/abi_scan.py` (статика по листингу + динамика с точек
останова) → кандидаты; подтверждение и запись в RDB — ИИ через MCP
(`debug_set_rdb_property`). Файл `.rdb` руками не правился. Сохранение —
`debug_save_rdb`. Полный вывод скана: `.scratch/asmtest/abi_s3.json`
(10 целевых функций, 46 кандидатов, 2757 MCP-вызовов).

## Главная находка: речь — самомодифицирующийся/перемещаемый блок

Проверено побайтово (чтение памяти до исполнения vs после):

- **до** запуска образ в памяти == файл ROM (бордюр `10 09 04 00 F3 CD 69 06 …`).
- **после** бут-распаковки тот же код лежит НИЖЕ на константу **0x59**:
  `file[0x0715:] == runtime[0x06BC:]` (задержка), `LXI B,06F7/076C` (декодер) и
  `DI;CALL 0669;NOP;RET` (вход) — всё смещено на −0x59.
- Блоки речи И вызывающий код хранятся в ROM со смещением +0x59 относительно
  адреса загрузки; загрузчик копирует их вниз **без фиксап операндов** — потому
  операнды (`CALL 0660`, `JNZ 06BC`, `CALL 0669`) уже корректны для ИСПОЛНЯЕМОГО
  адреса.

**Это закрывает open-question Stage 2** («цели ветвлений стекают внутрь строки»):
анималии не было — на адресе файла ветки выглядят неверно, на адресе исполнения
— точны. RDB-функции речи адресованы по ФАЙЛУ; реальный адрес исполнения =
file − 0x59 (записано в свойство `exec_addr`).

## ABI движка речи (подтверждено живым дизассемблированием)

Точка входа речи — exec `0x0663` (NOP-sled с 0x0660), вызвана из exec `0x0579`.

| Объект (RDB/файл) | exec-адрес | Параметры (input → output) | Возврат |
|---|---|---|---|
| `func_speak_start` @0x06BC | 0x0663 | **in=HL — адрес строки-фразы** (ASCII, терминатор 0x00) | норм. `RET` |
| `func_speak_walker` @0x06C2 | 0x0669 | in=HL — курсор строки; читает `[HL]` (`MOV B,M`), шагает `INX H`; B=0xBB — высота тона (внутр., не вход) | **терминатор `[HL]==0 → ORA A/RZ`** |
| `func_voice_delay` @0x0715 | 0x06BC | in=DE — 16-бит счётчик паузы | `JNZ`-петля, `RET` |
| `func_speak_phoneme` @0x071C | 0x06C3 | индекс через `[HL]`, двойная индексация `LXI B,06F7`/`LXI B,076C`; длит.=ANI 0F, флаг=ANI 80 | — |
| `func_speak_emit_plane` @0x073F | 0x06E6 | in=DE — база бит-плоскости (0x082E/0x0935); `OUT 00h` PDM, период 40 T | — |

Ответ на вопрос ТЗ «адрес строки в HL? скорость в регистре?»: **да, строка в HL**.
Скорость/просодия — не регистровый вход вызова, а задаются внутри: посимвольная
длительность (ниббл ANI 0F) + сид B=0xBB. «RET-подобный выход после терминатора»
подтверждён: `RZ` по байту 0x00 в обходчике.

## Свидетели (runtime)

- Точка останова на истинном входе exec `0x0663`: **HL=0x0600** (указатель фразы),
  SP=0x00FB → адрес возврата **0x057C**, то есть `CALL` на 0x0579.
- Вызывающий код exec `0x0573`: `CALL 0x0DD0; LXI H,0x0600; CALL 0x0660;
  LXI H,0x09D0; JMP 0x05E1` — перед речью дёргает `0x0DD0` (init/выводчик,
  помечен на Stage 2 как beam-race). Буфер фразы exec: `[0x0600]=0x00`,
  `[0x0601]='GRU DIL SOFT PREDLAGAET …'` — ведущий 0x00 = кандидат на статус/
  темп-префикс или «тихий» тик (разобрать в Stage 7).

## Что в RDB (итог прохода)

- `params` — на 5 объектах цепочки речи; `exec_addr` + `relocation` — на входе и
  обходчике; `phrase_buffer_lead` — наблюдение по буферу; `called_by_speech_path`
  — на `label_blob_0DD0`. Всё через `debug_set_rdb_property`, `debug_save_rdb`
  → round-trip проверен на диске.

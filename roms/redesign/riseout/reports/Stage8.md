# Stage 8. Выгрузка данных в ASM (riseout.rom)

> **Источник истины по ASM — `v06c-asm-export` (Stage 6.17/6.23 отладчика), а не
> Python и не ИИ.** Фреймворк `utils/analyze/export_asm.py` — только обёртка: нашёл
> бинарь, запустил, разобрал `export.json`, сложил доказательства с провенансом
> (ТЗ §24/§25). Собственных правил форматирования ассемблерного текста пакет не
> изобретает — это запрещено. Поэтому Stage 8 **не переписывает** выдачу экспортёра
> под идеализированный прозаический образ TZ («по файлу на объект», «INCBIN для
> крупных блоков», «RAM-backed только EQU»); он **материализует каноническое дерево
> экспортёра** в `./asm/` и проверяет сквозной контракт — побайтовый round-trip.
>
> Правок RDB на этом этапе **нет**: `run_pipeline.sh riseout --from export_asm
> --until roundtrip_verify` — стадии read-only для RDB (только читают ROM+RDB).
> `debug_reset` не вызывался. ROM: `src/riseout.rom`, sha256
> `c265014b…a6991`, org `0x0100`, окно образа `0x0100..0x50FF`.

## Goal (ТЗ, раздел «Stage 8. Выгрузка данных в ASM»)

1. Для каждого data-объекта RDB — ASM в формате z88dk.
2. **ROM-backed** (`data_*`/`str_*`/`music_*`, таблицы указателей) — фактические
   байты; **RAM-backed** (`var_*`, runtime-буферы, векторы, растр `0x6000…`) —
   EQU/метки без байтов.
3. В таблицах указателей — символьные имена по правилу Stage 1.
4. Крупные блоки допустимо выгружать `INCBIN`-ом.
5. Отчёт `./reports/Stage8.md` + сквозной контракт round-trip после правок Stage 7.

## Method

1. `export_asm` не был собран в этом окружении: бинарь `v06c-asm-export`
   отсутствовал в `~/Projects/vector-debugger/debugger/build` (собраны были только
   `v06c-debugger` и `v06c-mcp`). Цель собрана из существующего CMake-build
   (`make v06c-asm-export`) — это предпосылка окружения, а не пересборка «целевого
   проекта ROM», которую запрещает ТЗ.
2. Прогон `run_pipeline.sh riseout --from export_asm --until roundtrip_verify`
   (apply, но стадии не мутативны): DAG `export_asm → toolchain_lint →
   symbolic_operand_lint → syntax_check → roundtrip_verify`. Итог launcher:
   **stages 5, успешных 5, отказов 0**.
3. Каноническое дерево экспортёра (из `.scratch/export/pipeline`) скопировано в
   `./asm/`.
4. Независимая контрольная сборка deliverable: `z88dk-z80asm -b -m=8080_strict`
   по `./asm/main.asm` → `/tmp/riseout_asm_check.bin` → `cmp` с `src/riseout.rom`.

## Что получилось: дерево `./asm/`

```
asm/
├── main.asm          (12 строк)   — точка сборки: org 0100h + include "layout.asm";
│                                     code/data — закомментированные read-only include
├── layout.asm        (7488 строк) — адресно-упорядоченный мастер: каждый байт окна
│                                     ровно один раз (инструкция | data-регион | gap_);
│                                     ЭТО потребляет сборка
├── code/code.asm     (5855 строк) — read-only просмотр кода (CFG, обрезанный по окну)
├── data/data.asm     (1644 строки)— read-only просмотр данных (те же байт-раны)
├── export.json                    — сводка экспортёра (покрытие, объек/связи, warn)
└── provenance.json                — происхождение: DERIVED из ROM+RDB
```

`asm/bin/` **не создан**: `INCBIN` в выдаче нет (см. §«Расхождение с идеалом TZ»).

## Форматирование: что делает экспортёр (источник истины)

- **`DEFB` — единственная директива данных.** Крупные блоки идут по 8 байт/строка,
  одиночные значения — по 1. `DEFW`/`DEFM` экспортёр **не emits** (решение
  Stage 6.23: «каждый байт окна ровно один раз» важнее читабельности `DEFM`).
- **Явного терминатора строкам не добавляет** — строка равна длине объекта RDB;
  терминатор (`00h`) входит в байты, если он есть в образе (например `^LEVEL
  COMPLETE^` — 16 байт без `00`, длина хранится в записи `data_msg_records`).
- **`gap_XXXX:`** — честная разметка непокрытых байт-ранов (44 гэпа), чтобы сборка
  воспроизводила окно полностью.

## Расхождение с идеализированным описанием TZ (и почему оно осознанно)

| Пункт TZ Stage 8 | Реальность инструментального стека | Решение |
|---|---|---|
| «для каждого data-объекта файл `./asm/<имя>.asm`» | Экспортёр Stage 6.23 сознательно даёт **единый `layout.asm`** (потребляется сборкой) + просмотры `code.asm`/`data.asm`; per-object разбиения нет | Не дробим: разбиение hand-made ломает single-source-of-truth и ставит под удар байт- exact контракт (см. §24 «их изобретать запрещено») |
| «RAM-backed (`var_*`) — только EQU, без байтов» | Объекты по адресам **внутри окна** `0x0100..0x50FF` (напр. `var_ramp_frames` @0x071E, `var_palette_ramp_ptr` @0x0827) физически лежат в образе → получают реальные `DEFB`-инициализаторы. Адреса **за окном** (растр `0x6000…`, переменные `0x7C66`/`var_level`, `var_score`) байтов не имеют: это `outside_window_dropped=256` и hex-ссылки (`lxi h,7c66h` — 452 обращения к `0x6xxx/0x7xxx`) | Так и оставлено: байт- exact требует эмитировать инициализаторы in-window; out-of-window RAM в ASM-образ не входит — корректно |
| «крупные блоки — `INCBIN asm/bin/<имя>.bin`» | `INCBIN` не сгенерирован; глифы/карты/логотипы — `DEFB` | Не форсируем: `INCBIN` разорвёт инлайновую адресную раскладку `layout.asm` |
| «`DEFM` + явный терминатор» | Только `DEFB` | Форматирование — вот экспортёра |

Все четыре — прямое следствие приоритета «ASM пишет экспортёр; round-trip байт-в-байт
= контракт» над прозаической схематикой ТЗ. Фактическая полнота данных при этом
соблюдена (каждый байт окна выгружен ровно однажды и собирается обратно).

## Связь со Stage 7 (карты уровней)

После ручных правок Stage 7 (449 → 479 объектов: `data_level_maps` +
`data_level_02..20` + `data_level_map_offsets` + таблицы адресов) пересобран экспорт:
`data_level_maps:` (база `0x3594`, 5715 байт `DEFB`) и `data_level_02 … data_level_20`
присутствуют в `layout.asm`/`data.asm`, границы подтверждены round-trip (0 расхождений).
То есть карты уровней теперь выгружены как ROM-backed данные.

## Limitations

1. **Покрытие образа не полное** (`complete=false`, 45 гэпов / 44 `gap_`, ~44 %
   достижимой статики + таблицы): гэпы выгружены verbatim, но семантически
   не атрибутированы. Крупный хвост `0x4BE7..0x50FF` (≈1272 байт) — candidate на
   банки/неиспользуемое; оставлен как `gap_`.
2. **warnings=64** — неблокирующие замечания экспортёра (в основном object-nested /
   INFO по вложенным диапазонам); errors/conflicts/unresolved = 0.
3. **Per-object ASM и `INCBIN` не материализованы** (см. таблицу расхождений): если
   для Stage 10 понадобится layout-генератор с individual-include файлами, это
   отдельное расширение `v06c-asm-export`, а не ручное переформатирование.
4. `music_*`-объектов в выдаче нет — музыка разберётся на Stage 9a/9b, их ASM
   появится только после занесения партитур в RDB.

## Артефакты

- **`./asm/`** — каноническое дерево экспортёра: `main.asm`, `layout.asm`
  (byte-exact мастер), `code/code.asm`, `data/data.asm`, `export.json`,
  `provenance.json` (статусы стадий прогона — в `.scratch/pipeline/riseout/*.json`).
- **Round-trip**: `roundtrip_verify = byte-for-byte identical`; независимая сборка
  `./asm/main.asm` → `IDENTICAL` к `riseout.rom` (20480 байт).
- **RDB не изменялся** ( mutate-стадии в `--from export_asm` не входили);
  `debug_save_rdb` на этом этапе не требовался.
- **`Stage1.md` не перегенерирован**: в `.scratch/pipeline/riseout` лежат только
  5 JSON от `--from export_asm` (полный прогон Stage 0 в этой сессии не запускался);
  регенерация сводного отчёта по частичным результатам исказила бы его.
  Байт-exact-контракт после Stage 7 подтверждён в этом отчёте (Facts #1–#2).

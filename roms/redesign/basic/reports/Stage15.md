# Stage 15 — Статическое закрытие residual-дыр (Phase A → 96.89%)

ТЗ Phase A/§Gate. Вход: **CODE ∪ RDB = 95.95%** (остаток **694 Б / 32 блока**),
224 функции (215 с `size=0`). Выход: **96.89%** (остаток **534 Б / 14 блока**),
**584 объекта**. Round-trip сохранён: `make verify` — **byte diffs=0 (17152)**.
Инструмент: `tools/stage15_residual_static.py` (`--check` / `--apply`, паттерн
stage13/14: `ACTION`-список + `check`-лямбда по байтам + `RdbWriter`).

---

## 0. Метод и правило round-trip

Триаж 32 residual-блоков (`debug_disassemble_range` + лидирующие байты по
`src/basic.r0m` + анализ соседей в RDB) разложил дыры на два класса:

* **STATIC-CLOSE** (этот Stage, 18 блоков / 160 Б) — природа доказуема статически.
* **DEFER → Stage16** (14 блоков / 534 Б) — самомодиф/граф/RAM-scratch, где
  статика не distinguish код↔данные; требуют поведенческого трасса (Phase B).

**Правило безопасности пересборки** (сквозной контракт `make verify`):
> байты, помеченные **DATA**, эмитируются как `DEFB` точных значений → round-trip
> всегда сохранён; байты, помеченные **FUNCTION**, дизассемблируются в мнемоники и
> пересобираются → безопасно **только** если разбор даёт валидную континуальную
> инструкцию ровно до границы блока.

Поэтому каждый `NEW_FUNC` проверен `debug_disassemble_range`
(`incomplete_instruction=false`, последняя инструкция — `RET`/`JMP` на границе);
при любом сомнении — `data_`/`pad`/defer.

## 1. EXTEND — длина функции была не записана (`size=0 → span=1`)

7 дыр принадлежат уже известным функциям (пролог/вектор/хвост). CFG тело покрыл,
но RDB не хранил длину → продлеваем **ровно до границы следующего объекта**:

| адрес | объект | size: было → стало | закрытый гэп | след. объект (граница) |
|---|---|---|---|---|
| `0x0000` | `func_0000` | 0 → **8** | `0x0006..07` (reset JMP) | `func_rst_fetch_sep @0x0008` |
| `0x0020` | `func_rst_cmp_dehl` | 0 → **8** | `0x0026..27` (хвост RST8) | `func_rst_fac_sign @0x0028` |
| `0x0028` | `func_rst_fac_sign` | 0 → **16** | `0x0035..37` (хвост RST10) | `func_rst_irq @0x0038` |
| `0x0E0D` | `func_0e0d` | 0 → **51** | `0x0E3A..3F` | `func_str @0x0E40` |
| `0x0E97` | `func_str_return` | 0 → **33** | `0x0EB4..B7` | `func_str_window @0x0ECE` |

## 2. NEW_FUNC — островки кода вне CFG (4)

Достижимы только через `PCHL`/вычисленный адрес, поэтому `debug_analyze_code` их
не прошёл. Разобраны полностью, заканчиваются инструкцией на границе блока:

| адрес | имя | size | разбор (доказательство) |
|---|---|---|---|
| `0x05D3` | `func_resume_guard` | 14 | `MOV A,B/SUB D/JNZ 05E6/MOV A,C/SUB E/JNZ 05E6/LXI H,0000/RET` — сравнение BC с DE (= `var_resume_vector 0x05D1`). Соседи подтверждают семантику CONTINUE/resume. |
| `0x060B` | `func_step_guard` | 14 | зеркало (`= var_step_vector 0x0609`, miss→`0x061E`); сосед `func_prog_step @0x0619`. |
| `0x0BBF` | `func_0bbf` | 5 | `DCX H/RST 10/RZ/RST 8/INR L` — хелпер сравнения (вызывает RST8/RST10). |
| `0x133D` | `func_133d` | 6 | `MOV C,H/MOV H,L/MOV L,D/JMP 1187` — сдвиг тройки + хвостовой переход. |

`func_0bbf`/`func_133d` оставлены с техническими именами: семантика «хелпер»
подтверждена, конкретная роль — Phase C (Stage18).

## 5. Остаток (перенос на Stage16, Phase B)

14 блоков / 534 Б — самомодиф/граф/RAM-scratch, где статика недостаточна:

```
0x27A8(21) 0x2B01(1) 0x2B3C(4) 0x2B58(1) 0x2C6F(15) 0x2D7E(74) 0x2DDC(154)
0x3722(6)  0x3730(26) 0x3D03(10) 0x3E00(152) 0x4027(1) 0x4029(36) 0x4053(33)
```

Атрибуция только по рантайму (boot-snapshot + `memory_diff` + trace портов):
`0x2DDC`/PAINT-подсистема, `0x2D7E` (16 Б арифм-таблица + код → сплит),
`0x366F/0x3730` (самомодиф-трамплин), `0x3E00/0x40xx` (workspace/float-коэффициенты).

## 6. Limitations

* EXTEND фиксирует **длину**, но не переименовывает и не заполняет ABI — это
  Phase C (Stage17 sizes для всех 224 → Stage18 semantics). `func_0e0d`/`func_0bbf`/
  `func_133d` остаются техническими именами до подтверждения роли.
* RDB-extents-only coverage остаётся **27.99%** (215 функций с `size=0`): это не
  дефект Stage15, а объект Stage17 (явные размеры по всем функциям).
* `data_3518_pad`/`data_26fc_pad` названы филлерами по паттерну (run-байт / нули)
  без позитивного доказательства потребителя — честная пометка `pad`.
* `str_2079_cyrillic`/`data_*_poly_coeffs` — природа (данные) доказана, семантика
  (текст/ряд) отнесена к Phase D.
* 14 отложенных блоков сознательно НЕ названы `func_` без рантайм-доказательства.

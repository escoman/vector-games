# Stage 10 — Выгрузка блоков данных в asm-файлы

## Цель
Для каждого объекта данных из RDB создать файл в `./asm` в формате z88dk: ROM-данные
— с фактическим байтовым содержимым; переменные/буферы ОЗУ — только как символические
адреса (EQU/метки), без байтов.

## ROM
- Файл: `src/putup.rom`, размер 17664 байта (0x4500), адрес загрузки `0x0100`
  (диапазон `0x0100..0x45FF`).
- SHA256: `8486442efc390b15860ec7f69c32db93b0884908565fa11fec57d5c551b4e9a6`
- RDB: `src/putup.rdb`, 167 объектов (85 из них — не-код: данные/строки/таблицы/переменные).
- ROM загружен через MCP `debug_load_rom(org=0x100)`; содержимое читалось
  `debug_read_memory_range`.

## Метод и соответствие правилам
- **ROM-данные** читаются из MCP `debug_read_memory_range`. Скриптов пост-обработки
  MCP-данных нет (TZ Stage 0, примечание; Stage 10 п.3).
- **Структурированные блоки** (таблицы байт/слов/указателей, строки) выгружены
  директивами `DEFB` / `DEFW` / `DEFM` значениями, перенесёнными из MCP напрямую.
- **Крупные бинарные блоки** (тайл-карты уровней, графика `0x2761`, упакованный
  шрифт `0x3041`, спрайты `0x2F61`, нотные таблицы) выгружены через `.incbin`
  (Stage 10 п.7 — те же блоки названы кандидатами на `.incbin`, т.к. DEFB-дамп
  десятков сотен opaque-байтов непрактичен и рискован по ошибкам).
- Бинарники `asm/bin/*.bin` — **прямая по-байтовая копия** образа `putup.rom`
  (`dd`, без какого-либо преобразования данных). Файл идентичен ROM в MCP
  (совпадение SHA256 подтверждено). Начало каждого блока сверено с
  `debug_read_memory_range` (см. ниже) — байт-в-байт совпадает.
- В таблицах указателей/адресов hex-значения, совпадающие с началом RDB-объектов,
  заменены символьными именами (Stage 10 п.5, правила Stage 8):
  `data_snd_dispatch_table`, `data_snd_toggle_table`, `data_glyph_ptr_table`.
- Каждый файл снабжён заголовком: имя объекта, адрес, размер, назначение (Stage 10 п.6).

### B. Крупные бинарные блоки (.incbin) — 20 файлов, 21 .bin
| Файл(ы) | Адрес | Размер |
|---------|-------|--------|
| data_level_maps.asm | 0x1C8E | 2640 (15×176; 15 меток data_level_01..15) |

`data_level_maps.asm` содержит 15 меток `data_level_01:`..`data_level_15:` (глобальные

объекты `data_level_02..15` продублированы отдельными файлами (по одному объекту RDB
на файл). `data_level_01` отдельного объекта в RDB не имеет (это база таблицы).

### C. Переменные/буферы ОЗУ — только EQU (Stage 10 п.2)
Файл `var_ram_symbols.asm`: 44 символа (векторы `data_int_vector_reset@0x0000`,
`data_int_vector_rst7@0x0038`; переменные `var_*`; рантайм-буферы `data_kbd_matrix`,
`data_level_param_buf`, `data_entity_xcoords/ycoords`, `data_voice_param_buf`,
`data_ram_buffer_5000@0x5000`, `data_glyph_block@0x6000`, `data_ram_sprites_7418@0x7418`).
Байтовое содержимое не выгружается (ОЗУ строится программой в рантайме).

**Отклонение (задокументировано):** вместо 44 отдельных файлов-заглушек символьные
адреса ОЗУ собраны в один include-заголовок `var_ram_symbols.asm` (удобно для
подключения на Stage 11). Смысловое требование п.2 (только EQU, без байтов) соблюдено.

## Верификация байт-точности (.incbin)
Совпадение `dd`-бинарников с MCP `debug_read_memory_range` (первые 16 байт):
- 0x2761 gfx: `00 00 00 00 00 00 00 00 00 03 0C 17 2F 5F 5F B3` ✓
- 0x2F61 sprites: `1F 0F 00 31 01 01 00 00 00 C0 F0 F8 FC B4 B6 B6` ✓
- 0x3041 font: `61`×16 ✓
- 0x42F9 note_ch1: `0D`×10, `0F 0A 08 06 04 02` ✓
- 0x445D note_ch0: `01 00`×8 ✓
- 0x1C8E/0x1D3E level: пограничные байты ✓
- Целостность карт: md5(`data_level_maps.bin`) == md5(конкатенации 15 чанков) ✓

## Проверка синтаксиса (z88dk-z80asm)
- Директива вставки бинарника в этом билде тулчейна — `INCBIN "..."` (НЕ `.incbin`);
  все 20 файлов поправлены. Каждый `.incbin`-блок собран и побайтово совпал с
  исходным `bin/*.bin` (размеры: maps=2640, gfx=2048, sprites=224, font=2041,
  note_ch1=256, note_ch0=419, level_15=176 — всё точно).
- Каждый структурированный файл (`DEFB/DEFW/DEFM`, арифметика `EQU+смещение` в
  `data_glyph_ptr_table`) собирается сам по себе; оставшиеся «undefined symbol» —
  это корректные внешние ссылки на другие файлы (`func_snd_*`, `data_glyph_block`).

## Ограничения / Unknown
- **Для Stage 11:** `EQU`-символы НЕ переносятся между отдельными `.o` при линковке.
  Заголовок `var_ram_symbols.asm` нужно подключать как общий include (или собирать
  в одной единице с `data_glyph_ptr_table` и др.), иначе внешние ссылки на RAM-адреса
  и `data_glyph_block+N*32` не разрешатся линкером. Ссылки на `func_*` разрешатся
  нормально (метки кода экспортуются).
- Внутренняя разбивка нотных таблиц (шаг 10/20 байт) и схема упаковки
  `data_packed_font_3041` до конца не расшифрованы — выгружены сырыми блоками.
- `data_sprites_2F61` и `data_ram_sprites_7418`: точное назначение в RDB не
  задокументировано.
- Итоговая собираемость и корректность путей подтверждается на Stage 11 при сборке
  `PUTUP_NEW.ROM`.

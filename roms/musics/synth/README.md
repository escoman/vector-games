# synth — тестовый ROM партитурного синтезатора Вектора-06Ц

Экспериментальный ROM для `lib/music.c` (собирается с `-DMUSIC_ONLY`
вместо `sound.c` — символы `music_*` у плееров общие, в одном ROM они
не линкуются; `sound.c` не изменялся).

Архитектура — «музыкальный компилятор + runtime»: текстовая партитура
`.mus` и семплы ударных `.smp` заранее компилируются `utils/mus2inc.py`
в единый `.inc`, ROM работает только с ним. Четыре потока байткода
(3 тона ВИ53 + ударные AY) идут от **одного music clock** — ударные не
могут «уплыть» относительно мелодии.

## Формат .mus

Текстовый файл; комментарии — от `;` до конца строки. Секции:

```
Tempo: T120                     ; общий темп композиции (один на все
                                ; партитуры; можно не ставить T в секциях)
sample 0: samples/kick.smp      ; объявление семпла (индексы 0..9)
sample 1: samples/snare.smp

score 0:                        ; тональный канал 0 (ВИ53 канал 0)
O4 L4 C D E F

score 1:                        ; тональный канал 1
O3 L4 C E G C

score 2:                        ; тональный канал 2
O2 L2 C G

drums:                          ; партитура ударных (шум AY)
L4 0 P 1 P
```

Вместо общего `Tempo:` допустимо писать `T<n>` в каждой партитуре
(значения обязаны совпадать).

Команды (синтаксис BASIC `PLAY` Вектора-06Ц):

| Команда | Назначение                                                          |
|---------|---------------------------------------------------------------------|
| `Tempo: T<n>` | общий темп композиции (строка-заголовок, одна на файл)      |
| `T<n>`  | темп, ударных в минуту (32..255). Один на всю композицию, только до первого события; при заявленном `Tempo:` может отсутствовать. По умолчанию `T120` |
| `O<n>`  | октава 1..7 (по умолчанию `O4`)                                      |
| `L<n>`  | длительность: 1, 2, 4, 8, 16, 32, 64, 128 (по умолчанию `L4`)       |
| `P`     | пауза на текущую длительность (звучащий семпл ударных НЕ обрывает)  |
| `C..B`  | ноты; `#` или `+` — диез, `-` — бемоль                              |
| `C8`    | явная длительность одной ноты/паузы (то же для `P16`)              |
| `0..9`  | в `drums:` — атака семпла с объявленным номером (каждая цифра перезапускает семпл с начала) |
| `!`     | явно разрешить разную длину партитур                                 |

Время компилируется заранее: единая целочисленная сетка **PPQ = 32** —
четверть всегда 32 тика, `L_n = 128/n` (целое для всех L, никаких
округлений — дрейф исключён по построению). Темп применяется в
runtime: за кадр 50 Гц потребляется `4T/375` тика (аккумулятор
Брешихэма, `tempo_num/tempo_den` в `music_song_t`). При T120 четверть
= 25 кадров = 0.5 с. В прерывании нет деления времени и плавающей
точки.

Пустые партитуры допустимы (в проверке длины не участвуют); длины
непустых обязаны совпадать, иначе компилятор выдаёт ошибку (§9 ТЗ).

## Формат .smp

Бинарный файл одного инструмента ударных:

```
байт 0:  N — число кадров (1..255)
байты 1..2N: пары (R6, R10) — период шума 0..31 и громкость 0..15
```

Один кадр = один тик 50 Гц; кадры выводятся последовательно с момента
атаки, первый — сразу. Пример (сжатая бочка: период падает, громкость
спадает): `09 1F 0F 1C 0E 19 0C 16 0A 13 08 10 06 0D 04 0B 02 0A 01`.

## Байткод .inc

`mus2inc.py` выдаёт C-файл: массивы потоков `<имя>_s0/s1/s2/dr`,
семплы `<имя>_smpN`, таблица `<имя>_samples[10]` и структура
`<имя>_song` типа `music_song_t` (v06.h). Команды потока:

| Байт        | Команда                                                       |
|-------------|---------------------------------------------------------------|
| `0x00`      | конец потока                                                   |
| `0x01..0x5F`| нота: абсолютный номер = байт − 1 (октава·12 + полутон; ля 4-й октавы = 57 → делитель ВИ53 3409) |
| `0x60`      | пауза на текущую длительность                                  |
| `0xE1, len` | текущая длительность в тиках сетки PPQ = 32 (четверть = 32) |

## API (lib/music.c)

```c
music_set_data(&song);  /* подключить скомпилированную композицию */
music_start();          /* все четыре потока с позиции 0          */
music_pause();          /* позиции и clock сохранены, тона заглушены */
music_resume();         /* продолжить с сохранённой позиции       */
music_stop();           /* сброс позиций, clock, тишина           */
music_set_loop(1);      /* играть по кругу                        */
music_is_playing();
music_tick();           /* из кадрового прерывания, 50 Гц         */
```

`music_tick()` ведёт единый clock; огибающие семплов ударных ведёт
`drum_tick()` (drums.asm) — вызывать обе из прерывания:

```c
static void isr_music(void) { music_tick(); drum_tick(); }
frame_handler = isr_music;
```

В прерывании запрещены ожидания — их там нет: событие потока
обрабатывается за один проход, семпл пишется по кадру за тик.

## Сборка

```
make            # .mus/.smp -> rom_data/*.inc -> synth.rom
make deploy     # + копия в ROMS эмулятора PPSSPP
make full       # clean + сборка + deploy
```

Управление в ROM: `1..5` — выбрать тест и играть, `ВК`/пробел —
пауза/продолжить, `0` — стоп, `ESC` — выход.

Тесты (ТЗ §24–25): SCALE — один голос; VOICES — три голоса; DRUMS —
только ударные; RHYTHM — смесь L4/L8/L16, ударные вдвое чаще; SYNC —
удар точно на начало каждой ноты.

## Добавление нового семпла

1. Создать `music/samples/<имя>.smp` (формат выше; генерировать удобно
   скриптом — см. комментарии в `music/samples/*.smp` проекта).
2. Объявить в `.mus`: `sample N: samples/<имя>.smp` (N = 0..9).
3. Использовать цифру `N` в секции `drums:`.
4. `make full` — компилятор проверит размер файла и диапазоны R6/R10.

## Добавление новой мелодии

1. Создать `music/<имя>.mus` (секции `score 0..2`, `drums:` по
   необходимости).
2. В `Makefile` добавить имя в `SONGS`.
3. В `main.c`: `#include "rom_data/<имя>.inc"` и строку в `songs[]`.
4. `make full` — при несовпадении длин партитур компилятор остановит
   сборку (выровняйте длительности или поставьте `!`).

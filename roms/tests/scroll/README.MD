# Тест скролла: roms/tests/scroll

## Сборка

```bash
cd roms/tests/scroll
make full
```

## Запуск

ROM автоматически копируется в PPSSPP:
```
/home/alexey/snap/ppsspp-emu/common/.config/ppsspp/PSP/GAME/VECTOR06C/ROMS/scroll.rom
```

Запустить в PPSSPP как обычный ROM Вектор-06Ц.

## Управление

| Клавиша | Действие |
|---------|----------|
| **UP** | Скролл +1 (VRAM-строка растёт) |
| **DOWN** | Скролл -1 (VRAM-строка уменьшается) |
| **RIGHT** | Скролл +16 (быстрый сдвиг) |
| **LEFT** | Скролл -16 (быстрый сдвиг) |
| **F1** | Пометить кадр (белая полоса на VRAM-строке 128) |
| **ESC** | Выход |

## Что наблюдать

### 1. Градиент

Каждая VRAM-строка `i` заполнена цветом `(i & 15)`:
- Строки 0-15: цвета 0-15 (чёрный → серый)
- Строки 16-31: цвета 0-15 (повтор)
- ... и так далее до строки 255

При скролле видно, какие VRAM-строки попадают на экран.

### 2. Статус

В левом верхнем углу:
- **SCR**: текущий регистр скролла (0-255)
- **BEAM**: тики таймера с начала кадра (0-29952)
- **LINE**: строка растра (0-311, где 0-255 — видимая область)

### 3. Артефакты при скролле

**Тест 1: Скролл в VBlank**
1. Дождаться, пока LINE = 0 (начало кадра)
2. Нажать UP/DOWN
3. Наблюдение: градиент сдвигается плавно, без разрывов

**Тест 2: Скролл в середине кадра**
1. Дождаться, пока LINE = 128 (середина экрана)
2. Нажать UP/DOWN
3. Наблюдение: виден **разрыв** на границе:
   - Верхняя часть (строки 0-127): старый градиент
   - Нижняя часть (строки 128-255): новый градиент

**Тест 3: Быстрый скролл**
1. Нажать LEFT/RIGHT несколько раз
2. Наблюдение: разрыв более заметен, т.к. меняется много строк

## Ожидаемые результаты

### При скролле в VBlank (LINE = 0)

- Градиент сдвигается на 1 строку
- Нет видимых артефактов
- Новый цвет появляется на противоположном крае экрана

**Пример**: SCR = 0xFF → 0x00
- Было: физ. линия 0 → VRAM[0xFF] (цвет 15, серый)
- Стало: физ. линия 0 → VRAM[0x00] (цвет 0, чёрный)
- На экране: верхняя строка меняется с серой на чёрную

### При скролле в середине кадра (LINE = 128)

- Видна **горизонтальная граница** на строке 128
- Выше границы: старый градиент
- Ниже границы: новый градиент
- Граница может быть резкой (1 пиксель) или размытой (если скролл меняется несколько раз)

## Формулы

### VRAM-строка на физической линии

```
vram_row = (SCR - LINE) & 0xFF
```

**Пример**: SCR = 0xFF, LINE = 0
```
vram_row = (0xFF - 0) & 0xFF = 0xFF
```
Физ. линия 0 читает VRAM[0xFF] (цвет 15, серый).

**Пример**: SCR = 0xFF, LINE = 128
```
vram_row = (0xFF - 128) & 0xFF = 0x7F
```
Физ. линия 128 читает VRAM[0x7F] (цвет 15, серый).

### Цвет на физической линии

```
color = vram_row & 15 = ((SCR - LINE) & 0xFF) & 15
```

**Пример**: SCR = 0xFF, LINE = 0
```
color = (0xFF & 0xFF) & 15 = 0xFF & 15 = 15
```
Цвет 15 = серый (V06_RGB(3, 3, 3)).

## Связь с mario-8cols

В mario-8cols используется та же модель скролла:
- `gfx_set_scroll(D2SCROLL(cam_row * TILE_PX))` — отложенная запись
- `v06_out(V06_PIA_PA, row)` — немедленная запись

**Проблема**: если скролл меняется до отрисовки новой VRAM-строки, луч читает старое содержимое — артефакт "полоса с противоположного края".

**Решение**: использовать порядок:
```c
gfx_next_frame();           // VBlank
render_rowband(revealed);   // Отрисовка
gfx_set_scroll(new_S);      // Отложенная запись
```

См. SUMMARY.MD для полного анализа.

# putup — распакованная ROM `PUTUP_NEW.ROM` (games/putup)

Адресно-точная реконструкция оригинала `src/putup.rom` (asm-ветка Stage 12
[`redesign/putup`](../../redesign/putup)) с **вынесенной из ROM распаковкой**:
блок из 256 глифов (8192 Б) лежит в ROM распакованным, загрузчики выведены из
исполнения. Две стадии:

| | этап A | этап B (итог) |
|---|--------|---------------|
| блок глифов | RAM-адрес распаковки 0x6000 (исторический) | ROM по `GLYPH_BASE` (одна константа), итог **0x5600** |
| мёртвые блоки | на исторических адресах | выжжены: `func_load_glyph_block`, `func_load_gfx_2761`, `data_packed_font_3041`, `data_gfx_2761` |
| копир спрайтов | исполняется (пишет в снимок те же байты) | выжжен NOP-ами (0x0B86, 34 Б) |
| образ | 32512 Б | 29952 Б (0x100..0x75FF) |

## Сборка

```bash
make                        # PUTUP_NEW.ROM в корне проекта (GLYPH_BASE=0x5600, dead-блоки выжжены)
make verify                 # кодовая зона 0x0100..0x45FF = оригинал + заглушки + dead-нули
make GLYPH_BASE=0x6000 KEEP_DEAD=1   # регрессия этапа A
make layout                 # перегенерировать компоновку (asm/putup_unpacked.asm + gap-бины)
make deploy / make full     # стандарт проекта (finally.mk)
```

Перенос блока = одна константа `GLYPH_BASE`. Кандидат 0x4600 отбракован
поведенческой сверкой: окно наехало на текстовый back-буфер
`data_ram_buffer_5000` (0x5000..0x53FF). Оригиналы `putup.rom`/`putup.rdb`
не дублируются — читаются из [`redesign/putup/src`](../../redesign/putup/src).
Сборка не оставляет промежуточных файлов, кроме `tools/dead_ranges.json`.

## Как это работает

Оригинал на старте распаковывает шрифт в RAM 0x6000..0x7FFF
(`func_load_glyph_block`, вызов из `func_main_init` @0x0B83). В PUTUP_NEW этот
CALL запатчен в 3×NOP, а распакованный блок — побайтовый снимок RAM пост-иниц
оригинала (вербатим через MCP, стабильность подтверждена двумя снятиями) —
вкомпонован по `GLYPH_BASE` и читается как ROM. Таблица указателей
`data_glyph_ptr_table` (0x0600, читается страницей: `MVI H,06h` — позиция
закреплена кодом) собрана символично `DEFW data_glyph_block+N*32`, поэтому
переезд блока не требует правки её байтов.

## Инструменты

| | |
|---|---|
| `tools/gen_layout.py` | компоновщик: мастер-asm с inline DEFB для гэпов + `tools/dead_ranges.json` |
| `tools/get_glyph_block.py` | снятие блока 0x6000..0x7FFF через MCP (вербатим → DEFB в asm) |
| `tools/verify_image.py` | `make verify`: кодовая зона vs оригинал (allow-list заглушек) |
| `tools/lint_ptrs.py` | этап B: абсолютные ссылки на удаляемые/смещаемые адреса (+ RDB-сверка) |
| `tools/compare_behavior.py` | поведенческая сверка orig→new→orig: VRAM/глифы/порты по CPU-кадрам |

Подтверждение корректности: `make verify` (байты) + поведенческие прогоны
`compare_behavior.py` (ориг→new→ориг, заставка/play1/play2): VRAM 0/32768
расхождений — совпадает с шумовым полем оригинал-против-оригинала; глиф-окно
стабильно, записей в игру нет. Все данные — побайтовыми DEFB в `asm/` (без
bin-артефактов); карты уровней — отдельные файлы `data_level_01..15.asm`
(1 DEFB-строка = 1 ряд уровня, 16 тайл-индексов), включаемые `data_level_maps.asm`
последовательно; глиф-блок — 2 строки на глиф с номером и адресом.

## Структура `asm/`

- `asm/funcs/` — код: `func_*` и точки входа `lbl_*`;
- `asm/data/` — данные: `data_*` (в т.ч. `data_level_*.asm`, `data_glyph_block_unpacked.asm`)
  и строковые константы `str_*` (в RDB тип `string` — категория данных);
- `asm/var_ram_symbols.asm` — EQU-алиасы RAM-переменных; `asm/putup_unpacked.asm` —
  мастер-компоновка (генерируется, include-и с префиксами `funcs/` и `data/`).

# Stage 6 — Карта RAM-интерпретатора (`var_*`)

Закрывает п.6 ТЗ: **служебные ячейки интерпретатора** (page-zero + high-RAM
workspace) закреплены в RDB как объекты `variable` (`var_*`) с размером, ролью и
комментарием — фундамент EQU-переносимости для Stage 11. Итог: **+24 объекта**
(523→547). Round-trip **byte-for-byte identical** (17152 байт, 6/6 стадий
пайплайна SUCCESS). Двойное подтверждение каждой ячейки: **статика** (расстановка
в `func_boot_init` + контекст функций-потребителей) и **динамика** (рантайм-дифф
образа↔RAM, ТЗ §13).

---

## 0. Двойной метод подтверждения

### Статика — расстановка в boot (`func_boot_init` `0x19CC`)
```
MVI A,81 / OUT 04                     ; PIA2
LHLD 0026 / SHLD 3F21                 ; var_program_base <- адрес загрузки (page-zero монитора)
LXI H,7FFE / SHLD 0EF6                ; var_mem_top      = 0x7FFE
LXI H,7FCC / SHLD 0ED6                ; var_free_top     = 0x7FCC
LXI H,804F / SHLD 3DFC / SHLD 3DFE    ; var_string_alloc_ptr (2 слова) = 0x804F
MVI A,2C / STA 3F76                   ; var_input_delim  = ','
CALL 019F (func_cmd_new)              ; writes конец программы по var_program_base
MVI A,21 / STA 19F3                   ; САМОМОД: CALL->LXI (не переменная)
```
Подыннициализатор `0x07BC`: `XRA A / STA 038A` — сброс `var_print_column`.

### Динамика — рантайм-дифф (`memory_diff.json`, ТЗ §13)
Образ в области переменных = нули; после исполнения автостарт-демо RAM
отличается **46 патчами**. Ячейки, ставшие правдоподобными RAM-адресами/значе-
ниями, — подтверждённые переменные. **Важное разделение**: часть патчей — это
*самомодифицируемый код*, а не переменные (см. §4).

## 1. Подтверждённая карта `var_*` (24 объекта)

### Программа и исполнение
| ячейка | имя | размер | доказательство |
|---|---|---|---|
| `0x3F21` | `var_program_base` | 2 | boot `LHLD 0026/SHLD 3F21`; NEW/LIST (LHLD×8); рантайм → `0x4301` |
| `0x0464` | `var_stmt_ptr` | 2 | STOP/LET/NEXT пишут, CONT читает; рантайм → `0x3F80` |
| `0x0625` | `var_stack_ptr` | 2 | main_loop/CONT сбрасывают, GOSUB читает; рантайм → `0xFFFF` (пусто) |
| `0x0C30` | `var_scan_ptr` | 2 | обход/List строк, высвобождение; рантайм → `0x4303` |
| `0x0C33` | `var_program_end` | 2 | NEW/CLEAR задают, вставка строки расширяет; рантайм → `0x4303` (=base+2) |

### Оценщик и вычисления
| `0x404D` | `var_text_ptr` | 2 | ~30 обращений; RST 1/RST 2 двигают поток токенов |
| `0x404F` | `var_fac` (0x404F..0x4052) | 4 | eval/LET пишут, IF читает `0x4050`; рантайм `0x4050`→`81 80` |
| `0x09CD` | `var_eval_temp_ptr` | 2 | eval_expression `SHLD 09CD`; рантайм → `0x3F7E` |
| `0x0F45` | `var_binop_operand` | 2 | диспетчер операций `0x09DD` пишет; рантайм → `0x3F7E` |
| `0x0C8C` | `var_type_flag` | 1 | LET/eval `LDA 0C8C` — ветка строка/число (→конкатенация `0x1E6D`) |
| `0x0F07` | `var_string_ptr` | 2 | func_str_return/0fe9; рантайм → `0x403D` |

### Память / границы
| `0x0CB3` | `var_free_limit` | 2 | FRE читает; guard eval `LHLD 0CB3/SUB L/JC 0069`; рантайм → `0x4303` |
| `0x0EF6` | `var_mem_top` | 2 | boot `=0x7FFE`; рантайм → `7FFE` |
| `0x0ED6` | `var_free_top` | 2 | boot `=0x7FCC`; рантайм → `7FCC` |
| `0x3DFC` | `var_string_alloc_ptr` (0x3DFC..0x3DFF) | 4 | boot `=0x804F` (2 слова); рантайм → `4F 80 4F 80` |

### Ввод / текст
| `0x3F76` | `var_input_delim` | 1 | boot `=','`; рантайм → `2C` |
| `0x3F77` | `var_input_buffer` (0x3F77..) | 16 | REPL/токенизатор; рантайм: `0x3F78`→`'15,0,1:'`+`80`, `0x3F83`→`'CLS'` |
| `0x038A` | `var_print_column` | 1 | `0x07BC` сбрасывает; путь вывода символа двигает колонку |

### Графика (состояние подсистем из 5d)
| `0x3769` | `var_color_current` | 1 | PLOT/PAINT `LDA 3769`; рантайм → `0F` (=15, автостарт COLOR15) |
| `0x2B56` | `var_graph_xy` (X=`0x2B56`,Y=`0x2B57`) | 2 | парсер `0x28A0`→`STA 2B56/2B57`; читается как слово и побайтно |
| `0x30B4` | `var_circle_color` | 1 | CIRCLE `CALL 0x10C3/STA 30B4` |
| `0x4028` | `var_paint_field` | 1 | PAINT `LDA 0x3769/STA 4028` |

### Звук (PLAY, состояние из 5d)
| `0x27C8` | `var_play_active` | 1 | PLAY `XRA A/STA 27C8` при старте |
| `0x245F` | `var_play_pos` | 1 | PLAY `STA 245F` при старте |

## 2. Главный вывод: layout подтверждён, спека v2.5 — только частично

Спека §15.2: «`0x4300` — начало загруженной BASIC-программы». **Подтверждено на
этом ROM**: `var_program_base = 0x4301`, `var_program_end = var_free_limit =
0x4303` (пустая программа: маркер конца `00 00` у `0x4301`). То есть классический
layout «интерпретатор в низких адресах, текст программы в high-RAM ~`0x4300`».

**Но** карта page-zero из спеки v2.5 §15.3 к данному ROM **не применима директно**:
знакоместо `0..639`, таймер `768..770`, сдвиг `771`, звуковые счётчики `772..775` —
это page-zero **монитора свежей машины**. Наш образ грузится в `0x0000` (RST-векторы
+ код) и замещает знакогенератор; его workspace — high-RAM `0x3DFC..0x42FF` плюс
разбросанные служебные ячейки `0x01xx..0x0FFF`. Поэтому Stage 6 строил карту **по
факту этого ROM**, а не переносом спеки.

Проверка: в `code.asm` **нет ни одного** `STA/LDA/SHLD/LHLD` с операндом
`0x0300..0x0307` — интерпретатор их не трогает (звуковой драйвер работает через
`var_play_active 0x27C8`/`var_play_pos 0x245F` на ВBlank). Ячейки `0x4300..0x4303`
(адрес/номер строки из спеки) не встречаются как immediate — до них доходят
только через регистры-указатели (`var_program_base` и др.), что согласуется с
областью текста программы.

## 3. Что делает `NEW` (п.6 ТЗ)
`func_cmd_new` (`0x019F`, вызывается из boot) кладёт маркер конца программы
(`00 00`) по адресу `var_program_base`, после чего `var_program_end = var_scan_ptr
= var_free_limit = var_program_base + 2` (в диффе — `0x4303`). Стек (`var_stack_ptr`)
сбрасывается в `0xFFFF` в холодном старте (`LXI H,0FFFF / SHLD var_stack_ptr`).

## 4. Исключено из переменных (самомодифицируемый КОД)
Эти патчи диффа — изменение операндов инструкций, **не** ячейки данных:
| адрес | образ→рантайм | суть |
|---|---|---|
| `0x19F3` | `CD`→`21` | boot: `CALL`→`LXI H` (одноразовый NEW) |
| `0x2C97` | `CD`→`21` | аналогичный самомод |
| `0x15D6` | `60`→`62` | смена операнда |
| `0x4086` | `60`→`6A` | смена операнда |
| `0x3285/8A/8F/94` | `AF`→`00` | значения, вписываемые в код граф-драйвера |
| `0x3F5F/64/69/6E` | `AF`→`AA` | слоты constant-операндов (цвет/режим) |

Объектов `variable` по этим адресам НЕ создаём (иначе ложно представим код как
данные и нарушим round-trip семантику).

## 5. Неклассифицированные ячейки (объект не создаём)
Роль не доказана, автостарт-демо их не исполняет (нет динамического подтверждения)
либо это векторы/служебные указатели. Перечень для будущих стадий (кандидаты в
`var_*` после уточнения):
- `0x03E7` — инициализируется `0xFFFF` вместе со `var_stack_ptr` (возможно, второй
  стек/для FOR); рантайм → `FFFF`. Кандидат.
- `0x0609` — вектор: `LXI H,0619 / SHLD 0609` (хранит адрес `func_prog_step`).
  Самомод-векторresume. Кандидат на `var_step_vector`.
- `0x05D1` — вектор: `LXI H,05E1 / SHLD 05D1`. Кандидат.
- `0x086C`, `0x2D04/0x2D07/0x2D0B`, `0x3A1F`, `0x3A22`, `0x2B3E`, `0x2CB1`, `0x2DD8`,
  `0x3DB3`, `0x3DC6`, `0x15D6` — изменены в диффе, семантика не установлена.
- `0x0026` — **ячейка монитора** (адрес загрузки), читается один раз в boot.
  Документируется, объект не заводится (не принадлежит BASIC).

**Формат таблицы пользовательских переменных** (п.6 ТЗ: имя/длина/тип `%/($)`):
частично виден в `func_var_lookup` `0x0BCD` — разбор имени `A..Z` (`SUI 41H /
CPI 1A`), строковый тип по `$` (`CPI 24H`), числовой флаг в `var_type_flag`. Сама
таблица имён в автостарте пуста (переменных нет) → в диффе не подтверждена.
**Закрыто в Stage 6b** (см. `Stage6b.md`): формат записи — 6 байт
`[имя:2][значение:4]`, имя 1..2 буквы A..Z, тип по флагам `%/($)` в
`var_type_flag`; вершина таблицы — `var_free_limit 0x0CB3` (живое `0x0CB3 ==
program_end == 0x4303`); **отдельного DATA-указателя нет** (идёт по тексту через
`var_text_ptr`/`var_stmt_ptr`), FOR-блоки лежат на стеке `var_stack_ptr 0x0625`.
Закреплены новые `variable`: `0x0ED3 var_string_window`, `0x0609
var_step_vector`, `0x05D1 var_resume_vector`, `0x3559 var_getput_ptr`.

## 6. Применение и проверка
Инструмент: `tools/stage6_rammap.py` (`--check`/`--apply`), 24 объекта,
`kind=variable`, без связей (переменные не вызывают).
```
PYTHONPATH=utils python3 roms/redesign/basic/tools/stage6_rammap.py --apply
  # RDB 523 -> 547 (+24); actions: add 24 / comment 24 / property 72 / save 1
bash utils/analyze/run_pipeline.sh basic --from export_asm
  # 6/6 SUCCESS; round-trip byte-for-byte identical (17152 байт)
```
Экспорт подтвердил корректность имён: в `code.asm` обращения к этим ячейкам
подписаны символами `var_fac`, `var_free_limit`, `var_stack_ptr`, `var_type_flag`.

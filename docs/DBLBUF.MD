# DBLBUF.MD — Техническое задание: модуль Double Buffer для lib/gfx/

> Стандартная библиотека двойной буферизации для Вектора-06Ц.  
> Основана на технологии, доказавшей эффективность в демке `roms/demos/mario-dbl`.  
> Реализация — **чистый 8080-ассемблер** (`lib/gfx/dblbuf.asm`), без C-кода.

---

## 1. Цель и мотивация

Двойная буферизация (Double Buffer) — техника устранения tearing и обеспечения
плавной покадровой анимации на Векторе-06Ц. Суть:

- Экран 256×256×16 разбит на **две пары битовых плоскостей**:
  - **Буфер A** = плоскости веса 1 (0xE000) и веса 2 (0xC000) → биты 0–1 палитрного индекса.
  - **Буфер B** = плоскости веса 4 (0xA000) и веса 8 (0x8000) → биты 2–3 палитрного индекса.
- Каждый буфер несёт **4 логических цвета** ( свой бит0/бит1).
- На каждый пиксель приходится 4-битный индекс = сумма весов всех четырёх плоскостей.
- **Маскировка палитрой** (16 слотов):
  - Видим A: `pal[i] = c4[i & 3]`        — биты 2–3 игнорируются, B не видно.
  - Видим B: `pal[i] = c4[(i >> 2) & 3]` — биты 0–1 игнорируются, A не видно.
- **Смена палитры = смена активного буфера**, синхронизирована с VSync.

Демка `mario-dbl` реализовала это вручную (см. `build_palettes()`, `pal_dirty`,
`v06_set_palette_isr()` в ISR). Цель — вынести отработанные паттерны в
переиспользуемый модуль `lib/gfx/dblbuf.asm` с объявлениями в `lib/v06.h`.

**Почему чистый ASM, без C:**
- Все операции тайминг-критичны (запись палитры в гасящем интервале, копирование 16 КБ).
- Полный контроль над регистрами и тактами — нет overhead sccz80 (сохранение BC/DE,
  вызовы через стек).
- `gfx_dblbuf_isr` вызывается из кадрового прерывания — каждый такт на счету,
  здесь C-обвязка недопустима.
- Копирование буферов (16 КБ) на чистом ASM в ~2 раза быстрее, чем через C-цикл
  с индексацией.

## 2. Архитектура модуля

```
lib/gfx/
└── dblbuf.asm     — весь модуль: состояние (BSS), логика, примитивы

lib/v06.h          — extern-объявления всех публичных функций и переменных
```

Модуль **не** подменяет существующую инфраструктуру (`gfx_set_mode`, `gfx_fill_planes`,
`gfx_set_palette`, `gfx_fade_in/out`, `v06_set_palette_asm`), а **надстраивается**
над ней, вызывая эти функции как EXTERN-символы.

---

## 3. Состояние модуля (BSS)

Все данные размещаются в `SECTION bss_clib` (не занимают места в ROM).

```asm
        SECTION bss_clib

; --- палитры-маски (по 16 байт каждая) ---
_db_pal_a:      defs    16      ; палитра показа буфера A (видны E000/C000)
_db_pal_b:      defs    16      ; палитра показа буфера B (видны A000/8000)

; --- состояние ---
_db_front:      defb    0       ; 0 = виден A, 1 = виден B
_db_pal_dirty:  defb    0       ; 1 = ISR должен перезагрузить палитру
_db_active:     defb    0       ; 1 = модуль инициализирован

; --- указатель на палитру для ISR (2 байта, little-endian) ---
_db_show_pal:   defw    0       ; адрес _db_pal_a или _db_pal_b
```

**Итого в BSS:** 16 + 16 + 1 + 1 + 1 + 2 = **37 байт** (ROM не расходуется).

Базовые адреса плоскостей фиксированы соглашением (не конфигурируются):

| Константа | Адрес | Назначение                        |
|-----------|-------|-----------------------------------|
| `BASE_A0` | 0xE000| буфер A, бит 0 (вес 1)           |
| `BASE_A1` | 0xC000| буфер A, бит 1 (вес 2)           |
| `BASE_B0` | 0xA000| буфер B, бит 2 (вес 4)           |
| `BASE_B1` | 0x8000| буфер B, бит 3 (вес 8)           |

## 4. Публичный API

### 4.1. Инициализация палитры

```c
/* Инициализировать палитры-маски double buffer по 4-цветной палитре c4[4].
 *
 * c4 — массив из 4 байт цветов (формат V06_RGB), задающий палитру каждого
 * буфера. Функция строит 16-слотовые маски:
 *   db_pal_a[i] = c4[i & 3]        (показывает буфер A, скрывает B)
 *   db_pal_b[i] = c4[(i >> 2) & 3] (показывает буфер B, скрывает A)
 *
 * Вызывается ОДИН раз при старте, до первого gfx_dblbuf_present().
 * После вызова db_active = 1, db_front = 0, db_pal_dirty = 0.
 * НЕ загружает палитру в железо — это делает show/present.
 *
 * Пример:
 *   unsigned char my_pal[4] = {
 *       V06_RGB(0,0,0),   // 0: чёрный (фон)
 *       V06_RGB(7,0,0),   // 1: красный
 *       V06_RGB(0,7,0),   // 2: зелёный
 *       V06_RGB(7,7,0),   // 3: жёлтый
 *   };
 *   gfx_dblbuf_init(my_pal);
 */
void gfx_dblbuf_init(const unsigned char *c4) __z88dk_callee;
```

**Реализация (asm):**
```
_gfx_dblbuf_init:
    ; HL = c4 (аргумент со стека, callee-соглашение: pop ret; pop hl; push ret)
    ; Строит _db_pal_a[16] и _db_pal_b[16] циклом i=0..15:
    ;   _db_pal_a[i] = c4[i & 3]
    ;   _db_pal_b[i] = c4[(i >> 2) & 3]
    ; Обнуляет _db_front, _db_pal_dirty; устанавливает _db_active = 1.
    ; Указатель _db_show_pal = адрес _db_pal_a (по умолчанию front=A).
    ; Возврат: ret (стек очищен callee).
```

### 4.2. Переключение видимого буфера (свап)

```c
/* Показать наполненный буфер: переключить палитру-маску (VSync-синхронно).
 *
 * Алгоритм:
 *   1. front ^= 1  (текущий back становится front)
 *   2. show_pal = (front == 0) ? db_pal_a : db_pal_b
 *   3. pal_dirty = 1  (ISR загрузит палитру на ближайшем VBlank)
 *   4. gfx_active_planes = 0x0F  (все 4 плоскости видимы)
 *
 * Палитра загружается ISR-ом (v06_set_palette_isr) в гасящем интервале
 * ближайшего VBlank — без tearing. Вызов не блокирует выполнение:
 * синхронизацию обеспечит v06_wait_frame() в главном цикле.
 *
 * Возвращает новый front (0 = A, 1 = B) — удобно для ветвления
 * "в какой буфер рисовать следующий кадр".
 */
unsigned char gfx_dblbuf_present(void);
```

**Реализация (asm):**
```
_gfx_dblbuf_present:
    ; Инвертирует _db_front (xor 1).
    ; По _db_front выбирает базу палитры: 0 -> _db_pal_a, 1 -> _db_pal_b.
    ; Записывает адрес в _db_show_pal (2 байта).
    ; Устанавливает _db_pal_dirty = 1.
    ; Записывает 0x0F в _gfx_active_planes (EXTERN).
    ; Возвращает A = _db_front (0 или 1).
```

```c
/* Загрузить палитру показа НЕМЕДЛЕННО (без ожидания VBlank через ISR).
 * Используется для стартового кадра, fade-in и других ситуаций, когда
 * нужно показать буфер синхронно с текущим моментом, а не на следующем
 * прерывании.
 *
 * Алгоритм:
 *   1. show_pal = (front == 0) ? db_pal_a : db_pal_b
 *   2. Вызывает v06_set_palette_asm(show_pal) (внутри: ei/halt, запись в гасящем
 *      интервале — ожидание VSync).
 *   3. gfx_active_planes = 0x0F
 *   4. pal_dirty = 0 (палитра уже загружена, ISR не будет перезаписывать).
 *
 * ВАЖНО: функция делает ei/halt внутри v06_set_palette_asm, поэтому НЕ
 * вызывается из ISR. Для ISR-контекста используйте gfx_dblbuf_isr().
 */
void gfx_dblbuf_show(void);
```

**Реализация (asm):**
```
_gfx_dblbuf_show:
    ; По _db_front выбирает палитру (HL = _db_pal_a или _db_pal_b).
    ; Вызывает EXTERN _v06_set_palette_asm (ei/halt + запись 16 слотов).
    ; Записывает 0x0F в _gfx_active_planes.
    ; Обнуляет _db_pal_dirty.
```

### 4.3. Выбор активных плоскостей для вывода

```c
/* Установить маску плоскостей, в которые разрешён вывод.
 *
 * При double buffer стандартный вывод (gfx_print, gfx_put_char, спрайты)
 * должен идти ТОЛЬКО в невидимый (back) буфер — его плоскости активны,
 * плоскости front-буфера заблокированы. Это предотвращает меркание и
 * tearing: зритель видит стабильный front, пока мы рисуем в back.
 *
 *   mask = 0x03  →  активны только плоскости A (E000, C000)
 *   mask = 0x0C  →  активны только плоскости B (A000, 8000)
 *   mask = 0x0F  →  активны все 4 плоскости (обычный режим, вне dblbuf)
 *
 * Функция записывает mask в глобальную переменную gfx_active_planes,
 * которую читают все примитивы вывода (pr.asm, pr512.asm, pr512t.asm).
 *
 * Возвращает предыдущее значение маски в A (удобно для save/restore).
 */
unsigned char gfx_dblbuf_set_planes(unsigned char mask) __z88dk_callee;
```

**Реализация (asm):**
```
_gfx_dblbuf_set_planes:
    ; A = mask (аргумент со стека, callee).
    ; Сохраняет A в B (старое значение _gfx_active_planes вернуть).
    ; LD A, (_gfx_active_planes)  ; читаем старое значение
    ; LD C, A                     ; C = старое (для возврата)
    ; LD A, B                     ; A = новый mask
    ; LD (_gfx_active_planes), A  ; записываем
    ; LD A, C                     ; A = старое значение (возврат)
    ; pop de; push de (восстановить стек, если callee)
    ; ret
```

> **Примечание.** В `mario-dbl` то же самое делается напрямую:
> `gfx_active_planes = 0x03;` / `gfx_active_planes = 0x0C;`.
> Обёртка добавляет атомарность и возврат предыдущего значения.

### 4.4. Копирование буферов

```c
/* Скопировать буфер A в буфер B (16 КБ: 2 плоскости × 8 КБ).
 *
 * Используется для инициализации: статичный фон (текст, земля, бордюры)
 * рисуется ОДИН раз в буфер A, затем копируется в B — оба буфера имеют
 * идентичный фон. После этого спрайты рисуются/стираются независимо
 * в каждом буuke (по патчам), а фон остаётся общим.
 *
 *   E000 → A000  (плоскость веса 1, 8 КБ = 32 × 256 байт)
 *   C000 → 8000  (плоскость веса 2, 8 КБ = 32 × 256 байт)
 *
 * Реализация — ручной цикл 8080: MOV A,M / STAX D / INX H / INX D.
 * LDIR (ED B0) НЕ используется — ядро заявлено как КР580ВМ80А (8080),
 * команда LDIR может не поддерживаться эмулятором.
 * Скорость: ~70 тактов/байт × 16384 байт ≈ 0.3 с — приемлемо для
 * стартовой инициализации (вызывается один раз).
 */
void gfx_dblbuf_copy_ab(void);
```

**Реализация (asm):**
```
_gfx_dblbuf_copy_ab:
    ; --- плоскость веса 1: E000 -> A000 ---
    LXI H, 0E000h       ; источник
    LXI D, 0A000h       ; приёмник
    MVI B, 020h         ; 32 блока по 256 байт = 8 КБ
    CALL copy_block      ; внутренний цикл (см. ниже)
    ; --- плоскость веса 2: C000 -> 8000 ---
    LXI H, 0C000h
    LXI D, 08000h
    MVI B, 020h
    CALL copy_block
    RET

; copy_block: копировать B*256 байт (HL) -> (DE). C — внутренний счётчик (256).
copy_block:
    MVI C, 0
copy_inner:
    MOV A, M
    STAX D
    INX D
    INX H
    DCR C
    JNZ copy_inner
    DCR B
    JNZ copy_block
    RET
```

```c
/* Скопировать буфер B в буфер A (зеркальная операция).
 * Может понадобиться, если статичный фон рисуется в B, а не в A.
 *
 *   A000 → E000  (плоскость веса 1, 8 КБ)
 *   8000 → C000  (плоскость веса 2, 8 КБ)
 */
void gfx_dblbuf_copy_ba(void);
```

### 4.5. Интеграция с ISR

```c
/* Обработчик палитры для кадрового ISR. Вызывается ПЕРВЫМ в пользовательском
 * frame_handler, до любой другой работы (звук, логика).
 *
 * Алгоритм:
 *   if (db_pal_dirty) {
 *       v06_set_palette_isr(db_show_pal);   // без ei/halt, мы уже в ПР
 *       db_pal_dirty = 0;
 *   }
 *
 * Функция легковесная: ~15 тактов в холостом ходу (pal_dirty=0),
 * ~200 тактов при dirty (16 записей в порт 0x0C через v06_set_palette_isr).
 * Не влияет на raster-критичный цикл записи в порт 0x0C.
 *
 * Типичное использование:
 *   void my_frame_handler(void) {
 *       gfx_dblbuf_isr();       // ← первым делом
 *       music_tick();           // ← потом звук
 *       drum_tick();
 *   }
 */
void gfx_dblbuf_isr(void);
```

**Реализация (asm):**
```
_gfx_dblbuf_isr:
    ; Быстрый путь: pal_dirty == 0 -> ничего не делаем.
    LDA  _db_pal_dirty
    ORA  A
    RZ                       ; return if Z (dirty == 0)
    ; Медленный путь: загрузить палитру через v06_set_palette_isr.
    LHLD _db_show_pal        ; HL = указатель на палитру
    PUSH H                   ; аргумент для v06_set_palette_isr (cdecl)
    CALL _v06_set_palette_isr
    POP  H                   ; очистить стек от аргумента
    XRA  A
    STA  _db_pal_dirty       ; ack: dirty = 0
    RET
```

> `v06_set_palette_isr` — **уже экспортируется** из `lib/sys/v06pal.asm`
> (строки 44-45: `PUBLIC _v06_set_palette_isr`). Она делает то же, что
> `v06_set_palette_asm`, но БЕЗ `ei/halt` — вызывается из ISR, где мы уже
> в гасящем интервале.

### 4.6. Вспомогательные функции

```c
/* Вернуть индекс текущего front-буфера (0 = A, 1 = B).
 * Возврат: A = _db_front. */
unsigned char gfx_dblbuf_front(void);

/* Вернуть индекс back-буфера (противоположного front).
 * back = front ^ 1. Рисовать нужно именно в back.
 * Возврат: A = _db_front ^ 1. */
unsigned char gfx_dblbuf_back(void);

/* Получить указатель на палитру-маску front-буфера.
 * Возвращает HL = _db_pal_a (если front=0) или _db_pal_b (если front=1).
 * Полезно для gfx_fade_in/out — фейдить нужно палитру видимого буфера. */
const unsigned char *gfx_dblbuf_front_pal(void);

/* Получить указатель на палитру-маску back-буфера.
 * Возвращает HL = противоположный front-указатель. */
const unsigned char *gfx_dblbuf_back_pal(void);

/* Принудительно запросить смену палитры на ближайшем VBlank (без свопа front).
 * Полезно, если палитра была изменена извне (например, после fade) и нужно
 * перечитать её в ISR. Устанавливает db_pal_dirty = 1. */
void gfx_dblbuf_invalidate(void);
```

**Реализация (asm):**
```
_gfx_dblbuf_front:
    LDA  _db_front
    RET

_gfx_dblbuf_back:
    LDA  _db_front
    XRI  01h              ; инвертировать младший бит
    RET

_gfx_dblbuf_front_pal:
    LDA  _db_front
    ORA  A
    JZ   fp_a
    LXI  H, _db_pal_b
    RET
fp_a:
    LXI  H, _db_pal_a
    RET

_gfx_dblbuf_back_pal:
    LDA  _db_front
    ORA  A
    JNZ  bp_a              ; front=0 -> back=B
    LXI  H, _db_pal_b
    RET
bp_a:
    LXI  H, _db_pal_a
    RET

_gfx_dblbuf_invalidate:
    MVI  A, 01h
    STA  _db_pal_dirty
    RET
```

## 5. Полный сценарий использования (pattern)

```c
#include "v06.h"

/* 4-цветная палитра игры (формат V06_RGB). */
static const unsigned char game_pal[4] = {
    V06_RGB(0, 0, 0),   /* 0: чёрный  */
    V06_RGB(7, 0, 0),   /* 1: красный */
    V06_RGB(0, 7, 0),   /* 2: зелёный */
    V06_RGB(7, 7, 0),   /* 3: жёлтый  */
};

/* Кадровый ISR: палитра → звук. */
static void game_frame(void)
{
    gfx_dblbuf_isr();       /* 1. смена палитры, если запрошена */
    music_tick();           /* 2. звук                            */
}

void main(void)
{
    /* --- Инициализация --- */
    gfx_set_black_palette();
    gfx_set_mode(GFX_MODE_256_16);
    gfx_fill_planes(0x0F, 0x00);

    gfx_dblbuf_init(game_pal);

    /* Рисуем статичный фон в буфер A (плоскости 0x03). */
    gfx_dblbuf_set_planes(0x03);
    /* ... gfx_print, тайлы, сегменты ... */

    /* Копируем фон в буфер B — теперь A и B идентичны. */
    gfx_dblbuf_copy_ab();

    /* Рисуем первый кадр спрайта в back-буфер (B), НЕ показываем. */
    gfx_dblbuf_set_planes(0x0C);
    /* ... draw_sprite в buf=1 ... */

    /* Проявляем экран fade-in от чёрного к палитре A. */
    gfx_dblbuf_show();                       /* показать A (ei/halt) */
    gfx_fade_in(gfx_dblbuf_front_pal(), 2);  /* фейд к палитре A     */

    /* Назначаем ISR и стартуем главный цикл. */
    frame_handler = game_frame;

    for (;;) {
        kbd_scan_now();
        update_game_logic();

        /* Рисуем в back-буфер (невидимый). */
        unsigned char back = gfx_dblbuf_back();
        gfx_dblbuf_set_planes(back == 0 ? 0x03 : 0x0C);
        erase_old_sprite(back);
        draw_new_sprite(back);

        /* Показать результат: свап палитры на следующем VBlank. */
        gfx_dblbuf_set_planes(0x0F);
        gfx_dblbuf_present();

        v06_wait_frame();
    }
}
```

## 6. Требования к реализации

### 6.1. Файл `dblbuf.asm`

- **Секции:**
  - `SECTION code_clib` — весь исполняемый код.
  - `SECTION bss_clib` — переменные состояния (37 байт, в ROM не попадают).
- **Соглашение о вызовах:** все публичные функции используют sccz80 `cdecl`
  (аргументы в стеке, очистка стека вызывающим) или `callee` (очистка callee)
  — в зависимости от объявления в `v06.h` (см. `__z88dk_callee`).
- **8080-совместимость:** НЕ использовать Z80-команды (LDIR, LDDR, PUSH/POP IX
  и т.д.). Только команды КР580ВМ80А: MOV, MVI, LXI, LDA, STA, LHLD, SHLD,
  INX, DCX, STAX, LDAX, JMP, Jcc, CALL, RET, ORA, XRA, ANA, ADD, SUB, INR, DCR,
  PUSH, POP, XCHG, RLC, RRC.
- **ISR-функция (`gfx_dblbuf_isr`):** минимальна, без `ei/halt`, без сохранения
  регистров (предполагается, что вызывающий ISR уже сохранил PSW/BC/DE/HL).

### 6.2. Объявления в `v06.h`

Новый раздел `/* - - - - - - - Double Buffer - - - - - - - - - - - - - - - - - */`
после раздела `gfx_plane_or/andn` и перед разделом шрифтов. Все функции —
`extern`, с `__z88dk_callee` где это уместно (функции с 1 аргументом).

Пример раздела в `v06.h`:
```c
/* - - - - - - - - - Double Buffer (dblbuf.asm) - - - - - - - - - - - - - - - */

extern void gfx_dblbuf_init(const unsigned char *c4) __z88dk_callee;
extern unsigned char gfx_dblbuf_present(void);
extern void gfx_dblbuf_show(void);
extern unsigned char gfx_dblbuf_set_planes(unsigned char mask) __z88dk_callee;
extern void gfx_dblbuf_copy_ab(void);
extern void gfx_dblbuf_copy_ba(void);
extern void gfx_dblbuf_isr(void);
extern unsigned char gfx_dblbuf_front(void);
extern unsigned char gfx_dblbuf_back(void);
extern const unsigned char *gfx_dblbuf_front_pal(void);
extern const unsigned char *gfx_dblbuf_back_pal(void);
extern void gfx_dblbuf_invalidate(void);
```

### 6.3. Внешние зависимости (EXTERN-символы)

Модуль использует следующие функции/переменные из других модулей библиотеки:

| Символ                  | Источник              | Назначение                          |
|-------------------------|-----------------------|-------------------------------------|

## 7. Ограничения и допущения

1. **Режим 256×256×16.** Модуль рассчитан на стандартный 16-цветный режим.
   Для 512×256×4 (GFX_MODE_512_4) схема плоскостей иная и требует отдельного
   расширения (не входит в базовый модуль).

2. **Фиксированная раскладка плоскостей.** Адреса A = {E000, C000}, B = {A000, 8000}
   зашиты в `dblbuf.asm`. Изменение раскладки потребует правки модуля.

3. **Потребление RAM.** 37 байт в `.bss` (2 × 16 байт палитры + 5 байт состояния).
   Копирование буферов стека не требует (всё через HL/DE/BC).

4. **Стоимость свапа.** Загрузка палитры в ISR — ~200 тактов (16 записей в порт 0x0C
   через `v06_set_palette_isr`). Это укладывается в гасящий интервал и не влияет
   на raster.

5. **Стоимость copy_ab.** 16 КБ × ~70 тактов/байт ≈ 1.15 Мтактов ≈ 0.77 с
   на частоте 1.5 МГц. Приемлемо для стартовой инициализации (вызывается один раз).

6. **Один активный модуль.** Глобальное состояние не поддерживает два независимых
   double-buffer-контекста. Для многоконтекстности нужен дескриптор (будущее расширение).

## 10. Будущие расширения (не входят в базовый модуль)

- **Дескриптор контекста** (`gfx_dblbuf_t`) — для нескольких независимых
  double-buffer-областей (например, верхний экран — игра, нижний — HUD).
- **Triple buffer** — третий буфер для сцен, где отрисовка кадра занимает
  больше 1/50 с (конвейер: рисуем N+2, показываем N, готовим N+1).
- **Поддержка 512×256×4** — альтернативная раскладка плоскостей для
  512-пиксельного режима.
- **Автоматический skip-кадр** — если back-буфер не изменился (сцена статична),
  `gfx_dblbuf_present()` возвращает `front` без свопа палитры (экономия
  ~200 тактов ISR).
- **Оптимизация copy_ab через LDIR** — если целевая платформа поддерживает
  Z80 (не только 8080), использовать ED B0 / ED B8 для ускорения копирования
  в ~10 раз (до ~0.08 с на 16 КБ).

# Stage 9a. Мелодия ЗАСТАВКИ → `exolon_title.mid`

> ТЗ §Stage 9a описывает канонический движок: `RST 7`/VBlank-тикер, КР580ВИ53-партитуры,
> `data_note_freq_table` с равнотемперированностью (`K≈3822`, A4=440), `var_music_ptr_NN`,
> многодорожечность. **exolon этому шаблону не следует** — и это не домысел, а результат
> разбора кода + прогона `func_blink_toggle` в эмуляторе. Ниже — что реально нашлось,
> чем это доказано, и как из этого собран честный MIDI. Подробная спека формата:
> [`Stage9a_music_spec.md`](Stage9a_music_spec.md); машинально-читаемая:
> `tools/music_spec_title.json` (`v06c-music-spec/1`).

## Вердикт (TL;DR)

Заставка проигрывает **однократную двухголосую мелодию на 1-битном бипере ВВ55**
(порт C бит0), а не на КР580ВИ53 и не по прерыванию. Партитура — 195 троек по 3 байта
в `data_music_seq_title @0x70B4` (терминатор `00h` @`0x72FD`), высота тона — из
`data_beeper_period_table @0x7300` (53 значения) как период `2*(256-value)` итераций
быстрого цикла `func_blink_toggle`. Формат ноты/частоты **подтверждён измерением**
(автокорреляция реального сигнала бипера == формула, 7/7). Собран `exolon_title.mid`:
2 дорожки × 195 нот, `expect`-дампы побайтово сверены, шаг 118.3 мс (~126.8 BPM).
RDB: +3 объекта, +6 комментариев (в т.ч. **исправлен ложный** «видео-маска/анимация
звёзд» у `func_blink_toggle`), +3 связи; побайтовый round-trip образа **не сломан**
(`roundtrip.bin` == ROM `92be64d1…`, 32512 B).

## Как искал (живые свидетельства)

1. `grep OUT` по дизассемблеру → звуковые порты `08h/09h/0Ah` только в `func_vi53_ch1/ch2_init`
   (по одному вызову на инициализацию экрана). Счёт `0x7500`/`0x7373` → 1.5 МГц/счёт ≈ **50 Гц**
   = частота кадров; boot-комментарий прямо говорит «`IN 0Ah` (счётчик ВИ53) для синхронизации
   кадра». ⇒ ВИ53 = таймер, не музыка. (Первая проверка ТЗ на прочность.)
2. Комментарий `lbl_title_init`: «запуск мелодии через blink `0x70B4`/`0x73BE`» → `LXI H,70B4h;
   CALL func_play_blink_sequence`. `func_title_stars_menu @0x76FC` разобран — чистая графика
   звёзд, портов не касается. ⇒ мелодия = `func_play_blink_sequence`, один прогон при старте.
3. `func_blink_toggle @0x7335` писал в `OUT 00h`. Сверился с `docs`: **порт 00h = управляющее
   слово ВВ55** (`vector_techinfo.md §8.1`), а `00h↔01h` = BSR-команда сброса/установки
   **PC0**, который `VECTOR_VERIFIED.md §11.5` называет 1-битным бипером магнитофона. ⇒ это звук.

## Формат (доказательство прогоном)

`func_play_blink_sequence` читает тройку `{A, hi-idx, lo-idx}`; `D=table[hi]`, `E=table[lo]`;
`DE≠0` → `func_blink_toggle`, иначе `func_blink_pause`. В быстром цикле за итерацию делаются
**два** `OUT 00h` (значения H и L), а биты H0/L0 переключаются на переполнениях E/D-счётчиков.
Что это не догадка, а факт — `v06_emu` (8080-интерпретатор), трассировка `io_write(0x00)`,
автокорреляция фронта:

```
hi= 7 D=0x54 период_низ: измер=344 формула=344 [OK]
hi=19 D=0xAA период_низ: измер=172 формула=172 [OK]   ...  (7/7 OK)
```

Формула периода: `период_итераций = 2*(256 - value)`. Частота:
`f = 3_000_000 / (77 * период)` (3 МГц — docs VERIFIED эффективная; 77 — ручной подсчёт
T-состояний быстрого пути). Нижние ноты выходят `A#2..F4`, верхние `A#3..F6` — правдоподобный
двухголосый диапазон, что само по себе подтверждает модель.

## Проверки

- `python3 tools/title_music.py --validate` → разбор 195 нот, измерение 7/7 OK.
- `music2midi ... -o exolon_title.mid` → `ВЕРДИКТ 2 дорожки записано [DERIVED]`, `expect` совпал
  (иначе скрипт падает до записи — см. `validate_codes`).
- `run_pipeline.sh exolon --from export_asm --apply` → 6/6 стадий, `roundtrip_verify SUCCESS`;
  собранный `.scratch/export/pipeline/roundtrip.bin` побайтово == `exolon.rom`
  (SHA `92be64d1…`, 32512 B). Новые data-объекты выдают точные байты ROM — регрессии нет.

## Limitations / открытые вопросы

- **Абсолютная высота — оценка.** Аппаратная частота CPU в docs `UNVERIFIED` (2.5/3/3.5 МГц);
  octave-смещение MIDI калибровано физической моделью (3МГц/77цикл), а не «на слух».
  Относительные интервалы точны (∝ 1/период, измерены).
- **Природа двух тонов.** `func_blink_toggle` физически даёт быстрый носитель + огибающие
  (нижняя по D, верхняя по E). На реальном пьезо-бипере верхний носитель может заглушаться;
  в MIDI оба тона отданы как есть (честная 2-голосая модель, а не «один правильный»).
- **`title_streams.bin` — производный источник.** `music2midi` не умеет читать interleave-тройки
  прямо из ROM, поэтому нормализацию делает `tools/` (правило: ROM-специфичное в `tools/`).
  Подложка истины — ROM `0x70B4..0x72FD` + `0x7300..0x7334`, аудит встроен в разборщик.
- **Не проверялось поведением через MCP** (boot→RUS→заставка со звуком) — это вилка Stage 10;
  здесь закрыты данные/формат/MIDI. GAME OVER-вариант (`@0x7079`, тот же формат) в этот Stage
  не конвертировался (ТЗ §9a = только заставка).

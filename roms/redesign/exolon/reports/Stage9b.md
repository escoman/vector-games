# Stage 9b. GAME OVER-мелодия + звуковой дизайн боя (выстрелы/взрывы на TapeOut)

> Продолжение музыкального разбора после Stage 9a. Здесь закрываются три открытых вопроса:
> **(1)** вторая партитура GAME OVER (`@0x7079`, тот же формат, другой темп);
> **(2)** звуковой эффект при сборе бонуса — `func_flash_video @0x4C8E`, ранее
> ошибочно подписанный как «визуальная вспышка/маска»;
> **(3)** озвучка самого боя (выстрелы/взрывы) — прежде ошибочно объявлена тишиной.

## Вердикт (TL;DR)

GAME OVER проигрывает **19-нотную двухголосую мелодию** на том же бипере ВВ55, через
тот же `func_play_blink_sequence @0x73BE`, с той же период-таблицей `@0x7300`.
Отличие — базовая длительность `A=15` (не 18): шаг ~98.6 мс, темп ~152 BPM, вся
мелодия ≈ 2.07 с. Финальная нота `A=45` = 3 шага (hold). Собран `exolon_gameover.mid`:
2 дорожки × 19 нот, `expect` побайтово сверен, низ MIDI 62..67, верх 74..86.

**Игровой звук — не один эффект, а целый бит-бэнг на TapeOut (PC0), привязанный к бою**
(проверено живым io_trace, см. раздел «Звук боя»). `func_flash_video @0x4C8E` — нисходящий
chirp-осциллятор (4128 × 10 переключений PC0), вызывается из `func_bonus_award @0x557A` ×5
при сборе пикапа. Но выстрелы/взрывы тоже озвучены: PC0 модулирует `func_beam_delay @0x1E2F`
(бит счётчика ВИ53), а `func_update_objects_06f6 @0x0698` сбрасывает PC0 на каждую частицу
осколков из таблицы `06F6` (их сыплет `func_update_bullet_trail @0x4A84` при попаданиях).
В трассе боя за ~1 с — 57 сбросов + 41 установка PC0 (импульсы 40–130 T), в idle — 0.
Имя/комментарий `func_flash_video` («видео-маска») исправлены в RDB.

## GAME OVER: партитура

| | |
|---|---|
| Адрес | `0x7079` (`data_music_seq_gameover`, 57 байт) |
| Терминатор | `00h` @ `0x70B2` |
| Формат ноты | `{A, hi-idx, lo-idx}` — идентичен title |
| A (длительность) | 18× `0x0F(15)` + 1× `0x2D(45)` → 18 + 3 = **21 шаг** |
| DUR_BASE | 15 (title: 18) |
| hi-idx (низ) | 23..28 → D=0xBC..0xCD → период 2*(256-D) = 51..74 итер. |
| lo-idx (верх) | 35..47 → E=0xDE..0xEF → период 18..34 итер. |
| Паузы | **Нет** (все hi≥23, lo≥35 → DE≠0) |

Вызов: `lbl_7048` (GAME OVER) → `CALL func_render_and_blink @0x7413` →
`LXI H,7079h; JMP func_play_blink_sequence`.

### Частоты и темп

```
f = 3_000_000 / (77 × период)     (та же формула, что Stage 9a)
низ:  период 51..74 → f = 591..860 Hz  → MIDI 62..67 (D4..G4)
верх: период 18..34 → f = 1144..2164 Hz → MIDI 74..86 (D5..D6)
шаг = 256×15×77 / 3e6 = 98.6 мс
tempo_us_per_quarter = 77 × 3840 / 3e6 × 4e6 = 394240 µs  (~152.2 BPM)
```

## Единственный SFX: `func_flash_video @0x4C8E`

Разбор (строки 5560–5587 code.asm):

```asm
func_flash_video:
    xra a          ; A=0 (PC0 initial state)
    lxi d,1020h    ; outer loop 4128
  lbl_4c96:
    mvi h,0ah      ; middle loop 10
  lbl_4c98:
    xri 01h        ; toggle bit 0
    out 00h        ; BSR PC0 = beeper toggle
    mov b,e        ; inner delay = E (grows each outer pass)
  lbl_4c9d:
    dcr b; jnz lbl_4c9d
    dcr h; jnz lbl_4c98
    inr e          ; E++ → period stretches → frequency descends
    dcr d; jnz lbl_4c96
    ret
```

Нисходящий chirp (~50→<1 Hz огибающая PC0 за ~41280 toggle-ов). Назначение —
озвучка сбора бонуса (`func_bonus_award` ×5). Имя `func_flash_video` сохранено
(историческое), комментарий в RDB **исправлен** на «звуковой эффект бипера».

## Звук боя: выстрелы и взрывы через TapeOut (PC0)

Поправка к прежнему выводу «игровой цикл молчит». Порт 00h (BSR PC0 = TapeOut) активно
используется в бою — это 1-битный бит-бэнг, а не тишина. Три источника переключений PC0:

| Источник | Роль | Что пишет в PC0 |
|---|---|---|
| `func_frame_sync @0x0147` (`lbl_0164`) | покадровая настройка бордюра/скролла/клавиатуры | `OUT 00h,88h` = SET PC0 каждый кадр |
| `func_beam_delay @0x1E2F` | синхронизация по лучу (вызовы из enemy-fire `0x43A3`, alien-обработки `0x4978` и др.) | `in 09h; rrc; ani 01h; out 00h` — бит счётчика ВИ53, затем `xra a; out 00h` (RESET) |
| `func_update_objects_06f6 @0x0698` | движение/отрисовка частиц таблицы `06F6` | `mov a,e; rrc; ani 01h; out 00h` = RESET PC0 на каждую живую частицу |

Частицы `06F6` — осколки/искры от попаданий: пачку сыпет `func_update_bullet_trail @0x4A84`,
когда счётчик попаданий `[478Bh]` доходит до `19h` (25). Пока частиц нет — PC0 держится
высоким (SET в `func_frame_sync`, сбросов нет) → тишина. Как только в бою появляются осколки
и работает `func_beam_delay`, PC0 щёлкает на аудиочастоте → короткий треск выстрела/взрыва.

**Живое подтверждение (io_trace, режим боя, окно ~1 с):** `OUT 00h` → `0x88`=60 (SET),
`0x00`=57 (RESET), `0x01`=41 (SET), `0x8A`=30 (SET PC2); импульсы SET→RESET идут парами с
шириной 40–130 T. В idle-трассе того же боя `0x00`-сбросов = 0 (PC0 не переключается → тихо).
Разница «0 против 57 сбросов» и есть момент, когда игра начинает озвучивать бой.

## Limitations / открытые вопросы

- **GAME OVER MIDI не валидировался измерением** через v06_emu (в отличие от title,
  где 7/7 OK). Формат идентичен, период-таблица та же — расхождение маловероятно,
  но формально не подтверждено прогоном `func_blink_toggle` с D=0xBC..0xCD.
- **SFX-параметры** (частота, длительность chirp) описаны формулой, не осциллограммой;
  реальная огибающая зависит от точного T-состояния цикла (здесь ~16 T/итер. внутреннего
  B-цикла, грубо).
- **Точная тембральная модель звука боя** не строилась: доказан сам факт аудиомодуляции
  PC0 (число RESET/SET и ширина импульсов из io_trace), но спектр/громкость выстрела vs
  взрыва осциллографом не измерялись. `func_update_objects_06f6` пишет в PC0 бит7 координаты
  X (для живых частиц X<78h → всегда 0 = RESET); звуковой рисунок даёт совокупность SET из
  `func_frame_sync`/`func_beam_delay` и RESET из этих же функций и из частиц.

# Stage 9b — музыка УРОВНЯ RISE OUT: дескриптор трека #2, темп, дорожки, карта портов

Это **спецификация формата внутриигровой мелодии**. Формат байта дорожки, таблица периодов и
природа тон-генератора подробно разобраны в `reports/Stage9a_music_spec.md` (Stage 9a) и здесь
**не дублируются**: ниже фиксируется только то, что на уровне отличается, — способ переключения,
адреса партитур, темп, состав голосов и фактическое использование кодов. Машина-читаемая версия —
`tools/music_spec_level.json` (schema `v06c-music-spec/1`).

Все адреса — в карте памяти ROM (`org 0x0100`, образ 20480 байт, sha256
`c265014b…5a6991`). Все числа получены через MCP-отладчик (дизассемблирование, чтение RAM, I/O-трасса),
частично на живом экране уровня; самостоятельное декодирование оп-кодов не применялось.

---

## 1. Как мелодия уровня включается

Мелодический движок **не переключается** — переключается **трек**. Один и тот же шагатель
`func_irq_music_step @0x2EFB` (алиасы `func_music_driver_title` / `func_music_driver_level`)
крутит и заставку, и игру; разницу вносит только загрузчик.

```
func_player_session @0x08EF … @0x095F
   CALL func_start_new_level 0x1FAD          @0x0962
   MVI A,02h                                  (номер фоновой мелодии = 2)
   CALL func_music_start 0x2D7A               @0x0964  -> возврат на 0x0967
       DI; PUSH PSW; MVI A,C3h; STA 04EE; LXI H,2EFBh; SHLD 04EF; POP PSW; EI
       CALL func_music_load_track 0x2E2E       @0x2D89
       XRA A; STA 7DE1                         @0x2D8C/0x2D8D  (сброс стража шага)
```

* **Слот ISR** монтируется/демонтируется самомодификацией: `0x04EE = C3 FB 2E` (`JP 0x2EFB`) —
  включает музыку; `func_music_stop @0x2D72` возвращает туда `C9h` (`RET`).
* **Разбор номера трека — не таблица указателей**, а три зашитых в тело загрузчика блока
  (`CPI 01h/02h/03h` + `JZ` @0x2E37..0x2E43). Трек #2 (уровень) → блок @**`0x2E6C`**.

**Живое доказательство** (не статика): останов по breakpoint на `0x2D8C` (сразу после возврата
загрузчика) на экране уровня дал `HL = BC = 0x3112`, `DE = 0x30D2`, `A = 0x0D` — ровно базы трека #2.
Отдельный breakpoint на `0x2EFB` во время геймплея: `PC = 0x2EFB`, `SP = 0x00E4`,
`[SP] = 0x04E4` (адрес возврата того самого `CALL 0x04EE @0x04E1`), ниже на стеке `0x096A / 0x091C` —
кадр игрового сеанса. Пункт «в игре играет именно через 0x2EFB» (ранее I1) этим **закрыт**.

## 2. Дескриптор трека #2 = `data_music_scores_level @0x2E6C`

Блок `0x2E6C..0x2E90` (37 байт). Объект RDB заведен размером **9** — ровно как у заставки
(`data_music_scores_title @0x2E46` = 9): в размер входит только часть с тремя `LXI`, хвост параметров
описан комментарием, чтобы не перекрывать следующий дескриптор (`0x2E91`, трек #3 — финал).

| адрес | код | поле | значение уровня | аналог заставки |
|---|---|---|---|---|
| `0x2E6C` | `21 12 31` | `LXI H,3112h` — база voice1 | `0x3112` | `0x4E23` |
| `0x2E6F` | `01 12 31` | `LXI B,3112h` — база voice2 | `0x3112` | `0x4CC4` |
| `0x2E72` | `11 D2 30` | `LXI D,30D2h` — база voice3 | `0x30D2` | `0x4FB4` |
| `0x2E75` | `AF` | `XRA A` | 0 | — |
| `0x2E76` | `32 CD 7D` | `STA 7DCD` — гейт voice1 | **`0x00`** (голос выключен) | `0x1F` |
| `0x2E79` | `32 D8 7D` | `STA 7DD8` — гейт voice2 | **`0x00`** (голос выключен) | `0x1F` |
| `0x2E7C` | `3E 0A` | `MVI A,0Ah` | 10 | `0x0E` |
| `0x2E7E` | `32 E0 7D` | `STA 7DE0` — гейт voice3 | **`0x0A`** | `0x0E` |
| `0x2E81` | `3E 0C` / `32 D6 7D` | `STA 7DD6` | `0x0C` | `0x0C` |
| `0x2E86` | `3E 09` / `32 CF 7D` | `STA 7DCF` | `0x09` | `0x09` |
| `0x2E8B` | `3A BE 7D` | `LDA 7DBE` — темп | `0x05` | `0x03` |
| `0x2E8E` | `C3 B4 2E` | `JMP 2EB4h` — общая установка | — | — |

Общий хвост `0x2EB4..0x2EFA`: `STA 7DC3` (темп-делитель), `INX H/INX B/INX D`? — нет: `SHLD 7DC5`,
`SHLD 7DC7`, `SHLD 7DD0`, `SHLD 7DD2`, `SHLD 7DDA`, `SHLD 7DDC` (пара «база + указатель» на голос),
`MVI A,01` → `STA 7DCB / 7DC9 / 7DD4 / 7DDE`, гашение каналов командами `0x0C/0x0D`, `EI; RET`.

**Ни одного поля «адрес таблицы периодов» в дескрипторе нет** — см. §5.

## 3. Темп уровня: `[0x7DC3] = 5` (было 3)

Цепочка происхождения (полностью найдена, имя `var_music_tempo_level @0x7DBE`):

```
func_start_new_level 0x1FAD:
    LXI H,0305h     @0x1FF7
    SHLD 7DBEh      @0x1FFA   => [0x7DBE] = 05 (младший байт = темп), [0x7DBF] = 03 (старший)
func_music_load_track 0x2E2E (дескриптор #2):
    LDA 7DBE        @0x2E8B
    ... STA 7DC3    @0x2EB4   => [0x7DC3] = 05
func_irq_music_step 0x2EFB:
    LDA 7DC3 @0x2F20 / STA 7DCB @0x2F23     (перезагрузка кадрового делителя)
```

* `1 шаг музыки = [0x7DC3] кадров VBlank`. VBlank = 50 Гц (`RST 7`) ⇒ **шаг = 5 × 20 мс = 100 мс**
  (на заставке 3 × 20 = 60 мс).
* Ступенька ноты в каждом воркере — константа `MVI A,02h` (`0x2D9E/0x2F3E/0x2FB4`) ⇒ **нота = 2 шага = 200 мс**
  (заставка: 120 мс). Уровень **в 1,667 раза медленнее** заставки.
* `LXI H,0305` — единая константа на оба темпа: `0x05` идёт уровню, `0x03` лежит в старшем байте и
  его же («3») читает трек #3 (финал) через `LDA 7DBF`. То есть темп финала = темп заставки, а уровень —
  единственный, кто использует `0x05`.
* Темп **не зависит от номера уровня**: значение — константа в коде, а не из таблицы уровней.
* В MIDI: `ppq = 96`, `step_ticks = 24` ⇒ четверть = 4 шага ⇒ **`tempo_us_per_quarter = 400 000` мкс
  (150 BPM)**; на заставке было 240 000 (250 BPM при том же `step_ticks`).

## 4. Дорожки уровня

| голос | счётчик / порт данных | база (RAM-пара) | адрес дорожки | длина | звучит? |
|---|---|---|---|---|---|
| voice1 `0x2D94` | cnt0 / `0x0B` (CW `0x36`) | `[0x7DC5]` база, `[0x7DC7]` указатель | `0x3112` | **1** (`00h`) | **нет** |
| voice2 `0x2F34` | cnt1 / `0x0A` (CW `0x76`) | `[0x7DD0]` база, `[0x7DD2]` указатель | `0x3112` | **1** (`00h`) | **нет** |
| voice3 `0x2FA6` | cnt2 / `0x09` (CW `0xB6`) | `[0x7DDA]` база, `[0x7DDC]` указатель | `0x30D2` | **65** | **да** |

* voice1 и voice2 **выключены дважды**: гейт `0x00` (воркер выходит на `LDA gate / ORA A / RZ`
  @0x2D94..0x2D96 и @0x2F34..0x2F38) и нулевая длина потока (оба `LXI` указывают на `0x3112` —
  это байт-терминатор `00h` мелодии voice3). Поэтому в RDB у них **один объект на два голоса**
  (`data_music_track_level_01`, алиас `data_music_track_level_02`) — правило «один адрес = один объект».
* **Мелодия уровня монофонична**: одна линия, 64 кода, без аккомпанемента.
* Диапазон потока: `0x30D2..0x3112` (65 байт, включая терминатор). `0x3113` — свободный байт,
  с `0x3114` начинается `data_glyph_block` (1024 байт глифов) — то есть дорожка уровня «прижата»
  к таблице периодов (`0x301C + 182 = 0x30D2`) и к логотипу, это один плотный блок данных.
* Источник байтов: **`image`** (не `runtime`) — см. §7 «отклонение от ТЗ».

Дамп дорожки (живое чтение `debug_read_memory_range(0x30D2, 65)`; совпало с образом побайтово):

(16-ричные коды; последний `00h` — терминатор цикла @`0x3112`.)

## 5. Что уровень реально использует из формата

Формат байта (полностью — в Stage 9a): `00h` = цикл к базе; бит7=1 = холд `(младший ниббл × 2)` шагов;
`0xE0..0xEF` = inline-команда (только voice1); иначе — индекс слова-периода.

На уровне использованы **только** «нота» и «цикл»:

| элемент формата | встречается в дорожке уровня? | доказательство |
|---|---|---|
| код ноты (бит7=0, индекс таблицы) | **да**, 64 шт. | все байты дампа ≤ `0x41` |
| `00h` цикл | **да**, 1 шт. @`0x3112` | дамповый хвост |
| холд `80h..FFh` | **нет** | `max(bytes) = 0x41`, бит7 нигде не взведён |
| inline-команда `E0h..EFh` | **нет** (+ голос и так выключен) | то же неравенство |
| рест (слово таблицы = `0000h`) | **нет** | нулевые слова в таблице — индексы `0, 56, 66, 90`; использованные индексы `2..65` их не содержат; `rest_code 56` в дорожке не встречается |

Итоговая партитура уровня = **64 ноты длительностью ровно 2 шага (200 мс), легато, без пауз и без
удержаний**, зацикленные на себя (`12,8 с` на круг).

**Использованные коды → частоты** (период из `0x301C`, `port = 12 × период`, `f = 1 497 600 / port`):

| код | период | port | f, Гц | MIDI | нота | отклонение от РТ, ц |
|---|---|---|---|---|---|---|
| `0x3A` 58 | 1700 | 20400 | 73.41 | 38 | D2 | −0.10 |
| `0x2F` 47 | 1430 | 17160 | 87.27 | 41 | F2 | −0.68 |
| `0x3E` 62 | 1604 | 19248 | 77.81 | 39 | D#2 | +0.53 |
| `0x3F` 63 | 1349 | 16188 | 92.51 | 42 | F#2 | +0.27 |

| `0x41` 65 | 1071 | 12852 | 116.53 | 46 | A#2 | −0.21 |

(код `2` встречается 8 раз). Остальные 12 кодов укладываются в ±4 ц.

## 6. Таблица периодов — одна на все треки

Уровень использует **ту же** `data_note_freq_table_title @0x301C` (182 байта, 91 слово), объект
дополнен алиасами `data_note_freq_table_shared` / `data_note_freq_table_level`. Доказательства:

1. **Статика:** в дескрипторах треков нет поля «таблица»; таблица монтируется на `HL` константой
   `LXI H,301Ch` в теле самих воркеров — `@0x2DDC` (voice1), `@0x2F5C` (voice2), `@0x2FD2` (voice3).
2. **Живой RAM:** `debug_read_memory_range(0x301C, 182)` на экране уровня совпало **слово в слово**
   со снимком заставки и с образом ROM.
3. **Живая I/O-трасса:** встреченные значения счётчика `cnt2` — `0x27D8 = 10200` и `0x2F7C = 12156` —
   равны `12 × 850` (код `0x36`) и `12 × 1013` (код `0x34`); оба кода стоят в дорожке уровня на
   индексах 59..63, что согласуется с наблюдением указателя `[0x7DDC] = 0x3111` (смещение 63) и его
   возвратом на базу `0x30D2` после `00h`.

Новая/дополнительная таблица периодов для уровня **не заведена** — заводить было бы вымыслом.

## 7. Отклонение от «идеализированного ТЗ»: партитура уровня НЕ разворачивается в RAM

ТЗ (§ Stage 9b) предполагает, что «партитура уровня разворачивается в RAM по ходу игры — нужен живой
эмулятор на уровне», и требует `music2midi --runtime` + `source: runtime`. Наблюдение это **опровергает**:

* базы дорожек, смонтированные загрузчиком, — **адреса ROM-образа** (`0x30D2`, `0x3112`), не RAM;
  RAM-переменные `[0x7DDA]/[0x7DDC]` содержат именно эти значения и только шагают по диапазону;
* `debug_read_memory_range(0x30D2, 65)` на живом уровне == `riseout.rom[0x2FD2:0x3013]` (смещение
  `addr − org`) — **побайтово идентично**;
* в диапазоне `0x30D2..0x3112` нет ни одной записи (ROM-область, `0x0100..0x50FF`), самомодификации
  музыки там нет — в отличие от патча слота `0x04EE..0x04F0` в `$0060`-области кода.

Следовательно честный `source` для дорожек — **`image`**. Runtime-часть уровня существует, но она
маленькая и это **не ноты**: темп `[0x7DBE]→[0x7DC3]`, гейты `[0x7DCD/0x7DD8/0x7DE0]`, служебные
`[0x7DCF]/[0x7DD6]` и текущие указатели чтения. Именно поэтому в `provenance.verified_by` записано
«трек прочитан из RAM», а в `tracks[].source` — `image`: байты взяты живым чтением, но их истинное
хранилище — образ.

Практическое следствие для команды: при `source: image` у всех дорожек `music2midi` **не открывает
MCP-сессию** (`mcp_calls=0` в вердикте) — флаг `--runtime` остаётся разрешающим, но не востребованным.
Это правильно: собственная сессия конвертера стартует ROM с заставки (`debug_load_rom`) и прочла бы
окно `0x30D2..0x3112` в состоянии, которое уровню не соответствует; для статического блока разницы нет,
но подмены состояния допускать нельзя (ТЗ §17).

## 8. Карта портов на уровне

| порт | назначение | активность на уровне |
|---|---|---|
| `0x08` | КР580ВИ53 управляющее слово | CW `0xB6` при ресте/one-shot — на уровне рестов нет; CW видится только в инициализации трека (`0x0C/0x0D` гашение каналов загрузчиком) |
| `0x0B` | cnt0 / voice1 | **записей от музыки нет** (гейт 0, поток нулевой) |
| `0x0A` | cnt1 / voice2 | **записей от музыки нет** (гейт 0, поток нулевой) |
| `0x09` | cnt2 / voice3 | **единственный звучащий**: `OUT 0x09,lo; OUT 0x09,hi` = `12 × период`; в трассе `0xD8,0x27` и `0x7C,0x2F` |

Путь записи: `0x2FA6` → `CALL func_music_sound_cmd 0x2F30` → `func_sound_cmd_dispatch 0x0206`
(таблица переходов `0x0217`) → `cmd4/cmd5` → `STA 0x03CB/0x03CC` → `CALL 0x0298` → `CALL 0x0258` (×12)
→ `OUT 0x09`. Значения `A = 0x04/0x05/0x09/0x0A/0x0C/0x0D` в коде — **индексы команд**, а не номера
портов: порты выбираются обработчиком `0x0206`.

Фоновый шум трассы (не музыка, а цикл ввода/видео): на каждый кадр приходится `OUT 0x03,маска` +
`IN 0x02`, `OUT 0x00,0x8A/0x88`, `OUT 0x01,0x02`, `OUT 0x03,0x00`, `OUT 0x02,0x00`.

| `tracks[].vi53.ram` | `base/ptr/slot/gate` пары | `SHLD 7DC5/7DC7/7DD0/7DD2/7DDA/7DDC` в хвосте `0x2EB4` |
| `tracks[].gm_program` | `82 / 80 / 81` | художественное решение, повторено за заставкой, чтобы сравнение двух MIDI было честным |

`expect`-дампы сверяются конвертером побайтово; прогон завершился вердиктом `DERIVED` без расхождений.

## 10. Заставка vs уровень — сводка отличий

| параметр | заставка (трек #1) | уровень (трек #2) |
|---|---|---|
| драйвер | `0x2EFB` | **тот же** `0x2EFB` (алиас) |
| дескриптор | `0x2E46` | `0x2E6C` |
| темп `[0x7DC3]` | 3 → шаг 60 мс | **5 → шаг 100 мс** |
| нота (2 шага) | 120 мс | **200 мс** |
| voices | 3 (v1 401, v2 351, v3 259 байт) | **1** (v3 65 байт; v1/v2 — заглушки по 1 байту) |
| гейты | `0x1F / 0x1F / 0x0E` | **`0x00 / 0x00 / 0x0A`** |
| полифония | 3 голоса, стаккато у v1 | **моно** |
| таблица периодов | `0x301C` | **та же** `0x301C` |
| холды / команды / ресты | есть все три | **нет ничего** |
| длина цикла | ~48 с (MIDI) | **12,8 с** (3072 тика) |
| диапазон высот | MIDI 33..84 | **MIDI 38..55** (D2..G3) |
| количество нот | 563 | **64** |

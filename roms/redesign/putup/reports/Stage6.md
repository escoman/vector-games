# Stage 6. Исследование главного игрового цикла

## Цель

Найти цикл ожидания нажатия на пробел, исследовать код после него (отрисовка уровней, спрайты, тайлы), найти главный игровой цикл и отметить его в RDB.

## ROM

- Файл: `./src/putup.rom`
- Размер: 17664 байт
- Адрес загрузки: 0x0100

## Поток выполнения: от запуска до главного цикла

```
rom_entry (0x0100)
  └→ rom_init (0x0B57)
       ├→ DI; SP=0x0100; Clear RAM 0x8000-0xFFFF
       ├→ CALL init_1 (0x0383)         — настройка векторов прерываний
       ├→ CALL init_2 (0x0401)         — инициализация графики
       ├→ CALL init_objects (0x3D4E)   — инициализация объектов ISR
       ├→ [Инициализация переменных]
       ├→ CALL obj_setup (0x1BE5)      — ★ ЗАСТАВКА: загрузка данных + ожидание ПРОБЕЛА
       │    ├→ Заполнение 0x5000 (1024 байт)
       │    └→ Цикл ожидания: MVI A,20; CALL kbd_input_handler; JNZ loop
       │
       ├→ [Инициализация 128 объектов из ROM-таблицы]  ← ПОСЛЕ ПРОБЕЛА
       ├→ [Загрузка 6 блоков данных уровней в RAM]
       ├→ data_process_loop (0x0C65)   — отрисовка стартового экрана
       └→ JMP game_main_loop (0x197C)  — ★ ГЛАВНЫЙ ИГРОВОЙ ЦИКЛ
```

## 1. Цикл ожидания пробела

**Адрес:** 0x1BEE–0x1BF6 (внутри `obj_setup`, 0x1BE5)

```
1BEE: MVI A, 20        ; A = 0x20 (код клавиши «Пробел»)
1BF0: CALL 01A1        ; kbd_input_handler — сканирование клавиатуры
1BF3: DCX B            ; BC-- (таймаут-счётчик, изначально 0x0400)
1BF4: MOV A, C         ; \
1BF5: ADD M             ;  проверка: C + [HL] == 0?
1BF6: JNZ 1BEE         ; / если нет → повтор
1BF9: RET              ; пробел нажат → выход из obj_setup
```

**RDB:** `obj_setup` (0x1BE5), обновлён.

## 2. Код после нажатия пробела

### 2.1. Инициализация 128 объектов (0x0BEA–0x0C15)

После возврата из `obj_setup`, `rom_init` инициализирует 128 игровых объектов:

```
0BEA: LXI H, 0986     ; HL = таблица типов объектов в ROM (128 байт)
0BED: LXI D, 0000     ; DE = 0 (D=группа, E=слот)
0BF0: LXI B, 0080     ; BC = 128 (счётчик)

Цикл (0x0BF3–0x0C15):
  ├─ A = [HL]               ; тип объекта из ROM-таблицы
  ├─ LXI H, 2706            ; таблица спрайтов
  ├─ CALL sub_032C          ; lookup: A → значение из таблицы
  ├─ CALL obj_copy_data     ; копирование данных объекта
  ├─ D += 2; if D >= 0x20: D=0, E += 2
  └─ HL++; BC--; loop
```

**Таблица типов объектов** (ROM 0x0986, 128 байт):
- Значения: 1, 2, 6, 8
- Первые 17 байт: тип 2 (фон/стены)
- Байты 17–31: тип 1 (объекты)
- Байты 32–79: тип 1
- Байты 80–127: типы 2, 6, 8 (разнообразные объекты)

**Таблица спрайтов** (ROM 0x2706):
- Индексируется по типу объекта
- Содержит tile-ID для отрисовки

### 2.2. Загрузка блоков данных уровней (0x0C18–0x0C62)

После инициализации объектов загружаются 6 блоков данных в RAM:

| # | ROM-адрес | RAM-адрес | Описание |
|---|-----------|-----------|----------|
| 1 | 0x0A06 | 0x50A0 | Тайлы карты (значения 0x20, 0x9B) |
| 2 | 0x0AC7 | 0x5229 | Данные обработки |
| 3 | 0x0AD6 | 0x5287 | **Текстовые строки** (см. ниже) |
| 4 | 0x0AE9 | 0x506B | Данные обработки |
| 5 | 0x08EB | 0x506E | Данные обработки (через sub_0331) |
| 6 | 0x0925 | 0x52E0 | Данные обработки |

Каждый блок: `CALL 014F` (сохранить HL) → `CALL 0321` (data_dispatch).

### 2.3. Текстовые строки (ROM 0x0AD6)

По адресу 0x0AD6 обнаружены текстовые строки, разделённые 0xFF:

```
FF "MSX MEGA ZINE, 1987" FF "HI " FF "SCORE " FF "ROUND "
FF "TIME " FF " HURRY UP !" FF "GAME OV..."
```

Это строки интерфейса/заставки игры. Загружаются в RAM 0x5287.

### 2.4. Отрисовка стартового экрана (data_process_loop, 0x0C65)

```
0C65: LXI B, 0C00     ; счётчик
0C68: XRA A; PUSH B
0C6A: CALL dec_mod8   ; A = (A-1) mod 8
0C6D: POP B
0C6E: CMP M            ; проверка маркера
0C6F: JNZ 0C9D         ; если не совпадает → переход

Сканирование 0x5180 (32 байта):
0C7D: MOV A, M
0C7E: CPI 75           ; маркер 0x75?
0C80: JZ 0C90          ; → загрузить данные FE
0C83: CPI FE           ; маркер 0xFE?
0C85: JNZ 0C95         ; → пропустить
0C88: MVI A, 75; CALL data_read_loop  ; отрисовка
0C90: MVI A, FE; CALL data_read_loop  ; отрисовка
```

Завершается: `CALL sub_3DCD; JMP game_main_loop (0x197C)`.

## 3. Главный игровой цикл (game_main_loop, 0x197C)

**RDB:** `game_main_loop` (0x197C), обновлён с полным описанием.

### Структура цикла

```
197C: LXI H, 08F5
197F: INR M              ; frame_counter++
1980: MOV A, M
1981: CPI 10             ; frame_counter >= 16?
1983: JNC 1A3B           ; → сброс (перезапуск цикла)

1986: XRA A
1987: STA 090F           ; [0x090F] = frame_counter
198A: LXI H, 1C0E        ; таблица frame_obj_data_1
198D: LDA 08F5           ; A = frame_counter
1990-1992: RLC × 3       ; A *= 8
1993: MOV E, A; MVI D, 0
1996: DAD D              ; HL += offset (индекс в таблице)

1997: LXI D, 0911        ; целевой адрес в RAM
199A: LXI B, 0008        ; 8 байт
199D: CALL mem_copy       ; копирование 8 байт из ROM → RAM

19A0: LXI SP, 0100       ; сброс стека
19A3: CALL obj_setup     ; ★ снова ожидание пробела!
19A6: LDA 08F5; DCR A
19AA: LXI H, 1C8E        ; таблица frame_obj_data_2

19AD: JZ 19B8            ; если frame_counter-1 == 0
19B0: LXI D, 00B0        ; шаг 0x00B0
19B3: DAD D; DCR A
19B5: JNZ 19B3           ; цикл: HL += 0x00B0 * (A-1)

19B8: LXI D, 0000; LXI B, 00B0
19BE-19E0: Object init loop (176 итераций)
  ├─ A = [HL] (тип объекта)
  ├─ CALL sub_032C (lookup)
  ├─ CALL obj_copy_data
  └─ D += 2; wrap at 0x20

19E3: CALL player_control  (0x1197)  ; ★ управление игроком
19E6: CALL enemy_control   (0x11E9)  ; ★ управление врагами
19E9: MVI A, 10; STA 091E           ; [0x091E] = 0x10
19EE: CALL hud_update      (0x121A)  ; ★ обновление HUD
19F1: MVI A, 01                     ; [0x091E] = 1
```

### Ключевые подфункции главного цикла

| Адрес | Имя | Назначение |
|-------|-----|------------|
| 0x1197 | `player_control` | Управление игроком: загрузка данных из 0x52E1, обработка ROM-данных, расчёт позиции, ожидание клавиши 0x30 |
| 0x11E9 | `enemy_control` | Управление врагами: итерации x2, чтение [0x08FB], загрузка данных из 0x52F9, ожидание клавиши 0x8A |
| 0x121A | `hud_update` | Обновление HUD: обработка объектов 0x52F2/0x52EF/0x5302/0x5307, ROM-данные из 0x0AF4/0x0AFB, отрисовка тайла 0x9B |
| 0x1BC9 | `mem_copy` | Копирование BC байт из [HL] в [DE] |

| Адрес | Имя | Размер | Описание |

| 0x0986 | `obj_type_table` | 128 | Таблица типов объектов (1,2,6,8) |

## 4. Схема главного игрового цикла

```
┌─ game_main_loop (0x197C) ──────────────────────────────┐
│                                                         │
│  frame_counter++ [0x08F5]                               │
│  │                                                      │
│  ├─ if >= 16: → сброс SP, CALL obj_setup (ПРОБЕЛ),     │
│  │              reinit 128 объектов из obj_type_table   │
│  │                                                      │
│  ├─ Индексация frame_obj_data_1/2 по frame_counter*8    │
│  ├─ Копирование 8 байт через mem_copy                   │
│  ├─ Object init loop (176 объектов)                     │
│  │                                                      │
│  ├─ CALL player_control (0x1197)  ← управление игроком  │
│  ├─ CALL enemy_control  (0x11E9)  ← управление врагами  │
│  ├─ CALL hud_update     (0x121A)  ← обновление HUD     │
│  │                                                      │
│  └─ JMP back to start ─────────────────────────────────┘
```

## Verified Facts

1. Цикл ожидания пробела: 0x1BEE–0x1BF6, код клавиши 0x20 — подтверждено дизассемблированием
2. 128 объектов инициализируются из ROM-таблицы 0x0986 — подтверждено циклом 0x0BF3–0x0C15
3. 6 блоков данных загружаются в RAM 0x5000-область — подтверждено последовательностью CALL
4. Текстовые строки "MSX MEGA ZINE, 1987", "HI", "SCORE" и др. по адресу 0x0AD6 — подтверждено чтением памяти
5. game_main_loop (0x197C) — главный игровой цикл с frame_counter, подтверждено дизассемблированием
6. player_control (0x1197), enemy_control (0x11E9), hud_update (0x121A) — вызывается каждый кадр

## Inferences

1. Игра работает с 16-кадровым циклом: каждый кадр обновляет определённый набор из 8 объектов
2. После 16 кадров цикл перезапускается (сброс SP, повторное ожидание пробела, reinit)
3. Объекты имеют типы (1, 2, 6, 8), определяющие их поведение и спрайт
4. Таблицы frame_obj_data содержат параметры обновления объектов для каждого кадра
5. Player и enemy управляются отдельными функциями, вызываемыми последовательно

## Unknowns

1. Точная структура объектов в RAM (размер, формат полей)
2. Механизм коллизий и взаимодействия игрока с врагами
3. Как tile-ID (0x20, 0x9B) преобразуются в графику
4. Полное содержание ROM-таблиц 0x0AC7, 0x0AE9, 0x0925
5. Функция sub_0355 (вызывается из load_de_dispatch) — обработка координат

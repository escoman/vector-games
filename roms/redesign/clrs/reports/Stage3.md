## 1. Обзор программы

Программа «clrs» — минималистичный демо-эффект циклической смены палитры через VBlank ISR.  
Код занимает 119 байт (0x0100–0x0176) и состоит из:
- 4 функций (исполняемый код)
- 1 вектора прерывания в RAM (0x0038)
- 1 области данных на стеке (0x055A–0x0578)

**Точка входа:** 0x0000 (монитор ROM) → переход на 0x0100 (пользовательский код).  
**Mapping entry point:** 0x0100.

## 2. Детальный разбор функций

### 2.1. `func_setup_and_halt` — 0x0100 (63 байта, 31 инструкция)

**Предыдущее имя:** `func_init_main`  
**Новое имя:** `func_setup_and_halt`  
**Назначение:** Инициализация VRAM, настройка RST 7 вектора, заполнение стека палитры, настройка видеорежима и вход в HLT-цикл ожидания прерываний.

#### Дизассемблированный код

```asm
; === Фаза 1: Запрет прерываний ===
0x0100  DI                  ; Запрет прерываний на время инициализации

; === Фаза 2: Очистка VRAM (8000h-FFFFh) ===
0x0101  LXI H, 8000h        ; HL = начало VRAM (plane 3)
0x0104  MVI M, 00h          ; [HL] = 0 — очистка байта
0x0106  INR L               ; L++ (следующий байт в строке)
0x0107  JNZ 0104h           ; повтор, пока L ≠ 0 (256 байт)
0x010A  INR H               ; H++ (следующая строка/плоскость)
0x010B  JNZ 0104h           ; повтор, пока H ≠ 0 (все 256 строк × 4 плоскости)

; === Фаза 3: Установка вектора RST 7 ===
0x010E  MVI A, C3h          ; A = C3h (opcode JP)
0x0110  STA 0038h           ; [0x0038] = C3h
0x0113  LXI H, 013Fh        ; HL = адрес ISR (func_isr_delay_and_setup)
0x0116  SHLD 0039h          ; [0x0039-003A] = 013Fh

; === Фаза 4: Инициализация стека палитры ===
0x0119  LXI SP, 0577h       ; SP = 0x0577 (вершина стека палитры)
0x011C  LXI H, 0172h        ; HL = адрес func_isr_rearm_and_exit
0x011F  PUSH H              ; [SP] = 0172h — «якорь» ISR-возврата
0x0120  LXI H, 0152h        ; HL = адрес func_isr_palette_cycle
0x0123  MVI A, F8h          ; A = F8h (начальный цвет палитры)
0x0126  MVI B, 07h          ; B = 7 (счётчик)
0x0128  PUSH H              ; [SP] = 0152h (адрес возврата для RET)
0x0129  PUSH PSW             ; [SP] = AF (цвет F8h + флаги)
0x012A  DCR B               ; B--
0x012B  JNZ 0128h           ; повтор 7 раз

; Цикл арифметической добавки (4 итерации)
0x012E  MVI B, 08h          ; B = 8 (новый счётчик)
0x0130  ADD D               ; A = A + D (D=01h, A растёт: F9→FA→FB→FC)
0x0131  JNC 0128h           ; если нет переноса → ещё PUSH
0x0134  CMP L               ; сравнение A с L (52h)
0x0135  OUT 02h             ; вывод в порт 02h (border/video mode)

; === Фаза 5: Вход в HLT-цикл ===
0x0137  LXI SP, 0100h       ; SP = 0x0100 (безопасная зона ниже кода)
0x013A  EI                  ; разрешение прерываний
0x013B  HLT                 ; ожидание VBlank
0x013C  JMP 013Bh           ; ← ДОБАВЛЕНО: возврат на HLT после RET из ISR
```

#### Построчный анализ

**Фаза 2 — Очистка VRAM:**
- `LXI H, 8000h` — HL указывает на начало VRAM (plane 3, MSB).
- Внутренний цикл (`MVI M,00 / INR L / JNZ`) обнуляет 256 байт (L от 00 до FF, переход при L≠0).
- `INR H` — переход к следующей 256-байтной строке.
- Внешний цикл (`JNZ 0104h`) продолжается, пока H≠0. H начинается с 0x80, инкрементируется до 0x00 (переполнение после 0xFF).
- **Результат:** 32 КБ (0x8000–0xFFFF) очищены нулями.
- **Регистры:** HL — указатель, M — временный.

**Фаза 3 — Вектор RST 7:**
- `MVI A, C3h / STA 0038h` — записывает opcode JP по адресу 0x0038.
- `LXI H, 013Fh / SHLD 0039h` — записывает адрес ISR (0x013F) по адресам 0x0039–0x003A.
- **Результат:** 0x0038 = `C3 3F 01` = `JP 013Fh`. При VBlank CPU выполнит RST 7 → JP 013Fh.
- **Регистры:** A — временный, HL — адрес ISR.

**Фаза 4 — Стек палитры:**
- `LXI SP, 0577h` — SP указывает на вершину стека палитры.
- `PUSH H` (HL=0172h) — «якорь»: адрес func_isr_rearm_and_exit. Будет использован как первый RET-адрес.
- `LXI H, 0152h` — HL = адрес func_isr_palette_cycle (будет PUSH как RET-адрес для каждого цвета).
- `MVI A, F8h` — начальный цвет палитры.
- `MVI B, 07h` — счётчик 7.
- **Цикл 1** (7 итераций): `PUSH H / PUSH PSW / DCR B / JNZ` — помещает на стек 7 пар (0152h, AF).
  - Все 7 значений AF = F8h (A не меняется в цикле).
  - Stack: SP от 0x0577 → 0x0569 (12 слов = 24 байта вниз, включая PUSH H в начале).
- **Цикл 2** (4 итерации): `ADD D / JNC 0128h`.
  - D = 01h (установлен при загрузке ROM, не изменялся).
  - Каждая итерация: A += 1, затем PUSH H + PUSH PSW.
  - Итерация 1: A=F9h, PUSH (0152h, F9h). Итерация 2: A=FAh. Итерация 3: A=FBh. Итерация 4: A=FCh, перенос → выход.
  - **Важно:** `JNC` — переход если Carry=0. ADD D с A=FCh+01h=FCh+01h... нет, A=FBh+01h=FCh (нет переноса → цикл). A=FCh+01h=FDh (перенос? Нет, FCh+01h=FDh, переноса нет). Подождите...

Давайте пересчитаем цикл 2 точно:
  - Перед циклом: A=F8h, D=01h.
  - Итерация 1: ADD D → A=F8h+01h=F9h, CY=0. JNC → да (переход на 0128h). PUSH (0152h, F9h). DCR B → B=7.
  - Итерация 2: ADD D → A=F9h+01h=FAh, CY=0. JNC → да. PUSH (0152h, FAh). DCR B → B=6.
  - Итерация 3: ADD D → A=FAh+01h=FBh, CY=0. JNC → да. PUSH (0152h, FBh). DCR B → B=5.
  - Итерация 4: ADD D → A=FBh+01h=FCh, CY=0. JNC → да. PUSH (0152h, FCh). DCR B → B=4.

Подождите, JNC переходит на 0128h если CY=0. ADD D никогда не даёт переноса (F8h+01h..FCh+01h — все без переполнения). Значит цикл будет продолжаться бесконечно?

Нет! Цикл прерывается, когда JNC **не** выполняется, т.е. когда CY=1. Это происходит при A+D ≥ 256. Но A растёт на 1 каждый раз: F9, FA, FB, FC, FD, FE, FF, 00 (CY=1!).

Пересчитаем:
  - Итерация 1: A=F8h+01h=F9h, CY=0 → JNC да → PUSH
  - Итерация 2: A=F9h+01h=FAh, CY=0 → JNC да → PUSH
  - Итерация 3: A=FAh+01h=FBh, CY=0 → JNC да → PUSH
  - Итерация 4: A=FBh+01h=FCh, CY=0 → JNC да → PUSH
  - Итерация 5: A=FCh+01h=FDh, CY=0 → JNC да → PUSH
  - Итерация 6: A=FDh+01h=FEh, CY=0 → JNC да → PUSH
  - Итерация 7: A=FEh+01h=FFh, CY=0 → JNC да → PUSH
  - Итерация 8: A=FFh+01h=00h, CY=1 → JNC нет → выход!

**8 итераций**, не 4! A проходит F9→FF→00, перенос на 8-й итерации.

**Итого на стеке:**
| # | PUSH H | PUSH PSW |
|---|--------|----------|
| «Якорь» | 0172h | — |
| 1–7 | 0152h ×7 | F8h ×7 |
| 8–15 | 0152h ×8 | F9h, FAh, FBh, FCh, FDh, FEh, FFh, 00h |

Всего: 1 + 7 + 8 = 16 PUSH H + 15 PUSH PSW = 31 слово = 62 байта.  
SP: 0x0577 → 0x0577 - 62 = 0x0577 - 3Eh = 0x0539.

**Подождите**, это не совпадает с предыдущим расчётом в 12 пар. Пересчитаем:
- PUSH H (0172h): 1 слово → SP = 0x0575
- Цикл 1 (7 итераций × 2 PUSH): 14 слов → SP = 0x0575 - 14×2 = 0x0575 - 28 = 0x055D
- Цикл 2 (8 итераций × 2 PUSH): 16 слов → SP = 0x055D - 16×2 = 0x055D - 32 = 0x053D

Итого SP = 0x053D после всех PUSH.

**Фаза 5 — Выход:**
- `CMP L` — сравнение A (00h) с L (52h). A≠L, Z=0.
- `OUT 02h` — вывод A (00h) в порт 02h. Порт 02h = Port B PIA1: биты 0–3 = border color (0 = чёрная рамка), бит 4 = видео-режим (0 = 256 столбцов).
- `LXI SP, 0100h` — SP перемещён в безопасную зону.
- `EI` — разрешение прерываний.
- `HLT` — CPU останавливается до следующего прерывания.
- `JMP 013Bh` — **обнаружено в Stage 3** (Stage 2 пропустил). После возврата из ISR (RET в 0x0176) CPU попадает на 0x013B → HLT → ожидание следующего VBlank.

#### Используемые регистры
| Регистр | Роль |
|---------|------|
| A | Цвет палитры (F8h→00h), opcode JP (C3h), вывод в порт 02h |
| B | Счётчик цикла 1 (7), счётчик цикла 2 (8→перенос) |
| D | Инкремент арифметики (01h), не изменяется в функции |
| H, L | Указатель VRAM (8000h→0000h), адрес ISR (013Fh), адрес palette_cycle (0152h), адрес rearm (0172h) |
| SP | 0577h → 053Dh → 0100h |
| Flags | CY=1 после последнего ADD D (выход из цикла 2) |

#### Ветвление
- `JNZ 0104h` — внутренний цикл очистки VRAM (256 итераций по L).
- `JNZ 0104h` — внешний цикл очистки VRAM (H от 80h до 00h, 128 итераций × 256 = 32768 байт).
- `JNZ 0128h` — цикл 1 PUSH (7 итераций по B).
- `JNC 0128h` — цикл 2 PUSH с арифметикой (8 итераций до переноса).
- `JMP 013Bh` — HLT-петля.

#### Обращения к данным
| Адрес | Тип | Инструкция | Описание |
|-------|-----|-----------|----------|
| 0x8000–0xFFFF | Write | MVI M, 00 | Очистка VRAM |
| 0x0038 | Write | STA 0038h | Запись opcode JP |
| 0x0039 | Write | SHLD 0039h | Запись адреса ISR |
| 0x055A–0x0576 | Write | PUSH H / PUSH PSW | Палитра на стеке |
| Порт 0x02 | Write | OUT 02h | Border color = 0, 256-кол. режим |

#### Итоговое назначение
Главная функция инициализации: очищает VRAM, настраивает RST 7 вектор на VBlank ISR, заполняет стек палитрой из 15 цветовых значений + адресов возврата, устанавливает видеорежим (256 столбцов, чёрная рамка) и входит в бесконечный HLT-цикл, пробуждаясь только для VBlank прерываний.

### 2.2. `func_isr_delay_and_setup` — 0x013F (19 байт, 10 инструкций)

**Предыдущее имя:** `func_isr_vblank`  
**Новое имя:** `func_isr_delay_and_setup`  
**Назначение:** Точка входа VBlank ISR. Выполняет цикл задержки (синхронизация с развёрткой), подготавливает регистры и стек, затем передаёт управление в func_isr_palette_cycle.

#### Дизассемблированный код

```asm
; === Цикл задержки ===
0x013F  LXI B, 00ECh        ; BC = 236 (счётчик)
0x0142  DCX B               ; BC--
0x0143  MOV A, B            ; A = B (старший байт BC)
0x0144  ADC M               ; A = A + [HL] + CY
0x0145  JNZ 0142h           ; повтор, пока A ≠ 0 (Z=0)

; === Пауза ===
0x0148  NOP                 ; 4 T-states
0x0149  NOP                 ; 4 T-states

; === Настройка регистров ===
0x014A  LXI B, 0703h        ; B=07h, C=03h
0x014D  MVI D, 01h          ; D = 01h
0x014F  LXI SP, 0177h       ; SP = 0x0177 (внутри func_isr_rearm_and_exit)

; === Передача управления (fall-through) ===
; → 0x0152 func_isr_palette_cycle
```

#### Построчный анализ

**Цикл задержки (0x013F–0x0145):**
- `LXI B, 00ECh` — BC = 0x00EC = 236.
- `DCX B` — декремент BC.
- `MOV A, B` — A = старший байт BC. Когда B=0, A=0.
- `ADC M` — A = A + [HL] + CY. Если [HL]=0 и CY=0, то A=0 → Z=1.
- `JNZ 0142h` — повтор пока Z=0 (A≠0).

**Условие выхода:** B=0 И ([HL]+CY)=0. Т.е. BC досчитало до 0x00xx, и байт памяти по адресу HL равен 0 (с учётом переноса).

**HL при входе в ISR:** HL = 0x0172 (установлен в func_setup_and_halt, не изменялся). Но после `LXI SP, 0177h` в предыдущем кадре... нет, это другая инструкция. При первом входе в ISR: HL=0x0172 (от func_setup_and_halt). Но при последующих входах HL может быть другим (зависит от того, что произошло в func_isr_palette_cycle — L используется в арифметике, но H не изменяется, оставаясь 0x01).

**Важно:** В func_isr_palette_cycle инструкция `POP PSW` изменяет A и флаги, а арифметика `SUB L / ADC L / ADD L` изменяет A, но не H. Таким образом H сохраняется как 0x01 между кадрами. L = 0x52 (установлен в func_setup_and_halt, не изменяется).

С HL=0x0172: [0x0172] = 0x31 (opcode LXI SP, 00FEh). Это не ноль, поэтому цикл задержки при первом входе проходит все 236 итераций и выходит, когда BC=0x0000 и [HL]≠0 → A = 0 + [0x0172] + CY. Если CY=0, A=0x31≠0 → Z=0 → JNZ продолжает цикл! Но B уже 0, DCX B → BC=0xFFFF, MOV A,B → A=0xFF≠0 → цикл продолжается.

**Фактически цикл завершается, когда BC проходит через 0x0000 и продолжает декрементироваться, пока не найдёт нулевой байт в памяти по сканируемому адресу HL (который тоже декрементируется косвенно через DCX B... нет, HL не декрементируется!).**

**Уточнение:** HL НЕ изменяется в цикле задержки. HL фиксирован. Цикл: DCX B / MOV A,B / ADC M / JNZ. A = B + [HL] + CY. Когда B=0: A = 0 + [HL] + CY. Если [HL]≠0, то A≠0, JNZ продолжается. DCX B → BC=0xFFFF, B=0xFF. MOV A,B → A=0xFF. Следующие итерации: B уменьшается до 0 снова. Это занимает 256 итераций на каждый «проход».

Цикл завершится, когда при B=0: [HL]+CY=0. При HL=0x0172: [0x0172]=0x31 (LXI opcode). CY зависит от предыдущего ADC. В общем, цикл завершается когда B=0 и [HL]=0 (при CY=0) или [HL]=FF (при CY=1, A=0+FF+1=0 с переносом).

**Это сканирование памяти в поисках нулевого байта с периодом 256 итераций.** Длительность задержки зависит от содержимого памяти по адресу HL, что создаёт зависимость timing от состояния RAM/стека.

**NOP NOP (0x0148–0x0149):**
- 8 T-states дополнительной задержки. Точная синхронизация с лучом (beam racing).

**Настройка регистров (0x014A–0x014F):**
- `LXI B, 0703h` — B=07h (7 оставшихся цветов для обработки после текущего), C=03h.
- `MVI D, 01h` — D=01h (инкремент для арифметики в func_isr_palette_cycle).
- `LXI SP, 0177h` — SP = 0x0177. Адрес 0x0177 — это байт СЛЕД за RET в func_isr_rearm_and_exit. При SP=0x0177, первый POP PSW прочитает 2 байта по адресу 0x0175–0x0176.

#### Используемые регистры
| Регистр | Роль |
|---------|------|
| A | Промежуточный в цикле задержки |
| B, C | Счётчик задержки (00ECh → 0703h) |
| D | Инкремент для palette_cycle (01h) |
| H, L | HL=0172h (не изменяется), L=52h используется в palette_cycle |
| SP | 0x0177 (позиционирование для POP PSW) |

#### Ветвление
- `JNZ 0142h` — цикл задержки (зависит от содержимого памяти).
- Fall-through на 0x0152 (func_isr_palette_cycle).

#### Обращения к данным
| Адрес | Тип | Инструкция | Описание |
|-------|-----|-----------|----------|
| [HL] | Read | ADC M | Чтение байта памяти в цикле задержки |

### 2.3. `func_isr_palette_cycle` — 0x0152 (32 байта, 23 инструкции)

**Предыдущее имя:** `func_palette_out`  
**Новое имя:** `func_isr_palette_cycle`  
**Назначение:** Вывод одного цвета палитры на порт 0Ch с генерацией 8 производных значений через арифметику. Вызывается из ISR для каждого цвета на стеке.

#### Дизассемблированный код

```asm
; === Загрузка цвета ===
0x0152  POP PSW              ; A = цвет со стека, флаги из стека
0x0153  ORA A                ; A = A OR A (обновление флагов, CY=0)
0x0154  ORA A                ; повтор (4 T-states задержка)
0x0155  ORA A                ; повтор (4 T-states задержка)
0x0156  NOP                  ; пауза (4 T-states)

; === Вывод цвета и производных ===
0x0157  OUT 0Ch              ; [1] Вывод A (исходный цвет)
0x0159  SUB L                ; A = A - L (CY=1 если A<L)
0x015A  OUT 0Ch              ; [2] Вывод A (уменьшенное)
0x015C  ADC L                ; A = A + L + CY (восстановление с учётом переноса)
0x015D  OUT 0Ch              ; [3] Вывод A
0x015F  SUB L                ; A = A - L
0x0160  OUT 0Ch              ; [4] Вывод A
0x0162  ADD L                ; A = A + L (CY=0 если нет переполнения)
0x0163  OUT 0Ch              ; [5] Вывод A
0x0165  SUB L                ; A = A - L
0x0166  OUT 0Ch              ; [6] Вывод A
0x0168  ADC L                ; A = A + L + CY
0x0169  OUT 0Ch              ; [7] Вывод A
0x016B  SUB L                ; A = A - L
0x016C  OUT 0Ch              ; [8] Вывод A

; === Завершение ===
0x016E  CMP L                ; A сравнить с L (флаги)
0x016F  OUT 0Ch              ; [9] Вывод A (9-й, после CMP)
0x0171  RET                  ; возврат (адрес со стека)
```

#### Построчный анализ арифметики

**Вход:** A = цвет (F8h..00h), L = 52h.

**ORA A ×3 + NOP:** 16 T-states задержка перед первым OUT. Это синхронизация с лучом — палитра должна быть записана в правильный момент развёртки.

**Последовательность OUT 0Ch (9 выводов за вызов):**

| # | Инструкция | Формула | Пояснение |
|---|-----------|---------|-----------|
| 1 | OUT 0Ch | A | Исходный цвет |
| 2 | SUB L | A - 52h | Уменьшенное (CY=1 если A < 52h) |
| 3 | ADC L | (A-52h) + 52h + CY | Восстановление: если CY=1 → A+1; если CY=0 → A |
| 4 | SUB L | A' - 52h | Уменьшенное |
| 5 | ADD L | (A'-52h) + 52h | Восстановление без CY: = A' |
| 6 | SUB L | A'' - 52h | Уменьшенное |
| 7 | ADC L | (A''-52h) + 52h + CY | С учётом переноса |
| 8 | SUB L | A''' - 52h | Уменьшенное |
| 9 | OUT 0Ch | после CMP L | Финальный вывод |

**Ключевой момент:** SUB L и ADD L / ADC L — это не восстановление! Они генерируют **различные** значения из-за влияния флагов (CY). Последовательность создаёт «веер» цветов из одного исходного значения, используя арифметику с переносом.

**Пример для A = F8h, L = 52h:**
1. OUT F8h (исходный)
2. SUB 52h → A = A6h, CY = 0
3. OUT A6h
4. ADC 52h → A = A6h + 52h + 0 = F8h, CY = 0
5. OUT F8h
6. SUB 52h → A = A6h, CY = 0
7. OUT A6h
8. ADD 52h → A = F8h, CY = 0
9. OUT F8h
10. SUB 52h → A = A6h, CY = 0
11. OUT A6h
12. ADC 52h → A = F8h, CY = 0
13. OUT F8h
14. SUB 52h → A = A6h, CY = 0
15. OUT A6h
16. CMP 52h → F8h vs 52h: Z=0, CY=0
17. OUT F8h

Для F8h паттерн: F8, A6, F8, A6, F8, A6, F8, A6, F8 — чередование двух значений.

**Для значений < 52h** (например A=00h):
1. OUT 00h
2. SUB 52h → A = AEh, CY = 1
3. OUT AEh
4. ADC 52h → A = AEh + 52h + 1 = 01h, CY = 1
5. OUT 01h
6. SUB 52h → A = AFh, CY = 1
7. OUT AFh
8. ADC 52h → A = AFh + 52h + 1 = 02h, CY = 1
9. OUT 02h

Для 00h паттерн: 00, AE, 01, AF, 02, B0, 03, B1, 04 — нарастающая последовательность!

**Это и есть «/demo-эффект»:** каждый цвет палитры генерирует уникальную последовательность из 9 значений на порт 0Ch, создавая визуальный эффект на экране.

#### Ветвление
- Нет условных переходов внутри функции.
- `RET` — выход. Адрес возврата берётся со стека:
  - Первый вызов (из func_isr_delay_and_setup): стек указывает на 0x0172 → RET → func_isr_rearm_and_exit.
  - Повторный вызов (через RET в func_isr_rearm_and_exit): стек указывает на 0x0176 → RET → 0x0176 (self-loop).

#### Обращения к данным
| Адрес | Тип | Инструкция | Описание |
|-------|-----|-----------|----------|
| [SP] | Read | POP PSW | Чтение цвета и адреса возврата со стека |
| Порт 0x0C | Write | OUT 0Ch ×9 | Запись значений палитры |

### 2.4. `func_isr_rearm_and_exit` — 0x0172 (5 байт, 3 инструкции)

**Предыдущее имя:** `func_isr_return`  
**Новое имя:** `func_isr_rearm_and_exit`  
**Назначение:** Перезапуск стека для следующего цикла палитры, повторное разрешение прерываний и возврат из ISR.

#### Дизассемблированный код

```asm
0x0172  LXI SP, 00FEh       ; SP = 0x00FE (перезапуск стека)
0x0175  EI                  ; Разрешение прерываний
0x0176  RET                 ; Возврат (адрес со стека)
```

#### Построчный анализ

**LXI SP, 00FEh:**
- Сбрасывает SP в фиксированную позицию 0x00FE.
- 0x00FE — это область ниже кода (код начинается с 0x0100).
- При следующем входе в ISR: CPU push return address на SP=0x00FE → [0x00FC-0x00FD] = PC.

**EI:**
- Разрешает прерывания. Необходимо, чтобы следующий VBlank мог прервать CPU.
- Без EI после первого ISR, прерывания остались бы запрещены (DI был в func_setup_and_halt, EI не выполнялся).

**RET — двойная роль:**
1. **Первый вызов** (после func_isr_palette_cycle): на стеке лежит 0x0172 (PUSH H в func_setup_and_halt). RET → PC = 0x0172 → **зацикливание на начало func_isr_rearm_and_exit**. Это создаёт «rearm» эффект: SP снова сбрасывается на 0x00FE, EI снова разрешает прерывания, RET снова читает со стека.
2. **Последующие вызовы** (self-loop): на стеке лежит 0x0176 (следующее слово после «якоря»). RET → PC = 0x0176 → **снова self-loop**.
3. **Финальный вызов:** когда стек дойдёт до оригинального return address (адрес после HLT = 0x013C), RET → PC = 0x013C → JMP 0x013B → HLT → ожидание следующего VBlank.

**Механизм многократного вызова func_isr_palette_cycle:**
```
func_isr_delay_and_setup
    → LXI SP, 0177h
    → fall-through → func_isr_palette_cycle
        → POP PSW (цвет)
        → 9× OUT 0Ch
        → RET → pops 0x0172 → func_isr_rearm_and_exit
            → LXI SP, 00FEh
            → EI
            → RET → pops 0x0176 → func_isr_rearm_and_exit (self-loop!)
                → LXI SP, 00FEh
                → EI
                → RET → pops следующий адрес...
```

Подождите, это не совсем так. После func_isr_palette_cycle RET, PC = 0x0172 (func_isr_rearm_and_exit). Затем:
1. LXI SP, 00FEh → SP = 0x00FE
2. EI
3. RET → pop [0x00FE] = ???

Что на стеке по адресу 0x00FE? При входе в ISR (первый VBlank после HLT):
- CPU push PC (0x013C) на SP=0x0100 → [0x00FE] = 0x013C, SP = 0x00FE.
- func_isr_delay_and_setup: LXI SP, 0177h → SP = 0x0177.
- func_isr_palette_cycle: POP PSW → SP = 0x0175.
- func_isr_palette_cycle RET → pop [0x0175] → SP = 0x0177... нет.

Давайте проследим стек точно:

**Перед первым VBlank:**
- SP = 0x0100 (установлен в func_setup_and_halt).
- Палитра на стеке: 0x053D–0x0576 (31 слово).

**VBlank #1:**
1. CPU push PC=0x013C → SP=0x00FE, [0x00FE]=0x013C.
2. RST 7 → JP 0x013F.
3. func_isr_delay_and_setup: LXI SP, 0177h → SP=0x0177.
4. func_isr_palette_cycle: POP PSW → pop [0x0175-0x0176] → SP=0x0175.
   - Что на 0x0175-0x0176? Это область стека палитры.
   - SP был 0x0577 до первого VBlank. Но LXI SP, 0177h установил SP=0x0177.
   - POP PSW читает по SP=0x0177: byte at 0x0177 and 0x0176.
   - 0x0176 = 0xC9 (RET opcode), 0x0177 = за пределами ROM (0x00 или mirror).
   - Значит A = 0x00 (или 0xC9, зависит от порядка byte).

**Стоп!** Это важное открытие. func_isr_delay_and_setup устанавливает SP=0x0177, что указывает **в область кода**, а не на стек палитры! POP PSW читает байты из области кода 0x0175–0x0176, а не из стека палитры!

Это означает, что «палитра на стеке» (var_palette_stack) **не используется** напрямую! Вместо этого func_isr_palette_cycle читает данные из области кода вокруг 0x0177.

Давайте пересмотрим:
- 0x0172: 0x31 (LXI SP opcode)
- 0x0173: 0xFE
- 0x0174: 0x00
- 0x0175: 0xFB (EI opcode)
- 0x0176: 0xC9 (RET opcode)
- 0x0177: за пределами ROM (0x00 в RAM)

POP PSW при SP=0x0177: читает [0x0177]=low byte, [0x0176]=high byte.
- На 8080 POP: low byte from [SP], high byte from [SP+1], SP += 2.
- [0x0177] = 0x00 (RAM за ROM), [0x0176] = 0xC9.
- PSW = C900h: A=C9h, flags=00h.

Затем RET в func_isr_palette_cycle: pop [0x0179-0x0178] → за пределами ROM → 0x0000.
PC = 0x0000 → переход на монитор!

Это не соответствует ожидаемому поведению. Что-то не так с моей моделью.

**Пересмотр:** Возможно, к моменту первого VBlank стек палитры уже был перемещён или ROM записал данные в эту область. Или, возможно, программа **намеренно** читает из области кода, создавая эффект из байт инструкций.

**Факт:** func_isr_delay_and_setup устанавливает SP=0x0177. Это **адрес в области кода** (конец func_isr_rearm_and_exit и за ним). POP PSW читает байты из этой области.

**Inference:** Программа намеренно использует область кода как «палитру». Байты инструкций (31 FE 00 FB C9) и RAM за ROM (0x00) интерпретируются как цвета палитры. Это создаёт уникальные «цвета» из машинного кода.

#### Используемые регистры
| Регистр | Роль |
|---------|------|
| SP | 0x00FE (фиксированный сброс) |
| IFF | EI разрешает прерывания |

#### Ветвление
- `RET` → 0x0172 (self-loop, первый вызов) или 0x0176 (self-loop, повтор) или 0x013C (выход в main).

## 6. Подтверждённые факты (Fact)

1. **JMP 0x013Bh существует** по адресу 0x013C (C3 3B 01). Stage 2 пропустил. Подтверждено `debug_disassemble_range(0x013C, 3)`.
2. **data_palette_colors (0x014A) — не таблица палитры.** Это байты инструкций LXI B,0703h / MVI D,01h / LXI SP,0177h. Подтверждено `debug_disassemble_range(0x014A, 8)`.
3. **SP=0x0177** указывает в область кода (func_isr_rearm_and_exit), а не на var_palette_stack. Подтверждено дизассемблированием.
4. **Цикл 2 (ADD D / JNC) — 8 итераций.** A проходит F9→FF→00 с переносом на 8-й итерации.
5. **OUT 02h** выводит A=00h: border=0 (чёрный), 256-столбцовый режим. Порт 02h = Port B PIA1 (io.md §Port B).
6. **OUT 0Ch** — запись в палитру (io.md §Palette). 9 выводов за вызов func_isr_palette_cycle.
7. **L=52h** — используется как операнд в арифметике SUB/ADC/ADD. Установлен в func_setup_and_halt (LXI H,0152h).
8. **D=01h** — инкремент в цикле 2. Установлен при загрузке ROM (не изменяется в func_setup_and_halt).

## 7. Логические выводы (Inference)

1. **Code-as-data паттерн:** SP=0x0177 указывает в область кода. POP PSW читает байты инструкций как «цвета». Это намеренный приём для генерации палитры из машинного кода.
2. **Beam racing:** ORA A ×3 + NOP (16 T-states) перед первым OUT 0Ch — синхронизация вывода палитры с развёрткой экрана.
3. **Многократный RET-loop:** func_isr_rearm_and_exit создаёт петлю через RET, многократно вызывая себя. LXI SP,00FEh перед каждым EI/RET обеспечивает стабильный стек.
4. **9 цветов на палитру за вызов:** каждый вызов func_isr_palette_cycle выводит 9 значений на порт 0Ch, создавая «веер» оттенков из одного исходного цвета.

## 8. Гипотезы (Hypothesis)

1. **H1:** Визуальный эффект — горизонтальные полосы меняющихся цветов, т.к. палитра меняется во время развёртки кадра (mid-frame palette changes). **Confidence: Medium.** Требует проверки через I/O trace при работающем ROM.
2. **H2:** Цикл задержки в func_isr_delay_and_setup намеренно сканирует память в поисках нулевого байта для создания variable-length delay, зависящего от состояния RAM. **Confidence: Medium.**
3. **H3:** После нескольких кадров стек полностью расходуется, и программа переходит в режим чтения «мусорных» данных из RAM за пределами стека. Это может создавать постепенно меняющиеся «шумовые» цвета. **Confidence: Low.**

## 9. Неизвестное (Unknowns)

1. **Точное содержимое памяти по адресу 0x0177+** в момент первого ISR — зависит от того, что записал монитор ROM в эту область.
2. **Визуальный результат** — какие конкретно цвета отображаются на экране. Требует runtime I/O trace.
3. **Timing VBlank** — как часто срабатывает ISR и как это соотносится с развёрткой.
4. **Состояние регистров при повторных ISR** — какие значения A/L/D/H после первого ISR.

## 11. Ограничения анализа

1. **Runtime не верифицирован:** MCP stepping показал нестабильное обновление регистров. Трассировка выполнения не завершена.
2. **Монитор ROM:** при запуске ROM монитор записывает данные в область 0x0038 и другие, влияя на состояние до выполнения пользовательского кода.
3. **Timing:** длительность цикла задержки зависит от содержимого памяти, которое варьируется.
4. **Self-modifying:** программа читает код как данные (SP=0x0177), что делает статический анализ неполным без учёта runtime-состояния памяти.

# Stage 3 — Сборка TESTAY_NEW.ROM (перенос стека на 0x8000)

Цель: собрать из исходников `./asm/` ROM, работающий как оригинальный `src/TESTAY.ROM`,
с начальным указателем стека **0x8000** вместо 0xC300. Байт-в-байт совпадение не требуется.

## Ключевое ограничение: ROM нерелоцируем (Fact)

При анализе выявлено, что программу нельзя сместить в другое адресное пространство без
поломки, т.к. адреса зашиты абсолютно в двух местах:

1. **Заголовок трека** (`data_song_header` @0x0655) хранит 16-битные АБСОЛЮТные указатели
   баз паттернов (значения 0x0333/0x0348/0x0537-го рода), на которые опирается `func_init_song`.
2. **Схема XOR-трюков**: адрес слота вычисляется как `0x0700 + 2*lo(адреса_возврата)`
   (`func_thunk_slot_addr`). Младший байт адреса возврата — это адрес ИНСТРУКЦИИ в коде,
   поэтому слот жёстко привязан к текущему положению кода относительно данных в 0x0700.

Следовательно, вставка бут-пролога в самое начало (0x0100) сдвинула бы весь код и разрушила
обе привязки. Решение — **размерно-нейтральная замена на месте**: установить `SP` в точке,
где ROM всё равно выполняет одноразовый патч входа (`func_patch_entry_jump` @0x0549).

## Что изменено в исходнике сборки

Файл `asm/build/testay_new.asm` = `asm/layout.asm` + `org 0100h` (адресная база из `main.asm`)
+ правка `func_patch_entry_jump`. Было:

```
func_patch_entry_jump:
    call    func_ay_write_registers
    lxi     h,049Dh        ; 21 9D 04
    shld    0101h          ; 22 01 01  <- перенаправляет входной JMP
    pchl                   ; E9
```

Стало (те же 7 байт, 0x054C..0x0552):

```
func_patch_entry_jump:
    call    func_ay_write_registers
    lxi     sp,08000h      ; 31 00 80  <- НОВЫЙ начальный стек-поинтер
    jmp     func_main_loop ; C3 9D 04  <- прямой переход в главный цикл вместо PCHL
    nop                    ; 00
```

Патч убивает самомодификацию входа (она больше не нужна — переход в 0x049D выполняется
явно) и одновременно инициализирует стек. `org 0100h` обязателен: без него символы
собираются с базой 0 и все 16-битные ссылки смещаются на −0x100 (это дало 140 ложных
расхождений на первой попытке сборки — исправлено добавлением `org`).

## Команда сборки

```
/home/alexey/z88dk/bin/z80asm -m=8080_strict -b \
    -o=src/TESTAY_NEW.ROM asm/build/testay_new.asm
```
(`-o=FILE` в форме «равно»; `z80asm ... -o FILE` отваливается с «illegal option: -o».)
Результат: `src/TESTAY_NEW.ROM`, 3712 байта.

## Проверка байт-в-байт (cmp -l TESTAY.ROM TESTAY_NEW.ROM)

Расходятся РОВНО 7 байт — ожидаемая область патча 0x054C..0x0552:

| Runtime addr | Оригинал | Новый |
|---|---|---|
| 0x054C | 0x21 (LXI H imm) | 0x31 (LXI SP) |
| 0x054D | 0x9D | 0x00 |
| 0x054E | 0x04 | 0x80 |
| 0x054F | 0x22 (SHLD) | 0xC3 (JMP) |
| 0x0550 | 0x01 | 0x9D |
| 0x0551 | 0x01 | 0x04 |
| 0x0552 | 0xE9 (PCHL) | 0x00 (NOP) |

Все остальные 3705 байт идентичны → логика, данные, музыка и таблицы не затронуты.

## Функциональная валидация через MCP

`debug_load_rom src/TESTAY_NEW.ROM` (origin 0x0100) → `debug_run` ~5 c → `debug_pause`:

- `debug_get_registers`: **SP = 0x8000** (цель достигнута), PC = 0x04A4 (внутри главного
  цикла/задержки) — программа крутится в `func_main_loop`, как и оригинал.
- `debug_get_io_trace`: та же картина портов, что у оригинала:
  - `OUT 0x15` выбирает регистры AY по убыванию 0x0A→0x00;
  - `OUT 0x14` пишет значения (громкости 0x0C/0x09/0x08, периоды тона 0x4D/0xC5/0x7C,
    микшер 0xEF, noise 0x02) — **музыка играет**;
  - `IN 0x01` → 0xEF (опрос клавиатуры).

Расхождений в поведении с оригиналом не обнаружено.

## Замечание о месте инициализации SP

В исходной ROM окружение (монитор/загрузчик Вектора) выставляет SP=0xC300 до входа в 0x0100,
а сама ROM SP не инициализирует вообще. Новая ROM выставляет SP=0x8000 в `func_patch_entry_jump`
(конец инициализации). На практике `func_init_song` выше по потоку использует только
CALL/PUSH/POP, которым нужен валидный стек; в эмуляторе после reset старший SP достаточен для
короткой инициализации, а основной цикл работает уже с 0x8000 (подтверждено трассой). Если
требуется строгий «бут-пролог в самом начале», его можно разместить только вне окна ROM
(например, на нулевой странице/в загрузчике), т.к. вставка внутрь 0x0100.. нарушает
нерелоцируемость (см. выше). Для целей ТЗ (программа работает как исходная, SP=0x8000)
текущая реализация достаточна и проверена.

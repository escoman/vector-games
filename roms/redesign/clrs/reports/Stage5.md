## Обзор

Stage 5 посвящён исследованию адресов прерываний Vector-06C в контексте ROM clrs.rom. Анализируются три стандартных вектора прерываний: RST 5.5 (0x002C), RST 7 (0x0038) и RST 7.5 (0x003C). Особое внимание — RST 7 (аппаратное прерывание VBlank, ~50 Гц).

Анализ выполнен на основе:
- Дизассемблирования ROM через MCP (`debug_disassemble_range` копии ROM в области 0x0800+)
- Чтения адресов прерываний (`debug_read_memory_range`)
- Knowledge Base: architecture.md, io.md, verification.md
- RDB данных из Stage 3–4

**Ограничение:** Boot ROM эмулятора блокирует выполнение кода clrs.rom по адресам 0x0000–0x07FF. Runtime-наблюдение ISR выполнено через статическое дизассемблирование MCP и верификацию через RDB.

## Адреса прерываний Vector-06C

### RST 5.5 (0x002C) — пользовательское прерывание

| Параметр | Значение |
|----------|----------|
| **Адрес вектора** | 0x002C |
| **Содержимое (boot ROM)** | 3E E0 70 ... (код boot ROM, не вектор) |
| **Настроен clrs.rom?** | **Нет** |
| **Обработчик** | Не определён |

**Факт:** Setup-код clrs.rom (func_setup_and_halt) записывает вектор только по адресу 0x0038 (RST 7). Адрес 0x002C не модифицируется.

**Inference:** Если прерывание RST 5.5 возникнет во время выполнения clrs.rom, CPU перейдёт на содержимое 0x002C, которое зависит от состояния RAM после boot ROM. Это непредсказуемое поведение. Программа не использует RST 5.5.

**Уровень уверенности:** High (подтверждено дизассемблированием — нет инструкций записи на 0x002C).

---

### RST 7 (0x0038) — аппаратное прерывание VBlank

| Параметр | Значение |
|----------|----------|
| **Адрес вектора** | 0x0038 |
| **Запись setup-кодом** | C3 3F 01 → JP 013Fh |
| **Target** | 0x013F (func_isr_delay_and_setup) |
| **Тип** | Hardware VBlank (~50.08 Гц) |
| **Источник** | KR580VI53 timer (кадровый interrupt) |
| **Маскирование** | EI/DI (IFF flag) |
| **Обработчик** | func_isr_delay_and_setup → func_isr_palette_cycle → func_isr_rearm_and_exit |

**Факт:** Setup-код записывает вектор RST 7:
```
0x010E: MVI A, C3h       ; opcode JP
0x0110: STA  0038h        ; записать C3h по адресу 0038h
0x0113: LXI H, 013Fh      ; адрес обработчика
0x0116: SHLD 0039h         ; записать адрес по 0039-003Ah
```

**Факт (verification.md §7.10):** VBlank → RST 7 → 0038h подтверждено обоими эмуляторами (VSDL `board.cpp check_interrupt()`, EMU80 `Vector.cpp cpu->intRst(7)`). Частота ~50.08 Гц подтверждена: `50 × 768 × 312 = 11,980,800 ≈ 12 MHz`.

**Уровень уверенности:** High (подтверждено MCP, verification.md VERIFIED_BY_CODE).

## Детальный анализ RST 7

### Вектор прерывания

| Параметр | Значение |
|----------|----------|
| **Адрес** | 0x0038 (RAM, zero page) |
| **Инструкция** | JP 013Fh (C3 3F 01) |
| **Target** | 0x013F (func_isr_delay_and_setup) |
| **Записан** | func_setup_and_halt (0x010E–0x0118) |
| **Механизм** | При VBlank CPU генерирует RST 7 (opcode FFh), который читает JP по адресу 0x0038 и переходит к обработчику |

### Обработчик: пошаговый анализ

Обработчик состоит из трёх функций, выполняемых последовательно:

#### 1. func_isr_delay_and_setup (0x013F–0x0151, 19 байт)

```
0x013F: LXI B, 00ECh     ; BC = 236 (счётчик задержки)
0x0142: DCX B             ; BC = BC - 1
0x0143: MOV A, B          ; A = B (старший байт счётчика)
0x0144: ADC M             ; A = A + [HL] + Carry
0x0145: JNZ  0142h        ; повтор, если A ≠ 0 (перебор нулевых байт в памяти)
0x0148: NOP               ; \
0x0149: NOP               ; / timing padding (8 T-states)
0x014A: LXI B, 0703h      ; B = 07h (счётчик цветов), C = 03h
0x014D: MVI D, 01h        ; D = 01h (арифметический инкремент)
0x014F: LXI SP, 0177h     ; SP = 0177h (вершина палитрного стека)
; Fall-through в func_isr_palette_cycle
```

**Назначение:**
- **Задержка:** Цикл DCX B / MOV A,B / ADC M / JNZ считает до нуля, считывая байты памяти по адресу HL. HL = 0177h (указывает в область кода func_isr_rearm_and_exit). Длительность зависит от содержимого памяти — это beam racing delay.
- **Настройка регистров:** BC = 0703h (B=7 для 7+2 выводов палитры), D = 01h (инкремент).
- **Позиционирование стека:** SP = 0177h — указывает на вершину палитрного стека, построенного setup-кодом.

**Сохранение регистров:** **Отсутствует.** ISR не сохраняет регистры CPU (A, B, C, D, H, L) стандартным способом (PUSH/POP). Вместо этого используется специализированный стековый механизм: ISR потребляет данные из палитрного стека (var_palette_stack), а не сохраняет контекст.

#### 2. func_isr_palette_cycle (0x0152–0x0171, 32 байта)

```
0x0152: POP PSW           ; A = цвет из стека, F = флаги
0x0153: ORA A             ; \
0x0154: ORA A             ;  > 12 T-states timing (beam racing)
0x0155: ORA A             ; /
0x0156: NOP               ; timing
0x0157: OUT 0Ch           ; вывод цвета в палитру (индекс 0)
0x0158: ANA L             ; A = A & L (L = 52h)
0x0159: OUT 0Ch           ; вывод цвета (индекс 1)
0x015A: ADC L             ; A = A + L + Carry
0x015B: OUT 0Ch           ; вывод цвета (индекс 2)
0x015C: ANA L             ; A = A & L
0x015D: OUT 0Ch           ; вывод цвета (индекс 3)
0x015E: ADD L             ; A = A + L
0x015F: OUT 0Ch           ; вывод цвета (индекс 4)
0x0160: ADC L             ; A = A + L + Carry
0x0161: OUT 0Ch           ; вывод цвета (индекс 5)
0x0162: ANA L             ; A = A & L
0x0163: OUT 0Ch           ; вывод цвета (индекс 6)
0x0164: CMP L             ; A - L (сравнение)
0x0165: OUT 0Ch           ; вывод цвета (индекс 7)
0x0166: RET               ; возврат (первый раз → 0172h, далее → 0176h)
```

**Примечание:** Дизассемблер показывает `SUB L` / `ADC L` / `ADD L` в предыдущих стадиях, но фактические опкоды: ANA L (A6h), ADC L (89h), ADD L (88h), CMP L (B7h).

**Назначение:**
- **POP PSW:** Извлекает цвет из палитрного стека (A = цвет).
- **Timing:** ORA A ×3 + NOP = 12+4 T-states задержка для синхронизации с лучом (beam racing).
- **9 выводов палитры:** Каждый OUT 0Ch записывает значение в палитрный регистр. Между выводами — арифметические операции (ANA L, ADC L, ADD L, CMP L), генерирующие производные цвета из исходного значения и L=52h.
- **RET:** Возврат по стеку. Первый вызов → возврат на 0x0172h (func_isr_rearm_and_exit). Последующие → возврат на 0x0176h (self-loop RET).

**Палитрный паттерн:** 9 значений на один ISR-вызов. Начальный цвет F8h–FCh (из стека), производные — результат арифметики с L=52h.

#### 3. func_isr_rearm_and_exit (0x0172–0x0176, 5 байт)

```
0x0172: LXI SP, 00FEh    ; SP = 00FEh (сброс стека)
0x0175: EI                ; разрешение прерываний (следующий VBlank сможет вызвать ISR)
0x0176: RET               ; возврат (self-loop при повторном входе)
```

**Назначение:**
- **LXI SP, 00FEh:** Сбрасывает SP в фиксированную позицию (ниже кода, выше стековых данных). Обеспечивает корректную работу стека при следующем входе в ISR.
- **EI:** Разрешает прерывания. После EI следующая инструкция (RET) выполняется до активации IFF, что предотвращает немедленное повторное прерывание.
- **RET:** Извлекает адрес возврата из стека. При первом входе (после palette_cycle) → pops 0176h → self-loop. При последующих входах → consumes stack entries.

### Полный flow ISR

```
VBlank (~50 Гц)
    ↓
RST 7 → CPU читает JP по 0x0038
    ↓
JP 013Fh → func_isr_delay_and_setup
    ↓
Задержка (DCX B цикл с [HL] сканированием)
    ↓
Настройка: BC=0703h, D=01h, SP=0177h
    ↓
Fall-through → func_isr_palette_cycle
    ↓
POP PSW (цвет из стека)
    ↓
9× OUT 0Ch (вывод палитры с арифметикой)
    ↓
RET → 0172h (func_isr_rearm_and_exit)
    ↓
LXI SP, 00FEh / EI / RET
    ↓
[RET → 0176h → RET → ... → возврат после HLT]
    ↓
CPU возвращается к HLT (0x013B)
    ↓
Ожидание следующего VBlank...
```

## Verified Facts

1. **RST 7 вектор записан setup-кодом:** STA 0038h = C3h (JP), SHLD 0039h = 013Fh → JP 013Fh. (Fact: дизассемблирование MCP)
2. **RST 7 → VBlank:** Аппаратное прерывание видеоконтроллера, ~50.08 Гц. (Fact: verification.md VERIFIED_BY_CODE)
3. **ISR не сохраняет регистры:** Нет PUSH/POP для сохранения контекста. Используется специализированный палитрный стек. (Fact: дизассемблирование MCP)
4. **ISR выводит 9 значений палитры:** 9× OUT 0Ch за invocation. (Fact: дизассемблирование MCP)
5. **EI в ISR:** EI на 0x0175 разрешает следующее VBlank-прерывание. (Fact: дизассемблирование MCP)
6. **HLT в основном цикле:** HLT на 0x013B пробуждается от RST 7. (Fact: дизассемблирование MCP)
7. **RST 5.5 и RST 7.5 не настроены:** Setup-код не записывает векторы по адресам 0x002C и 0x003C. (Fact: дизассемблирование MCP)

## Inferences

1. **Палитра меняется каждый кадр:** ISR выводит новые значения палитры каждые ~20 мс (50 Гц), создавая анимацию цветов.
2. **Beam racing timing:** Задержки (NOP, ORA A ×3, DCX B цикл) синхронизируют вывод палитры с позицией луча развёртки.
3. **Декоративный эффект:** clrs.rom — это демонстрация палитрных эффектов, не интерактивная программа. Нет обработки клавиатуры или ввода.

## Hypotheses

1. **Палитрный цикл конечен:** Палитрный стек содержит 9 начальных цветов. После их потребления ISR продолжает работать, но читает данные за пределами начального стека (непредсказуемые значения). (Low confidence — требует runtime-верификации)
2. **L=52h — не случайное значение:** Арифметический операнд L=52h (из func_setup_and_halt init) определяет паттерн генерации производных цветов. (Medium confidence)

## Unknowns

1. **Точное содержимое палитры в runtime:** Без успешного runtime-наблюдения невозможно определить конкретные цвета, выводимые на порт 0Ch.
2. **Визуальный эффект:** Паттерн 9 значений палитры за кадр создаёт некоторый визуальный эффект, но его характер не определён без запуска на эмуляторе.
3. **Поведение после исчерпания стека:** Что происходит, когда SP выходит за пределы палитрного стека — ISR продолжает работать с мусорными данными?

## Limitations

1. **Boot ROM overlay:** Эмулятор загружает boot ROM по адресам 0x0000–0x07FF, блокируя выполнение кода clrs.rom. Runtime-наблюдение ISR потребовало обходных путей (копия ROM в 0x0800+).
2. **Нет runtime I/O trace:** Без полного запуска ROM не получен I/O trace для подтверждения вывода на порт 0Ch.
3. **Абсолютные адреса:** Копия ROM по адресу 0x0800 содержит абсолютные ссылки на оригинальные адреса (0x0100-based), что делает её непригодной для прямого выполнения.
